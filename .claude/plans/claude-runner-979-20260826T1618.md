# claude-runner-979: Claude Code becomes an installable provider in the engine (kosmos#979, Claude half, branch A of two)

## Why

Josh's ruling (2026-08-26 10:32 CT, recorded on #979): Claude Code is a provider
like the others, not part of the platform. "Not everybody is going to have Claude
Code... we're not forcing people to have Claude Code as part of the installer."
Second-order consequence (Splinter, pinned on the card): today a failed Claude Code
download in setup preflight calls die() and kills the ENTIRE install; as a provider,
that failure must happen inside the Connect step and leave Kosmos working.

## The two-branch split, and why this branch is only A

- **Branch A (this one)**: the ENGINE knows Claude as a provider -- resolves it,
  reports it, LINKS one already on the Mac, and refuses in words when there is
  none -- with the same observable job shape OpenAI got in #987. Nothing about the
  installer changes; setup.sh still pre-installs Claude today.
  ⚠️ **It does NOT download.** The original wording of this bullet said "can
  install Claude Code in-flow", which is what two wrong implementations tried to
  deliver. Downloading is #997; see footnote two.
- **Branch B (later, gated)**: setup.sh stops pre-installing Claude. Deliberately
  held until the in-flow path exists END TO END (this branch, plus Mona Lisa's
  screens): removing the pre-install first would hand a bare-Mac Claude user the
  exact dead-end class #987 just fixed for OpenAI. Josh is walking installs today;
  the order of these two branches is the difference between his walkthrough
  passing and breaking.

## What (all engine-side)

1. **A second manifest KIND, `vendor-external`.** Claude Code is not a pinned
   tarball: its version and per-platform SHA256 are discovered at run time from the
   vendor's own manifest, which `engine/connect.js` has been reading and verifying
   since 2026-08-12. So `MANIFEST.claude` carries no `url` and no `integrity` pin,
   and says why; `pinnedVersion` and `downloadBytes` are null, spelled as null so
   the absence survives `JSON.stringify`.
2. **`install('claude')` LINKS, and refuses in words when it cannot.** A Claude Code
   already on this Mac but not at the canonical path gets a symlink (phase
   `linking`), which is setup.sh's near-miss handling carried in-flow. With none
   found, the job FAILS with a sentence a person can act on. It does not download.
   ⭐ **Downloading is #997 and is deliberately not on this branch** -- see footnote
   two. A failure is a JOB ANSWER: nothing exits, nothing kills an install, Kosmos
   keeps running. That is the `die()`-path replacement the card demands.
3. **`resolveBin('claude')`**: env `AGENT_WORKFORCE_CLAUDE_BIN` authoritative, then
   the canonical `~/.local/bin/claude`. The env rung is an absolute path and is keyed on
   nothing; the two things that share `homeDir()` are the canonical rung and
   `findElsewhere`, which is the pair that used to disagree.
4. **Present means RUNNABLE** (`accessSync(X_OK)` on a plain file), for BOTH
   providers -- the #133 folder-sails-through trap, closed on every rung.
5. **One definition of where Claude lives, in JavaScript.** `create.js`,
   `connect.js` and `subscription.js` each held their own copy; all three now call
   the resolver.
   ⚠️ **A FOURTH SPELLING SURVIVES AND IT IS NOT REACHABLE FROM HERE:**
   `install/setup.sh` has `${AGENT_WORKFORCE_CLAUDE_BIN:-$HOME/.local/bin/claude}`,
   keyed on `$HOME` rather than `AGENT_WORKFORCE_HOME`, with a comment naming
   `create.js binPaths` as the source it mirrors -- which is exactly the rung this
   branch changed. Production-identical today (both unset) and it is shell, so it
   cannot call the resolver. Recorded rather than left for someone to discover:
   "all copies agree" is true of the JS and one file too narrow as a claim.
   `connect.js`'s install child is passed the matching `HOME` so where we LOOK and
   where the vendor WRITES cannot disagree.
6. **Routes**: `/api/runners` and the install POST already iterate the manifest, so
   Claude appears with `present`/`job` for free. Both are now tested: the GET for the
   documented shape, and the POST through its **override-refusal** arm.
   ⚠️ The POST's vendor-external arm is deliberately NOT tested -- see the coverage-gap
   section: reaching it runs the default `findElsewhere`, which finds the operator's real
   Claude on any machine that has one. An earlier version of that test did exactly that
   and announced itself by returning 200 instead of a refusal.

## ⚠️ Stated coverage gap: the DEFAULT findElsewhere is not exercised

Every Claude test seams `findElsewhere` out, so the default -- the only production
code on this branch that spawns a child -- has no test. **This is deliberate and it
is not laziness.** The default probes three ABSOLUTE machine paths
(`/opt/homebrew/bin`, `/usr/local/bin`, `~/.npm-global/bin`) and then `which`. On
this Mac none of the three exist and `which claude` answers
`/Users/agent1/.local/bin/claude` -- the fleet's real, in-use Claude. Under a
sandboxed `AGENT_WORKFORCE_HOME` that answer is NOT equal to the sandbox's
canonical path, so the self-exclusion would not fire and the test would **symlink
the sandbox's canonical path at the operator's live binary**, or worse, run
`install()` against the real `~/.local/bin`.

That is precisely the sandbox escape this branch closed in `tools/browser-checks.sh`,
and writing a test that recreates it would be trading a coverage number for the
thing the coverage is meant to protect. The honest fix is a candidate-roots seam so
the default's own logic can be driven against a temp tree; that is worth doing and
it is not worth doing inside a branch about something else. Recorded, not hidden.
