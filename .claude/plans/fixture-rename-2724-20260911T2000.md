# fixture-rename-2724: avoid a live-roster fixture collision

Card: #2724. Branch: `fixture-rename-2724`. Date: 2026-09-11.

## Problem

`web.qask-clear-clamp-2808.test.js` registered a fixture named `liukang`.
On a fleet box where a created-roster worker has that name, the fixture reads
live machine state and the otherwise unrelated test fails. The collision is
with a roster-registered worker, not merely another tmux or Discord instance.

## Change

Rename only that test fixture and its lookup to `fixture_liukang`. Production
behavior is unchanged. The systemic cure remains the cut isolation tracked by
#2724; this rename is a narrow unblock for validation on the affected box.

## Verification

The changed test file passes all 11 tests. The canonical repository validation
also passes when the Codex launcher's ambient `CODEX_HOME` is removed, so tests
use their own account fixtures rather than this running agent's real sign-in.

## Decision record

Chosen: a fixture-specific name because it is reversible and cannot collide
with the registered worker that triggered the failure.

Rejected: changing production roster behavior, because this branch only needs
to remove test contamination and #2724 owns the systemic isolation work.

Weakest premise: another machine could register a worker named
`fixture_liukang`. A generated per-test identity would be stronger, but it is a
larger fixture-framework change than this unblock. Evidence of another such
collision would change this decision.
