# kosmos#8959 slice B3: the Kosmos+ address and who is signed in, native; the account screen opens no web page

Stacked on slice B2 (branch billing-8959). Base becomes origin/main once B2 merges.

## Measured (kosmos-relay origin/main, 2026-11-24 18:10 CST)
- signin.html, inside the app, still showed four things the native screen lacked after B2: "Signed in as <email>"
  (#signed-in-as), the account's address while it has no computer (#addr-line), the offer of an address to an account
  with no name (#name-offer, opening #step-name), and Open my Kosmos per address.
- Open my Kosmos, inside the app, opens the web board in the app's web view: the navy page #8952 is removing. The
  native tabs are the person's Kosmos already, so it is not ported.
- `POST /v1/account/name {name}` (signin.rs claim_name) takes the session bearer. Answers: 200 {name, address}; 400
  invalid or reserved; 409 taken / held by a computer / already owns another name; 403 the review account; 402
  address_not_bought ("... buy one at <url>, then sign in again") for an account that already had a computer.
- /me's has_name is false only with no live computer (session_view), and false for a refused device.

## The call
- Account.nameState ports the page's rules exactly: noMac = no addresses and not denied; ownAddress = noMac and an
  account_address; offer = has_name === false, not denied, no ownAddress.
- nameClean / nameValid / nameSuggest / the step's words are the page's, ported step for step; whitespace is
  JavaScript's \s exactly (review 1 measured CharacterSet differing on U+0085, U+200B and U+FEFF). The suggestion line
  goes on the first keystroke, as on the page.
- The save takes Kosmos+'s answer as the page does, with one exception: a 402 or address_not_bought is never shown in
  Kosmos+'s words, because they tell the person to buy an address at a web page (kosmos#718). The phone says "This
  account cannot choose an address." instead (review 1: no "on this iPhone", which hints at elsewhere). A 5xx reads as
  "Kosmos could not be reached just now.", not as a verdict on the name. A 401 reads "You are signed out." rather than
  the server's "no such account" (review 4); a 403 (only the review account) reads as the 402 does (review 7).
- After a save the section shows the address Kosmos+ gave ("Saved. This is your permanent private address.") and the
  /me read runs again. A 401 on that read, or no session, clears it with the rest of the account's lines (review 4).
- "Signed in as <email>" at the top, with the plan line.
- With no computer (the page's noMac from /me; before /me answers, no computer in the list that is neither retired nor
  held; review 3), the computers section says the page's "No computer is connected yet." and its how-to-connect words.
  A refused device says the page's own "Your computer said no to this device last time. It is asking again; if that
  was you, allow it there." instead (relay#217, review 7). With no email shown, "this
  email" reads "the email you signed in with". The page's download link stays off, as the page keeps it off in the
  apps (CAN_LINK_OUT).
- The offer waits while a retire, a second-step setup or a passkey is asking, so two sheets never compete (review 2).
- The "More on Kosmos+" row and its footer go. AccountView no longer takes openPage; Settings.accountURL had no other
  caller and goes with its test line.

## Rejected
- Porting Open my Kosmos: it opens the navy board, which is what this card removes.
- Showing the 402 sentence: a purchase link-out inside the app.
- Offering the name only with no computer (stricter than the page): the page's rule already means no live computer,
  since has_name is true with one.

## Tests
- LogicTests/account: 163 in the tally, 65 more than B2's 98: nameState in every page state, nameClean/nameValid cases, nameSuggest's alphabet
  and length with a fixed generator, the request, every answer including the 402 and the code alone, signedInAs.
  Mutants caught: drop the 402 arm (3 fail), drop the denied check from the offer (1), noMac always true (2), keep a
  leading hyphen (1).
- LogicTests/settings 47/47 after removing accountURL's check.
- AccountScreenUITests (still 3 methods, so ui-sample.sh's count holds): no More row or footer; Signed in as; the offer;
  the sheet prefilled with eight characters and the suggestion words; cleared, Save disabled; "Ada Love!" cleaned to
  ada-love with its preview; Save shows the address and the offer goes. Shots: account-plan, account-name-suggested,
  account-name-typed, account-name-saved, light and dark.
- Typecheck of ios/Kosmos and of the UI test file against the simulator SDK.

## Not ported, decided (review 7)
- A live computer's full address (the page printed it under Open my Kosmos). The native row shows the computer's name;
  the address is the name plus .kosmosplus.com and is shown where it matters, with no computer.
- "Your address is confirmed!" after a save on a home with a computer: unreachable, since has_name is true with one.

## Weakest premise
That nothing else on the in-app page is lost. The page's device line (#pending-note) is ported only for a refused
device (review 7); its other two forms ("already allowed", and the match code while a computer asks) are not, because
the native board shows its own allow state (BoardLogic). If a review finds a person relying on it, it is one more line from /me. The page's `notice`
line is not ported either: signin.rs sends it only in dev mode (DEV_NOTICE), never on a production coordinator.
