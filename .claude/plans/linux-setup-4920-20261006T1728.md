## What the PR does (from its description)
- Preflight accepts Linux (x86_64, aarch64).
- Finds tmux on Linux, or installs it with apt.
- Resolves a system node when the bundled runtime cannot run.
- Wires .bashrc or .profile.
- Skips the macOS app bundle and notes.
- Writes and enables a board systemd user unit, and enables linger.
- Adds a workflow that installs, starts, stops and uninstalls on ubuntu-latest.

## Change needed before review: one board unit, not two
- setup.sh writes its OWN kosmos-board.service in shell. Piece B (#4918, PR #4984) builds the board unit in
  engine/linuxboard.js, and B's review changed that unit in ways the shell copy does not have:
  - KillMode=process, so a board stop never kills the shared tmux server;
  - Restart=on-failure, because `Restart=always` restarted a stopped board every 5 seconds (measured on GitHub's
    ubuntu runner);
  - the system tmux path carried into the unit;
  - unsafe values refused.
- Two derivations of one unit drift, and the shell copy would bring back the restart loop.
- **Decided:** setup.sh calls B's `linuxboard.installBoard($KOSMOS_HOME)` through the node it has just resolved.
  This is also the production caller B deferred to D.
- So D waits for B to merge, then rebases onto it.

before the keep-alive step on the Mac path; to be checked on Linux.
