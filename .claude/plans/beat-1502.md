# beat-1502: the paneless path was inert, and a guard for the class

## What was wrong

`liveness.seen()` had **zero production callers** from the day I wrote it (#1120).
Both paneless arms gate on `liveness.alive(key) === true`, which cannot be true
with no record.

⇒ **A Windows agent could hold a valid token, report `blocked` correctly, and
never appear on any board.** #249's exact shape, in the mechanism built to
prevent it.

Runtime proof: the liveness directory had **never been created** on a machine
that has run Kosmos for a week. Control: `store.ROOT` had 20 entries.

## The fix

**`/api/report` calls `liveness.seen(who)`** after a successful record.
**A report is proof of life by definition**, so this is not a second signal to
keep in step with the first; it is the same fact, written where the roster reads
it. Throw-safe: liveness never refuses a report already recorded.

Deliberately NOT through `selfreport.record`, which refuses anything without a
state. Routing liveness through it would make a timer assert `working` and
overwrite a standing `blocked`: #900 and #1058, twice fixed.

## The number was wrong AND its premise was wrong

`STALE_AFTER_MS` was 35s, documented as *"three beats at the supervisor's
ten-second loop"*. **The supervisor never beat** (zero liveness references in the
repo copy and the installed one), **and could not have been the beater anyway**:
it runs per tmux session, and `panelessKeys` skips every key that HAS a pane. A
supervisor beat would only ever have covered agents already listed.

Now **180s**, three of `install/kosmos-report-hook.sh`'s 60s working heartbeats.
The window is bound to the actual beater's cadence, which is what the original
sentence was trying to say.

⚠️ **Its existing test asserted the wrong premise in words** and went red on the
change, naming *"three beats of agent-supervisor.sh's 10s loop"*. Restated.

## What this honestly does not cover

**An agent that reports `idle` and then genuinely says nothing sends no beat and
goes stale.** That is correct for a dead process and wrong for a quiet one, and
nothing here can tell them apart. A real beat loop in the runner closes it, and a
Windows runner needs one anyway.

## The guard, and why it is curated rather than a sweep

Splinter: *"a green suite proves the code works; nothing in it proves anything
calls the code."* Right, and two instances in one day from one author.

🛑 **I measured the blanket version before building it and it is theatre.**
315 of 643 engine exports look unwired; 150 of 462 after narrowing to functions
and excluding `set*` seams. Nearly all are constants and helpers exported for
testing, which is legitimate here. A guard with 150 false findings is dismissed
in a week.

⇒ **Entries earn their place by having actually bitten.** Two today, both mine.
