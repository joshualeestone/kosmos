# glm-7206: #7206 slice 2a, GLM (Z.ai) as a second vendor row, dark

Splinter's 10-26 call on #7206: build DeepSeek, GLM and MiniMax as one job, in three slices (DeepSeek, then GLM,
then MiniMax), each a Connect row with a key, a live check and tests. Slice 1 (DeepSeek) is merged, behind an off
switch (the compat-providers-on marker). The card was parked on DeepSeek's switch-on measurement, which hid that
slices 2 and 3 were never started.

## What (2a: the engine, no Connect flow on the page)
1. `engine/anthropiccompat.js` VENDORS gains `glm`, from Z.ai's own Claude Code guide (docs.z.ai/devpack/tool/claude,
   read 2026-11-05):
   - base `https://api.z.ai/api/anthropic`, the key as `ANTHROPIC_AUTH_TOKEN`;
   - models `glm-5.3` and `glm-5.3-flash`;
   - keys made at `z.ai/manage-apikey/apikey-list`.
2. The key check is the Coding Plan model list, `https://api.z.ai/api/coding/paas/v4/models`, which Z.ai's docs give
   Coding Plan keys. Measured with a made-up key, it answers 401. The Anthropic address cannot be the check: measured,
   it answers HTTP 200 with `{"code":401}` in the body for any key and any path, so every key would read as accepted.
3. One switch per vendor (review 1): `enabled(platform, vendor)` reads that vendor's own marker. DeepSeek keeps
   `compat-providers-on`; GLM's is `compat-glm-on`. Every place that knows its vendor asks for it, so measuring and
   switching on DeepSeek never carries GLM. The model list match stays exact.
4. `bin/agent-supervisor.sh` launches a `.kosmos-glm-*` home through the same case as DeepSeek.
5. Names wherever the engine pins every vendor:
   - the name `Z.ai GLM` in the table, the policy and the menus, with a coming-soon row in the three provider menus (#6233 requires every accepted
     provider to be named as a menu row names it);
   - the status model word;
   - the rollup's provider set.
6. The check route: with every switch off it refuses before the body, in DeepSeek's words as on main; otherwise it
   reads the account and refuses in that vendor's own name before any key is sent.
7. The agent guide's coming-soon list names DeepSeek and Z.ai GLM, as the menus do.

## Switch-on checklist for GLM (after 2b, before compat-glm-on is created)
1. A real Coding Plan key answers 200 at `api.z.ai/api/coding/paas/v4/models`.
2. Its list names `glm-5.3` exactly as the table does. If it says `GLM-5.3`, change the table's ids before switching on,
   or a good key is refused.
3. A real claude run against `api.z.ai/api/anthropic` with that key, in an empty config folder (the same measurement
   DeepSeek still owes).
4. A pay-as-you-go Z.ai key (not a Coding Plan key): if the Coding Plan list answers it 401, the add route refuses a key
   Z.ai would accept. Either the Connect flow says Coding Plan, or the check reads such a 401 as unknown.
