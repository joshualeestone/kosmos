## What finished looks like
With "Keep a copy before an agent edits a file" turned on in Settings (off by default), a closed task's receipt offers
"Undo this task's file changes": a list of the files a Claude agent edited during the task, each with what undo will do
(put back, or move a created file aside) or why it will not (changed since, another agent's edit, no copy), and a
confirm. Undo puts each chosen file back to the copy kept before the agent's first edit in the task, saving the current
version first. Nothing is deleted; nothing happens with the switch off.

## Pieces
1. engine/undo.js + routes (this commit): keep(), plan(), apply(), the switch (undo.json, no file = off).
2. Capture: the report hook calls the board (POST /api/undo/keep) just before Edit/Write/MultiEdit/NotebookEdit.
3. Page: the button and confirm list on the receipt; the switch in Settings.

## Why Kosmos's own copy, not Claude Code's backups (measured 2026-10-03)
Claude Code's file-history backups are undocumented; each is a file at some turn of the conversation (equal to commits
made around then), not "before this edit"; new files and command-made changes have none; on the busiest account 94 of
118 backups match no committed version and 227 have no backup file.

## Weakest premise
That "the copy before the agent's first edit in the task" is what a person means by undo, and that a second agent's
overlapping edit is rare (it is flagged and skipped unless chosen).

## Review 1 (opus): 1 BLOCKER, 5 WARNINGs, all taken (engine rewritten)
- BLOCKER, writing through a link: plan and apply require the file to be a plain file (or absent) now; a link or folder
  is 'not-a-file' and cannot be chosen; the file's real folder must match the one recorded at keep ('moved');
  a restore writes the copy beside the file and renames it into place (replaces the entry, never follows a link).
- The same agent on two overlapping tasks: an edit inside another task's hold is 'other-task' (choosable, unchosen).
- Incomplete history: the switch records when it was turned on; a hold that began earlier is 'incomplete' (choosable,
  unchosen). A file existing before and deleted after the close is 'gone', never brought back.
- Storage and privacy: copies only for a Kosmos agent's own Claude sessions (session id among its transcripts, or its
  folder); content-addressed blobs plus one index line per keep; files 0600, folders 0700; turning the switch off
  deletes every copy; a sweep drops what is older than 30 days at board start and at most daily. Settings says private
  files are copied too and that turning it off deletes them.
- Speed: plan and apply read one index file; apply uses the copy id plan chose.
- NITs taken: a path with a control character is refused in the engine and never sent by the CLI; the link test can
  fail now (skip only where links cannot be made).
- Remaining weakest premise (stated, not fixed): change detection is by modification time, so the person's own edits
  to a file during the task, or a tool that keeps old times, are not seen as later changes.

## Review 2 (opus): 1 BLOCKER, 6 WARNINGs, taken
- BLOCKER: turning the switch off deleted what an undo saved or moved aside (it lived inside the copies folder): those
  now live in store.ROOT/undo-saved, which neither the switch nor the sweep touches. Test: undo, switch off, still there.
- A late or missed copy was offered as "before this task": keep records the file's mtime; a first copy of a file already
  changed inside the hold, or a hold older than the copies kept, is 'incomplete'; a session missing from the agents'
  list is looked for again (at most every 5 s) before refusing.
- A failed restore could leave its temp file (old content) beside the file: removed on failure. Test.
- Moving aside across disks failed: copy, check, remove, else the original stays. Test (EXDEV).
- A file created in a new folder had no recorded folder, so the folder check was skipped: its folder must still be the
  path it was named by. Test (folder replaced by a link: nothing moved through it).
- With the switch off the route no longer works out a plan on every receipt view.
- The off-test assertion now looks where copies live. NITs taken: a torn last index line no longer swallows the next;
  stale temp blobs are swept. Not taken: the index keeps one line per edit (parse cost noted; dedupe could lose a
  hold's first copy); lexical path resolution (Claude passes normalized absolute paths).
