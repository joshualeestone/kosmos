## What finished looks like
With "Keep a copy before an agent edits a file" turned on in Settings (off by default), a closed task's receipt offers
"Undo this task's file changes": a list of the files a Claude agent edited during the task, each with what undo will do
(put back, or move a created file aside) or why it will not (changed since, another agent's edit, no copy), and a
confirm. Undo puts each chosen file back to the copy kept before the agent's first edit in the task, saving the current
version first. Nothing is deleted; nothing happens with the switch off.

## Pieces
1. engine/undo.js + routes (this commit): keep(), plan(), apply(), the switch (undo.json, no file = off).
2. Capture: the report hook calls the board (POST /api/undo/keep) just before Edit/Write/MultiEdit/NotebookEdit.
3. Page: the button and confirm list on the receipt; the switch in Settings.

## Why Kosmos's own copy, not Claude Code's backups (measured 2026-10-03)
Claude Code's file-history backups are undocumented; each is a file at some turn of the conversation (equal to commits
made around then), not "before this edit"; new files and command-made changes have none; on the busiest account 94 of
118 backups match no committed version and 227 have no backup file.

## Weakest premise
That "the copy before the agent's first edit in the task" is what a person means by undo, and that a second agent's
overlapping edit is rare (it is flagged and skipped unless chosen).
