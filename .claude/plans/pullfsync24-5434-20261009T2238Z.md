# pullfsync24-5434: a pulled feedback report is flushed before it counts (#5434 slice 24)

Addresses #5434. `engine/feedbackpull.js` `pull` writes each collected feedback report to `<dir>/<name>.md` through
`<name>.md.tmp` + rename, unflushed (#5431). `dir` defaults to Kosmos's `collected-feedback`, but a caller can name any
folder.

## Change
- The write goes through `securewrite.writeSecret(dest, md, null, { atomicOnly: true, ownTempsOnly: true, umaskDefault: true })`.
  The old rule "remove only a .tmp this call wrote, never a concurrent pull's" now holds by construction: the temp is
  securewrite's unique `wx` name, removed on failure. ownTempsOnly because `dir` can be any folder. Error accounting
  (skipped, unwritten, lastWriteError) unchanged.
- `engine/feedbackpull.test.js`: four tests forced a local write failure by planting a directory at `<name>.tmp`; they
  now refuse that report's `.kosmos-` temp at open (`blockReportWrite`), each still asserting the report went unsaved.
  The "rename fails removes the .tmp it wrote" test now checks that no `.kosmos-` temp is left. One new test: a pulled
  report is flushed before its rename.

## Decided
- **ownTempsOnly, umask mode:** the same options as the slice 3 settings writers in folders Kosmos does not own.
- **Coupling direction:** the re-aimed tests now fail if the writer goes back to the old temp name (5 fail on main),
  rather than passing for the wrong reason.

## Tests
- Mutation: main's feedbackpull.js fails 5 of 37 (the four re-aimed failure tests and the flush test). All test files
  mentioning feedbackpull pass.

## Weakest premise
That nothing outside feedbackpull reads `<name>.md.tmp`. Grepped: none.
