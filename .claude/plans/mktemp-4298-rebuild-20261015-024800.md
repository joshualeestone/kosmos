# mktemp-4298-rebuild -- template every tools/test-*.sh mktemp, enforce it statically

Card: #4298 ("Shell tests leak tmp.* into the real TMPDIR: macOS mktemp ignores TMPDIR (#4273 slice 2)").
Branch rebuilt fresh on current main after measuring PR #4324 as 5437 commits behind with broad
conflicts and a drifted site set (decision posted on #4324; see that thread).

## What finished looks like (the done-when checks)
1. `tmp` is not in `tools/test-leak-allowlist.txt` (already true on main; confirmed) AND the checker
   reports zero template-less mktemp in `tools/test-*.sh`.
2. A STATIC enforcement guard (`tools/test-mktemp-template-4298.sh` running
   `tools/mktemp-template-check.js`) is wired into `test:shell` and passes; it catches a
   template-less mktemp on macOS where the runtime per-run-root scan cannot. Proven with a live red
   control on this Mac (one bare mktemp -> guard RED, and that call lands outside the scanned root).
3. The full local heavy `tools/run-tests.sh` is green on the converged head, and CI is green.

## Why the fix
macOS `mktemp` ignores `TMPDIR` (reads `confstr(_CS_DARWIN_USER_TEMP_DIR)`), so a bare `mktemp` /
`mktemp -d` / `-t name` lands in `/var/folders/.../T/`, outside the per-run root
`tools/run-tests.sh` sets each test (`$TMPDIR/kt$$`). The suite's runtime leak scan
(`tools/lib/test-leak-guard.sh`) scans only that per-run root, so on macOS it is blind to exactly
these leaks: it goes green because it looks in the wrong directory. A positional template
`"${TMPDIR:-/tmp}/<name>.XXXXXXXXXX"` lands under `TMPDIR` and carries the leaving test's name.

## Scope decision (reversible; the weakest part named)
Scope = `tools/test-*.sh` (118 sites, 72 files). The card scopes to test-*.sh, "non-test tools/*.sh
out of scope unless they leak," and Liu Kang's ruling restated test-*.sh. The non-test scripts
(release.sh, verify-served.sh, build scripts, bin/agent-supervisor.sh, etc.) carry bare calls too
(Liu Kang counted 34 in 18 files), and the test:shell chain `bash -n`'s many of them rather than
running them, but that is NOT proof they never execute: tests NAME several (bin/agent-supervisor.sh
at line 1043 is named by 47 test files, release.sh by 53, verify-served.sh by 5), and a named
script can be invoked and run its mktemp. So whether a non-test script leaks in-suite is an open
question answered by MEASUREMENT, not asserted. I deliberately did NOT inherit #4324's 232-script
scope (tools+install+bin): that expansion is what produced the broad conflicts, and templating a
production script changes its temp-dir behavior, which the card gated behind "unless they leak."
- Weakest part: a non-test script named by a test could be executed and leak into the real temp
  root without the guard (scoped to test-*.sh) seeing it. Mitigation (required by Liu Kang m5535):
  the heavy run snapshots the real TMPDIR (/var/folders/.../T) tmp.* BEFORE and AFTER, and
  attributes each new entry to its script. A proven leaker gets templated (a test-path change only
  if possible) or filed as a follow-up; if none shows, record that it was measured, not that the
  scripts are never executed. What would change my mind: a measured real-root leak traced to a
  specific non-test script during the suite.

## Design
- `tools/mktemp-template-check.js`: ported verbatim from #4324's 15-iteration-hardened matcher
  (per-line, code-vs-string mask, wrapper list, -t-always-leaks, quoted-name, continuations).
- `tools/test-mktemp-template-4298.sh`: scope arm (git ls-files tools/test-*.sh, floor 120), checker
  arm, negative control (35 bare shapes each on its own line), positive control (templated calls,
  messages, comments not flagged). Installer-production arms from #4324 dropped (install/ out of scope).
- 118 template edits: in-place, each `mktemp [-d]` -> `mktemp [-d] "${TMPDIR:-/tmp}/<script>.XXXXXXXXXX"`.
  Verified: additions == deletions per file, every added line carries the template token, checker clean.
- Wiring: `test:shell` runs `bash -n` + the guard; shell-shard.js runs test:shell as shard 1 of 1
  locally (a full in-order run) and splits it across 2 shards in CI. CLAUDE.md convention 8.
