# sandbox-4636: a sandboxed shell is told the board is running but out of its reach (#4636, #4580 item 10)

Built on top of #4622 (sendsafe-4466, Baron), which fixes the proxy half (#4635) with loopback NO_PROXY/no_proxy
and `_listener_is_our_board`. My arms were run against #4622 and pass (#4635 comment 5897980282). This branch adds
only the sandbox half, which #4622 does not cover.

## Finished looks like
- In a sandbox that blocks connections even to 127.0.0.1 (measured with macOS `sandbox-exec (deny
  network-outbound)`): `kosmos status` says the board is running but this shell cannot connect to it, exit 5;
  `start` (person or agent) says the same and changes nothing; `post` and the other verbs say why nothing was sent.
  No verb says "not running", gives start advice, or blames another app.
- A truly hung board is still recovered by the watchdog's start (Liu Kang's caution, m3594).
- Outside a sandbox nothing changes; a stopped board is still "not running" at once.

## Cause (measured on main 5d26fa568 and on #4622 087bf0149)
In the sandbox curl cannot connect at all (curl 7, the same code as "refused"), which the probe reads as nothing
listening. `/bin/ps` is denied, so `port_listener_owner` and `running_pid` (and #4622's `_listener_is_our_board`,
built on them) come back empty, and `start` says another app holds the port. lsof still works there.

## Change
- `_health_refused`: after one re-probe half a second later (so a board that starts listening in between answers
  instead of reading unreachable), curl 7 while lsof shows an IPv4 listener on 127.0.0.1:PORT or *:PORT is HEALTH_STATE
  `unreachable` (an IPv6-only socket really refuses 127.0.0.1, so it is not evidence). An unrestricted shell connects
  to such a socket; a hung process still accepts on it, so a hang stays a timeout (busy) and its recovery is
  unchanged. The words: "Kosmos is running" only when the listener's pid (lsof) is the one this install recorded
  in board.pid (board-run writes it; read without ps); anything else is "something (name) is listening ... it may
  be Kosmos", and start refuses rather than calling it running.
- A start with KOSMOS_RECLAIM_BUSY=1 (the watchdog, setup.sh after pausing the board) FAILS on unreachable: it cannot
  see whether the old board stopped, so succeeding would let an update report success over a stale board.
- `restart` refuses on unreachable before stopping anything (it would restart the board inside the blocked shell).
- A start that launches the board from a blocked shell (the board was stopped): a board started there inherits
  the sandbox (no outside connections for it or its agents), so as soon as the new process is the listener this
  shell cannot reach, it is stopped again, its pidfile removed, and the start fails with "start it from a normal
  Terminal" (was: 30 tries, then "did not come up"). Under launchd (no pid; the board runs outside the shell) the
  start says it started but cannot be used from here. Tested (the STOPPED arm).
- `unreachable` in every verb: `say_not_up`; `status` exits 5; `start` returns before any reclaim; `board-run`
  does not launch; `stop` with no pidfile leaves it alone (no stop marker); the agent guard refuses stop/restart and
  answers start; `open` does not start one.
- `bin/board-watchdog.sh`: status exit 5 is "cannot tell from here": no start or kickstart, the down streak ends,
  logged once per spell (a marker file), cleared on any other answer. tools/test-board-watchdog-2955.sh arm 6u, with
  arm 6 as its control (red with the branch removed, measured).
- `cli.sandbox-4636.test.js`: every verb in the sandbox (status, start as person and agent, post, stop, restart,
  open, board-run, the watchdog's start), a non-node listener, the hung-board arms, and controls.

## Decided
- Exit 5, not 4 (busy) or 1 (down): the watchdog must not count it toward a restart.
- A person's `start` still clears the deliberate-stop marker first (#2955's load-bearing order), also when it then
  finds the board unreachable: starting means "I want it running", and the board is. An agent never reaches that
  line (the guard answers first). So "start starts and stops nothing", not "changes nothing".
- The watchdog does not escalate a long exit-5 spell. Under launchd it only sees 5 from a real local network fault
  (the TIME_WAIT-leak shape), where restarting cannot fix the kernel's state and would only black the board out;
  nothing reads its alert file for a person, so a person-facing alert would be a feature of its own.
- `open` refuses with exit 5 even though the browser is outside the sandbox: opening an enforcing board needs a
  nonce minted over the network this shell does not have.
- `restart --force` refuses too on unreachable (setup.sh's `restart --force ... || true` from a blocked shell then
  does nothing, as it should: it cannot see the board it would restart).
- A first cut (branch boardreach-4580) also added `--noproxy` to every curl; dropped in favour of #4622's
  loopback NO_PROXY/no_proxy, which covers the same arms (measured).

## Weakest part
- A board that starts listening between curl's refusal and lsof is covered by one re-probe after 0.5 s; one that
  takes longer to answer than that still reads unreachable for that call. Each refused probe now costs one lsof
  call, and one with a listener also the 0.5 s re-probe (also on the hook path while the board is down).
- Measured only with macOS `sandbox-exec`; a sandbox that also blocks lsof keeps the old "down" reading, and so does
  a dual-stack or IPv6 bind (KOSMOS_BIND_HOST=::), which the IPv4-only lsof filter leaves out.
- `restart` now probes once before stopping: on a hung or busy board that is up to about 2 s more. And it refuses
  on unreachable even where this shell could stop the board (ps and kill allowed, connections blocked): a person
  there has no `kosmos restart` from that shell; the message sends them to one that can reach it.
- The per-verb sandbox arms (stop, restart, open, board-run, the watchdog's start) have no removed-branch control
  each; their assertions were checked against what each verb does without its branch (stop: writes the marker and
  says "not running"; restart: stop's "left alone" message; open: not exit 5; board-run: exec of a missing runtime,
  exit 1; the watchdog's start: "another app"), all of which the assertions reject. Reasoned, not run.
