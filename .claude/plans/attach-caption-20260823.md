# attach-caption: a file waits for its words, and a message carries several (#358)

**Josh, 1:59 PM:** "if I hit the upload button, it just instantly uploads it
into the dialog and I don't get to write a caption"; then "multiple pictures
or files... and then add copy in with it." An agent's own words, relayed by
Josh: "I got the screenshot but no note came with it. What is it for?"

## What finished looks like

- Picking or dropping a file ATTACHES it: a chip beside the composer with
  its name and an x; up to ten. Nothing is sent until Send or Post.
- Send or Post carries the words and every pending file as one message
  (`attachments: [ids]`); with no words, the file names are the words. The
  chips clear only when the send is answered, so a failed send keeps them.
- The row carries `attachments` (all, in order) and `attachment` (the first),
  so the card drawn against one file keeps working until the page draws all.
- The pane's bracketed line lists every file's path in order. The room post
  and both threads accept the list; one bad id refuses the whole send; more
  than ten is refused in words.

Drawing every card for a multi-file row is the page's (Mona Lisa's) half;
the composer's styling per the pack (the + inside the box, the yellow Post)
is hers too.
