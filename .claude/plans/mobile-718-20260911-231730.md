## Decision: PWA-core, progressively wrapped

The Kosmos board already runs on a phone and is already an installable PWA
(`web/manifest.webmanifest` + the PWA head in `web/index.html`). The macOS app
(`native-app/main.swift`, #677) is "a window pointed at the board". Mobile
follows the same reuse philosophy:

- **Android store = a Trusted Web Activity (TWA)** wrapping the PWA → Google
  Play. Google's blessed path; not the "just a website" rejection a naive
  WebView wrapper hits (Apple 4.2). This is what `android/` implements.
- **Not** a from-scratch native client (forks the UI forever, discards a board
  that already works on a phone).
- **iOS store = a genuine native shell**, deferred: it needs Xcode (Josh's Apple
  ID + sudo, routed to him) and real native surface to clear Apple 4.2. Not in
  this branch.

## Load-bearing dependencies (surfaced on #718, not decided here)

- **A single fixed front-door origin** (e.g. `app.kosmos.io`) is REQUIRED: a TWA
  verifies ONE origin via Digital Asset Links (no wildcard), but the relay hands
  each user a per-user hostname. The store app must target one front door that
  routes to the user's Mac. This is a relay-architecture decision (Splinter /
  Josh), not a mobile detail. The skeleton uses `app.kosmos.io` as a clearly
  marked PLACEHOLDER in exactly one file (`strings.xml`).
- **A service worker in the board** turns the already-installable shell into a
  push-capable, offline PWA. Not built yet.
- **Push = web push, outbound from the Mac**, which fits the relay's
  outbound-only model (no inbound to the Mac needed). This is what makes the
  PWA-core choice work.

## What this branch contains

`android/`, a TWA Gradle project:
- Gradle 8.9 wrapper (real jar), AGP 8.6.1, compile/target SDK 35, minSdk 24,
  androidbrowserhelper 2.5.0. No system Gradle or Android Studio required.
- `app/` is pure TWA: zero hand-written Java/Kotlin; the LauncherActivity and
  the four config values in `strings.xml` are the whole surface.
- Launcher icons scaled per density from `web/icons/`.
- `tools/`: asset-links template + signing-fingerprint helper for Digital Asset
  Links verification.
- JDK pin: `gradle/gradle-daemon-jvm.properties` (`toolchainVersion=21`) +
  `org.gradle.java.installations.paths`, because the box default JDK 26 cannot
  run Gradle. Verified: builds green launched under the default 26.

## Weakest part of my own reasoning (named deliberately)

The front-door origin and the service worker are prerequisites owned by others,
so this skeleton is genuinely unfinishable-to-shippable on its own, it builds,
but it cannot be submitted to Play until the front door exists and the PWA has a
service worker at that origin. The risk is that a reader treats the placeholder
`app.kosmos.io` as a decision. The README and #718 both state it is not.

## Out of scope

iOS/Xcode (no toolchain here), the front-door origin itself, the service worker,
the web-push send path, Play Console setup, a real signing key.
