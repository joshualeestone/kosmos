# move-imports-6063: an account move carries the external imports answer

Card: kosmos#6063. Task 11 of Kosmos Inside Out.

## What finished looks like
1. On an account move the old account's own answer for that folder is carried over, and a missing or No answer is
   never turned into Yes.
2. A test fails on main's code and passes with the change, with a control for the never-answered case.
3. The full suite is green and a pull request is open.

## What is wrong
Claude Code asks "allow external imports?" once per folder per account. Moving a Claude agent to another account
through the board restarted it onto that question, with "No" highlighted, and an unattended agent waited there.
Kosmos already pre-answers three first-run questions on a move (folder trust, bypass consent, onboarding). This is
the fourth, and the only one where the answer is the person's, not Kosmos's.

## The card's weakest premise, checked
The card assumed two keys in `projects[<folder>]` of the account's `.claude.json` are the whole record. Read in the
installed Claude Code 2.1.296 binary:
- it asks only when `hasClaudeMdExternalIncludesApproved` and `hasClaudeMdExternalIncludesWarningShown` are both
  falsy and the folder's instructions import files outside it;
- answering writes exactly those two: approved = the answer, shown = true.
So copying both keys reproduces the earlier answer. Only that one version was read.

Also seen on this box: my own folder holds false/false on the default account and was never asked, because on the
default account the imported files sit inside the account's own folder. That is why this bites after a move.

## Change
1. `engine/trust.js`: `carryExternalImports(dir, {fromConfigDir, configDir})`. Reads the old account's entry for the
   folder. If it holds an answer (either key true) and the new account holds none, it merges the two keys into the
   new account's entry as they were. It never creates the config file and refuses on a link or an unreadable file.
2. `engine/create.js` `setAccount` (Claude path): calls it after `trustFolder`, with the account the job was on
   before the rewrite. Best effort and reported in the result as `imports`, like the three writes beside it.
3. Tests: `engine/trust.imports-6063.test.js` (eight cases), one move test in `engine/create.test.js` (out, never answered, back, and a move to the same account), and one in `engine/create.switch-claude-5091.test.js` (a provider switch carries nothing).

## Decisions
- **Chosen:** option 1 of the card, carry the person's earlier answer.
- **A No is carried as a No.** The agent then starts without waiting and without the imports, as on the old account.
- **An answer already on the new account wins.** It is that account's own answer.
- **Rejected:** writing Yes for every Kosmos agent (it is not Kosmos's answer to give); option 2 of the card
  (show the question as "needs you") as part of this change. It is still worth doing for the never-answered case
  and stays on the card.
- **Not covered:** a brand-new agent created on an account that has never seen its folder. It has no earlier
  answer to carry.
- **A provider switch onto a picked Claude account carries nothing, on purpose.** The switch lands on the main
  account for a moment and then moves, so the move would read the main account as the one being left, though the
  agent never ran there. `setProvider` passes `carryImports: false`. Found in review round 2.
- **A folder inside a git repository is not helped.** Claude Code keeps this answer under the repository's root
  there; this looks under the folder's own path, finds nothing and carries nothing. Safe, but the agent is asked
  again. Kosmos-made folders are not inside a repository. Read in the binary by a reviewer, not run. Left on the card.
- **The answer is keyed by path.** A folder removed and made again under the same name inherits the old answer on
  the old account already (Claude Code honours it there); the move extends that to one more account of the same
  person. Accepted.
- **Weakest part:** one Claude Code version was read. If a later version keys the answer differently, the copy
  does nothing and the agent waits on the question as it does today.
- **What would change my mind:** an agent that still stops on the question after a move with both keys true in
  the new account's file.
