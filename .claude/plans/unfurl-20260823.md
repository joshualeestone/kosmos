# unfurl: link previews, the engine half (#357)

**2026-08-23.** Josh, 12:05: "the board can fetch it, don't leak IPs". Mona
Lisa's page half (#377) reads `m.preview` on a message row as
`{url, title, description, image, site, fetchedAt}` and drops an image that is
not a board-served `/api/` path. This branch makes that field exist.

## What finished looks like

- `engine/unfurl.js`: one gate (`allowed`) applied to the first request and
  every redirect: http(s) only, no sign-in in the URL, no loopback, link-local,
  private, carrier-NAT, multicast or mapped address by number, no localhost /
  .local / .internal by name, and every name RESOLVED and every address it
  resolves to checked before a byte moves. Three redirects, 512 KB of page,
  5 MB of image, five seconds each; a page past the cap keeps its first
  512 KB (the tags are in the head), an image past it is refused. A refusal
  is a sentence; "no tags" is `nothing to show`. Answers cached ten minutes,
  refusals one; the image cache is budgeted by bytes.
- `/api/unfurl?url=` answers the preview with the image rewritten to
  `/api/unfurl/image?url=`; `/api/unfurl/image?url=` serves the bytes through
  the same gate, raster image types only (no SVG: script on the board's
  origin), nosniff, and a sandboxing CSP. Both refuse a request the browser
  marks as cross-site (Sec-Fetch-Site, or a Referer this board does not answer
  for), because a GET is reachable from any website the person has open.
- Every payload that carries message rows (the project room's rows, the two
  threads, `/api/messages`) runs `withPreviews`: a row whose first link is
  cached gets `preview`; a link never asked for starts its fetch and is carried
  on the next poll; a refusal attaches nothing. No payload waits for the
  internet.
- Nothing is fetched on paste; only when a message carrying the link is served.
- Agents' links are fetched the same way (card item 2), and the card says so.

## Named residual

DNS rebinding between the check and the fetch is possible and bounded by the
caps; stated in the module header rather than pretended away.
