# #5223: a Windows agent's page stops saying its window cannot be reached

**Posture:** production

## Done looks like
On Windows, an agent's AI Settings page (and a project's "Its screen" block) says plainly
that a Windows agent runs without a window and what it says is in its conversations,
instead of "we could not read its window just now (we could not reach the agents on this
computer)". Proven by a unit test that fails without the change, a Mac control that still
captures from the pane, and the new code run against this Windows box's real agent cards.

## What was wrong (measured on the Windows box, 2026-10-04, Windows 0.7.21 in prod)
`chat.viewport()` reads an agent's window with `tmux capture-pane`. Windows agents run
headless (`claude -p`, stream-json) under their supervisor; there is no tmux and no window.
The capture fails and its refusal sentence reads like an outage. Every agent page on every
Windows install shows it (checked on reh-a and on three brand-new agents during the Windows
pass of #5111).

## Change
- `engine/chat.js` `viewport()`: after the shared name and ownership gates, a card with
  `reachedByChannel === true` returns `{ text: null, because: 'on Windows an agent runs
  without a window, ...' }` before tmux is asked. The same card mark `send` already branches
  on (chat.js, #570 7c-4) and the Codex-hooks refusal uses; one derivation of "this is a
  Windows agent", made where the card is built (status.js from win32roster).
- The return also carries `noWindow: true`, so the two routes' question clause (an agent asking
  with no words of its own) says "on Windows there is no screen to read the question from"
  (`NO_WINDOW_QUESTION_BECAUSE`, server.js) instead of "could not read its screen", without
  matching the engine's wording.
- The two sibling Windows refusals that told the person to use the agent's "own window" no longer
  do. `keysAllowed` (Stop now, stop helpers, the Gemini quota Stop) says `WIN32_NO_KEYS_SENTENCE`:
  nothing was pressed, use Restart under AI Settings (Restart works on Windows, #3431); the Codex
  hooks answer just says Kosmos cannot answer it on Windows yet.
- web/index.html, two small branches on `noWindow`: the agent page sets the sentence as a sentence
  (capital, full stop) and the project page drops its "We cannot see its screen right now." lead,
  which would call a lasting fact a passing failure. Every other refusal renders as before. The
  Send box under the panel posts to the agent's thread (the Talk path), which works on Windows,
  so it stays. No browser-check pins this copy; the commit carries a Browser-check trailer, and
  the route tests pin the flag the page reads.
