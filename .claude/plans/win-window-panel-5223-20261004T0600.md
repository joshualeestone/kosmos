# #5223: a Windows agent's page stops saying its window cannot be reached

**Posture:** production

## Done looks like
On Windows, an agent's AI Settings page (and a project's "Its screen" block) says plainly
that a Windows agent runs without a window and its conversation is in its Direct Message,
instead of "we could not read its window just now (we could not reach the agents on this
computer)". Proven by a unit test that fails without the change, a Mac control that still
captures from the pane, and the new code run against this Windows box's real agent cards.

## What was wrong (measured on the Windows box, 2026-10-04, Windows 0.7.21 in prod)
`chat.viewport()` reads an agent's window with `tmux capture-pane`. Windows agents run
headless (`claude -p`, stream-json) under their supervisor; there is no tmux and no window.
The capture fails and its refusal sentence reads like an outage. Every agent page on every
Windows install shows it (checked on reh-a and on three brand-new agents during the Windows
pass of #5111).

## Change
- `engine/chat.js` `viewport()`: after the shared name and ownership gates, a card with
  `reachedByChannel === true` returns `{ text: null, because: 'on Windows an agent runs
  without a window, ...' }` before tmux is asked. The same card mark `send` already branches
  on (chat.js, #570 7c-4) and the Codex-hooks refusal uses; one derivation of "this is a
  Windows agent", made where the card is built (status.js from win32roster).
- No page change: both surfaces already show the engine's sentence. The Send box under the
  panel posts to the agent's thread (the Talk path), which works on Windows, so it stays.

## Not in scope
- The project page prefixes the sentence with "We cannot see its screen right now." That
  reads slightly odd with a permanent fact after it, but changing it is a web/index.html
  edit with browser-check cost, before Monday's public beta. Follow-up if wanted.
- #5224 (What's new says "On a Mac" on Windows): separate card.

## Evidence
- engine/chat.test.js: new #5223 test passes; with the chat.js change stashed it fails
  (control). Mac control passes. Full file: 141/144 with the change, 139/142 on plain main;
  the same 3 fail on both with identical assertion messages (Windows-environment tests:
  slow-vs-missing tmux, unreadable file, unwritable chats dir).
- server.projects.test.js "screen we cannot read SAYS so" and server.test.js "agent window
  route sits behind the knownAgent gate" pass.
- Live cards: all 7 agents on this box carry reachedByChannel=true and isNamedOurs=true;
  the worktree's viewport() fed those real cards returns the new sentence.
