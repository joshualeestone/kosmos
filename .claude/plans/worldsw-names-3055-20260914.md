# #3055 fast-follow — the switcher reads the ungated /api/worlds/names first

**Branch:** `worldsw-names-3055`
**Card:** kosmos#3055 (fast-follow to the render-side fix that merged as #3061)
**Depends on:** Pete's #3063 (GET /api/worlds/names, merged to main, squash bf3ef6cd9)

## The problem this closes

#3061 (already merged) made the Kosmos switcher not fail closed: on a failed
`/api/worlds` read it falls back to a last-known localStorage list and renders it
degraded with an honest "last-known" note, plus an 8s self-heal retry. That keeps the
user reachable, but on the actual #3055 lockout state — an UNSIGNED board left behind by
a broken switch — the switcher shows a STALE list with a stale-current-world mark,
because `/api/worlds` is token-gated and 403s/500s there.

Pete's #3063 added `GET /api/worlds/names`: an UNGATED (PUBLIC_WORLD_ROUTES) names-only
route that returns exactly what the switcher renders —
`{ worlds:[{id,name}], activeWorldId, bootedWorldId }` — and nothing else (no filesystem
paths, no agent data; there is a server test asserting no leak, and a control that a POST
is not exempt).

## The change

1. **web/index.html — `worldsFetch`:** move the PRIMARY list read from the token-gated
   `GET /api/worlds` to the ungated `GET /api/worlds/names`. Because that route answers
   200 even on the unsigned post-switch board, the switcher renders LIVE there — no stale
   note needed. The token-gated `/api/worlds` is no longer read by the switcher at all
   (it carried nothing the switcher uses beyond id/name/the two markers). The last-known
   localStorage list stays as the DEEPER fallback for the remaining failure — the board
   genuinely unreachable (a fetch throw, or `/api/worlds/names` itself down) — rendered
   degraded with the honest note; the 8s retry is unchanged. With NO cache and an
   unreachable board the switcher stays hidden (today's clean single-world degrade).

2. **docs/browser-checks/render-worldsw-lockout-3055.js:** stub the two world routes
   SEPARATELY (`/api/worlds/names` is the new primary; `/api/worlds` is the old
   token-gated route the fast-follow no longer reads). Keep the existing arms (A/A'/B/C/D)
   working — they now drive the primary read via the same `s.ok`/`s.throwIt` fields. Add
   arm E: an UNSIGNED board — `/api/worlds/names` live (200), `/api/worlds` 403, and NO
   cache — asserts the switcher renders LIVE from the names route with NO stale note and
   caches for next time. Arm E is the control that REDS on the pre-fast-follow page
   (old code reads `/api/worlds` → 403 → no cache → hidden), proving the primary-read
   swap, not just the localStorage net, cures the lockout.

## What finished looks like

- On an unsigned post-switch board the switcher renders the LIVE list from
  `/api/worlds/names`, no stale note — the user can switch back immediately.
- On a genuinely unreachable board the localStorage net still catches it (degraded +
  honest note + retry), unchanged from #3061.
- The browser-check passes headless on the new code and arm E reds on the old page.

## Weakest premise / disclosures

- **`/api/worlds/names` returns `bootedWorldId` from `worldenv.bootedWorld()`.** On an
  unsigned board that value should still name the world the board booted into;
  `worldswRender` falls back to `activeWorldId` when `bootedWorldId` is null, so the
  current-world mark is correct in the common case. If a specific unsigned state returns a
  wrong `bootedWorldId`, the mark could be off — but the list is LIVE and switching still
  works, which is the whole point (the user wants to switch away).
- **This is additive to #3061**, which is already merged. The localStorage net is retained
  deliberately; it is no longer the primary cure but remains the correct fallback for the
  board-unreachable case that the names route cannot help with.
- **The rich `/api/worlds` GET is now unread by the switcher.** Verified it was the only
  switcher reader of that route (worldswSwitch uses `/api/worlds/active`; New Kosmos uses
  POST `/api/worlds` + GET `/api/worlds/list`). No other consumer depended on `worldsFetch`
  having read the rich fields.

## What is deliberately NOT in scope

- The deeper switch-restart / per-world-token failures (symptoms #1/#2/#3 on #3055) are
  PigeonPete's engine lane. This is the render/read side only.
