# frame-mobile-718: the app frame on a phone (#718)

Addresses #718 (mobile priority, plan comment
https://github.com/joshualeestone/kosmos/issues/718#issuecomment-5825987811, Raiden's screens:
top bar, navigation between areas, agents list, home).

## Finished looks like

At every phone width (320 to 720px) the top bar is ONE row, whatever notices are showing, so a
chat has room for more than one message. Typing in any composer gives the bar's height to the
thread. The page never draws under the status bar, and that rule enforces itself.

## Change (web/index.html)

- Header at <=720px: `minmax(0, 1fr) auto` columns with `.headleft` stretched, so the world name
  is what shrinks (ellipsis). The account button shows only the face; its name stays for
  assistive tech (Label in Name, #3051).
- Header notices (`.utoast`) at <=720px become a 28px dot in their own tone; tapping it opens the
  whole notice as a card under the bar, a second tap closes it. One delegated listener
  (`utoastPeek`) because the notices are re-rendered by innerHTML from several places.
- Collapse while typing: `body:has(textarea.cinput:focus) > .apphead { display: none; }` at
  <=720px (Liu Kang m582, seam agreed with Scorpion m584). No script.
- Safe area: `--safe-top/right/bottom/left` on `:root` = `env(safe-area-inset-*, 0px)`. The
  viewport meta keeps NO `viewport-fit=cover` (Liu Kang m592/m596; the iOS shell #3688 relies on
  WebKit's default insets), so they read 0 today. Scorpion's pinned composer uses
  `var(--safe-bottom)`.
- `web.safe-area-718.test.js`: red if the viewport meta gains cover while the frame (`body` or a
  `.apphead` rule) does not pad by all four variables. Controls flip it both ways, and padding in a
  comment or on a non-frame element does not count.

## Rejected

- Adding cover now: nothing on the board needs edge-to-edge drawing yet, and cover without padding
  is the exact bug #3688 found. The test makes the pairing mandatory for whoever adds it.
- A `.safe-bottom` class instead of variables: the composer adds the inset to its own padding
  (`calc(Npx + var(--safe-bottom))`), which a class would fight.
- Letting the header wrap (the old rule): measured 233px tall at 375px with one long notice.

## Verification (measured)

- mobile-shots full sweep on this branch: 160 shots (10 screens x 4 sizes x 2 themes x Chromium
  and WebKit), 0 overflow on the frame screens (home, nav-menu, agents-list, agent-page). The only
  flag is Kano's projects screen at 375px in Chromium, which main has too (reported to Kano).
- Safe-area test: 5/5 pass; adding cover to the real meta tag turns it red on all four sides.

## Weakest part

- A notice dot is not in the keyboard tab order, so a narrow desktop window with a keyboard has to
  widen past 720px to read it.
- "The frame" in the safe-area test means `body` or `.apphead`; padding on another wrapper would
  read red. Widen the selector rather than delete the test.
- WebKit here is Playwright's engine, not iOS Safari.

## What would change my mind

Johnny's shell check against this branch showing the bar under the status bar or clipped, or a
real iPhone showing the collapse-while-typing leaving a gap when the keyboard closes.
