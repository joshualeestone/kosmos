## What finished looks like
1. The TWA opens `https://login.kosmosplus.com/` (strings.xml, the only per-deployment file).
2. Kano holds a precise, copy-pasteable spec for `/.well-known/assetlinks.json` on the
   coordinator, with the release fingerprint measured from the keystore, not remembered.
3. The APK declares notification delegation, so a web push delivered to the coordinator
   origin's service worker is posted by Chrome **under the Kosmos app's identity** (app
   name + icon, the app's own notification permission on Android 13+), and the tap is
   handled. What the tap opens is measured or stated as unmeasured, never assumed.
4. A signed debug APK (and a release APK signed with the #3447 upload key) build green,
   and the proof of each claim is recorded with the command that produced it.

## Facts measured so far (2026-09-24)
- android/ on main is a zero-code TWA: `LauncherActivity` only, placeholder origin
  `app.kosmos.io`, `POST_NOTIFICATIONS` already requested, **no DelegationService
  declared**, so notification delegation is currently OFF: pushes would show as Chrome's.
- androidbrowserhelper 2.5.0 ships `trusted.DelegationService` (its constructor registers
  `NotificationDelegationExtraCommandHandler`, i.e. the Android 13 permission bridge) and
  `trusted.NotificationPermissionRequestActivity`. Its own manifest declares neither, so the
  app must. Measured with `javap` on the cached aar.
- Upload keystore (#3447): alias `kosmos-upload`, SHA-256
  `21:4A:61:04:67:09:08:20:B0:05:DC:40:D9:EC:EE:09:65:84:44:2E:40:AB:0F:DC:0F:EF:32:E6:EC:43:78:E8`,
  measured with `tools/print-signing-fingerprint.sh` against the keystore file; matches the
  secrets-map header.
- Coordinator (`kosmos-relay` origin/main b639b9c): serves `/` (sign-in page), `/sw.js`,
  `/v1/push/vapid-key`, `/v1/push/subscribe`. **No `/.well-known/assetlinks.json` route.**
- Coordinator `sw.js` `notificationclick` opens `https://<address>/`, where `address` is
  `<mac-name>.kosmosplus.com` (notify.rs builds it). **The tap lands on the per-Mac origin,
  not on the verified coordinator origin.**

## Steps
1. strings.xml: repoint `launchUrl`, `hostName`, `assetStatements` to `login.kosmosplus.com`.
2. AndroidManifest.xml: declare
   - `com.google.androidbrowserhelper.trusted.DelegationService` (exported, intent-filter
     `android.support.customtabs.trusted.TRUSTED_WEB_ACTIVITY_SERVICE` + `DEFAULT`),
     with `android.support.customtabs.trusted.SMALL_ICON` meta-data;
   - `com.google.androidbrowserhelper.trusted.NotificationPermissionRequestActivity`.
   Add a monochrome `drawable/ic_notification` (status-bar icons must be white-on-alpha).
   Still zero hand-written Java/Kotlin.
3. assetlinks spec for Kano (posted on #718, tagged to Kano), derived from the built APK:
   package `io.kosmos.app`, fingerprints = upload key now, plus the Play app-signing key
   once Josh's Play account exists (Play re-signs; without it, Play installs fail to verify).
   Serving rules: HTTPS, 200 with no redirect, `Content-Type: application/json`, public.
   Update `tools/assetlinks.template.json` to the real shape.
4. Build `assembleDebug` and `assembleRelease` (upload-key signed); verify with
   `apksigner verify --print-certs` and `aapt2 dump xmltree` that the manifest carries the
   service, the permission activity, and the new origin.
5. Device proof, as far as this box allows. There is no emulator or device on Mortals
   (`emulator`/system images absent, `adb devices` empty). Decision: install the SDK
   emulator + one Google Play x86_64/arm64 system image via the existing `sdkmanager`
   (reversible, ~3 GB, disk 380 GB free), because Chrome is what performs delegation and
   only a Play image carries Chrome. With DAL not yet served, launch Chrome with
   `--disable-digital-asset-link-verification-for-url="https://login.kosmosplus.com"` to
   exercise delegation before Kano ships the route. Measure: (a) the app launches full-screen
   on the sign-in page, (b) the notification permission prompt is the app's, (c) a
   notification shows with the Kosmos name/icon, (d) what the tap opens.
6. README: update the origin, delegation, and the tap caveat.
7. /challenge-loop, then PR with `Addresses #718`, reviewer joshualeestone.

## Risks and what is not mine
- **The tap target (biggest open item).** `sw.js` opens the per-Mac origin. That origin is
  not in the app's verified set, and it cannot be listed statically (one subdomain per user;
  DAL has no wildcards). Reasoned, not yet measured: Chrome will open it either in the app
  with a URL bar or in a Chrome tab. This is the same undecided half Liu left with
  Splinter/Josh on #2854, so I measure it and report; I do not pick the architecture.
- **`applicationId io.kosmos.app`** was chosen to mirror the old placeholder origin. It is
  permanent after the first Play upload. Not changed here (reversible until then); flagged to
  Josh as a decision to make before the first upload.
- Sign-in on the phone depends on the email sender (#718 sign-in lane); not in this slice.

## Weakest part of this plan
Step 5 depends on an emulator image with a Chrome new enough to do notification delegation
and on the coordinator's sign-in completing inside the app to get a subscription. If sign-in
cannot complete on the emulator, the push half is proven only up to "delegation is declared
and Chrome accepts the service", not "a real push arrived". I will say which one I reached.
