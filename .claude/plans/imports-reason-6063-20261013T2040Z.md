# imports-reason-6063: the card says what the external imports question asks

Card: kosmos#6063 (option 2). Task 12 of Kosmos Inside Out. Follows PR #6085.

## What finished looks like
1. On the real captured screen the reason says what is asked, not the generic prompt line.
2. An unlabelled confirm dialog still gets the generic reason, and an idle screen stays idle.
3. The full suite is green and a pull request is open.

## Measured before building
On main 7ef94612f, with Claude Code 2.1.296, I started Claude Code in a scratch folder whose CLAUDE.md imports one
file outside it, captured the question screen, and ran `classify` on it with the pane fixture the status tests use.
It already read `needs_you`, with the generic reason "it is waiting for you to answer a prompt". The family
detector for confirm dialogs (#1919) catches it. So option 2 of the card was mostly true already; what was missing
is the reason saying which question it is.

## Change
One entry in `CONSENT_PROMPT_HEADINGS` in `engine/status.js`, a few lines in `consentPrompt` that give an entry a
live-dialog check, and five tests in `engine/status.test.js` built on the captured screen (one row changed: the
imported file's path).

## Decisions
- **The heading is matched as a whole row.** The bypass heading beside it is matched anywhere in a row. A whole-row
  match means prose that quotes the question above another dialog does not label that dialog.
- **The label needs the question to be the live dialog (review round 1).** The entry names its own answer row.
  That row must be the last "Yes ..." row on the screen and the heading must sit above it. So an answered copy
  still on screen, or the heading printed on a row of its own, does not label a different dialog beneath.
- **This entry is tried before the bypass one (review round 2).** The bypass entry matches its words anywhere on
  the screen. An old mode footer, or an imported file with those words in its path, labelled the imports question
  as the bypass one, with a claim about the default that is not checked for it. That was so on main before this
  change. The bypass entry's own matching is not changed here.
- **Known limits, all recorded in the code comment.** A heading wrapped by a narrow pane, or twelve or more
  imported files (the heading leaves the 25-row tail), fall back to the generic reason. An answered copy above a
  live confirm dialog that has no "Yes" row of its own would keep this label; no such dialog is known.
- **No claim about the default answer.** The detector does not read the highlight, and an existing test forbids
  claiming it.
- **Nothing presses the answer.** It is the person's.
- **Not changed:** answer buttons on the agent's page. `chat.optionsIn` returns nothing for this screen; that is
  separate work and not measured further here.
- **Weakest part:** the heading text comes from one Claude Code version. If a later version rewords it, the card
  falls back to the generic reason, which is what it shows today.
- **What would change my mind:** a card that shows this reason for a screen that is not this question.
