# Sub-plan: #3595 phase 2, Assigner idle-assign

Author: April, 2026-09-24. Branch `assigner-idle-3595`.
**Master plan:** `.claude/plans/recommender-assigner-3595-2026-09-24.md` (the card-level plan for
all three phases; its "Assigner design" and "Build order" item 2 are the spec for this branch).
Phase 1 (Recommender) merged as #3617.

## What this branch builds
- `engine/assigner.js`: pure `step` / `runOnce`. Idle for assignment = the card is ours and reads
  `idle`, commitments read `clear`, and the agent has no open part of any task, continuously for
  `IDLE_MS` (20 min). It gives the first open part of a task nobody is on, in a live project the
  agent belongs to: soonest due date first (dated before undated), then oldest. Caps: 1 per agent
  and 10 overall per hour. A refused give refunds its charge.
- `server.js`: `heardBy` and `tellEveryoneOn` hoisted from the request handler to module scope,
  unchanged, and one `givePart()` shared by the part-assign route and the Assigner runner (parts
  valve for a process caller, `tasks.assignPart`, the pane line against the heard budget, the
  instruction re-sync). The runner is gated on live execution and reads commitments for idle
  cards only (commitments are not on the board card).
- `engine/assigner-setting.js`: default flipped ON with the behaviour (missing reads on, corrupt
  or unreadable reads off, as heartbeat-setting).
- Settings: the Assigner toggle is live with the Recommender's status contract.

## Decisions (each reversible in one commit)
- **No "held" clause.** The master plan said "not held"; Kosmos has no held state (surveyed
  2026-09-24), so the clause is dropped rather than invented. `idle` already excludes stopped,
  restarting, blocked and needs_you.
- **Commitments `unknown` never counts as clear**, so a quiet agent mid-task is left alone.
- **One task per agent at a time**: an agent with any open part is not idle for assignment.
- **The label keeps #2619's wording** ("Turn your goals into assigned work"); goals-to-tasks is
  phase 3, so the hint names only what ships.
- **Default ON, and what that actually means.** It is not only "it sets `who`": the write also
  types "you were given task N" into the agent's pane, and agents run with bypass permissions, so
  an idle agent will start on a task a person wrote down but never assigned. Splinter's 11:08
  default (Assigner ON, Recommender OFF) stands because the task is the person's own, in the
  person's own project, and the agent's normal limits (money, public posting, deletion) still
  apply; recorded on the card so Josh rules on the real behaviour.
- **Given, but never told, is not allowed**: the Assigner's pane line is not budget-gated, and a
  line that reaches nobody (COULD_NOT) takes the assignment back.
- **It may fire rarely.** Commitments go stale after 30 minutes and idle needs 20 continuous
  minutes, so an agent qualifies only if it reported `clear` recently. That errs safe; a quiet
  Assigner is not a bug.
- **Multi-part tasks**: only the first open part is given; the task then counts as somebody's, so
  its other parts are left to people.
- Weakest premise: that `clear` commitments are reported reliably enough. An agent that never
  reports reads `unknown` and is never assigned, which is the safe direction.
- What would change it: agents that are idle and clear yet already mid-task in a way the tasks
  model does not show; then the idle predicate needs another signal.
