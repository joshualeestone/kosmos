## Goal / definition of done

The iOS half of #718. Deliverable, exactly as scoped by the PM: a green
`xcodebuild` against `iphoneos26.5` from a clean clone. That is what "done"
means for this build skeleton.

Verified: `xcodebuild -project Kosmos.xcodeproj -target Kosmos -sdk iphoneos26.5
-configuration Debug CODE_SIGNING_ALLOWED=NO build` produces `Kosmos.app`, and
the same build was re-run against a clean extract of the committed tree.

## Decision: a native WKWebView shell, same shape as Android and macOS

iOS has no Trusted-Web-Activity path, and Apple rejects a repackaged website
(Review Guideline 4.2), so App Store presence needs a genuine native app that
renders the board and later grows real native surface (APNs, biometric unlock,
notification actions). This skeleton is the buildable first step: a SwiftUI app
whose `ContentView` hosts a `WKWebView` over the board, mirroring the macOS app
(`native-app/main.swift`) and the Android TWA.

## Blocking dependency (not decided here)

App Store presence is gated on the single fixed front-door origin (#2854),
identical to Android: a store app needs ONE fixed public origin routing to each
user's Mac, because the relay hands each user a per-user hostname. Xcode being
installed does NOT clear this. `KosmosConfig.boardURL` is a clearly marked
placeholder (`app.kosmos.io`), the one place to repoint.

## Buildable, not runnable; app icon deferred (same gate)

No iOS simulator runtimes are installed, and the device platform support that
`-scheme`/`-destination` wants is absent. Installing it (`xcodebuild
-downloadPlatform iOS`) is a large admin download, a Josh operator action. Two
consequences, both gated on that step: running in a simulator, and the app icon
(asset-catalog thinning queries the absent runtimes). Neither blocks the build
deliverable, which is compile+link against the SDK. The app icon is kept as
local gitignored scratch until the platform is installed.

## Weakest part of my own reasoning (named deliberately)

The `-target` build (not `-scheme`) and the absent app icon are both shaped by
the missing platform runtimes, an environment state that will change when Josh
runs the download. The risk is that a reader treats this environment-driven
shape as the intended final design. The README ties both explicitly to the
runtime install so they are revisited then.

## Out of scope

The front-door origin (#2854), the board service worker, the web-push / APNs
send path, the native surface that clears Review 4.2, a signing certificate,
App Store submission, and simulator execution.
