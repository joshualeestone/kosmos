- [NIT] server.js:12307 `.find((d) => d.device_id === id)` takes only the FIRST row with that id. The contract is one row per id, so this is correct today, but if the tunnel ever lists an id twice (for example one row per holding key), a later row carrying the session key is ignored and the removal goes through: the fail-open direction. Fix: `rows.filter((d) => d.device_id === id).some((d) => Array.isArray(d.keys) && d.keys.some((k) => ownKeys.includes(k)))`, same cost.
