# #2163 -- pre-flight permissions-expectations screen (plan)

## The ask (Josh, 2026-09-04 fresh-install test)
"A screen that comes before basically everything else that says: you're going to get
warned by these sorts of things because you're setting your agent up to help you run the
computer." Sets expectations for the macOS permission gauntlet (folder access,
Accessibility, background-activity notices) so a new user is not alarmed.

## Design decision: an interstitial, NOT a numbered pane
The first-run wizard is a numbered flow (fr-pane-1..7, FR_STEPS, per-step branches). Two
options were weighed:
- A numbered pane inserted early: faithful to "a screen", but renumbers the whole 1..7
  flow AND its ~7 browser-checks (the #1214/#1801 cascade) -- high regression risk on the
  first thing every user sees. Rejected.
- An INTERSTITIAL (id="fr-pane-intro", class "fr-pane") shown between the Success screen
  and Welcome, OUTSIDE the numbered step count (like the Success screen is). Chosen.

Reinforcing the choice: the two natural fold-hosts (the Success and Welcome panes) are
both Josh-RULED, scope-locked copy surfaces that must not carry this content -- which
confirms a distinct screen is intended, and an interstitial delivers it with zero
renumber.

## Implementation
- web/index.html: `fr-pane-intro` (the expectations copy) + `frShowExplainer()` (shows it
  from the Success "Set up Kosmos" button, sets the shared title/eyebrow/step/segs like an
  intro, focuses #fr-title for WCAG 4.1.3, and sets Continue -> frGo(2)). `frGo` hides
  `#fr-pane-intro` on entering any numbered step. Not deep-linkable; a reload returns to
  Success (correct forward-only behaviour).
- docs/browser-checks/render-preflight-2163.js: drives the real flow and asserts the
  interstitial shows before the setup steps, sets expectations, focuses the title, stands
  outside the numbered count, and Continue enters at Welcome. Wired + indexed.
- docs/browser-checks/lib-firstrun-steps.js: `paneCount` restricted to `fr-pane-<number>`
  (matching its docstring) so the non-numbered interstitial does not inflate the segment
  cross-check.
- docs/browser-checks/click-first-run.js: the fixed-click-from-Success walks bumped +1 for
  the interstitial (Section 3: 2->3; two machine-step sections: 3->4). advanceToAboutYou
  walks are content-based and absorb the extra step.

## Scope
For the LEGITIMATE, unavoidable prompts (Accessibility, background-activity notices). The
suppressible ones (the app disk-scan Documents access) STAY suppressed (#2148 / #2125
slice 1); this screen never excuses a prompt we could avoid.
