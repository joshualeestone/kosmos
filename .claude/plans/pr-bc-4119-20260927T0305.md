## Weakest part
Source-derived selectors are a heuristic. A check that builds a selector at runtime (string
concatenation, a variable) is invisible to it, and a common class like `.msg` over-selects. The
over-selection is cost, not a wrong verdict; the under-selection is the same gap as today, now
smaller. What would change my mind: a nightly showing many selected checks red on the runner
for runner reasons, which would turn the added coverage into noise.

The string scan pairs quotes naively: a regex literal holding a quote (`/'/`) can mis-pair with the
next quote on its line. Measured 2026-09-27 on all 247 checks, by blanking regex literals first and
comparing: 0 selectors lost (106 such literals; query-call extraction does not depend on the
string scan). A future check could still hit it; the symptom would be a check not selected.
A trailing `//` comment after a quote on the same line is not stripped. It sits at the end of its
line and a string cannot cross a newline, so it can only add tokens (over-select), never hide one.
