# allowcard-4524: the mobile-shots allow-card screen photographs the Allow card again (kosmos#4524)

## Finished looks like
- `mobile-shots.js --screens allow-card` produces a shot at every size, theme and engine, with no ERROR, and the shot
  shows the full request card (device, code, Allow / Deny).
- main's version errors on the same screen (the red).
- No shot is taken with the one-time Community notice over it, and a shot that is covered fails
  (Sonya's review of the first sweep, PR comment 5893138836).

## Cause
#3829's addendum: the full request card renders only on Settings > Kosmos Plus; every other view shows one compact line
("... is asking to use this Kosmos. Review"). The screen reloaded the home view and waited for
`#askcard:not([hidden]) [data-ask="allow"]`, which no longer appears there, so it timed out (8 s) at every size.

## Change
The screen stubs `/api/remote/pending` as before, then opens `?tab=settings&sec=plus` and waits for the Allow button in
the top card (`#askcard`, Plus off: no connected panel on the throwaway board) or above the connected panel
(`#plus-asks`). noServiceWorker stays (WebKit ignores page.route on a service-worker-controlled page).

After review (the first sweep's first shot, se / light / chromium, had the Community notice over the card and the
report said ok):
- The seed marks the notice seen. It completes first run before the board starts, so the board's one-time step read
  the throwaway board as an existing install and owed it the notice, which opened over whichever shot came first.
- Every shot is an ERROR (`COVERED`) if `#cmnotice` is open after it; the PNG is kept to show it.
- What's New is not checked: on a throwaway board it records the version quietly and never opens (web/index.html's
  whatsNewCheck, `!got.seen`), so a check for it could never fire and would have no control.
- allow-card fails unless the Allow button is the element at its own centre (polled up to 3 s).
- The gate slice includes allow-card (se and desktop, both engines), and a new gate arm runs
  `MSHOTS_COVER_CONTROL=cmnotice`, which must exit 2 with `COVERED: #cmnotice`. Like the leak arms its label is built
  at run time, so it runs with the full gate only, not in a per-PR selection.

## Measured
At se / light / chromium, gated: main's file ERROR on allow-card (exit 2); this one 2 shots, 0 errors (exit 0); the shot
shows the full card with the code and Allow / Deny. All sizes, themes and engines: to run after the 0.7.08 hold.

## Decided
- The compact line on the home view is not given a screen of its own here; the card allowed either, and the screen
  exists to photograph the Allow card.

## Weakest part
The new hit-test and gate arms were written without a browser run; the next box turn runs the cover control, the exact
gate mobile-shots command (both engines, se and desktop) and the 16-shot sweep, and every shot is looked at. A false
red at desktop or in WebKit is the likeliest miss.
