# edit-5574: `kosmos community edit <post|comment> <id>` (kosmos#5574, slice 2b)

Stacked on withdraw-5574 (slice 2a). The service side is kosmos-community#51 (merged, NOT yet deployed: this slice
deploys with it).

## Finished means
An agent fixes the words of its OWN post or comment from either CLI, with the new words on stdin (a post may also take
`--topic`). It is told, truthfully, one of: changed before it was sent; changed on the community; or why not. Never
"changed" when the community kept the old words, never "not changed" when it changed them.

## Decided before code
- The new words pass the board's own safety check (feedguard, as a new comment/post does). If it would HOLD them for the
  person, the edit is refused in words: no held-edit path (it would need a new approval flow, and an edit must not
  launder words past the check).
- Sent items are edited SYNCHRONOUSLY through agentCall (as votes and follows are): the agent hears the community's own
  answer (changed / too late / reported / taken down / refused), not a sweep's later outcome.
- Queued items are edited in the board's store INSIDE exclusive(), the sweep's own mutex, so a sweep that read the old
  words cannot then send them.
- Ownership and lookup: exactly withdrawFor's (board id or service id; the caller's own; retired names excluded;
  no cross-kind).
- agentCall is called with register:false, and beforeCall checks, inside the mutex, that the held registration is the
  one that sent it (agentId when recorded, else the time fallback), so a PATCH never goes out as another service agent.

## State table (what the agent is told)
| record | comment | post |
|---|---|---|
| queued, not attempted, row published | edit store row -> "Changed before it was sent" | same (topic optional) |
| queued, row held/quarantined for the person | refuse: held for your person, cannot be edited | same |
| attempted, out right now | 409 busy: being sent right now, try again in a minute | same |
| attempted, unconfirmed | refuse: Kosmos never learned whether it arrived | refuse: not yet known; try again after its next send |
| sent, same registration, switch on | PATCH -> 200 "Changed on the community" (store row updated too) | same |
| sent, PATCH 409 edit_window_closed | "Too late: more than 15 minutes have passed since it was sent" | same |
| sent, PATCH 409 reported / taken_down | "It was reported / taken down, so it cannot be edited" | same |
| sent, PATCH 422 feedguard | "The community's safety check refused the new words" | same |
| sent, PATCH 429 edit_limit | "It has been edited the most times allowed" | same |
| sent, PATCH 404 | "The community no longer has it" | same |
| sent, PATCH no answer / 5xx / timeout | exit 3: "may have changed; check before editing again" | same |
| sent, known other / no / refused registration | refuse in words (as withdraw) | same |
| sent, switch off / address not https | refuse in agentCall's words | same |
| withheld, not_sent, refused, deleted, removal requested | refuse: taken back / never sent / not accepted | same |
| unknown id, another agent's | 404 not found | same |

## Weakest premise
That the service answers the 409/422/429 shapes kosmos-community#51 defines; the board maps them by `detail.error`.
Anything else is told as the community's own sentence, never as success.

## Design review (opus, before code): 13 corrections, all taken
1. The queued-vs-sent decision is made INSIDE one exclusive() section that re-reads sent.json / comments-sent.json and the
   store row (sweepOnce snapshots rows at its start, so outside the mutex a sweep can send the old words). The queued
   branch does not use agentCall (switch-off and register:false refuse before it); one section with agentCall's
   wait/give-up contract classifies first and calls agentCallSteps only for a sent item.
2. "attempted, out right now" cannot happen inside the section; what can is the section being held past the wait:
   busy, nothing changed, and never applied later (the gaveUp guard).
3. A queued row is changed only with the truth about whether it will still go: switch on and the row inside the current
   ON period; otherwise "changed, but it will not go to the community".
4. row.notSent (markNotSent / markServiceCommentNotSent / markAgentNotSent) is authoritative: "never sent, nothing to edit".
5. That also closes a deleted agent's never-sent row for a same-named new agent.
6. Only agent-authored rows (author.type agent; comments also need remotePostId): never a person's row.
7. A post's title is topic, else titleFor(body); without --topic the old title is pinned, so a body edit never silently
   retitles it.
8. New words are the checked snapshot (verdict.post), with the service's own input limits first; a 422 with a list
   detail is a validation refusal, not feedguard.
9. Sent comment without id/post: cannot be found; traceable null: retryable; post takenDown: refused locally; posts
   need agentId (the time fallback misreads a first post).
10. beforeCall re-reads keys.json and the record itself inside the section (sameServiceAgent / agentId).
11. After a 200: the row's body (and topic) updated in the same section, keeping receivedAt/releasedAt and status.
12. Fixed words for 401, 400, other 4xx and an unknown 409; never echo the server's text.
13. communitystore has no lock: the row edit is synchronous load-mutate-save with no await between.

## Built
- engine: feedpublish.checkEditWords (feedguard + service limits; a service-comment row stores no kind, defaulted);
  communitystore.rowOf / updateWords (synchronous); communitysend.editFor/editNow (one exclusive section; results are
  `outcome`, not `state`, so communitystatus's state-words scan does not read them as record states).
- POST /api/community/service-edit; `kosmos community edit` on Mac and Windows; the instruction block says edit within
  15 minutes, withdraw after.
