# winmodes-6113: the orgenroll owner-only and unreadable-id tests hold on Windows

Addresses #6113 (items 1 and 2; item 3, engine.reachable #5548, waits on a Windows run and is not in this change).

## Finished means
- engine/orgenroll-5531.test.js passes on Windows for the right reason, with no change to what it checks on Mac and Linux.
- The comment says what keeps the two files owner-only on Windows, marked as reasoned, not measured.

## Change (test file only)
- The two `0600` mode assertions run only where POSIX modes exist (not win32). Windows reads a file back as 0666.
- The unreadable-id test: on win32 the id file is replaced by a folder of the same name (chmod 000 does not stop a
  read on Windows); Mac and Linux keep chmod 000. The original bytes are kept and restored.

## Decisions
- Chosen: gate the mode checks, and keep the unreadable case running on Windows with a folder instead of skipping it.
- Rejected: skipping the whole unreadable-id test on win32 (loses the arm that matters); an ACL check in the test
  (needs icacls and a Windows box, and the default is the profile's, not Kosmos's).
- Weakest part: the Windows protection (profile permissions: the person, SYSTEM, Administrators) is read from
  Windows' documented defaults, not measured; an icacls read is asked for on the card.
- Would change my mind: icacls output showing other users can read the file (then it is a private security report).
