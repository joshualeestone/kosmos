## Fixes (a test-environment cause, not a skip)
- test-support/tmpscope.js: on Windows the scope is resolved with realpathSync.native, so a short 8.3 TEMP
  (`RUNNER~1`) and the product's long realpath name the same file the same way; a Windows test hands a child the
  box's own TEMP and asserts the long form.
- server.projects and server.connect set USERPROFILE with HOME (os.homedir() reads USERPROFILE on Windows).
- server.projects' escape link points at the sandbox root as a junction instead of /etc.
- server.connect's "certainly alive other process" is process.ppid on Windows only (no pid 1 there); pid 1 elsewhere, unchanged. Its claude stand-in is node on Windows (no /bin/echo there; iteration 7), and every request asks for connection: close (no request reset in runner passes 11 and 12, #9282). With the node stand-in the 8 arms that read idle pass on Windows (pass 12), so their skip is gone; the 6 sign-in arms check the tmux launch, which Windows does not use (it runs engine/win32signin.js), so they skip for that reason.
- server.file-download's two name arms use a name without * or a double quote on Windows instead of skipping (iteration 6). (Pinning
  the sign-in host to darwin was tried and measured not to help on the runner; reverted.)
- project-rename #7968: only its off-Windows control line is guarded, so the Windows refusal runs on Windows.
- tools.run-tests-only-4929 and -file-timeout-6668 start the runner directly on Windows (Git Bash perl has no
  setpgrp); 4929 reads paths with either separator and the --only path in Git Bash form on Windows.
- switch-account #8666 reads the refusal in the words Windows uses; owner-only (0o600) assertions are left out on
  Windows only (a file reads 0o666 there) in supervisor-refresh, provider-accounts, qwen-accounts, preview-sweep.

## Skips, by mechanism
- Shell-script stand-ins (fake tmux, claude, codex, gemini, grok, agy, gh), which Windows cannot run by name:
  owed on #9262.
- POSIX modes (chmod-unreadable), FIFOs, names Windows does not allow, NFD names, lsof, deleting a working
  folder, macOS Terminal through osascript, linked windows, a macOS-shaped fixture folder (files-preview parity).
- Board refusals by design on Windows: DeepSeek/GLM/MiniMax, installing claude, the
  source-channel stamp in the updater, the case-blind path check.
- Stand-ins that are absolute POSIX paths (/bin/echo as codex or claude): owed on #9262.
- run-tests.sh signal and process-group arms: owed on #9278.
- The message log reader taking a folder for an empty log (a real product bug): #9279.
- An unknown runner name refused with the wrong sentence on Windows (a real product bug): #9287.
- qwen-local's two setup arms are not skipped: they run the Mac path on every system through qwenlocal.platformForTest
  (the Windows refusal keeps its own arm).
- connect (#9282, both causes found and fixed): the resets stop with connection: close and the idle arms pass with node as
  the claude stand-in (passes 11-13); the 6 sign-in arms skip because they check the tmux launch, which Windows replaces
  with engine/win32signin.js (covered by engine/connect.win32signin.test.js).

## Rejected
- Whole-file skips: only the arms that fail are skipped, so a file's passing arms keep running on Windows.
- Listing the files in ALSO (run on Windows CI): the card's method lists every file it touches in
  HOST_BRANCH_EXCLUDED; moving measured-green files to ALSO is better done once all four clusters land, so the
  Windows CI job grows once and in one place. Until then the fixes here are guarded only by these runner passes.
- A Windows-runnable stand-in program (a .cmd shim): Node will not start a .cmd without a shell, and the engine
  spawns these without one; that is #9262's work, not a skip-list change.
