# agentnav-2916 -- agent-view nav restructure (Model and Memory / Instructions / Advanced)

Card: kosmos#2916 (label: josh-review). Josh's 6.59 QA, verbatim:
"On the agent view I want to combine the model content with the memory content as well. I want to
combine the instruction content with the skills content so we'll label them. The label for the nav
will be Model and Memory and the other label will just be Instructions. We won't specifically say
Skills but we'll put the skills stuff below Instructions. And instead of Terminal being the nav
label, let's change that to Advanced."

## What finished looks like
The agent detail view's left nav has fewer pills: "Model and Memory" (shows the model and memory
sections together), "Instructions" (shows the instructions section with the skills section below it,
no "Skills" pill), and "Advanced" (the former "Terminal" pill). The separate Memory and Skills pills
are gone. Each section's own content + JS wiring is UNCHANGED.

## Approach (lowest-risk: group reveal, no DOM content moves)
`detailGo` mapped one pill to one section (1:1). Rather than physically move memory content into the
model section (which risks each section's intricate wiring: model-picker, memory controls, skills
lazy-load, instruction editor + "needs you" dot), I made one pill reveal a GROUP of adjacent
sections:
- `DETAIL_SECTION_GROUPS = { model: ['model','memory'], instr: ['instr','skills'] }`
- `DETAIL_SECTION_PILL = { memory: 'model', skills: 'instr' }` (a folded section reached
  programmatically lights its pill).
- `detailGo` reveals every section in the pill's group, hides the rest, focuses the group's FIRST
  section (the folded one sits below in DOM order, which is already the layout).
The member sections keep their own `data-sec`, ids, and handlers, so nothing about model/memory/
instr/skills internals changed.

Changes:
1. Nav: relabel `model` pill "Model and Memory" (aria-controls "d-sec-model d-sec-memory"); remove
   the `memory` and `skills` pills; `instr` pill keeps its label + adds aria-controls
   "d-sec-instr d-sec-skills"; relabel `term` pill "Terminal" -> "Advanced".
2. Section aria-labels: d-sec-model -> "Model and Memory"; d-sec-term -> "Advanced".
3. `detailGo`: group reveal + pill-highlight mapping (above).
4. Skills lazy-load: it fired on the removed `skills` pill; now fires when the `instr` pill opens
   (skills shows alongside Instructions).

## Test impact (verified + handled)
- 4 browser-checks clicked the removed `data-go="memory"` button -> updated to `data-go="model"`
  (memory content is now revealed there): render-memory-controls, regress-a-night, render-made-before,
  named-controls (its restart-dialog surface). named-controls' agent-panel section sweep list drops
  'memory' (no pill).
- No check clicked `data-go="skills"` (skills was always lazy-loaded, not swept).
- The Terminal browser-checks (render-open-terminal, render-trust-restart) reveal `#d-sec-term`
  DIRECTLY, not via a nav click, so the pill rename does not touch them.
- Node tests: web.terminal-hatch asserts the word "Terminal" appears (it still does, in the section
  content); web.token-usage's ">Model<" is the usage-table column, not the nav pill. Neither breaks.
- Structural verify (pw-runtime): "Model and Memory" reveals model+memory, "Instructions" reveals
  instr+skills, "Advanced" reveals term, a programmatic detailGo('memory') lights the model pill; no
  JS errors.

## Weakest premise (named)
That "combine" means one pill revealing two stacked sections (vs physically merging into a single
section with no internal Model/Memory sub-labels). The group-reveal keeps each section's own
aria-label (Model, Memory), so a screen-reader user hears two labeled regions under one pill. If Josh
wants a single seamless section with no internal headers, that is a larger follow-up; this delivers
the nav consolidation he asked for with the section wiring intact. josh-review, reversible.
