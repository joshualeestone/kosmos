# #7395: a key glued to an identifier after an underscore is masked

**Branch:** `akia-7395` · **Card:** kosmos#7395 (found in review round 5 of #7386) · **Taken:** Splinter, 2026-10-27 19:20.

## The defect

Every key shape in `engine/secretmask.js` PATTERNS started with `\b`, and `_` is a word character, so a key glued to an identifier never started a match. Measured on main after `_`: AWS (AKIA and ASIA), xAI, Slack, Stripe, GitLab and JWT keys showed; Anthropic, OpenAI, Google and long GitHub keys were caught only by the generic catch-all.

## The change

Each leading `\b` becomes `(?<![A-Za-z0-9])`, and the AWS id's trailing `\b` becomes `(?![A-Za-z0-9])`. A letter or digit before a prefix still blocks a match, so a word that only contains a prefix is not taken for a key. Since every place `\b` matched before a word character also has a non-alphanumeric character before it, each new pattern matches at least everywhere the old one did: no key main masked can show.

## Tests

`engine/secretmask.test.js`: every changed shape after `mcp__`, `MY_`, `_` and `x-` (each arm fails with its pattern reverted), the AWS id followed by `_prod`, and controls long enough that their shape would match with no boundary (they fail with the lookbehinds removed). 66 masking-related and repo-wide audit files: 2582 pass, 0 fail.

## Decided

A few invented `_`-joined names (use_sk-learn-pipeline-config) are now masked; none appeared in a 1.57M-line corpus of real text. An inner `_sk-` can split a long random token, as main already does with `-`.
