# s7dc4-6590: the certificate warning that pauses new browsers, acknowledged at the computer (kosmos#6590, S-7d branch c, c4)

Stacked on s7dc3-6590. The design is private (kosmos-relay `.claude/plans/s7dc-6590.md`).

## Scope (only under the board-v2 marker)
- engine `deviceCtAck(finding)`: `devices ct-ack --state-dir <d> --finding <hash>` with the finding from the same waiting
  answer; a changed finding is refused (nothing acknowledged unseen); the board's own lost-report acknowledgement is
  written only after the tunnel answered acknowledged, so the two never disagree.
- server: `POST /api/remote/waiting/ct-ack` behind the same gate as allow/drop/clear (no forwarder, made on this computer,
  this board's session, a person at the screen).
- page: while the tunnel's ctAlarm stands, "New browsers are paused" with one button, I have seen it (off when no finding
  is named); afterwards it says new browsers can ask again and to reload a waiting phone. The existing lost-report Got
  it, while ctAlarm stands, goes through the same path.

## Tests

writes the board note after; nothing to acknowledge), the route in the gate test, and browser check T11.
