## Scope (only under the board-v2 marker)
- engine `deviceCtAck(finding)`: `devices ct-ack --state-dir <d> --finding <hash>` with the finding from the same waiting
  answer; a changed finding is refused (nothing acknowledged unseen); the board's own lost-report acknowledgement is
  written only after the tunnel answered acknowledged, so the two never disagree.
- server: `POST /api/remote/waiting/ct-ack` behind the same gate as allow/drop/clear (no forwarder, made on this computer,
  this board's session, a person at the screen).
- page: while the tunnel's ctAlarm stands, "New browsers are paused" with one button, I have seen it (off when no finding
  is named); afterwards it says new browsers can ask again and to reload a waiting phone. The existing lost-report Got
  it, while ctAlarm stands, goes through the same path.

## Rebase onto main after c1 merged (2026-10-23 evening)
c1's CI fix (a poll repaints only when waitSig() changes) met this part's pause, which draws from two values waitSig
did not have: WAIT.ctFinding (the button is off without one) and WAIT.cw (the reason sentence). Without them a finding
that arrives, or a lost report becoming a foreign one, while the pause stands would never reach the screen.
- Decided: both go into waitSig (cw as the three fields the pause reads: lost, foreign, state). Browser check T11c pins
  each: a finding arriving on a poll turns the button on, and the reason follows the check's state on a poll.
- Rejected: repainting from plusCw's own path when WAIT.cw changes. It would fix cw only, and put a second paint
  trigger beside the one c1 made the single one.
- Mutants: dropping ctFinding from waitSig fails only the T11c button arm; dropping the cw fields fails only the
  reason arm. Both pass with the fix.
- Weakest premise: that nothing else paintWaiting draws changes without a poll. busy is set and cleared inside waitAct, which
  paints both times; typed is the field's own value, updated in place (a repaint would take the cursor). Both are left
  out of the signature on purpose.
