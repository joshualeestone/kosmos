# Plan: working-line dots animate continuously, not reset every poll (#3421)

## Problem
Josh, 0.6.88 live test (2026-09-22): the "<name> is working..." busy line's
three-dot `.act` animation "plays four times and then hard-resets" with an abrupt
pop/shift. Screenshot: avatar + three green dots + "Alexandra is working...".

## Root cause
The `work` keyframes (`.act i`) are already `1.1s ease-in-out infinite` and
seamless (0% == 100%). The reset was NOT the keyframes: `paintBusy` (the detail/DM
busy line `#d-busy`) ran `el.innerHTML = busyRow(...)` UNCONDITIONALLY on every
~5s poll, which recreates the `.act` dot DOM nodes and restarts their CSS loop from
0%. 1.1s x ~4.5 loops = ~5s = "plays four times then hard-resets."

The sibling painter `paintRoomBusy` (the project-room busy line) already guards
this with `if (el.innerHTML !== html) el.innerHTML = html;` ("written only when it
changed"), so the room line was fine; only `paintBusy` was unguarded.

## Decision
Add a change-guard to `paintBusy`. Do NOT copy paintRoomBusy's `innerHTML !==`
compare: `busyRow`'s initials branch (no avatar) emits an inline
`style="background:...;color:..."` that the browser reserializes (adds spaces), so
a serialized-string compare there never matches and would rebuild every poll
anyway. Instead key on the inputs `busyRow` actually varies on:
`sessionName / state / name / hasAvatar`. Rebuild only when the key changes; clear
the key when hiding. An unchanged working agent then keeps ONE continuous
animation.

## Rejected
- Editing the `work` keyframes: rejected, they are already seamless + infinite; the
  node rebuild was the defect.
- An `animation-iteration-count` / negative-delay CSS tweak: rejected, there is no
  iteration cap; the restart comes from DOM-node recreation, which CSS cannot fix.
- Copying paintRoomBusy's `innerHTML !==` guard verbatim: rejected, it is unreliable
  for busyRow's inline-styled initials branch (serialization round-trip).

## Weakest premise
That `busyRow` has no per-poll dynamic content that must refresh even when the key
is unchanged. Verified: it renders avatar (URL with no cache-buster) + name + dots
+ verb; all derive from the keyed inputs. If a future per-poll field is added to
busyRow, include it in the key.

## Files
- `web/index.html`: `paintBusy` change-guard (data-key).
- `docs/browser-checks/render-busy-anim-3421.js`: new self-serve check (node
  identity across repaints + a real-change control).
- `tools/browser-checks.sh` + `docs/browser-checks/README.md`: wiring.

## Test plan
`render-busy-anim-3421.js` drives the real `paintBusy` on a working-agent fixture
and asserts DOM-node IDENTITY: repeated repaints preserve the `.act` node (probe
survives -> animation uninterrupted); a real state change rebuilds it (control, so
the guard is not a frozen node). Node-identity, not a screenshot, because the
defect is temporal. Rides 0.6.89 with the other design polish.
