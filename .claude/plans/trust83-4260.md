# trust83-4260: trust an 8.3-spelled agent folder under the spelling Claude Code reads (kosmos#4260)

**Posture:** production

## The measurement that settled the card (Windows box, 2026-11-09, Claude Code 2.1.316)
Claude Code started interactively in a real console with an ISOLATED config (`CLAUDE_CONFIG_DIR` holding only
`hasCompletedOnboarding` and one trust entry); a helper attached to the console and read its screen.

| cwd as given | trust entry | result |
|---|---|---|
| untrusted folder | none | trust dialog (instrument control) |
| `...\trust-probe` (long) | long, fwd slashes | no dialog |
| `...\TRUST-~1` (8.3) | long only | **TRUST DIALOG** |
| `...\TRUST-~1` (8.3) | short | no dialog |
| `...\via` (junction to trust-probe) | long only | no dialog |
| `c:\users\...\trust-probe` (lowercase) | long only | no dialog |
| `Q:\trust-probe` (`subst Q:` of the parent) | long `C:/...` only | **TRUST DIALOG** |
| `Q:\trust-probe` | `Q:/trust-probe` | no dialog |

So Claude Code resolves links and case but keeps 8.3 names and a subst drive letter as given: exactly Node's JS
`fs.realpathSync`.

## Change (engine/trust.js)
- `runnerSpelling(dir, nativeKey)`: on Windows only, the JS realpath (fwd slashes) when it differs from the native
  key by more than letter case, else null: an 8.3 name and a subst drive (both measured), and by the same rule a
  mapped network drive (not measured: none here).
- `trustFolder`: also writes that key (merged, with what it displaced), in the same save. Reported apart as
  `also: { key, madeEntry, displaced?, forgettable }`, and only when written, so every answer without one keeps its
  exact shape. `forgettable` is true only when the key went into CONFIG(), the file every undo (forgetFolder) edits,
  compared case-blind on Windows (an agent on another account: an undo there could reach a same-spelled key that is
  the person's own).
- `ownedAlso(also)`: ONE rule for every path that records or takes back a second key (shaped like one, absolute key,
  not `forgettable: false`). `recordWriteInner` keeps it; `forgetFolderInner` takes it back in the same save under the
  same guards (only if it still says yes; the entry goes only if we made it). A missing or malformed `also` is
  ignored, and a malformed second-key ENTRY is skipped, so neither can block taking back the main key.
- A second-key entry we cannot read is left alone (not written, not refused): the main key is what a launch promised.
- `folderTrusted`: asks the key the runner reads (the second spelling when there is one).
- Callers: `engine/create.js` records and rolls back `also` (alongside the main key, on `already: false`);
  `engine/remove.js` passes the record's `also`. Three lines in all.

Decided (challenge-loop iteration 4, after three rounds of growing bookkeeping): when the main key was ALREADY true
(the person trusted it, or an agent made before this change relaunches), the answer stays `already: true` (a main key
the person trusted must never be recorded as ours) and the second line it adds is NOT recorded. Tracked on #8322
rather than solved here: attaching it to records by main key, recording it alone at creation and rolling it back
alone were each built and each grew new edges (stale records owning another agent's line, another account's config,
two records owning one key). Kosmos hands over the agent's own long folder name, so the second key differs from the
main one only in a PARENT folder's spelling; for the leftover line to trust a different folder, that parent would have
to be deleted and a like-named one take its 8.3 alias.

Rejected: spawning agents in the native realpath (moves the session folder of junctioned agents, losing their
`--continue`); replacing the main key with the JS spelling (that keeps case, which Claude Code corrects).
Weakest part: a folder spelled with BOTH an 8.3 name and wrong letter case gets a second key in that case; Claude
Code was not measured on that combination. The record has one second-key slot.

Out of scope, on #8322 too: the "allow external imports" answer (`carryExternalImports`, #6063) is still keyed on
the native spelling only, so an 8.3-spelled agent with external CLAUDE.md imports could still be asked that.

Reach: an agent folder recorded in 8.3 spelling or on a subst (or mapped) drive, or such an `AGENT_WORKFORCE_WORKERS`;
never a folder Kosmos creates under the long home folder. A relaunch (win32launch calls trustFolder) writes the key
for such an agent (unrecorded, as above).

## Tests (engine/trust.win32-key-2281.test.js, in the Windows CI selection)
The 8.3 spelling is asked of Windows (`%~sI`) for a long-named folder the test makes, so the arms run on any volume
that makes short names (the box and the runner; on CI a missing short name fails rather than skipping). Both keys
written and returned apart; long and lowercase spellings add nothing (control); the upgrade case (main key already
true) reports untrusted until the short key is added, then `already: true` with the main entry untouched; the
residual (no record gains the line); the undo through the record puts back the person's `false` and tools; an
unreadable second entry never blocks a launch or an undo; a `forgettable: false` key is never undone or recorded;
an undo with no or a damaged `also` behaves exactly as before; the three caller lines are pinned. The data root is
sandboxed before trust loads (the real trust-writes.json is checked unchanged after each run).

## Measured end to end
The branch's trustFolder wrote an isolated config for `...\TRUST-~1` (both keys); real Claude Code started in that
spelling went past the trust check with no dialog.
