# android-ci -- wire GitHub Actions CI for the Android module

**Card:** #718 (mobile). Next slice after the signing PR (#3447), approved by Liu
Kang (Mortal Kombat PM) as an in-lane, unblocked follow-up.

## Problem

`android/README.md` flags: "Android CI is not wired today; when it is, the runner's
JDK-21 provisioning is the piece to add." The Android module builds only when a
human runs `./gradlew` on a box with the pinned JDK 21. Nothing catches a break to
the Android build automatically.

## Scope

Add `.github/workflows/android.yml`:
- **assembleDebug** as an always-on gate (needs no secrets) on every push/PR that
  touches `android/**` or the workflow itself.
- **assembleRelease** as a CONDITIONAL job, gated on the signing secrets existing,
  so it stays inert until a repo admin provisions them.

## Decisions / guardrails

- **JDK-21 provisioning (the flagged gap):** `actions/setup-java@v4` (Temurin 21)
  sets `JAVA_HOME`, and Gradle auto-detects `JAVA_HOME` to satisfy the
  `toolchainVersion=21` daemon-JVM criteria -- that is the load-bearing mechanism.
  A control run confirmed it: with `installations.paths` pointed at a NONEXISTENT
  path (`-Dorg.gradle.java.installations.paths=/nonexistent/jdk/path`) but
  `JAVA_HOME` set to a JDK 21, `:app:assembleDebug --no-daemon` still builds green.
  Every gradle call additionally passes
  `-Dorg.gradle.java.installations.paths="$JAVA_HOME"` to replace the box-specific
  path in `android/gradle.properties` (absent on a runner) so it is never a stale
  entry -- defensive redundancy on top of `JAVA_HOME`, not the mechanism. The plain
  local build (box path present) is NOT a valid control for the override, since it
  would succeed either way; the control above and the first CI run are.
- **Runner:** `ubuntu-latest`. An Android Gradle build is platform-independent JVM
  tooling (unlike `test.yml`'s macOS-specific node suite); ubuntu is the Android-CI
  norm and ships the SDK. macos-latest is the documented fallback if a platform issue
  surfaces.
- **Advisory, not required.** Per `test.yml`'s header, branch protection was
  deliberately not enabled on this repo (it gates the whole roster and fights the
  merge-fast posture; `--admin` bypasses it). Making this a *required* status check
  is the same repo-admin decision, left to a human. This workflow is a visible signal
  the create-pr CI-watch already honors.
- **Do NOT add signing secrets myself (Liu Kang's guardrail).** Putting the upload
  keystore into GitHub Actions secrets is a repo-admin decision surfaced to Josh, not
  an autonomous call. The workflow only wires the conditional; the expected secret
  names (`KOSMOS_UPLOAD_KEYSTORE_BASE64`, `KOSMOS_UPLOAD_STORE_PASSWORD`,
  `KOSMOS_UPLOAD_KEY_PASSWORD`, `KOSMOS_UPLOAD_KEY_ALIAS`) are documented in the
  workflow as the contract for whoever provisions them.
- **Path-filtered** to `android/**` + the workflow file, so a node-only PR does not
  pay for an Android build. Safe because the check is advisory (a path-filtered
  *required* check can wedge unrelated PRs; an advisory one cannot).
- **Least privilege** (`permissions: contents: read`) and a `concurrency` group,
  mirroring `test.yml`.
- **Ordering vs #3447:** this branch is off origin/main (pre-#3447), which is safe --
  the workflow is additive/isolated (only `.github/workflows/android.yml` + this
  plan), no file overlap with #3447. The release job depends on #3447's
  `signingConfig`, but is inert (no secrets) so the dependency does not bite before
  both merge.

## Definition of done

- `.github/workflows/android.yml` added; YAML parses; assembleDebug command verified
  locally with the CI-shape `-D` override.
- On this PR's own CI, the workflow runs assembleDebug green (no secrets -> release
  step skipped).
- `/challenge-loop` to convergence; PR "Addresses #718" (non-closing).

## Weakest part (named)

I cannot run GitHub Actions locally, so the workflow's real proof is its first run on
this PR. Mitigations: the exact gradle command is verified locally; the YAML parses;
action versions are current stable (checkout@v4, setup-java@v4, setup-android@v3);
and the create-pr CI-watch will surface any red for diagnosis before merge. If the
runner's preinstalled SDK lacks a needed component, `android-actions/setup-android@v3`
+ AGP auto-download is the mitigation; macos-latest is the runner fallback.
