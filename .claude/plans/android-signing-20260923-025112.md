# android-signing -- wire Android release signing to an out-of-git upload keystore

**Card:** #718 (Android store-readiness prep). Dispatched by Liu Kang (Mortal
Kombat PM) as the reversible prep slice that does not need the external unblocks
(Play Console enrollment, front-door origin #2854).

## Problem

The TWA skeleton (#2865) ships debug-only signing. `android/app/build.gradle`
declares no `signingConfigs` and no `signingConfig` on the release build type, so
`./gradlew :app:assembleRelease` produces an **unsigned** APK. Play upload needs a
signed artifact, and the signing key must never enter git.

## Scope (this branch)

1. Create a proper Android **upload** keystore; keep all key material out of git.
2. Wire a release `signingConfig` that reads the keystore + passwords + alias from
   outside git, with a safe unsigned fallback when they are absent.
3. Re-verify the APK still builds green on current `origin/main` with the pinned
   JDK 21.

Explicitly **out of scope** (external/blocked, already surfaced to Josh): Play
Console enrollment, and deciding the front-door origin (#2854, still the
`app.kosmos.io` placeholder). The Digital Asset Links template
(`tools/assetlinks.template.json`) and fingerprint helper
(`tools/print-signing-fingerprint.sh`) already exist from #2865 and are left
unchanged.

## Approach / decisions

- **Keystore:** RSA-4096, alias `kosmos-upload`, validity ~27 years (to 2054),
  PKCS12. Filed via `/add-secret` into `~/.config/secrets/` (mode 600) as two
  credentials in the agent secrets map:
  - `kosmos-android-upload-keystore` (file-path) — the `.jks`.
  - `kosmos-android-upload-signing` (sourceable-env) — store/key passwords + alias.
  Random 48-char password, never printed. This is an *upload* key: under Play App
  Signing it is resettable by Google if lost, so generating one now is reversible.
- **Signing config:** `app/build.gradle` reads `KOSMOS_UPLOAD_KEYSTORE`,
  `KOSMOS_UPLOAD_STORE_PASSWORD`, `KOSMOS_UPLOAD_KEY_PASSWORD`,
  `KOSMOS_UPLOAD_KEY_ALIAS` from the environment (resolved once, shared by both
  config blocks). The release `signingConfig` attaches only when the keystore AND
  both passwords are present; a keystore-less checkout (fresh clone / CI) stays
  unsigned rather than failing to configure, and `assembleDebug` is never
  affected. A partial env (keystore set, a password missing) stays unsigned and
  prints a `WARN` rather than dying with an opaque packaging error.
- **assetlinks placeholder left as-is:** under Play App Signing the SHA-256 hosted
  at `/.well-known/assetlinks.json` must be Play's app-signing key, not the local
  upload key, so filling it now would be wrong.

## Definition of done

- `./gradlew :app:assembleDebug` green on `origin/main` (JDK 21).
- `./gradlew :app:assembleRelease` with the signing env produces a signed APK
  whose certificate matches the upload key (verified with `apksigner`).
- No key material or password committed anywhere.
- Standard gated flow: `/challenge-loop` to convergence, then PR "Addresses #718"
  (non-closing).

## Validation note

`android/` is a standalone Gradle module — no `Cargo.toml`, not a member of the
Rust workspace. The canonical Rust/TS validation helper detects `rust` from the
root `Cargo.toml` alone and would validate a build system this diff cannot touch
while failing on a missing `DATABASE_URL` in the worktree. Validation for this
diff is therefore the Gradle build (assembleDebug + signed assembleRelease +
apksigner cert match), which is the applicable and sufficient check.
