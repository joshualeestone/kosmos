# orgchart-agents-1280 — upload an org chart, get a working agent structure

## Objective (Josh's ruling, on the card)
THROUGHPUT, not interpretation. "If I could upload a simple org chart with 15 or 20 people and their
titles, we could spin up all those agents almost instantly." The value is spinning up a whole digital
workforce in seconds, not a clever chart parser. Ruled decisions on #1280:
- It is a **4th option in the existing create-agent flow** (after: project manager (recommended) /
  pick your own role / define your own role). It is the only one that creates MANY agents.
- Input tolerant: "paste names and titles" as text; degrade to that rather than demanding a real chart file.
- **Derive agents from TITLES; the person's name is a label the operator opts into** (do not name agents
  after real people by default — logs/commits/messages under a real name have consequences).
- Do NOT resume `origin/org-chart` (stale 2026-08-22, built on the pre-correction "interpretation"
  objective; superseded).

## What already exists (do NOT rebuild)
- **Batch-create backend is DONE**: `POST /api/team` (server.js, `pathname === '/api/team'`) → 
  `engine/team.createTeam` (merged #2247, the #1279 authoring seam). Takes `{ purpose, members:[{name, role, ...}] }`,
  cap-checked (`DEFAULT_TEAM_CAP` / `MAX_TEAM_CAP`, `resolveCap`), liveness-checked at parity with
  `POST /api/agents`, provenance (creator+purpose) stamped per member, returns
  `{ outcome, created:[], refused:[{name, because}], because }`. Auth: loopback + agent-token or board-token
  (the board UI has the board token).
- **Single-agent file-import UI pattern (#1652)** in the create flow: `import-file-btn` / `import-file`
  input / `import-msg` status (web/index.html ~10118-10132), and the JS around 32655+ (`/api/agent-import`).
  This is the affordance to model the paste UI on (textarea + status line + review-before-create).
- The create flow steps are driven by `cstep(which)` (web/index.html ~32234); role step holds the options.
- The client "org chart" is only a DISPLAY layout (`data-layout="org"`), NOT an input — no conflict.

## Build (frontend slice on the existing backend)
1. **4th create option** in the role step: "Upload an org chart" (label per Josh). Selecting it reveals a
   paste UI (reusing the #1652 textarea/status pattern), not the single-agent role form.
2. **Paste + parse**: a textarea, "Paste names and titles (one per line)". Parse tolerantly, one member per
   non-blank line: split on comma/tab (fallbacks) into (name, title); a single field is treated as the
   TITLE. Map each to a create spec: agent identity DERIVED FROM TITLE (a valid agent name from the title,
   `create.nameProblem`-safe), role/purpose = the title; the person's real name kept only as an opt-in label,
   never the agent's machine name by default.
3. **Preview + count + undo** (Josh's three): after parse, show "This will create N agents:" with the list
   (title → derived agent, name shown only if opted in) BEFORE committing. Cancel/undo returns to the paste
   box with the text intact (pre-commit undo). Post-commit: model an undo on the existing found-agents undo
   pattern (`render-found-undo`) if an agent-remove path is reachable; otherwise the pre-commit review is the
   guard — resolve during build and record which.
   - RESOLVED (build): shipped the PRE-COMMIT undo only ("Back to the list" returns to the paste box with the
     text intact, and Create is inside the preview box so it cannot fire without a review). No post-commit
     removal affordance is wired into this flow. Rationale: the objective is throughput, the preview with a
     count is the safety net Josh asked for, and a created agent is independently removable through the board's
     normal remove path. A post-commit bulk-undo can follow later if operators want it; it is not a gate on
     the import.
4. **Create**: `POST /api/team` with `{ purpose: <e.g. "Imported from org chart">, members }`. Surface the
   response: `created[]` → "Created N agents"; `refused[]` → list each with its `because` (name problem, cap,
   liveness remedy). Respect the cap (check `DEFAULT_TEAM_CAP`/`MAX_TEAM_CAP` cover Josh's 15-20; if the
   default is lower, surface it clearly rather than silently truncating).
