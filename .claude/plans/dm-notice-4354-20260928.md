# #4354: Kosmos's daily-limit notice clears "Nothing back yet." for good (Sonya Blade, 2026-09-28)

## Finished means (the card)
After a daily-limit pause and reset, a question the agent never answered shows "Nothing back yet." again; while
the agent is still paused, the notice alone stands with no line under it; tested both ways.

## Cause (measured on #4340)
The daily-limit sweep (swarm.sweepOnce) says its notice through swarmSweepDeps `say` -> keepAgentReply, in the
agent's name. chat.dmOwes counts every row from the agent as its answer, so the notice cleared the debt, and
nothing brought it back when the agent ran again.

## Decision
- The sweep's `say` marks its row `kosmos: true` (keepAgentReply takes `{ kosmos: true }`); appendMessage keeps
  the mark only when it is exactly `true` (its fixed field list would otherwise drop it). Every row already on
  disk has no mark and reads as the agent's own words, as before.
- `chat.dmOwes(rows, agent, { paused })`: a marked row counts as the agent having said something only while
  `paused`. No opts means not paused, so the line comes back rather than staying hidden.
- The DM thread route passes `paused` = the swarm is switched off now (`swarm.settingsOf(profile).active ===
  false`), for ANY reason: a switched-off swarm cannot answer. An unreadable profile or a non-swarm agent reads
  as running.
- The only Kosmos-authored writer in the agent's name is the sweep's `say` (checked: the outbox drain and
  /api/reply carry the agent's own words).

Rejected: skipping marked rows always (Liu Kang ruled, m2410, that the notice should stand while paused);
timing the notice out by the day boundary in dmOwes (duplicates the sweep's resume rule, and a person can
switch the swarm back on mid-day, which the profile sees and a clock does not).

## Weakest part
"Paused" is read from the profile NOW, not at the notice. If the person switches the swarm off for another
reason after a limit pause, the old notice keeps standing in until it is switched on again. That fails toward
no line while nothing can answer, which is what a switched-off agent means. What would change my mind: a
ruling that only a LIMIT pause should let the notice stand.

## Checks
- server.dm-notice-4354.test.js through the REAL sweep (swarmSweepDeps) and the REAL route: owed before the
  notice (control); paused -> clear and the stored row carries the mark; next day's sweep resumes -> owes; the
  agent's reply -> clear. Controls: without the fix it fails (no mark); with the route's pause ignored it fails
  at the paused case.
- engine/chat.dmnotice-4354.test.js: the rule (paused / running / no opts; a real reply always clears) and the
  mark through the real writer (only `true` kept; ordinary replies carry none). Sandboxed and asserted.
- web.owes-line.test.js: the source pin follows the new call.
