# sigwhy-8316: say why a node signature read threw, and keep the verdict for the run (kosmos#8316)

## Problem
tools/windows/publish-r2.ps1 Get-NodeExe falls back to the Kosmos app's runtime\node.exe only while it is Valid from the
OpenJS Foundation (#8285). (1) A Get-AuthenticodeSignature that THROWS was said as "its signature is unreadable", which
reads as an unsigned node; the known case is Windows PowerShell 5.1 started from pwsh 7 with pwsh's PSModulePath, where
the module does not load. (2) Each call re-read the signature (2 to 4 calls a run, about 0.5 s each, outside
-NodeTimeoutSec), so later calls could disagree with the one stderr line.

## Change
- A failure keeps the exception's first non-blank line (or its type name), and the line carries it after a colon.
  That includes Get-Command itself failing for the cmdlet, which is what the release PC showed (Homer, 11-11:
  5.1 started through cmd from pwsh 7 inherits pwsh's PSModulePath, and Get-Command throws CommandNotFoundException).
- A CommandNotFoundException (the command cannot run: its module did not load) takes the existing "no working
  Get-AuthenticodeSignature (check its module path)" branch, with the reason.
- Any other throw: "its signature could not be read (<reason>), so it is not known to be Valid from OpenJS Foundation".
- The verdict is kept in $script:RuntimeNodeVerdict with the file's length and last-write time
  ($script:RuntimeNodeStamp). A later call returns it without reading again while both are unchanged; if either
  changed (an update rewrote node.exe between calls, which can be minutes apart after uploads), it is read and said
  again. So the #8285 promise, a damaged or half-updated node is not run, still holds between calls. PATH's own node
  still wins on every call (checked before the kept verdict). A refusal is kept the same way.

## Rejected
- Treating every throw as "no working cmdlet": a locked or damaged file is not a module problem, and that line would
  send the reader to the module path for the wrong reason.
- Caching the PATH lookup too: it is cheap, and a node put on PATH mid-run should still win, as before.
- Keeping a Valid verdict for the whole run with no file check (the first build): it widened the check-to-run gap
  from one call to the whole run, so a rewrite in between would be run unchecked.

## Test
tools.win-publish-node-sigwhy-8316.test.js parses Get-NodeExe out of the real script and runs it under Stop and
StrictMode with a stub Get-AuthenticodeSignature (a function wins over the cmdlet, so it also holds on Windows):
a plain throw, a module that did not load, Get-Command itself failing (a stub with the release PC's non-terminating
error), a NotSigned control, a multi-line and a blank reason, Valid read once over three calls, a node put on PATH
after the verdict still winning, the file's write time alone and its length alone each causing a fresh read, and a
refusal kept over three calls.
Runs under pwsh on Mac and Linux, and under both PowerShells on the Windows job.

## Not testable here
A real 5.1-from-pwsh-7 module failure, and whether the real cmdlet's exception there is a CommandNotFoundException.
Homer runs the box check.
