# runner-install-979: the engine machinery that installs a provider's runner (kosmos#979, engine half)

## Why

Josh, live on his fresh Mac Mini (2026-08-26): picked OpenAI, generated a key, pasted
it, hit Add, and nothing visibly happened; earlier the flow told him "we could not find
the OpenAI runner on this computer." A fresh Mac cannot connect OpenAI at all:
`engine/openaiaccounts.js addWithKey()` hard-refuses when codex is missing,
`install/setup.sh` never provisions it, and the default probe path is
`/opt/homebrew/bin/codex`, which assumes Homebrew and a hand-installed codex.

Josh's ruling on the flow (2026-08-26 08:48, recorded on #979): no giant downloads or
blocking connections in the normal flow; announce what needs installing, yellow
Confirm, visible progress, "Download complete," then the credential step. Mona Lisa's
spec page carries the screens; this branch builds the engine those screens bind to.

- The UI screens and copy (Mona Lisa, after #980), pane reading / needs-you markers
  for codex agents (#244/#246 lineage), and installer (setup.sh) changes.

## Design

New module `engine/runners.js`, owning three things:

1. **Resolution, single-sourced.** `resolveBin(provider)` returns the runner path in
   priority order: `AGENT_WORKFORCE_CODEX_BIN` env override, the managed location
   `$KOSMOS_HOME/runners/openai/codex`, then the legacy `/opt/homebrew/bin/codex`.
   Today that priority list exists in TWO places with hardcoded defaults (server.js's
   add route and create.js's binPaths); both call sites move onto the one resolver so
   a runner installed by this machinery is immediately seen by agent creation too.

2. **A pinned manifest, not "latest".** Per provider: package version, the npm
   registry platform-tarball URL for darwin-arm64 (`@openai/codex-darwin-arm64`), the
   registry's vendor-published sha512 integrity for that exact tarball, and the
   real download size for the UI. Verified this morning against the live registry:
   0.149.1 exists with a published integrity value; the GitHub release
   (`codex-aarch64-apple-darwin.tar.gz`) is the fallback channel if the npm tarball
   shape surprises during execution. Same doctrine as the bundled Node ("PINNED, not
   latest: the bundle must not change under us because a release day happened").

3. **An install job with observable progress.** `install(provider)` runs one job at a
   time per provider: download to a staging file under `$KOSMOS_HOME/runners/.tmp`
   (streamed via node https, byte counts recorded as it goes), verify sha512 against
   the pinned integrity (crypto builtin; a mismatch DELETES the staging file and
   reports refusal), untar with /usr/bin/tar, stage the binary at the managed
   location, chmod +x, then PROVE it (`codex --version` exit 0, output recorded)
   before ever reporting installed. State machine per job:
   `idle -> downloading {receivedBytes, totalBytes} -> verifying -> unpacking ->
   proving -> installed | failed {because}`. All state readable at any time; a board
   restart mid-download leaves only the staging temp, which the next install sweeps.

HTTP surface (server.js):
- `GET /api/runners`: per provider `{present, bin, pinnedVersion, managed, job}`
  (field names as shipped; `pinnedVersion` is a manifest fact, never a claim about
  the binary on disk) where `job` is the live install state above. The wizard polls this for its progress bar
  (polling is the board's existing propagation idiom; no new push mechanism, and the
  root-cause question of stale screens stays on #972).
- `POST /api/runners/<provider>/install`: idempotent start (returns the running job
  if one exists; returns `installed` immediately if present).
- `POST /api/accounts/openai` (existing): when the runner is missing, responds with
  a structured `{error, needsRunner: true, provider: 'openai'}` instead of the bare
  string, so the UI can reveal the install step in place. The current error string is
  preserved verbatim inside `error` so today's UI keeps working unchanged.

## Execution notes (2026-08-26 09:53-10:00 CT)

- **The tarball was opened before the unpack shape was chosen**, and the plan's
  original guess was wrong twice over: the binary lives at
  `package/vendor/aarch64-apple-darwin/bin/codex` (not `package/bin/...`), and the
  package VENDORS sibling tools the binary resolves relative to itself
  (`codex-path/rg`, `codex-resources/zsh`, `bin/codex-code-mode-host`). Extracting one
  file would have stranded the runner from its own tools. The install therefore
  stages the whole package tree under `runners/openai/pkg/` and exposes one stable
  `runners/openai/codex` symlink, which is what the resolver and both callers use.
- **The pinned integrity is real**: the live tarball's sha512 matches the registry's
  published value exactly. Measured download size: 114,152,335 bytes (now the
  manifest's `downloadBytes`, previously null-until-measured).
- **Live proof, this machine, through the module itself** (sandboxed runners dir,
  legacy path pinned nonexistent): phases walked downloading -> verifying ->
  unpacking -> proving -> installed; the REAL binary answered `codex-cli 0.149.1`
  through the symlink (sibling resolution works); resolveBin then reports
  present+managed. Total wall clock 5.9s on this connection.
- **A failed prove takes the symlink down** so a broken runner can never read as
  present; the pkg/ tree stays for diagnosis.

## Challenge-loop iteration 1 additions (2026-08-26 10:04-10:12 CT)

One BLOCKER, three WARNINGs, one CONVENTION, four NITs from the first blind review,
all addressed:

1. BLOCKER: `install('constructor')` passed the unknown-provider guard via the
   prototype chain, reachable straight from the URL route, and its job would have
   swept a real install's staging file. MANIFEST is now null-prototyped AND the
   lookup uses `Object.hasOwn`; refused at both the module and (tested) the route.
2. The download gained a 60s socket-silence timeout, so a wedged connection fails
   the job (retryable) instead of parking `downloading` forever behind the
   idempotent join.
3. The .tmp sweep is provider-prefix-scoped, so concurrent installs of two future
   providers cannot delete each other's in-flight bytes.
4. The env override is now AUTHORITATIVE in resolveBin: an operator-set path is the
   answer, present or not, so diagnostics name the path they set (and the route
   tests become deterministic on a machine with a real legacy codex).
5. Truncated-but-clean downloads fail as truncation with byte counts, not as a
   checksum accusation; the integrity hash is streamed instead of buffering 114MB.
6. The job-shape comment documents `proved`; the plan's em dash removed; the plan's
   verification section amended to what exists (route tests added in
   server.runners.test.js, the download-seam decision stated honestly).

## Challenge-loop iteration 3 additions (2026-08-26 10:24-10:32 CT)

Three WARNINGs and five NITs, no blockers, all addressed:

1. API version honesty: the status field is now `pinnedVersion`, a fact about the
   manifest, never a claim about the binary on disk (a legacy codex of any age
   reads present). The job's `proved` line is the only field certifying what ran.
   A manifest bump does not auto-reinstall an existing runner; stated in the code,
   and that flow arrives with the first real bump.
2. Cross-process safety on the shared managed root: per-process staging names, the
   stray sweep is provider-prefixed AND age-gated (an hour), and the pkg tree is
   unpacked into a per-process dir then swapped in whole, so a concurrent reader
   can never see a half-written vendor tree that still answers --version. The
   remaining swap-vs-swap window is named in a comment as accepted residual until
   two boards on one Mac is a real configuration (a lockfile is the close).
3. The shipped MANIFEST is frozen (url and integrity are trust anchors for bytes
   that get EXECUTED); tests inject fixture manifests through a new opts.manifest
   seam instead of mutating the module. Frozen-ness itself is asserted by a test.
4. NITs: bail() also destroys the request socket; the managed symlink target is
   relative (survives a moved KOSMOS_HOME); presence retires a stale failed job in
   both status() and the install shortcut; the proving-window test breaks crisply
   on failure instead of spinning; the sentence const sits above its function's
   JSDoc; GET /api/runners accepts HEAD like its sibling read routes.
