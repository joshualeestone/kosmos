# stopmove-6214: stop a running account move

Addresses #6214. Follows #6173 (PR #6202). Liu Kang's assignment m5657 and ruling m5659. Windows and Linux slowness
stays with #6183 (Sub-Zero; disjoint files: they stay out of engine/accountmove.js).

## Finished means (yes/no, posted on the card)
1. A test stops a move in each of the three positions (already restarted, mid-restart, not reached) and asserts each
   agent's outcome and sentence, including a put-back that fails.
2. A test asserts every hold is empty and moveHoldsBoard is false once the stopped move ends, and that Update is then
   accepted.
3. A browser check presses Stop on a running move and reads the final sentence.

## Behaviour (agreed on the card)
- An agent already restarted keeps its result.
- The agent mid-restart is NOT cut (#3418): it finishes within its 330 s cap.
- Agents not reached are put back on their old account, with no restart (Liu Kang m5659). The put-back writes the old
  account ONLY if the saved account is still the one this move wrote; otherwise it is left and said so. A failed
  put-back is said as today's "saved, not restarted" (outcome partial).
- Stop is offered on the moving row in Settings, and in the refusals from Update, Roll back, Restart Kosmos and the
  Kosmos switch (from any page).
- A second stop changes nothing (200, already: true). With no move running: 409 "No account move is running."
- Out of scope: the one-agent Move, and Windows/Linux slowness (#6183).

## Change
- engine/accountmove.js: before each account write the move reads `from` (deps.readAccount), and after it `to`. The
  restart loop breaks when stopped. stop() puts back and releases every pending agent except the one restarting, and
  answers the move's view with `stopped` and `waitingFor`. putBack compares the current account against `to` and
  writes `from` only when they match.
- server.js: the bulk route wires a STRICT readAccount (a job that cannot be read throws; moveFromDir folds that into
  the default account, which the put-back must never take for "it was on the default account") and putBack
  (create.setAccount). POST /api/agents/account-moves/stop, matched before the read route. The four board-restart
  refusals carry moveStoppable when a move is what holds the board.
- web/index.html: stopAccountMove and offerStopMove (one button after the refusal sentence, at the four places). The
  moving row draws Stop the move once the board has the move (`onBoard`, set by the first progress answer), and the
  Move handler inserts it at that moment too, since pressing Move does not repaint the row. acctStopClick is shared.
  The row's final sentence needs no new code: `stopped` falls to "Not moved (X): <the board's sentence>".

## Decisions
- Put back, not leave saved (Liu Kang m5659; leaving them saved was rejected).
- Offer the row's stop from the first progress answer, not the press: a stop sent before the board has the move is
  told no move is running while the row says Moving.
- Server wiring tested by reading server.js as source, as #6173 did: no route test can reach a real move.
- Weakest part: the put-back's compare-then-write is not atomic against a hand change landing between the read and
  the write (same process, synchronous, so only another process writing the job file in that window). And the
  route wiring is proven by source match, not by a running board.
- Would change my mind: a caller that reads a stopped agent's outcome as moved.
