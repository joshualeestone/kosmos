# pbrestorescreen-7404: restore from a backup, into a separate copy

Card: #7404 (the screen slice; the routes are #7789). Owner: Baron Draxum.
Design: Mona Lisa, reviews 1 and 2 (fleetbuilders m2528, m2530), approved.

## What the person gets
Settings, Kosmos+, Personal backup, on view: a "Restore from a backup" section.
- See your backups: lists them (POST /api/personal-backup/backups) only when pressed,
  because a list spends the hourly Kosmos+ allowance. Each row is its time and Restore;
  a backup with a problem shows the problem and no button. "Older backups are not shown."
  when the list says more.
- Restore asks inline: "Restore <time>? It goes into a separate copy, so nothing here
  changes." (POST /api/personal-backup/files { key }).
- While it runs (GET /api/personal-backup/files every 5 s, once a minute otherwise, only
  while shown): "Restoring <time>, started <time>. This can take a while, and you can keep
  using Kosmos." with Stop, which asks first (POST /api/personal-backup/stop).
- The end: restored count and the copy's name, files not in the backup, failed files
  counted (and named at the computer; a remote session gets counts only), and Open the
  copy, which opens the Kosmos menu and its own restart-to-switch confirm.

## Decisions
- No progress bar: the restore reports no progress, so any bar would be invented.
- A stopped restore's answer names no copy (the job's `cut` carries no world), so its end
  says where the copy is in words and offers no button it cannot back.
- A restore cut off by a board restart is not said: the job keeps its state in memory.
- Failed files are named by path only. Their reasons are the restore's own engineer
  text, and the review rule is never to show raw reasons.
- Open the copy goes through worldswConfirmSwitch rather than switching directly, so
  the agents choice and the switch's progress reporting are the switcher's own.

## Weakest premise
That the switcher's list has the new copy when Open the copy is pressed: pbfOpen asks
worldsFetch to refresh first, but does not wait for it; the confirm names the copy by
the id and name the restore answered, which is what the switch posts.

## Not in this slice
- The copy's name format (engine-made, shared with the company restore): follow-up.
