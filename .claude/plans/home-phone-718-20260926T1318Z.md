# home-phone-718: the home screen and agents list on a phone

Issue: kosmos #718, row 6 of the phone-ready table
(https://github.com/joshualeestone/kosmos/issues/718#issuecomment-5842472848). Liu Kang assigned it (m986).

## Problem (measured by the harness, 375px, Chromium and WebKit)
Beyond the frame (row 5), the home grid and the agents list flag three kinds of small target:
- the agent names (`.namego`), 16px tall;
- "Answer" (`.ansgo`), 63x24;
- "Set them to start at login" (the survival fix under the board), 34px tall.

## Findings before changing anything
- A name is NOT the tap target on a phone. The board's click handler (`#grid` / `#alist`) opens the agent for a
  tap anywhere on its card or row (`closest('.acard[data-agent], .lrow[data-agent]')`); the name is a button only
  so the keyboard has a way in. The card is the target, and it is far bigger than 44x44. Growing the name would
  change nothing a thumb can feel.
- "Answer" already has a deliberate ~40px invisible hit area on touch (`@media (hover: none)`, the #718 comment
  above `.ansgo::after`), sized so it does not take taps meant for the row around it. Left as is.
- The survival button is a real 34px target with nothing larger around it.

## Done looks like
At the four harness phone sizes: "Set them to start at login" is at least 44px tall; a tap on an empty part of an
agent's card (grid) and of its row (list), away from the name, opens that agent; desktop is unchanged.

## Change
1. `@media (max-width: 40rem) { #restart-wrap .btn { min-height: 44px; } }`.
2. A gate browser check: the button's height at each phone size, the card and row taps, desktop height unchanged,
   with the size arm measured red on main.

## Rejected
- Growing `.namego` to 44px: the card around it already takes the tap, and a taller name would push the card's
  layout for no gain.
- Growing every `.btn` under 40rem: `.btn` is used across the app, including places other lanes own.

## Weakest part
The harness will keep flagging the names (it counts buttons, not what a tap lands on). That is a harness fact, not a
board fact; it is noted in the PR so the next reader of the report does not re-open it.
