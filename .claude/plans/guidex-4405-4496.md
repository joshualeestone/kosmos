# guidex-4405 (card kosmos#4496): the Kosmos Guide bubble's hover X

Josh, #admin 09-28 15:14 and 15:15 CDT (verbatim on kosmos#4496): hover the Guide bubble about a second and
a small circled X shows at its top-right; clicking it turns the Kosmos Guide switch OFF (reversible, deletes
nothing); the hit area is ONLY the circle, a click anywhere else on the avatar opens the chat.

## Design (decided)
- A SEPARATE `<button id="asb-close">` beside the bubble (a button cannot hold a button), 20px, border-radius
  50%, no padding, positioned so its centre sits on the bubble's top-right corner and following a lifted
  bubble. The hit area is clipped with clip-path: circle() (border-radius alone is not enough in WebKit,
  see below), so a point inside its square box but outside the circle is the avatar, in both engines.
- Shown after ASB_CLOSE_HOLD_MS (1000 ms) with the pointer on the bubble, or at once when the keyboard
  reaches the bubble (so Tab goes on to it); hidden when the pointer leaves both (a 250 ms grace to cross
  the gap). Never shown without its bubble.
- The click runs asbSwitchOff(), the ONE switch-off path shared with the Settings > Help switch (the same
  ASB.turning latch; the X is disabled with the switch while a save runs). A failed save says so in a
  status line for 5 s; a good one moves focus back to the page.
- No confirm dialog (Josh: reversible, the switch turns it back on).

Touch: the X needs a hover, which touch has no way to hold, so on a phone or tablet the Guide is turned off from
Settings > Help. That is Josh's spec (hover); stated so nobody reads it as a gap.

Not tested (review iteration 8): the hold timer re-checks :hover before showing the X, for a hold cut short by the
chat opening and folding back with the pointer never moving. A browser check could not build that state (any pointer
move fires pointerleave, which already clears the timer; a mutant without the re-check stayed green), so the arm was
removed rather than kept vacuous. Touch pointers start no timer (Josh's spec is a hover).

## Rejected
- The X inside the bubble: a nested button is invalid HTML and would forward clicks to the bubble.
- A larger padded hit target: Josh ruled the hit area tight.

## Weakest premise (resolved in review iteration 5)
The first version relied on border-radius for the tight hit area. A webkit arm (B2w, review iteration 5) showed
WebKit (the Mac app's engine) hit-tests the X by its SQUARE box: the corners still closed the Guide. The X is now
clipped with clip-path: circle(), which both engines hit-test by; B2x (chromium) and B2w (webkit) both assert a
point just outside the circle is the avatar. Windows WebView2 (Chromium-based) is not measured directly.
