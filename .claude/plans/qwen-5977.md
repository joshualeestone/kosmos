## Shape (decided 12:2x, see the card's correction comment)
- Provider `alibaba` (the UI's existing key and logo), runner `codex`. Every codex run/read path works unchanged.
- A Qwen ACCOUNT is a Codex-home folder like any per-account home (plist carries it as CODEX_HOME already), holding
  `kosmos-endpoint.json` {base_url, model, wire_api, key?} (mode 600) instead of auth.json.
  - "Qwen (on this computer)": base_url http://localhost:11434/v1, model e.g. qwen3.5:9b, no key.
  - "Any OpenAI-compatible endpoint": the person's URL, model name, optional key.
- Supervisor (agent-supervisor.sh, codex block ~1006-1080): when $EFFECTIVE_CODEX_HOME/kosmos-endpoint.json exists,
  skip the auth.json link and the "OpenAI account not signed in" line; add
  `-c model_provider=kosmos-endpoint -c model_providers.kosmos-endpoint.name=... .base_url=... .wire_api=...`
  (+ `.env_key=KOSMOS_ENDPOINT_KEY` and that var in the pane env when a key is set) and `-m <model>` unless the
  agent chose one. The private runtime home stays as is (it never copies account config; the overrides are argv).
- Provider-keyed places (not runner-keyed): create.js providerRunner('alibaba')='codex', providerLabel='Qwen',
  setProvider/createAgentInner allow-lists, accountConnectable; accountproblem PROVIDER_NAME (keyed by runner today:
  needs the provider); the OpenAI sign-in badge fed by codexsession contextUsedAt (gate on provider); runnerProvider's
  adopt inverse (codex -> openai: the brief must carry provider); server.js account rows (/api/accounts lists a Qwen
  row with its endpoint and a live reachability check, never the key); web/index.html: enable the four disabled
  "Alibaba Qwen" entries, an endpoint form (URL, model, key) in Add a provider.

## Gate before building past the registry
MEASURE that a 9B Qwen drives Codex's tools through Ollama (shell, apply_patch, `kosmos reply`, turn-end notify),
on a fixed task set, with qwen2.5:7b as the floor and Qwen Code as the comparison arm. If Codex cannot drive it,
the runner choice changes (Qwen Code needs its own reader) and only the provider/UI half of this plan survives.
Blocked now on: disk (12 GB free, a 9B pull is ~6.6 GB) and the machine queue (a model run beside a suite skews both).

## Weakest premise
That the provider reaches every provider-keyed place; the adopt inverse is the likeliest miss and gets its own test.
