# machine-check-979c: the machine check reports Claude Code, it does not require it (kosmos#979)

## Why

The third of three places that told a person Claude Code was mandatory. Josh found the first
himself at 14:45; the second is Mona Lisa's first-run panel; this one I found while answering
his question "do I need Claude Code to run Kosmos".

`engine/machine.js:268` listed it beside tmux as something the MACHINE needs, whichever
provider the person picked:

```js
const parts = [['Claude Code', claudeBin], ['tmux', tmuxBin]];
```

So somebody who chose GPT was told their Mac was missing something it does not need, **on the
screen whose job is to say whether they can proceed.** They can: an OpenAI agent runs on codex
and never touches the Claude binary.

## What

`parts` (required) becomes tmux alone. Claude Code moves to `informational`, is probed by the
SAME loop with the same #133 runnable rules, and its answer is published on a new `present`
map instead of driving the verdict.

⭐ **The fact stays, only the framing goes.** "Is Claude Code on this Mac" is true and useful
even when it is not a requirement, and Mona Lisa's confirm box needs it to know whether pressing
Connect will download anything. What was wrong was the word REQUIRED next to it. This is the
shape she and I agreed (her option (a)): her read does not change.

`present[label]` is `true` / `false` / **`null`**, where null means we could not look -- the
same distinction the rest of this function is careful about, kept rather than flattened.

## ⚠️ A structural consequence I am not hiding

With one required part, **two simultaneous required findings can no longer be constructed**, so
the three-bucket machinery (`missing` / `unreadable` / `unusable`) and its "every bucket gets
said" property are no longer reachable by test. That property was paid for by three separate
incidents.

**Kept, not removed**, and the trade is deliberate: it is correct code, and a second required
part is plausible. But the cost is larger than "untestable", and a reviewer measured it:
⚠️ **the output is UNOBSERVABLE, not merely untested.** With one required part, a populated
`unreadable` makes `problems` falsy, so the UNKNOWN return fires and builds its detail from
`unreadable` directly, never from `parts_` -- so that push can never be read by anything. Also
now unreachable: the plural title branch (`named` can only have length 1) and every multi-item
`join`. Saying "not reachable by test" understated it, and a future reader auditing for dead
code would have found more than they were told to expect. The test
that guarded it now asserts the half that IS still reachable (a refused path is said rather than
dropped, and the informational part is not named at someone who never chose it) and carries a
note saying what it lost and why.

## Tests moved with the product, not deleted

Six assertions used Claude Code as the thing that drives the verdict. Each was re-aimed at tmux,
keeping its original invariant, and each carries why. Two new cases were added:

1. ⭐ a Mac with **no Claude Code and tmux present is `ok`**, its row never says "Claude", and
   `present['Claude Code']` is `false`. **With a control** proving `present` is a real reading
   rather than a constant, or the assertion proves nothing.
2. an **unrunnable** Claude Code (a directory at the path, the #133 trap) reads `false` in
   `present` and still does not block -- because Connect must not skip installing over it.

## Review pass 1, applied

**The finding that mattered was a sequencing hazard between two of my own branches.** With the
required set reduced to tmux, a Mac with tmux and no Claude gets "Everything it needs is
installed" from this row -- and `createAgentInner` still refuses, because it needs the RUNNER for
the chosen provider. That is masked today only because the installer force-installs Claude, which
is the gate my `installer-979b` removes. So the two branches together would have produced a false
all-clear followed by a refusal.

Fixed at the honest end rather than by re-adding the requirement:

- **`present` now answers for BOTH runners**, `claude` and `codex`. #979 was filed because Josh
  picked OpenAI on a fresh Mac and nothing happened, so a map that answered for Claude and not
  codex omitted the runner the card is about.
- **`create.js`'s refusal points at Connect** instead of sending a person to
  `claude.com/claude-code` to do by hand what pressing Connect does for them with a checksum.
  That sentence was written when the installer guaranteed the binary and this arm was near
  unreachable; it is now the sentence a real person meets.

Also:

- **Keys are stable ids, not display labels.** The labels are the same strings the row's sentences
  are built from, so a copy edit would silently rename a JSON key; the consumer then reads
  `undefined`, which is falsy, which reads as ABSENT -- collapsing the `null`-vs-`false`
  distinction this change exists to protect. Asserted on the wire, including that
  `'Claude Code' in present` is false.
- **A route test pins `present` to the wire.** The engine tests exercise `installedCheck()`
  directly, so a route or serializer that dropped the map would have failed nothing.
- Two test names that overclaimed after being re-aimed, one assertion message that no longer
  described what it guarded, two stale worked examples in comments (one of which would have had a
  reader run its own repro and conclude the fix regressed), and a vestigial fixture.
