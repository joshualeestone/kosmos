# boardpage-8781: the board page's own fetches say so, for browsers with no Sec-Fetch-Site

kosmos#8781 (a customer's Safari 15.6.1 on a Kosmos Cloud box, 2026-11-19): the board's half. The connector's half is kosmos-relay branch oldsafari-8781.

## The problem
Safari before 16.4 sends no Sec-Fetch-Site. The connector gives the board token only for same-origin or none, so every board read from such a browser reaches the board with no token, gets 403, and the page shows "This page is signed out" forever. Measured on the coordinator's logs: Origin is sent on that Safari's POSTs but on none of its GETs.

## The change (web/index.html, the one fetch wrapper)
`fetchReadingRefusals` adds `X-Kosmos-Board-Page: 1` to every same-origin request (relative, absolute to this origin, or a URL object). Not to another origin (the page reads other computers' boards credentialed, and a custom header there would force a preflight). A Request object, or anything it cannot read, goes out exactly as it was. The page makes its data reads through fetch with a URL (no XHR, EventSource, beacons or Request objects in it; a test now fails if one appears). Not its images: agent avatars are `<img src="/api/agent/<name>/avatar">`, which cannot carry a header, so an old Safari may show them broken if that route needs the board token (fails closed; recorded on the card).

The connector (oldsafari-8781) then gives the token to a request with no Sec-Fetch-Site only for an exact own Origin, or for no Origin plus this header. Another site cannot put a custom header on a link, an image, a form or a redirect, and a cross-site fetch that asks to is preflighted, which nothing approves. The Referer was rejected as a signal (review 1 there): a redirect bounce from a link on this page carries it.

## Tests
`web.boardpage-header-8781.test.js` runs the page's real wrapper, sliced from web/index.html (and checks the slice is whole):
- the header on relative, absolute, protocol-relative and URL-object reads of this board; none, and the init untouched, for another computer's board, a protocol-relative URL to another host, data: and about:;
- the page's own method, body, headers (plain object, Headers object, pairs), signal, credentials, keepalive and cache kept; a value the caller set, in any case, kept rather than replaced or doubled;
- an unparseable URL, a refused header name and a real Request left exactly as they were;
- guards: the page uses no XHR, EventSource, WebSocket, Request or beacon; and the board writes exactly one redirect (its boot redirect, which the page's fetches never reach).
Red-capability, each measured: without the line that applies the header, "a relative read" fails; without the has() guard, the kept-value test fails; an XMLHttpRequest in the page fails the guard; the redirect census failed on a 304 before it was narrowed to redirect codes. `server.stepupbutton-6616.test.js` (the wrapper's other tests) and `fixture-discipline.test.js` pass.

## Known limits (fail closed)
- Everything the page loads as a navigation or a subresource rather than through fetch cannot carry the header, so on such a browser the connector refuses it the token: agent avatars, file downloads (the dlKeyed links), folder zips, the diagnostics download, PDF page and image previews, and the service worker's own fetches (its offline shell may not warm). The board itself (status, agents, projects, messages, every fetch) works. Recorded on the card so it does not read as "old Safari fully works".

## Weakest premise
Two premises, both spec reasoning, neither measured on a real Safari 15. First, that it sends a custom header on a same-origin fetch GET without a preflight. Second, that a GET redirected across origins and back arrives with Origin: null, which the connector refuses (that Safari sends no Origin on its plain GETs, measured, so this is a real question); it matters only if a board route the page's fetches reach ever redirects off-origin, which the tripwire test watches for. On the first: Same-origin requests are never preflighted in any browser. Proven against a recording stub; preflight behaviour was not measured in any engine, and not in a real Safari 15.
