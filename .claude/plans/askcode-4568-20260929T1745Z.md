# askcode-4568: the allow-card screen shows a real device code, and fails when a code leaves its card (kosmos#4568)

## Finished looks like
- mobile-shots' `allow-card` screen shows a request whose code has the real shape, and at all four phone sizes, both
  engines, light and dark, the code sits inside its card.
- The screen fails when a code box leaves its request card's padding, and that check is seen to fail: a gate arm
  (`MSHOTS_COVER_CONTROL=spill`) puts the seven-box code back and must exit 2 with its message.
- No product change.

## Cause (measured, and it changed the card)
#4568 was filed from the #4561 shots as a product bug: the code row runs past the card at every phone size. The code
in those shots, `482 913`, came from mobile-shots' own stub. A real device request's code is made by kosmos-relay's
`match_code` (crates/proto/src/matchcode.rs, unchanged on origin/main since 2026-08-29): always two symbols, a dash,
two symbols (`K7-3M`). `482 913` is the shape of the owner's six-digit sign-in code. devCodeHtml splits on dashes
only, so `482 913` is one group of seven boxes; the shared size fits five, and seven ran past the card (measured at
se: the farthest box 24px outside the card's padding). A real code is two groups of two and fits.

The board's own tests already use the real shape (engine/remote.test.js `K7-3M`; render-plus-panel-3829 `VR-D6`, with
an in-card check at 1400px). Only the phone stub was wrong.

## Change
- The allow-card stub's code is `K7-3M`.
- After the Allow hit-test, every `.devcode-cell` must end inside the request card's (`.askreq`) content box, or the
  shot fails with how many boxes leave it and by how much.
- `MSHOTS_COVER_CONTROL=spill` (allow-card only, refused otherwise) restores `482 913`; a third gate arm requires
  exit 2 with `the code does not fit its card`.

## Measured
Gated box turn at 7e28ccb87 (Liu Kang's go, heavy-gate CLEAR), 2026-09-29:
- 17:40:43Z, `MSHOTS_COVER_CONTROL=spill --screens allow-card --sizes se --themes light --engines chromium`: exit 2,
  "the code does not fit its card: 1 of 7 code boxes leave the card, the last by 24px".
- 17:40:50 to 17:41:30Z, `--screens allow-card` with `K7-3M`: 16/16 ok, 0 errors, exit 0; all 16 viewed, the code sits
  inside its card in both engines, light and dark.
The fit check was reworked after that run (every laid-out card, polled, farthest overflow on either side, the
desktop-only refusal); a re-run on the final head is owed.

## Decided
- No resize of long code groups in the product. A first cut did it (a width bound from `--devcode-w`), and it was
  reverted once the real code shape was read: it changed shared code sizing for a case no real request produces.
  What would change this: kosmos-relay lengthening match codes, or a single-group code reaching `.askcode`. The fit
  check fails in that case, so it would not ship unseen.

## Weakest part
The fit check runs in mobile-shots only (the gate slice at se and desktop, and the by-hand sweep); a longer real code
would first show there, not in a unit test.
