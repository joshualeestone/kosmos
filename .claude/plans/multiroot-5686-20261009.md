# multiroot-5686: a snapshot of several named roots

Card #5686 (the console's content view, read from the backup). Its weakest premise, measured 2026-10-09 (comment
6082194329): an E0.6 snapshot of one root does not cover every conversation surface. The default world keeps its data
(chats, rooms, task threads), its agents and its projects in three folders; agents' provider sessions live in a fourth
place per provider. Stacked on walker-5535 (PR #5693; Mortals full suite passed, 17817 tests, 0 fail).

## Change (engine/backupsnapshot.js)
- `takeSnapshot` input takes `roots: [{ name, path, exclude? }]` instead of `root` (and `exclude`). `root` alone still
  works and stores paths as they are.
- rootsOf: 1 to 64 roots; a name is lowercase letters, digits and hyphens, up to four parts joined by '/'; no name
  repeats or contains another (`sessions` and `sessions/claude`), so two roots can never write one restored path; each
  path absolute; `root` with `roots` refused.
- listRoots: each root's real path; a root inside another by real path is refused (its files would be stored twice);
  each root walked by listFiles with its own exclude and every existing rule; files stored as `<name>/<path in root>`,
  read from their own root (readListed takes the file's root and its path inside it). The file limit counts all roots.

## Decided
- Names fixed by the caller, not derived from folder names: restore needs stable, safe top-level names, and a folder
  name can be personal. Rejected: the folder's own name (personal, can clash).
- Nested roots refused rather than de-duplicated: the caller chooses the roots (data, workers, projects, a session
  folder per provider and agent), and nesting means a wrong choice.
- NOT in this slice: choosing the roots for a world (the backup schedule's caller, after E0.1/E0.2), and per-provider
  session selection (Claude by path, Gemini via projects.json, Codex by a rollout's first line, measured on #5686).
  Weakest premise: that every conversation surface is a whole folder a caller can name; Codex rollouts are not (one
  date tree for every agent), so that slice may need per-file selection, not a root.

## Review 1 (opus): a BLOCKER and three warnings, fixed
- BLOCKER: a root named with a Windows device name (`con`, `sessions/aux`) passed the name rule, but restore's
  pathProblem refuses every path under it: its files would be uploaded and charged and never come back. Every root name
  is now judged by restore's pathProblem and by the deny-list as a folder (`secrets` would have every file read and
  dropped). The stored (prefixed) path is judged by pathProblem too, and skipped if restore would refuse it (the prefix
  can push a path past restore's 4096-character cap; untestable on this Mac, whose paths stop at 1024).
- Nesting is found by the folders' identity (device and inode, from each root up to the volume's top), not by the
  spelling of their real paths: a real path keeps the case it was given on a case-insensitive volume, and a firmlink gives
  one folder two paths. Tests: the same folder twice, a trailing slash, a root reached through a symlink, a case variant
  (runs here: APFS is case-insensitive; skips on a case-sensitive volume).
- The skipped bound is shared across roots like the file limit; an unreadable root is named by its root name, not
  `<name>/.`.
- Mutants: no restore name check, no deny name check, nesting by spelling, no bare-root name: each fails. 84 pass.
- Not changed: messages still say "the work Kosmos" (true of the set of roots; naming the root per message is for the
  caller's slice).
