# pjquiet-6341: a project's "needs you" stays quiet when it should, and every row can be dismissed (kosmos#6341)

## Why
Josh, 2026-10-16 19:43 (testing on his laptop board): "I don't think we should be flagging users for these types of
notifications about needing you on a project ... when the project's already paused or the project's been inactive ...
there's not really a way to really dismiss it." And 19:47: "a couple agents were out of usage but that should never show
in the project, only on the agent". His screenshots: four projects with a red Issue; three of them idle for days (Sep 10,
Oct 1, Oct 15) and flagged by an agent's rate limit (`stuck_rate`), which `needsYouReason` counted on every project the
agent belongs to (#3726); one with a real question. Plus the same "Recommender: X is stuck" note posted twice, 1:14 pm
and 5:15 pm, in one room.

## Change
- `engine/projects.js` `describe()`: a member's reason is QUIET (not counted in `summary.needsYou`, `needsYouHere` null,
  kept as `needsYouQuiet: {reason, because}`) when:
  - `usage`: the reason is `stuck_rate` (Josh 19:47: on the agent only), on any project, live or not; and only when
    nothing else needs the person (`needsYouReasonPastUsage`, review 6: a rate limit never hides a second, real reason;
    the Tasks view uses the same rule);
  - `paused`: the project is paused or archived (any reason, a question included; the agent's own page and the Agents
    count, engine/status.js, untouched here, still show it);
  - `dismissed`: the person dismissed that member's exact reason on this project;
  - `inactive`: it is the agent's own condition (anything but its question about this project) and the room has had no
    post in 24 hours (`NEEDS_LIVE_MS`).
  A question about this project still counts in a quiet room: it is about the project, not the agent.
- Dismissals: `projects.dismissNeeds(projectId, agent, key)` keeps `needsDismissed: {agent: key}` on the project
  record (the board, not the browser: these can stand for weeks). The key is the engine's `needsYouKey` on the member:
  the reason, and for a question `question:<its words>` (review 5), so the agent's next question about the project is
  shown, not hidden behind the last one's dismissal. `describe()` drops a dismissal once that member's reason
  is gone or different, so the same reason returning later is shown again. An agent the board cannot see is not judged.
  `elsewhere` is the reason for a row the page lists after the counted ones (#5692): it stands while nothing is counted
  for that member here. A dismissal is dropped only once its reason has been away for 10 minutes (`needsDismissGone`
  holds when it was first seen away), so a reading that flickers between polls does not bring the row back.
- A room is live when it had a post in the last day OR the project was made, or a member added (`memberChanges`), in the
  last day (a new member is often silent because it is blocked). A message log that cannot be read counts the room as
  live.
- `engine/messages.js`: `lastPostAt(projectId)` (posts and outside messages only; Kosmos's own notes do not make a room
  live), kept incrementally against the reader's memory; `recommenderNoted(project, agent, because, since)`.
- `server.js`: `POST /api/project/<id>/needs-dismiss` `{agent, reason}` (board token; not on the agent-token list);
  the Recommender runner passes `alreadyNoted` (a matching note in the room in the last day) and logs it.
- `engine/recommender.js` `runOnce`: an item whose note the room already holds (a board restart forgot it) writes no
  note and asks nobody again; the stuck agent still gets its playbook, which says the room holds the earlier note and
  replies (`playbookText`'s `alreadyNoted`, kept on the item so a retry says the same), or, when that note asked
  nobody, says to decide (review 5: `recommenderNoted` returns who the note asked). Budget and retries are as for any
  convening; the room check is given the runner's `now`.
- `engine/projectview.js` `listOf` (`kosmos project list`): a member quieted by what the person did (a paused or
  archived project, a dismissed row) is not counted as waiting on the person; an idle room does not drop one, since that
  count is "waiting on the person at all, whichever project".
- `engine/tasks.js` `cardsNeedingPerson`: an agent only out of usage does not put its tasks in Needs your decision
  (Josh 19:47), so `waitingOnPerson`, `waitingOnOf` and `waitingSinceOf` agree.
- In a room silent for a day, a member red here for another project (#5692's uncounted rows) is quiet too (review 5).
- `web/index.html` `pjMember`: a member the engine marked quiet is not drawn red on the project's Members card. The
  agents list row (`lrow`, also used by the consolidated layout's rail for the open project's members) keeps the agent's
  own state: it is the agent's row, which is where Josh wants an agent's own condition to show (review 7, decided).
- `web/index.html` `pjNeedsNotice`: each row gets Dismiss beside Open/Answer (carrying the row's reason); a member with
  `needsYouQuiet` is not listed among the uncounted red rows; `pjNeedsDismissClick` posts, repaints, says it in the
  notice's status line, keeps focus on the next row's Dismiss; a refusal leaves the row and the button reads Try again.
  `pjKeepOpenFocus` keeps focus on Dismiss across the poll's repaint as it does for Open.

Same rule as Angel's join-banner dismiss (#6315 follow-up, confirmed with her 19:45): dismissed for that exact thing,
back when it changes. Hers is per browser (a join request lives minutes); this is on the board.

## Known limits
- "Inactive" is room posts only: a project busy with agents working quietly for a day loses an agent's own condition
  from its Issue (the agent's page and the Agents count still show it).
- An `elsewhere` dismissal holds while the member is still red here for a reason not counted here (a question about
  another project, a trust wait, a lost connection, a failed restart, a Kosmos give-up); once it is not, the 10-minute
  grace starts. So a second, different question about another project asked before it recovers stays hidden.
- A paused project lists nothing in its block, including a red member whose need is about another project.
- The Members card's quiet override reads the engine's last projects answer, so a member that changed state since is
  drawn by the older answer until the next read (one poll).
- A question is keyed by its first 300 characters, so two questions that differ only after that are one dismissal.
- The Tasks view (`engine/tasks.js`) leaves out an agent out of usage, but does not yet quiet a task in a paused or
  idle project, and has no Dismiss: that view is its own surface, raised for a follow-up card rather than widened here.
- The dismissal and gone-mark write happens on a read (as `everSeen` already does). It re-reads the store just before
  writing and changes only members whose dismissal and gone mark are still the ones it judged, so a Dismiss pressed in
  between is kept; a second process writing the projects file in between is not locked out.
- `lastPostAt` scans new rows once, but each call still pays `record()`'s copy of the rows; it is called only for a
  project with a member whose reason needs the live test.
- The Recommender's room check matches the same agent and the same words within a day, so the same words in a new
  episode on the same day write no new note (the stuck agent is still given its playbook).
