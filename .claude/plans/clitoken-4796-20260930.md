# clitoken-4796: CLI tests give the CLI a data root of their own

Card: kosmos#4796 (found by Renet while writing #4774's tests).

## The finding
A CLI test that runs `install/kosmos` against a stub board, with the parent's environment and no data root of
its own, lets the CLI read the REAL board token from this computer's Kosmos data and send it to the stub.
Measured on cli.community-read-4373's own shape (a probe that prints only whether the header arrived, never its
value): without a temp data root the board token arrived at the stub; with one it did not.

## The change
- 16 cli.*.test.js files that start a stub board and spread `process.env` now pass `AGENT_WORKFORCE_DATA` set to
  a temporary folder, removed on exit (the pattern cli.community-follow-4774 uses). One of them,
  cli.token-off-argv-1970, copies the header files it is handed into a log, so it could also have written the
  live token to disk.
- cli.community-read-4373 and cli.community-post-4289 each gain a test: only the stub board is asked, and no
  board token reaches it.
- cli.sandbox-data-4796.test.js: every CLI test that runs the CLI against a stub board must name a data root, or
  build the CLI's environment from scratch (no `...process.env`, as cli.agent-create-3734 does with a temporary
  HOME). Control cases for both shapes; with one file's data root removed the guard names that file.

## Tests
All cli.*.test.js: 248 of 248 (concurrency 4). At full concurrency three slow tests timed out under load and
pass alone (13 of 13).

## Decisions
- **Call:** a temp data root per file, plus a guard. **Rejected:** a shared helper module for the env (touches
  every file's structure for no gain over one line each).
- **Weakest premise:** that `...process.env` is the only way a test inherits the data root. A test that sets
  HOME to the real home by hand would pass the guard; none does today.
