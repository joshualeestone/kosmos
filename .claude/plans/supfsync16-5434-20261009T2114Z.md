# supfsync16-5434: the supervisor and report bridges are flushed before they are installed (#5434 slice 16)

Addresses #5434. Group 3 of the rename inventory (what Kosmos needs to start), first: `engine/create.js`
`installSupervisor` copies the supervisor (`bin/agent-supervisor.sh`, which EVERY agent launches through), the four
report bridges (codex, gemini, grok, agy) and the `engine-path` pointer to `<file>.<pid>.new`, then renames each into
place, at every board start. Nothing was flushed, so a crash could leave the supervisor at full length but zero-filled
(#5431): every agent launch on the machine would fail until the next board start rewrote it.

## Change
- A local `installCopy(src, to)` keeps the same `<to>.<pid>.new` staging name (the catch's cleanup still finds it):
  copy, chmod 755, `flushStaged(stg)`, rename. The five copies use it.
- `flushStaged(p)`: open `r+`, `securewrite.flushOrThrow`, close without masking an earlier error. Also used for the
  engine-path pointer before its rename (that step stays best effort).
- `securewrite.syncDir(bin)` once after the renames (POSIX; never throws).
- `securewrite` exports `flushOrThrow` and `syncDir` (the identical one-line change as slices 8, 12, 13, 14).
- New `engine/create.supfsync-5434.test.js` (3 tests), in `tools/windows-tests.js`.

## Decided
- **Flush in place, keep the staging names.** The per-process staging name is load-bearing (two installs must not
  interleave into one inode), and the catch removes exactly those names. Moving to writeSecret would change both.
- **A failed flush refuses the install** through the existing catch (staging removed, `{ ok:false }` naming the step),
  leaving the previously installed supervisor in place; before, a write failure did the same.
- **Cost:** six small file flushes and one folder flush per board start.

## Tests
- every rename into the bin folder (supervisor, four bridges, engine-path) is preceded by a flush of its staging file;
  the folder is flushed after (POSIX); a failed flush of the supervisor's staging refuses the install, keeps the
  installed supervisor, and leaves no `.new`; the installed supervisor stays 0755 (POSIX).
- Mutation: main's create.js fails 2 of 3 (the mode arm passes on main, as expected). Related set (80 files,
  list5434s16.txt): 2256, 0 fail, 3 skipped.

## Weakest premise
That `r+` on the 0755 staging file always opens (owner write). It does for the owner on POSIX; on Windows a 0755 file
is writable. What would change my mind: a staging copy created read-only by copyFileSync from a read-only source.
