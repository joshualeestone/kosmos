# wn-0750: What's New for 0.7.50

Built from the pool: `node tools/whats-new-pool.js build 0.7.50`. Prod now serves 0.7.49 (promoted 10-14 ~15:4x), so the
build recorded 0.7.49's five highlights as shown and moved lastProd from 0.7.47 to 0.7.49. Why now: the gap alarm
(kosmos#1050, 15:4x) said main is 52 commits past staging 0.7.49.

## Added to the pool (final wording, after review rounds 1 to 8)
- Kosmos has its own iPad layouts (#6107, PRs #6135 and #6156), rank 3, since 0.7.49. It SHIPPED in 0.7.49 with no
  entry (Angel's omission, found at the 0.7.49 notes preview), so it is still unannounced to prod users and eligible.
  Both PRs are in 0.7.49: #6156's merge 423bd47759 is an ancestor of the 0.7.49 freeze 7cf7dee0f (measured), and
  that build's web/index.html has TABLET_LAYOUT_MQ.
  Line: "Sideways at full width, an iPad shows Agents and Projects side by side (View is set per iPad); upright, most
  put agent cards two across."
  - Sideways: `TABLET_LAYOUT_MQ` (touch, no hover, landscape, 960px and up) opens the Agents and Projects tabs on the
    One screen view, side by side, unless that iPad's own View setting (`TABLET_LAYOUT_KEY`, kept on the iPad, apart
    from the board's setting) says otherwise. "At full width": Split View, Slide Over and an attached trackpad fall
    outside the rule. Every iPad is 1133px or wider sideways, so the agents rail starts open. Android tablets get it
    too; the line says iPad on purpose. "(View is set per iPad)" belongs to the sideways clause, where it is true;
    the on-screen word is View (the two choices are icon-only, their names are tooltips a touch screen never shows,
    so the line names neither "One screen" nor "Tabs").
  - Upright (portrait, 600px to 67.99rem, `#grid.cards`): agent cards go two across below 960px whatever the board's
    view (an 11 inch iPad, an iPad mini); a 13 inch iPad upright (1024px) gets it only with the board on Tabs, hence
    "most". Only the Agents board changes, hence "agent cards". The project room's tasks-first order is real but left
    out to fit.
  - #6156 said not to merge before Josh answered "split view or card grid" for landscape tablets, or noon CDT 10-14
    (stated default: split view). No answer is recorded on the PR; it merged at 17:00:23Z, noon CDT, so the stated
    default ships, and the window announces what ships.
- Decision tasks say who needs you (#6157 slice B, PR #6166), rank 6. Line: "A task in Needs Your Decision now names
  the agent waiting on you, when one is, and why." `waitingOnOf` (engine/tasks.js) feeds the Tasks row, which renders
  "Agent: reason" in the project page's words; a missed recurring run names no agent, hence "when one is". "Needs Your
  Decision" is the screen's own label.
- A restart after an update stops taking focus (#6158, PR #6165), rank 9, mac (title scoped to the restart in review
  9: "Updates ..." could read as covering the update's dialogs too). Line: "From the next update on, when
  Kosmos restarts itself onto a new version while another app is in front, it no longer takes focus."
  - The restart that DELIVERS 0.7.50 is performed by 0.7.49's code, which still activates, hence "from the next
    update on".
  - The code proves only that the fresh copy does not activate (`relaunchMayActivate`, `KOSMOS_RELAUNCH_QUIET`);
    `buildWindow()` still orders the window front, so the line does not claim it "opens behind" anything. "No longer
    takes focus" is REASONED from the activation path, not measured on a Mac.
  - A restart the person asks for, or one made while Kosmos is in front, still comes forward; the title says
    "Updates" so it stays inside its line. Three timer-raised dialogs (the restart question, the cannot-update notice,
    the could-not-open alert) can still come up over another app, as #6165 says.
  - Mac only: the change is in native-app/main.swift.
