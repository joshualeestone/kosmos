# phonepost-6254 -- per-kind phone notifications (board half of #6254)

Card #6254: phone notifications when agents post (mention/reply), when work is
ready, and for opt-in room posts, with one switch per kind. claimed:kano.
Relay half (web-push transport) already merged as PR #396. This branch is the
BOARD half; the posted-to-room tap routing is a separate kosmos-relay PR.

## Goal / what finished looks like

1. The phone-notify Settings section offers one switch per notification kind
   (needsYou, replied, postedMention, postedRoom, ready), shown only when the
   master switch is on and the phone is connected; each switch persists and
   repaints.
2. A `posted` kind fires when an agent posts to a room, and a `ready` kind
   fires at task-built; each is gated by its own per-kind switch and the
   generalized cooldown.
3. The phonenotify payload carries a `projectId` (resolved room project id),
   additive and backward-compatible, so a later relay change can deep-link a
   "posted" push to the room. Absent projectId resolves to null, unchanged for
   the pre-existing needs_you / replied callers.
4. Full suite green; the Settings surface change is backed by an updated
   browser check; `/challenge-loop` converges; PR opened (Scorpion reviews).

## Design

- `engine/phonenotify.js`: per-kind switches with defaults (postedRoom OFF, the
  rest ON); a resolveKinds/storedKinds pair that falls back to each switch's own
  default on a missing/corrupt kinds object and preserves only explicitly-set
  booleans; a generalized class-keyed cooldown (`lastSent`) replacing the single
  `lastNeedsYou` bucket, pruned on the longest window; `posted` and `ready`
  kinds; `status()` carries `kinds` in both available and unavailable branches;
  `payload()` always emits `projectId: cap(projectId, CAPS.project)`.
- `server.js`: `ready` buzz at the task-built route (not viaScreen, not clear,
  only when out.changed and a card exists); per-kind `/api/phone-notify` PUT via
  setKind (unknown kind -> 400); the `posted` send-site at the room-post route
  (namesPerson from `delivery.repliesToPerson`), carrying `projectId: pj?.id`.
- `engine/messages.js`: `repliesToPerson` boolean on the reply delivery return.
- `web/index.html`: the per-kind switch block under the master, each PUTting
  `{kind,on}` and repainting; master row reworded.
- `web/sw.js`: `ready` headline in KIND_HEADLINE.
- `docs/browser-checks/render-push-718.js`: a per-kind block asserting the
  switch markup and that it paints from board kinds.
