## #3598: Settings spacing
Josh: a fixed small gap between the pill nav and the content boxes at any width, and a top
margin under the header on Models, Connections, This Computer, Automation, Token Usage.
- Measured on a sandbox board before the fix: gap 142px at 1200 wide, 337px at 2400; those five
  sections had 0px top inset, the rest 24px.
- Cause 1: the consolidated `.dbody` nav column was `minmax(120px, 30%)` while `#s-nav` is only
  max-content, so the spare column width added to the gap. Now `max-content` with a
  `column-gap: var(--space-8)` (24px).
- Cause 2: the five are the tall sections. Opening one scrolls it into view inside
  `#panel-settings`, which scrolled past the panel's 24px top padding (scrollTop 24). Fix:
  `scroll-margin-top: var(--space-8)` on the sections, so the scroll keeps the inset.
- After: gap 24px and top inset 24px on every section, at 1200 and 2400.

## #3599: Kosmos+ in the consolidated view
Josh: the blue background the tab view has, behind the Kosmos+ content, in light and dark.
- Cause: `syncPlusChrome` turned on `body.plus-active` only when `URL_TAB === 'settings'`. The
  consolidated view opens Settings inside the projects column with URL_TAB still on projects,
  so the blue (and the star field and wordmark canvases) never mounted.
- Fix: one predicate, `plusOnScreen()` (the Settings tab on Plus, or Settings showing in that
  column on Plus), read by both `syncPlusChrome` and the #743 status tick, so Kosmos+ also keeps
  its 5s status repaint in the consolidated view. Re-synced when
  another overlay takes the column (`openConsolidatedCreate`; `openConsolidatedSettings` already
  did) or the column is navigated away (`pjView`), so the blue leaves with it.
