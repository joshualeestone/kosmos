Stacked on grok-5883 (slice 2). Rebuilt from main when the stack lands. Design posted on #5883 before building.

## Measured (this Mac, read-only, schema and column shapes only, no content opened)
agy home ~/.gemini/antigravity-cli: conversations/<id>.db, one SQLite file per conversation, WAL mode. No plain column
names its folder. conversation_summaries.db, table conversation_summaries: conversation_id + workspace_uris (a JSON
list of file:// URIs); 31 rows, all with a db. node:sqlite exports backup() (Node 26 is pinned; agysession.js and
usageproviders.js already use node:sqlite).

## What
- engine/backupagy.js stageAgy: ownership by workspace_uris (fileURLToPath, canonicalOnDisk, as every reader); each
  owned conversation copied ONCE with node:sqlite backup() into one shared staging folder (a consistent copy; a raw
  copy of a WAL db can lose the rows still in the WAL); one root per agent over the staging folder naming its copies
  (sessions/<seg>/agy). A conversation more than one agent claims is LEFT OUT at staging (review 1) and SAID (review
  3): a refused root sessions/<seg>/agy-shared for each owner, which the snapshot records in its skipped list; one
  larger than the snapshot's MAX_FILE likewise, as agy-large. Ids are checked (no path out of conversations/), links never copied, the summaries db never taken.
- engine/backuptick.js startHere: stage before the run (clearing stale copies first), clear after every run. The tick
  awaits roots(), so its running flag is now set BEFORE anything is awaited (an existing test caught the race my
  first wiring opened: a second tick in that gap started a second run).

## Weakest premise
That workspace_uris names the agent's launch folder. A conversation that opened several agents' folders is claimed by
each and so left out for all of them (said as agy-shared). A conversation started in a SUBFOLDER is not taken.
