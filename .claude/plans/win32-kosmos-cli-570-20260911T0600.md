# win32-kosmos-cli-570: a Windows agent can answer, message and post

Issue: #570. Found on 2026-09-11 while verifying the Windows zip. It is v1 BLOCKER 5
in `.claude/plans/WINDOWS-ROADMAP.md`.

## The defect, measured

Every operator message the board delivers reads "[message from your operator · to
answer, run: kosmos reply] ...", and every agent's instructions teach `kosmos msg`,
`kosmos post` and `kosmos task`. The Windows zip ships no `kosmos` command, and
`engine/clipath.js` has no win32 arm.

A live agent (e2e-2) answered its operator by running `kosmos reply "OSPREY"` in
PowerShell. It got "The term 'kosmos' is not recognized ...". The person messaged
the agent and never saw an answer. The 7c-6 R3 check missed it: it proved delivery,
the card state and the transcript, not an answer reaching the board.

A read-only survey of `install/kosmos` found two more reasons the bash CLI could not
simply ship:
- `msg`, `post` and `react` identify the sender only by `TMUX_PANE`, and a Windows
  agent has no pane. Their server routes are pane-only as well.
- The CLI is bash, with Mac paths: `runtime/bin/node`, the uid-derived port.

## The fix

1. **`tools/windows/kosmos-cli.js`**: the agent verbs in Node. It covers msg, reply,
   post, react, report (including show), whoami, room, and task list/add/close.
   - Each verb sends the SAME route and body `install/kosmos` sends, and prints the
     board's own `because`.
   - Exit codes match: 0, 1, 2, and 3 for "maybe", never 1.
   - The url, the board token and the agent-token check come from
     `engine/kosmos-report-hook.js`, the Windows client that already delivers
     every self-report. None of them is re-derived.
   - It presents `KOSMOS_AGENT_TOKEN` (put in every Windows agent's environment by
     its supervisor) as `x-kosmos-agent-token`, and the board token as
     `x-kosmos-board-token` (a Windows board enforces).
2. **server.js `senderFromAgentToken`**: /api/msg, /api/post and /api/react resolve
   a PRESENTED agent token through the same `resolveAgentSender` that /api/reply
   and /api/report use.
   - With no token, the pane path is untouched, so the Mac keeps its behaviour
     exactly.
   - A token that does not resolve is refused, never swapped for the pane.
   - `messages.send` and `sendPost` accept the resolved `sender`.
3. **`tools/build-kosmos-windows.sh`** stages `bin\kosmos-cli.js` and one committed
   shim per shell Claude Code uses:
   - `tools/windows/kosmos.ps1` for PowerShell. It hands the arguments over as JSON
     in a private temp file named after a flag (deleted after the call), so no
     Windows command line ever carries the message, at any length. Any failure
     is exit 1.
   - `tools/windows/kosmos.sh`, copied with any CR stripped, as the
     extensionless `kosmos` for Git Bash. It uses cygpath for its own paths and
     turns MSYS argument conversion OFF.
   - The zip is refused without them. There is NO `.cmd` (round 1, below).
4. **`engine/win32launch.js`**: `childEnv` puts `<zip>\bin` FIRST on the agent's
   PATH. It updates whichever PATH key the env already has (`Path` on Windows).
   `agentCliDir` finds that folder by its `kosmos-cli.js`, and a source checkout
   gets none. The bare `kosmos` every instruction already teaches then resolves in both
   shells.

## Measured on the box

- PowerShell resolves a bare `kosmos` to `kosmos.ps1` in the PATH folder. Git Bash
  resolves the extensionless `kosmos`.
- Claude Code's PowerShell runs with a process-scope `Bypass` execution policy, so
  the `.ps1` runs.
- Arguments arrive EXACTLY through both shims, including a newline, embedded
  quotes, `&`, `%PATH%`, `^` and `|`, and `/c/path` through Git Bash. The exit
  code comes back. A Windows-only test pins all of this.
- The first shim, a `.cmd`, did not survive this. Through PowerShell it kept one
  line of a multi-line message and ran the tail of a `"...&...` message as a
  command. PowerShell 5.1 also drops embedded double quotes on any native command
  line, which is why the `.ps1` passes JSON in a temp file instead.
- The CLI reached the real board with the board token (no 403). Without an agent
  token, the board refused the sender with the old pane sentence, as it should.
- With a candidate zip, a real agent's `kosmos reply` from PowerShell landed in
  its board thread, and its `kosmos msg reh-a` reached reh-a as that colleague.
  That was with the `.cmd` shim. RE-CHECKED WITH THE `.ps1` (2026-09-11, candidate
  zip `0.6.55+7fdaca1ba1c4`, unpacked over the running install with the old
  `kosmos.cmd` still beside it):
  - the full check passed (Z0-Z6) with `e2e-4`'s answers on the board (`OSPREY`,
    then `KESTREL` after a restore);
  - a TWO-LINE answer holding quotes and `&` landed exactly as
    `ALPHA-570\nBRAVO-570 "quoted" & done.`, sent by the agent's own PowerShell;
  - PowerShell picked `kosmos.ps1` over the stale `kosmos.cmd`.
## Tests

- `tools.windows-kosmos-cli-570.test.js`: every verb's route, body, headers and exit
  codes (3 on unconfirmed or timeout); local refusals that send nothing; the routes
  pinned to `install/kosmos`'s; and a real local server on the wire.
- `server.agent-token-sender-570.test.js`: through the real server, a paneless send
  with a valid token is placed as that agent. No token keeps the old refusal. A bad
  token is refused even with a pane. The engine honours a resolved sender.
- `engine/win32launch.test.js`: `bin` first on the existing `Path` key, one key
  only; nothing added for a source checkout; `agentCliDir`.
- `tools.build-windows-570.test.js`: the staging, both shims, no `.cmd`, the
  listing guard, and the folder and marker pinned equal to `win32launch.js`'s.
- `tools.windows-kosmos-shims-570.test.js` (Windows only): both shims run in real
  PowerShell and Git Bash, the message and exit code exact.

## Weakest part

The PowerShell shim is a `.ps1`, so it runs only where PowerShell's execution
policy allows scripts. Claude Code runs its PowerShell with a process-scope
Bypass policy (measured on this box: `Process Bypass`), and an agent's commands
are what this command is for. A person's own default Restricted PowerShell would
refuse it, and nobody but an agent is meant to run it. A signed PE shim would
remove the dependency. It is the follow-up, not this slice, because a committed
binary needs the provenance check `tools/windows/verify-launcher.ps1` gives the
launcher.

Also:
- On a board serving a NAMED world, the board token is at that world's root, while
  this CLI, like the report hook and `install/kosmos`, reads `store.ROOT` without
  the world. That gap is shared with the existing clients and is not introduced
  here.
- A shell Claude Code starts reads PATH from the environment the agent was launched
  with. That is measured with a real agent in the live check, not assumed.

## Review log

- Round 1 (opus) found:
  - [BUG] Through PowerShell, `kosmos.cmd`'s `%*` kept only the FIRST line of a
    multi-line answer and still exited 0. Multi-line answers are the normal shape.
  - [BUG/SECURITY] A message holding `"...&..."` was split, and cmd ran the tail
    as a command.
  - Both were fixed by replacing the `.cmd` with `kosmos.ps1` (the arguments go
    as JSON in the environment). The sh shim is now a committed file.
  - A new Windows-only test runs both shims in real PowerShell and Git Bash with a
    multi-line, quoted, `&`, `%PATH%`, `^` and `|` message, and asserts it
    arrives exactly with the exit code. A control that passes the arguments on a
    command line fails it.
  - [CONVENTION] Comments in `engine/clipath.js` and `engine/boardrestart.js`
    said the Windows zip has no `bin\kosmos`. Both now say it does, and why
    nothing may read it as a restart.
  - [BUG, minor] `react` said "Done." whichever way the toggle went. It now uses
    install/kosmos's add, remove and refusal sentences.
  - [TEST-GAP] Nothing pinned that msg, post and react stay behind the
    board-token gate. A test now checks that neither exempt set names them.
  - [NIT] `task add` no longer sends an agent token the route ignores. The header
    states the one exit-code difference (a timeout is 3). The sh shim's dead
    no-cygpath fallback is gone.
- Round 2 (sonnet) found:
  - [BUG] A missing node.exe made `kosmos.ps1` exit 0: the error was
    non-terminating, and `exit $null` is success. Now `$ErrorActionPreference`
    is Stop, a catch prints "kosmos could not run: ..." and exits 1, and a null
    code is 1.
  - [BUG] JSON over ~32K characters could not fit one environment variable. The
    agent got a usage error, although a room post may be 64 KB. The arguments
    now travel in a private temp file (UTF-8, no BOM, deleted in `finally`).
  - [BUG] An unquoted PowerShell list or table (`a, b`, `@{...}`) was stringified
    into different words ("[object Object]"). `argvFrom` now refuses it (exit 2)
    with a sentence to quote it.
  - [NIT] The sh shim checks for cygpath and says so, instead of three unrelated
    errors.
  - [TEST-GAP] Real-shell tests now cover a 40,000-character message, a missing
    node.exe (exit 1), an unquoted table (exit 2), and the temp file being
    removed.
- Round 3 (opus) found:
  - [BUG] Under `2>&1`, `2>$null` or a pipe, Stop turned the CLI's stderr into a
    terminating error, so a "maybe" (3) came back as 1, inviting the duplicate
    retry. Stop now covers only the file write. node.exe is checked with
    Test-Path, and the call runs under Continue. A real-shell test checks four
    redirection forms, and each returns 3.
  - [BUG, minor] PowerShell number tokens arrived rewritten (`007` became 7,
    `1kb` became 1024). Each plain value now goes as `[string]`, the typed text.
    Lists and tables go as themselves (`,$a`) and are refused. The JSON depth is 1.
  - [CONVENTION] A stray `out.txt` capture was committed. It is removed.
  - [SECURITY, low] A shim killed mid-call left the argument file on disk. The
    CLI now deletes it as soon as it has read it, with the shim's `finally` as
    the backstop.
  - [NIT] The `bin/kosmos` listing check moved above the comment it was
    splitting. The plan's "in the environment" is now "in a temp file". The
    temp-file test proves the file existed when read and is gone after.
  - Controls: Stop around node, no typed text, and no unlink each fail a test.
