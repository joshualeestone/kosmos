# pr-bc-4119: PR-time browser checks run the checks a page diff touches (#4119)

## Finished means
A PR that changes `web/index.html` runs, in the `browser-checks` PR job, the fixed DOM-state
allowlist PLUS every browser check the diff touches, and replaying the two 09-26 escapes selects
the check that caught each at the cut: #3985 (5a2aae1e3) selects render-talk, #4095 (743711ea6)
selects render-fields. Both checks are shown red on those pre-fix commits, and the added PR time
is measured.

## Measured before building (2026-09-27)
- The #2518 surface map alone selects NEITHER escape: render-talk and render-fields carry no
  `Browser-check-surface` annotation (138 of 251 checks carry none).
- Selectors read from each check's own source (ids/classes inside querySelector/locator/
  getElementById/... string arguments) select render-talk for 5a2aae1e3 (`.msg`, `.msg-t`,
  `.mwhen`). They cannot select render-fields for 743711ea6: render-fields sweeps every field on
  the page and names none of `#tsk-by`/`#tsk-sort`/`#tsk-search`. No selector map can.
- So page-wide invariant checks declare themselves (`// Browser-check-scope: page`) and run on
  every page change: render-fields (19.5 s on the runner) and contrast (82 s). named-controls is
  page-wide too and already in the allowlist.
- Cost, from the 09-26 nightly's per-check runner times over the last 40 page commits: median
  +20 checks / +9 min check time, p90 +14 min, max +27 min, on top of the current ~6.6 min step.
  The full suite is ~37 min.
- The 09-26 nightly passed 225 of 231 checks on the runner, so the 09-07 fear (paint/timing checks
  false-red wholesale on CI) no longer holds broadly.
- render-talk needs tmux on the runner (status.snapshot(); #3973, fixed for the nightly by #4076).
  The PR job did not install tmux; it now does.

## Build
1. `tools/bc-pr-select.js`: base/head -> selected check names, each with its reason
   (annotation token / source selector / page scope). Reuses `bc-surface-map.sh covering` for the
   annotation half so the map is not reimplemented.
2. `render-fields.js`, `contrast.js`: `// Browser-check-scope: page`.
3. `browser-checks.yml`: full-depth checkout, install tmux, compute the selection, run the
   allowlist plus the selection, print what was added and why.
4. `bc-pr-select-4119.test.js`: replays the two real commits (full history in test.yml) plus
   synthetic arms, including a red-capable control.

## Rejected
- Full render-* set on every page PR: ~37 min each, 4x the targeted median, for checks the diff
  cannot reach.
- Annotating render-talk/render-fields by hand only: fixes the two named cases and none of the
  other 136 unannotated checks.

## Weakest part
Source-derived selectors are a heuristic. A check that builds a selector at runtime (string
concatenation, a variable) is invisible to it, and a common class like `.msg` over-selects. The
over-selection is cost, not a wrong verdict; the under-selection is the same gap as today, now
smaller. What would change my mind: a nightly showing many selected checks red on the runner
for runner reasons, which would turn the added coverage into noise.
