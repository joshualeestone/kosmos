# lsattr-6149: an update refuses on a Linux immutable file before removing anything (kosmos#6149 point 9)

## Problem
Since #4455 an update lifts and checks every part before removing any. On macOS the locked-file flags are searched for; on Linux a file marked immutable or append-only (`chattr +i`, `+a`) was not, so the update removed `bin`, failed at `app` and left half an install, as before #4455.

## Change
- `install/setup.sh`: off macOS, where `lsattr` exists, each part is searched for an `i` or `a` flag: `lsattr -d` on the part folder itself and `lsattr -Ra` inside it (dot-files included; the . and .. entries skipped). The match is lowercase on purpose: uppercase I (indexed folder) and A (no access time) are harmless and common. A hit refuses the update before anything is removed, names the file, and gives the only line that clears it, `sudo chattr -R -i -a '<part>'`, on every flagged part. The refusal record (#6149 point 8) says `why=immutable`. A filesystem lsattr cannot read prints nothing and is not refused, as before.
- `engine/update.js`: `updateRefused()` accepts `immutable`.
- `web/index.html`: `updateRefusedText()` says it is marked immutable and gives the administrator's `chattr` line.

## Tests
- `tools/test-update-locked-app-4455.sh` (74 passed here):
  - LINUXSTUB, on any OS: a stub `uname` answering Linux and stub `lsattr`s answering for `app/` only. A flagged dot-file refuses, is named, gets the `chattr` line for that part only, and is recorded as immutable with its part; SELF: a flagged part folder refuses as immutable, not as a permissions problem; CONTROL: uppercase I and A, and a flagged `..`, do not refuse. Mutants, each failing its arm: the Linux branch removed (4), no `-d` (SELF), no `-a` (LINUXSTUB), `.`/`..` not skipped (CONTROL), a case-insensitive match (CONTROL).
  - REALIMMUTABLE: a real `chattr +i` dot-file (so it also proves `-a` against the real lsattr) where Linux, lsattr and password-free sudo exist (the CI runner); its CONTROL checks lsattr really shows the flag. Skipped elsewhere, saying so.
- `engine/update.refused-6149.test.js`, `web.update-refused-6149.test.js`: the new reason read and said.
- All web tests (2844 pass), the engine update tests, the installer guards.
