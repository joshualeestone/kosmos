# lsattr-6149: an update refuses on a Linux immutable file before removing anything (kosmos#6149 point 9)

## Problem
Since #4455 an update lifts and checks every part before removing any. On macOS the locked-file flags are searched for; on Linux a file marked immutable or append-only (`chattr +i`, `+a`) was not, so the update removed `bin`, failed at `app` and left half an install, as before #4455.

## Change
- `install/setup.sh`: off macOS, where `lsattr` exists, each part is searched with `lsattr -R` for an `i` or `a` flag. A hit refuses the update before anything is removed, names the file, and gives the only line that clears it, `sudo chattr -R -i -a '<part>'`, on every flagged part. The refusal record (#6149 point 8) says `why=immutable`. A filesystem lsattr cannot read prints nothing and is not refused, as before.
- `engine/update.js`: `updateRefused()` accepts `immutable`.
- `web/index.html`: `updateRefusedText()` says it is marked immutable and gives the administrator's `chattr` line.

## Tests
- `tools/test-update-locked-app-4455.sh` (71 passed here):
  - LINUXSTUB, on any OS: a stub `uname` answering Linux and a stub `lsattr` answering for `app/` only. A flagged file refuses, is named, gets the `chattr` line for that part only, and is recorded as immutable; CONTROL: an lsattr that flags nothing does not refuse. Mutant (the Linux branch removed): 4 fail.
  - REALIMMUTABLE: a real `chattr +i` file where Linux, lsattr and password-free sudo exist (the CI runner); its CONTROL checks lsattr really shows the flag. Skipped elsewhere, saying so.
- `engine/update.refused-6149.test.js`, `web.update-refused-6149.test.js`: the new reason read and said.
- All web tests (2844 pass), the engine update tests, the installer guards.
