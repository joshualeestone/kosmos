# toolloop-6071: slice D1 of #6071 (#5154 slice D), Claude Code

The card's plan is comment 6152129327 on #6071; this is increment D1 of it.

## What D1 does
A Claude Code agent's failed tool call (the PostToolUseFailure hook) is sent to the board as a digest, and the board
counts the SAME failure repeating inside one turn. Nothing is raised to the person yet (that is D2). The first time a
run reaches the threshold is logged, so the threshold can be read against real boards first.

- engine/reporthook.js: PostToolUseFailure joins HOOK_EVENTS (wired into every account's settings by ensureWired, merge
  only). A Claude Code too old to know the event ignores it ("unknown hook event; entry ignored", in 2.1.296).
- install/kosmos-report-hook.sh: the PostToolUseFailure branch. The signature is a hash of tool + tool_input (key-sorted)
  + the WHOLE error, made in the hook, so the input never leaves the Mac; only the error's first line is sent. Without
  jq: the whole payload with its per-call tool_use_id and duration_ms removed. An interrupt is not sent (jq reads
  `.is_interrupt`, so an input key of that name cannot hide a failure). Sent in the background, like report().
- install/kosmos: `printf <error line> | kosmos tool-failed <tool> <sig>`, internal (no help row; MAC_INTERNAL_VERBS).
  The error line comes on stdin and the body goes to curl on stdin, so neither is in an argument list `ps` shows.
- engine/kosmos-report-hook.js: the Windows twin (failureRequestFor, toolFailed), POST /api/toolfail itself.
- server.js: POST /api/toolfail, sender resolved as POST /api/report resolves it (resolveAgentSender, token first, the
  same pane refusal on an enforcing board); in AGENT_TOKEN_ROUTES (pinned in server.agent-token-sender-570.test.js).
  Body limit 8 KB. POST /api/report calls toolloop.noteTurnEnd on an automatic idle, stopped or started, BEFORE
  selfreport.record (which refuses an automatic idle over a standing deliberate wait: the turn ended all the same).
- engine/toolloop.js: the per-agent run at store/toolloop/<key>.json. Consecutive identical signatures count; a
  different signature starts a new run; a turn end (noteTurnEnd) starts a new run. LOOP_AT = 5. Forgotten on create,
  remove and delete, like stuckterminal.

## Known limit
Successful calls are not seen (no PostToolUse: it would start a hook process after every tool call). So an agent that
edits, reruns a test and gets the IDENTICAL failure (same whole error output) counts that rerun; one whose output
changed is a different signature. The same goes for a poll with the same input and a bare error (`until test -f`).
Only CONSECUTIVE identical failures count, so alternating failures never add up. Measured on real boards through the
log line before D2 shows anything; D2 decides the threshold from it.
- A turn ends on an automatic idle, stopped or started, and on the next prompt (`answering a prompt`, the hook's
  UserPromptSubmit sentence), so a turn the person ended with Esc (no Stop) is still a boundary.
- A digest sent in the background can arrive after the Stop that followed it; it then starts a new run at 1 (an
  under-count, the safe direction).
- POST /api/toolfail is not in REMOTE_AGENT_ROUTES (a network peer cannot write it; /api/report can be). An agent on
  another computer records no failures, so D2 must not read zero failures from a remote agent as zero loops.
- Without jq the signature keeps session-level fields (permission_mode): a mode change mid-run splits it, as would a
  per-call field a future Claude Code adds. Both under-count.
- The Windows hook waits for the digest (at most 3 s) as it does for its reports; the Mac sends it in the background.
- A digest that arrives within LATE_MS (2 s) of a turn end still counts in the turn that just ended (it was sent before
  the Stop but delivered after it).

## For D2, before anything is shown
- The stored error line is the tool's own first line, kept on this Mac (store/toolloop), after the diagnostics
  redactor (engine/diagredact.js) has taken out keys, tokens, emails and home folders; if redaction fails, nothing is
  stored. D2 still shows it on the Mac's card only and strips it from any phone push, as notify.js does for needs_you
  words: a redactor finds known shapes, not every secret.
- A turn end trusts `--auto` as the self-report guard does: an agent can shorten its own run, never invent one.

## Rejected
- Reading the transcript's is_error results on a tick: polling every agent's transcript, versus a hook pushed only on a
  failure that carries the error.
- Counting in the hook and raising through `kosmos report needs_you`: Stop clears a standing auto needs_you at the end
  of every turn, so a loop would vanish the moment the agent gave up.
- Sending the raw payload: a failed Write carries a whole file in tool_input.
- Reading turn ends from the self-report record (built first, review 1): the record refuses exactly the automatic idle
  a turn end writes whenever a deliberate wait is standing.
- Hashing only the error's first line (built first, review 1): a Bash failure's first line is just "Exit code N", so
  an agent rerunning a test that fails differently each time read as looping.

## Evidence for the weakest premise (that failing Bash calls reach PostToolUseFailure)
Every non-zero Bash exit in this agent's own 2.1.296 transcript (7 of 7) is a tool_result with is_error true, so Claude
Code treats them as failures. That the hook fires on that path is not yet measured; D1's records measure it.
