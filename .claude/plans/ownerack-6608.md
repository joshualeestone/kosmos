# ownerack-6608: a post that names one owner is left to them (kosmos#6608)

**Card.** Agent feedback, 2026-10-19: a room message naming one agent as owner still drew acknowledgements from the
others, blurring who owned it. Ask: hold back agreement-only replies from the others (unless they bring a conflict or
new information), or show them de-emphasised; an owner-status line was suggested. "Builder decides; reversible."
Taken by me on Splinter's instruction (00:05: take one from the unclaimed list and make the call).

**The call.** When the room's latest post that says something @-names exactly one member, an agreement-only reply from
any other agent (not that member, not that post's author) is not passed on, from the FIRST such reply. Same answer as
the existing run trigger (#4934/#5967): code `ack_only`, an honest because, nothing stored, nothing typed, and no valve
or refused row (it is not a hold). Agents are told the same in their instructions (doctrine v36).

**Done when.** In a room whose latest content post names one owner, another agent's "agreed" is refused at once and
the owner's own "ok" and anyone's content reply go through; two named, none named, or a later content post lift it;
the instruction tells agents to leave such a post to its owner.

## Change
- `engine/messages.js` sendPostWithDelivery, inside the existing ack block (same gate: the limit on, not the person,
  the room under its volume budget): find the latest post or external row in this project whose text is not
  acknowledgement-only (`chat.acknowledgementOnly`), the person's posts INCLUDED (the run trigger starts after them; an
  owner is usually named by the person). If its recorded `mentioned` has exactly one member and the incoming
  acknowledgement-only post is from neither that member nor that post's author, return `ack_only` with
  "That post named <display name> to take it, so Kosmos did not pass on an agreement-only reply from anyone else;
  posts with something new still go through." (no quotes: the CLI's sed stops at one).
- `engine/defaults.js`: one paragraph in the reactions section ("When a post names someone else to take it, leave it to
  them."); DOCTRINE_VERSION 35 -> 36 with its log entry; the v36 fingerprint pinned; `engine/doctrine-past.js`
  regenerated by `node tools/doctrine-past.js`.

## Review 1 changes
- Not applied when the owner-naming post asks something (a "?": its answers are wanted), when the reply's replyTo is a
  different post, or when the post is older than the room's counting window (`windowFrom`). The log is scanned newest
  first rather than filtered and sorted.
- The board sends `owner` with `ack_only`; install/kosmos and tools/windows/kosmos-cli.js name the owner instead of
  saying the reply "only agreed with what was already said" (an older board, without `owner`, keeps the old words).
- The instruction now reads: if the latest room post @-names one agent, that agent is not you, and it asks you nothing,
  do not post only to agree; still answer a question put to you. v36 re-pinned (unreleased).

## Review 2 changes
- A room-wide ask with no question mark (ROOM_ASK: everyone, everybody, all of you, anyone, confirm, let me know, reply,
  respond, thumbs up...) lifts it, as a "?" does. Deliberately wide: a missed ask drops an answer, a false one only lets
  an acknowledgement through.
- Freshness is countFrom, not the window: the person's later post (even an agreement-only one) or a reopen ends it, as
  it ends the run and the volume count.
- install/kosmos drops an owner name that arrived escaped (a quote or backslash), and says the general words.

## Review 3 changes
- The replying agent named in plain text in the hand-off (its session or display name, whole word, any case) is being
  asked something, so its reply goes through; the other agents' acknowledgements are still left out.
- The owner must still be a member of the room.
- The owner's display name is cleaned by printableName before it reaches the agent's terminal (lifted from ambiguousNote,
  #4653, so one definition serves both).
- Deferred: the cut-reply retry keeps the general words in both CLIs (they stay in step; the general words are not false
  there, only less specific).

## Review 4 changes
- A hand-off that also has an ambiguous @-word (ambiguousMentions) is not one owner. An outside row's display name never
  makes a local agent its author. A word-like name can match the plain-text check by accident; noted, safe direction.

## Review 5 changes
- A post since countFrom that @-names the replier, which the replier has not spoken after, is still owed an answer: a
  later hand-off to someone else does not swallow that answer (agents rarely set replyTo).
- The newest-first scan stops at countFrom (nothing older can be fresh).
- The owner test checks the roster's display name (an earlier test in the file can leave "Mara Lisa"), and each block
  clears the log; the WHOLE messages.test.js file is run, not only the #6608 tests (181/181).

## Rejected
- An owner-status line on the post (seen, working, done): new interface, against the no-new-UI rule.
- De-emphasising the replies on the page: they are still typed into every agent, which is the noise.
- Refusing on any @-name count: two or more named is a shared ask, and acknowledgements there can be the answer.

**Weakest premise.** The classifier reads "on it" as saying something, so the owner's own "on it" becomes the latest
content post and lifts the rule for later acks (the run trigger still applies to those). Accepted: the owner speaking
is itself the status line the card asked for, and changing what counts as an acknowledgement is a wider change.
