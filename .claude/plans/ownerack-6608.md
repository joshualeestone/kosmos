# ownerack-6608: a post that names one owner is left to them (kosmos#6608)

**Card.** Agent feedback, 2026-10-19: a room message naming one agent as owner still drew acknowledgements from the
others, blurring who owned it. Ask: hold back agreement-only replies from the others (unless they bring a conflict or
new information), or show them de-emphasised; an owner-status line was suggested. "Builder decides; reversible."
Taken by me on Splinter's instruction (00:05: take one from the unclaimed list and make the call).

**The call.** When the room's latest post that says something @-names exactly one member, an agreement-only reply from
any other agent (not that member, not that post's author) is not passed on, from the FIRST such reply. Same answer as
the existing run trigger (#4934/#5967): code `ack_only`, an honest because, nothing stored, nothing typed, and no valve
or refused row (it is not a hold). Agents are told the same in their instructions (doctrine v36).

**Done when.** In a room whose latest content post names one owner, another agent's "agreed" is refused at once and
the owner's own "ok" and anyone's content reply go through; two named, none named, or a later content post lift it;
the instruction tells agents to leave such a post to its owner.

## Change
- `engine/messages.js` sendPostWithDelivery, inside the existing ack block (same gate: the limit on, not the person,
  the room under its volume budget): find the latest post or external row in this project whose text is not

  "That post named <display name> to take it, so Kosmos did not pass on an agreement-only reply from anyone else;

- `engine/defaults.js`: one paragraph in the reactions section ("When a post names someone else to take it, leave it to
  them."); DOCTRINE_VERSION 35 -> 36 with its log entry; the v36 fingerprint pinned; `engine/doctrine-past.js`
  regenerated by `node tools/doctrine-past.js`.

## Rejected
- An owner-status line on the post (seen, working, done): new interface, against the no-new-UI rule.
- De-emphasising the replies on the page: they are still typed into every agent, which is the noise.
- Refusing on any @-name count: two or more named is a shared ask, and acknowledgements there can be the answer.

**Weakest premise.** The classifier reads "on it" as saying something, so the owner's own "on it" becomes the latest
content post and lifts the rule for later acks (the run trigger still applies to those). Accepted: the owner speaking
is itself the status line the card asked for, and changing what counts as an acknowledgement is a wider change.
