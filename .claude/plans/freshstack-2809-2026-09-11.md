# freshstack-2809: Fresh-start buttons size to content, not full width

**Card:** kosmos #2809 (night-shift rotation, Baron Draxum)
**Branch:** freshstack-2809 (agent-workforce)

## The ask

Josh, reviewing 0.6.56 live 2026-09-11: "Can you make a card to not make these
buttons full width, they look terrible." The buttons are the Memory-tab "Fresh
start" actions (Compact / Clear / Restart) on the agent detail page.

This reverses Josh's own earlier ruling (2026-08-23 19:57: "nice big fat buttons
that are all three stacked"), which had made them a full-bleed stack. After
seeing it live he wants them sized to their content instead.

## The change

`web/index.html`, the `.freshstack` CSS (around line 5091):

- Drop `display:block; width:100%` from `.freshstack .btn` and replace with
  `display:block; width:fit-content`. `display:block` keeps them stacked one per
  line and left-aligned (the block default); `width:fit-content` shrinks each to
  its label plus padding.
- Leave `.freshstack` itself a plain block (no flex). This is deliberate: a
  flex-column parent would also resize the sibling `.fmsg` status receipts that
  share the restart container. Scoping the rule to `.btn` avoids that side effect.
- Drop the now-vestigial `text-align:center` (with no extra width there is
  nothing to center).

Updated the two comments (the CSS rule and the markup block at ~7785) that still
asserted the full-bleed "big fat buttons" design, so a future reader is not
misled about the reversal.

## Verification

Layout-only change (no behaviour, no dark-mode token touched). Guarded by two
assertions added to `docs/browser-checks/render-memory-controls.js` (which
already renders this panel): each button is content-width (`btn <= container *
0.9`) AND the three stack one per line, left-aligned. Both are red-capable: a
re-widen to `width:100%` fails the width check; a flex-row regression fails the
stacking check. Verified in a live chromium render (screenshot) and the full web
suite (1278 tests) plus the browser-check guard tests are green.

## Decisions / rejected alternatives

- **Rejected: flex-column parent with `align-items:flex-start`** (the first
  implementation). It content-sizes the buttons but also turns the sibling
  `.fmsg` receipts into content-width flex items. `display:block; width:fit-content`
  achieves the same button layout without touching siblings.
- **Rejected: uniform width (all buttons the widest label's width).** Josh asked
  for "size to content", which is each button's own width; a shared width is a
  different design and not what was asked.
- **Weakest premise:** that three different-width, left-aligned buttons read as
  tidy rather than ragged. The live screenshot supports it; if Josh prefers them
  centered or uniform-width, that is a one-line follow-up.
