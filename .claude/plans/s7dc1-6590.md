# s7dc1-6590: the typed-code Allow, engine and routes (kosmos#6590, S-7d branch c, part c1a)

The design is private (kosmos-relay `.claude/plans/s7dc-6590.md`); this file says what this branch does and how it is
tested, nothing more. Base: origin/main c0d73b96e8. Needs the connector from kosmos-relay `s7dc0-6590` for the verbs it
calls; until a board writes the `board-v2` marker (a later part), all of it is inert.

## Scope
- engine/remote.js: `boardV2()` (the marker, read every time); `devicesWaiting()` (one shared read of `devices waiting`
  for a couple of seconds, concurrent asks share one spawn, nothing spawned without the marker or while off or not
  enrolled; rows and the certificate fields checked); `deviceAllowCode`, `deviceDropWaiting`, `devicesClearWaiting`
  (values after `--`; an empty code or one with a control character refused before any spawn; a sentence that holds
  the typed code is never passed on); `listedAsComputer(id)`; under the marker `pendingDevices()` keeps only computer
  rows.
- server.js: `GET /api/remote/waiting` (loopback peer, no forwarder, this board's own session); `POST
  /api/remote/waiting/{allow,drop,clear}` (no forwarder, made on this computer, this board's session, a person at the
  screen); under the marker `/api/remote/devices/{allow,deny}` refuse any id the snapshot does not list as a computer.

## Tests
engine/remote-typedallow-6590.test.js (7) and server.typedallow-6590.test.js (3). Ten mutants (each gate, the `--`,
the code scrub, the row filter, the marker gate) each go red. Related suites: 458 tests, 0 failed.

## Not in this part
The page (c1b), the Mac's own sign-in ack (c2), the automatic Allow (c3), the certificate acknowledgement (c4), and
writing the marker (c6).

## Weakest premise
That every new path is behind the marker. The tests pin the no-marker path for each engine call and route.
