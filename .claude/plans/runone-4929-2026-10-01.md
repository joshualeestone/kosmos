# #4929: run named test files with the suite's environment (`tools/run-tests.sh --only <file>...`)

Card: kosmos#4929 (found by #4911 review 8). Branch `runone-4929`.

## Problem, measured on main
`tools/run-tests.sh` always runs the whole node suite: extra arguments go to `node --test` after the full file list.
So the one way to run ONE file is a bare `node --test <file>`, which light queue runs use, and which skips what the
runner sets up for a test. That includes the dead-port phone-home URLs (#4253: without them a test that boots a
board tells installkosmos.com about a new install), the fake gh and vercel (#4326), KOSMOS_NO_LEGACY_MIGRATION, the
CODEX_HOME / KOSMOS_AGENT_TOKEN_ONLY unsets, the per-run temp root, the --require launch and tool guards, and the leak
guards.

## What this does
`tools/run-tests.sh --only <file>...` (the first argument): the named files run with everything above, and without
what belongs to the whole suite:
- no queue WAIT (a light queue turn already holds its place; that is the case the card names). A release's machine
  claim and a live install harness still refuse, asked once, as `yarn test` would. A run holding the claim's own
  cookie is not refused (tested with a live claim). Whether a light queue turn's command inherits that cookie is the
  queue's business (#4911); if it does not, the run is refused only by a claim that is foreign anyway;
- no whole-suite coverage count (#1934 counts every *.test.js; a named list is not the suite);
- no shell part;
- no branch browser-check gates (they say whether the branch may merge, not whether these files pass).
The node --test line, the --require guards and the leak guards are the same lines the full suite uses.

Refused before anything runs (exit 2): no files, an option in place of a file, a file not named *.test.js, a file
that is not there (relative paths are read from the repo root; absolute paths work), and --only with a
KOSMOS_TEST_PART or KOSMOS_SHELL_SHARD. One bad name stops the whole list.

Other runs' "is a suite live" checks (cut-guard's suite candidates, heavy-gate) match any run-tests.sh command line, so
they see a --only run as a suite and wait for it. That is the safe direction and is left as it is.

## Decided, with reasons
- **A mode of run-tests.sh, not a second script that sources shared setup.** About 30 tests and scripts read
  run-tests.sh's text (the #4253 exports, the flush-left `node --test` line, the `local where` anchor). Moving the
  setup into a library would move what they pin. A mode keeps the one file and the one node --test line.
- **No queue for --only.** The card asks for it: --only is meant to run inside a light turn. Weakest premise: someone
  runs a long list of files with --only outside any turn and shares the box without queuing. What would change it: a
  measured overlap; then --only waits like a light run.
- **Not changed here:** the light-lane text in #4911 that points at a bare `node --test` can point at --only once this
  lands (that is #4911's file).

## Tests
`tools.run-tests-only-4929.test.js` runs the real runner on probe files written outside the repo (a *.test.js inside
it would change the whole-suite count). The probe reports what a test sees: the dead-port URLs, the fake gh, the
migration opt-out, CODEX_HOME and KOSMOS_AGENT_TOKEN_ONLY unset, the kt temp root, both --require guards, and only one
test ran. Every run starts from an environment with none of what the runner exports and a plain TMPDIR, so each assertion can
only pass if the run under test set it up; this holds bare, under CI's KOSMOS_TEST_PART=node, and under the runner
itself (all three measured). A control shows a bare node --test sees none of it. A red file's failure comes back as a non-zero exit.
Each refusal exits 2 and runs nothing. A live claim (a holder kept alive, its own marker folder) refuses --only, and its
own cookie runs it; the test strips an outer claim cookie, so it holds inside a queue turn or a cut too. Red on main's
runner for every arm except the bare-node control.
