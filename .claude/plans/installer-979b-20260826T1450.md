# installer-979b: the installer stops putting Claude Code on every Mac (kosmos#979, branch B)

## Why

Josh's ruling, 2026-08-26 10:32 CDT: *"we assume that not everybody is going to have Claude
Code so you would be able to just set up with OpenAI and that we're not forcing people to
have Claude Code as part of the installer."*

He watched it happen anyway at 14:45 on a fresh install and sent screenshots. What ships
today, in the installer's own words: *"Kosmos needs Claude Code and this Mac does not have
it. Installing it now."* Then a 231MB download, no confirm, no way to decline, and a `die`
that kills the WHOLE Kosmos install if it fails.

## ⚠️ Two of my own beliefs were wrong, and correcting them is why this branch exists now

1. **"Add a confirm step to the installer."** I told Josh I could. **I cannot.**
   `install/pkg-scripts/postinstall:144` runs setup.sh as
   `curl -fsSL "$0" | /bin/sh` under `launchctl asuser` + `sudo -u`. There is no terminal,
   and stdin is the script's own bytes. A prompt there is not hard, it is impossible.
2. **"Removing the pre-install has to wait, or a bare-Mac Claude user has no way to get
   it."** I said this all afternoon and never checked it. **It is false.**
   `engine/connect.js:698-730` already probes for a runnable `claude`, and when there is
   none `runFlow` downloads it from the vendor, verifies the published per-platform SHA256,
   refuses an https→http redirect, and runs its installer. Shipping since 2026-08-12.

⇒ The thing supposedly blocking this ruling was a belief of mine, not a missing piece.

## What

`check_claude_code` (setup.sh:1586, called once at :1660) has four arms today: found-and-
runnable → ok; something-there-but-broken → **die**; found-elsewhere → **link**; nothing →
**install** (`curl … | sh`) or **die**. Under the provider model only the first is still
the installer's business.

It becomes **`note_claude_code`** -- renamed, because a function called `check_` that no
longer gates is a name that lies -- and it OBSERVES:

| what it finds | what it does now |
|---|---|
| runnable at `~/.local/bin/claude` | says so. Unchanged. |
| something there that cannot run | **says so and carries on.** No `die`. Kosmos installs; Claude simply is not available until the person deals with it. |
| a working `claude` elsewhere on PATH | **says so and LINKS it**, unchanged. See the correction below: removing this was a mistake. |
| nothing anywhere | **says so and carries on.** No download. |

Nothing is installed, nothing is linked, nothing dies.

## Out of scope, and say so rather than imply it

- **The yellow confirm box before the download.** That is a SCREEN and it is Mona Lisa's,
  against the spec page. Without it, pressing Connect on Claude starts the download with
  visible progress but no ask. ⇒ **This branch does not deliver Josh's confirm step.** It
  delivers the half that is mine: nothing downloads until a person presses something.
  📌 Mona Lisa's testable line for #979, which this branch is measured against: *on a
  machine with no Claude Code, nothing downloads it until a person has pressed Connect.*
- `AGENT_WORKFORCE_CLAUDE_INSTALL_URL` becomes unused here. It is the operator's mirror
  override; the surviving equivalent is connect.js's `AGENT_WORKFORCE_CLAUDE_DOWNLOAD_BASE`.
  Retire it **by name in a comment**, not silently, so an operator who set it learns it
  moved rather than discovering it stopped working.

## Review pass 1: two BLOCKERs, and one of them reversed a decision in this plan

**1. I removed the link arm on a belief that was wrong twice over.**
The plan above said `engine/runners.js`'s vendor-external `linking` phase does that job on
Connect, so doing it here was duplication. Checked after the reviewer flagged it:

- that phase is on an **unmerged branch**, not on `main`, so on this branch it does not exist
  at all; and
- **even merged it would not run**, because it is reachable only through
  `POST /api/runners/claude/install`, which no screen calls. `engine/connect.js` looks ONLY at
  the canonical `~/.local/bin/claude` and never at `command -v claude`.

⇒ So a person with Claude Code at `/opt/homebrew/bin/claude` would have been told a link was
coming and instead handed a fresh **231MB download of software they already have**. The arm is
restored, and its `die` is now a sentence that carries on.

📌 **It never breached the ruling anyway.** Josh's rule is that nothing INSTALLS and nothing
DOWNLOADS before a provider is chosen. A symlink moves no bytes and adds no software; it makes a
copy the person already chose to install usable. Removing it was strictly worse for them.

**2. `tools/clean-machine.sh` still asserted the behaviour this branch removes**, and it runs
against the SERVED artifact at release-verification time -- so it would have gone red on the
release, telling an operator the installer was broken when the harness was stale. That leg has
now asserted three different things in three days (#133 refuse, #548 carry, #979 install
nothing) and its file header was still describing the FIRST of them. Both moved with the product.

**Also fixed:** the pre-existing header three lines above the function still said "CLAUDE CODE IS
GATED HERE"; the deleted `AGENT_WORKFORCE_CLAUDE_BIN` override test is restored (the seam is
still read by the shipped function and pins eleven sandbox homes in `tools/test-install.sh`, and
had no other coverage); and the silent arm now writes one line to the **install log**, because
the transcript is what a stranger is asked to send us and the commonest machine state was
leaving no trace at all. A log is not a screen, so the ruling is untouched.


## Review pass 2: two BLOCKERs, and one of them was a release gate I made guaranteed-red

**1. `tools/clean-machine.sh`'s new "said nothing about Claude Code" leg could never pass.**
It grepped the WHOLE install transcript for `claude`, and `install/setup.sh` legitimately prints
*"(this answers Claude Code's one-time skip-permissions question for this whole Mac"* on the
SUCCESS branch of the permission merge, which is the normal path on a clean home. So the leg was
inverted against reality: it could only go green when an unrelated step FAILED. On the harness
that runs against the served artifact. ⇒ Scoped to the retired sentences instead
(`Installing it now`, `does not have it`, `We tried to install Claude Code`), which is what the
ruling actually forbids.

**2. My comment claimed Kosmos raises Claude Code "on the Connect step ... and nowhere else".**
False: `engine/machine.js`'s `installedCheck` lists it beside tmux as a machine requirement with
no provider awareness, and the first-run checks screen paints it. ⭐ **That state was unreachable
before this branch, because the install died first, so removing this gate is what EXPOSES it.**
Fixed on `machine-check-979c`; recorded here with the ordering requirement rather than quietly
narrowed, because a comment claiming the problem is already handled would have sent the next
reader hunting a bug that had just been created two files away.

**The one that changes behaviour:** the unrunnable arm returned before ever asking whether a
working `claude` exists elsewhere, which defeated the link arm in the exact case it exists for
(a broken link at the canonical path AND a working copy on PATH is the person who would otherwise
re-download the whole binary). The old gate handled that pairing; returning early dropped it
silently. Restored, with the one-shot replace remedy, and tested.

**Three states the rewrite had dropped are restored and tested:** link idempotence (updates re-run
this installer, so a link the function writes must satisfy its own accept test next time), a
symlink to a DIRECTORY (the other half of "-f follows symlinks"), and the non-fatal link failure.

**Also:** the silent arm's log line now carries the run id, like every other line in that file
(the invariant is stated in capitals up top: without it two overlapping runs interleave
invisibly, in the one file we ask a stranger to send us), with the redirection order fixed so a
failed append cannot print to the console in the one arm required to be silent. Half a comment
that survived an earlier edit is gone, and the leg no longer names its artefacts after a retired
ruling.
