# #4914: `kosmos task assign <project> <n> <agent>|me|nobody [--part <m>]`

Card: kosmos#4914 (slice 2 of #4887). Branch `taskassign-4914`.

## Problem, measured on main (7fd68d731)
`kosmos task` offers list|add|close|message|built|hold|unhold. A task given to the wrong agent can only be moved
on the page. The board's move is per part: `POST .../task/<n>/part/<m>/who` (givePart), which does not identify
the caller (so no `me`) and needs a part number the CLIs cannot see.

## What this slice does
1. **Board route** `POST /api/project/<id>/task/<n>/assign {who, part?}`:
   - Identifies the caller as `task add` does (processCaller + notOnProjectRefusal; added to the agent-token routes).
   - Resolves `who` with the same rules `task add --who` has, moved into one helper both routes call:
     - `me` is the calling agent (agents only; a member named exactly what was typed wins);
     - names match a member exactly, else by store key when exactly one member has it;
     - a given name that is only spaces is refused.
   - `nobody` (same exact-member-wins rule) takes the task's owner off: assignPart with null.
   - Picks the part. One part: that one. Several and no `part`: a 400 that lists them ("this task has 3 parts:
     1 Draft (mara), 2 Review (nobody), ...; name one with --part"). A `part` that is not one of the task's (or not a number): the route's own refusal, "task N has no part M".
   - Moves through givePart, so the parts valve, the paging allowance and the tell all apply unchanged. An agent
     that gives a task to itself is not paged, as with `task add`.
2. **Both CLIs** (Mac install/kosmos, Windows tools/windows/kosmos-cli.js): `task assign <project> <n> <who>
   [--part <m>]`, args checked before the board like `--parent`, and the answer says who has it now.

## Decided, with reasons
- **A new route, not the part route from the CLI**: the board knows the parts and the caller; the CLI knows neither.
- **Anyone who may add a task may move one**, any task on a project they are on: the page already lets the person
  move any part, and the board has no ownership rule for parts today. Weakest premise: an agent taking work from
  another agent mid-task. What would change it: a report of agents grabbing each other's tasks; then only the
  current owner or an unowned task could be taken.
- **`nobody`** rather than a flag: one word, read the same way as `me`. An empty `who` is refused, so `nobody` is the
  only way to take the owner off.
- **A part that is done is refused**, not moved: its new owner would be paged about finished work. A task on hold can
  still be moved (the person may be lining it up). What would change it: someone wanting to re-own finished work for
  the record; then it would move without paging.

## Tests
Server: me, name and key matching, nobody, one part vs several (the listing refusal), a bad part, a non-member,
an unidentified `me`, no self-page, a control move between two agents that pages. CLIs: both send it, bad forms exit
2 before the board, the answer names the new owner, `--part` is passed.
