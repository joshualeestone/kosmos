# flake3478-5832: render-plus-signin-3478 [existing-2fa] race on a slow runner (kosmos#5832)

## Problem
On CI (PR #5827, browser-checks run 38121665402, attempt 1), the check timed out twice on the "Finish signing in" click
(`#plus-si-register-go`). Playwright's log: the button was "not stable", then "not visible" until the timeout.

## Cause (measured)
- Before the click, the check flipped its `/api/remote` mock to `enrolled: true`.
- The page's own 5 s tick (`paintPlus`, which runs while the Plus screen is on) reads `/api/remote`. When it reads
  enrolled, it correctly hides the sign-in wizard and shows the connected flow.
- On a slow runner, the gap between the flip and the click is longer: the name is typed key by key, and several
  assertions run in between. If a tick lands in that gap, the button is gone.
- The page is right. The mock was ahead of the engine, which reads enrolled only once a register has succeeded.

## Change
- The scenario's register mock (`routeScenario`) sets `page.__registered` when it answers a successful register.
- The `/api/remote` mock stops replacing the earlier one. It answers enrolled only once `page.__registered` is set, and
  until then hands the request back to the scenario's own mock (`route.fallback()`).
- This covers both orders: a register that ran by itself before this point (`straight-session`), and one that runs
  after the click (`existing-2fa`). A refused register sets nothing.
- `KOSMOS_BC_CPU_THROTTLE=<n>` (off unless set) slows the page's CPU n times with Chrome's own throttle, starting just
  before the mock. It is the slow-runner control for this race.

## Evidence (20x throttle, this Mac, headless)
- OLD check: 7 of 12 runs failed at the click.
  - Run 1 of the aimed control failed at line 508, the "Finish signing in" click, with "element is not visible", the
    same symptom as CI. The other failed runs share its signature: rc 2, 64 PASS, one TimeoutError.
  - An earlier throttle that slowed the WHOLE run failed before the target, on the first-run overlay. It was discarded
    as the wrong red and re-aimed.
- First fix attempt ("registers since the flip"): 6 of 6 failed in `straight-session`, because there the register had
  already happened. That attempt was replaced by the success flag.
- NEW check: 6 of 6 runs passed at 20x (173 PASS each), and 2 of 2 unthrottled runs passed (173 PASS).

## Weakest premise
The 20x throttle stands in for "a slow CI runner". The only measured link is that the same assertion fails with the
same message.

## Verify
- `KOSMOS_BC_CPU_THROTTLE=20 node docs/browser-checks/render-plus-signin-3478.js`: all pass. Remove the
  `page.__registered` check and it fails at the click on some runs.
- `node docs/browser-checks/render-plus-signin-3478.js` (no throttle): all pass.
