# Plan: #3614 items 1, 2, 4 -- the agent page's Files list (April)

Author: April, 2026-09-24. Branch `agent-files-3614`, based on main. It was stacked on Renet's
`dm-files-3614` (item 3, the agent instruction, which defines the folder in `engine/dmfiles.js`)
until that merged as #3655 (f15706cb); this branch also adds the instruction's "on your page"
sentence, so the promise and the list ship together.

## The folder (item 1)
- `dmfiles.filesDir(sessionName)`: the folder BESIDE the agent's own instructions file
  (`dirname(instructions.fileFor(name))` + `Files`; Renet's contract on the card), not a rebuilt
  `create.workerDir(name)/Files` (they differ for names safeKey changes, e.g. Writer). This branch
  reads the folder ONLY through that function, so there is one derivation of the path.
- Created on first use: by the agent (the instruction tells it to), or by Kosmos when the person
  clicks "Open in Finder" and it is not there yet. Kosmos never creates it just by listing.
- Removal: Kosmos's remove never deletes the agent's folder (engine/remove.js), so these files
  outlive the agent in its folder. Recorded, not changed (Renet flagged it on the card).

## The list (item 2)
- Server: `GET /api/agent/:name/files` lists the folder with `projects.listFiles` (top level,
  dotfiles and non-files skipped, symlinks not listed, newest first, a change stamp). A folder
  that does not exist yet is the EMPTY state (`ok:true, files:[], missing:true`), not an error.
  An agent whose own folder does not exist is 404.
- `POST /api/agent/:name/files/open {name}`: `projects.openFile` (bare names only, the resolved
  target must sit inside the folder, isFile; Windows opens only safe types and otherwise selects
  the file in Explorer).
- `POST /api/agent/:name/files/reveal`: creates the folder if missing (non-recursive, inside the
  agent's existing folder), then `projects.revealFolder` (Finder on a Mac, File Explorer on
  Windows).
- Page: a "Files" block directly under the four-pack (inside `.dleft`, after `#d-nav`), rows
  with icon, name, date and size (the project documents row look), a click opens, a button
  "Open in Finder" (Windows copy "Open in File Explorer" through `data-win-copy`), an empty-state
  sentence, and refresh on the existing 5-second poll with the stamp so an unchanged folder does
  not repaint.

## Mac and Windows (item 4)
- The engine functions already branch on win32 (Explorer, UNC/device refusal, safe-type opening);
  the page copy uses the existing win-copy table.

## Decisions (reversible)
- Reuse main's engine functions and the documents-row CSS rather than the unmerged #2245 panel;
  when #2245 lands, the two can share a component.
- Show up to 20 files with a count of the rest, not a paged view: this is a glance list under the
  nav, and "Open in Finder" is the way to everything.
- Weakest premise (the card's own): that the agent's own folder is the right home. If people
  should find these outside Kosmos, a visible `~/Documents/Kosmos/<agent>` could be better; the
  "Open in Finder" button is the mitigation for now.
