# refusewhy-6149: a refused update's reason reaches the board (kosmos#6149 point 8)

## Problem
Since #4455, an update refuses before removing anything when part of the installed app cannot be removed (a locked file, or a folder this account may not change). The reason and the fix go to install.log only. The board's "The update did not take" overlay says "The installer stopped (code 1)" and points at the log; an automatic update's refusal shows nowhere.

## Change
1. `install/setup.sh`, in the #4455 refusal: write `logs/update-refused` (best-effort; a write that fails never stops the refusal) with `why=locked|permissions`, `at=<the first stuck path>`, one `part=<name>` line per locked part (bin, app or runtime; the board rebuilds the path from its own install root, so a record cannot point the unlock line anywhere else), and `ts=<UTC>`. A swap that completes removes the file.
2. `engine/update.js`: `updateRefused()` reads the file (same key=value discipline as `updateAbort`), and `lastAttemptView()` attaches it as `refused` to a FAILED attempt whose start is not after the refusal's `ts` (so an old refusal never explains a newer failure).
3. `web/index.html`: `updateSettleText`'s failed sentence, when the attempt carries `refused`, names the stuck path and gives the same two unlock lines the installer prints, the person's and the administrator's (locked), or the ownership sentence (permissions). Everything is escaped.

## Accepted
- A refusal is matched to an attempt by time only (stamped no more than a second before the attempt began). An install line pasted in Terminal that is refused while a board-started attempt fails for another reason could be shown as that attempt's cause. Closing it needs the board to pass its start stamp to setup.sh for the record to echo, a protocol change.
- The tests seed the failed attempt from disk; an attempt the board itself started goes through the same `lastAttemptView`, not separately tested.

## Not in scope
- A board notice for an AUTOMATIC update's refusal (no overlay is showing then). `updateAttempt` carries the reason, so a notice can read it later.
- Point 9 (lsattr on Linux).

## Tests
- `tools/test-update-locked-app-4455.sh`: the refusing arms find the record with the right why, at and parts; an update that goes on writes none; a refusal whose record cannot be written still refuses (NORECORD).
- `tools/test-install.sh`: a planted stale record is removed by an update that goes through (runs in the full install test).
- `engine/update` unit test: the reader's damage rules, the correlation with the attempt, and absence.
- `web` test: the failed sentence with and without `refused`, escaped.
