# code-grep-1570: turn #1570 from advice into a tool

#1570 records that a string search cannot tell USE from MENTION, and gives good
advice about it. **Advice about searching loses to how easy grep is.** That is
the "prose loses to tooling" shape the fleet has hit repeatedly: a rule in prose
cannot compete with a command already in your fingers.

So this is a command: `tools/code-grep.js`, which blanks comments and string
literals and then searches, so "find the code that DOES x" cannot land on a
comment TALKING about x.

## Why I took it, and the evidence

I hit this defect FOUR times inside #1592 alone, today:

    my site sweep          counted comments as call sites
    my verification grep   read my own new comment as an unfixed site
    my failure grep        matched test NAMES containing the word "fail"
    the guard itself       flagged a comment as a defect

Two of those produced a confident wrong statement about the state of the code,
and one of them was nearly a wrong statement about a colleague's work.

## The one property that makes it usable

**Comments are BLANKED, never deleted.** Deleting them shifts every line below,
so the tool reports a real defect at a line that does not contain it. I shipped
exactly that bug in the #1592 sweep, where it named `machine.js:191` for a call
at 412. A finding nobody can locate is barely a finding, so there is a test for
it: twelve comment lines above a call, and the hit must report line 14.

## Strings are blanked too, deliberately

The #1570 instance that started this anchored a mutation on a user-facing
MESSAGE. Message text is quoted in comments, tests and changelogs precisely
because it is user-facing, so it is the worst possible anchor. A tool that
stripped comments but kept strings would still have found that quote.

## The caveat is printed, and only when it matters

A zero from a search gets read as "it is not there", and that is the one
conclusion this tool cannot support: it reads source text, so it cannot see a
call built at runtime, reached through an alias, or named by a computed string.

So a zero result prints that, on stderr, at the moment somebody is about to
over-trust it. A match prints nothing, because a caveat on every run is noise
and gets ignored. Splinter asked for this after over-trusting his own sweep an
hour earlier.

## Known blind spot, asserted rather than left to be discovered

A regex literal containing a quote character confuses the scanner, which reads
the quote as a string opener. There is a test that PINS this as a known limit,
with a note saying that if it ever starts passing the scanner improved and the
test should be updated rather than deleted.
