# kosmos#8882: Settings bulk move warns when a target's model limit is full

## Finished looks like
1. In Settings, Accounts, each bulk-move target where a moved agent's own model limit is at 70% or more (the mover's target rule, engine TARGET_MAX_PCT) is marked "(N% used, a model limit is in the way)", or "may be in the way" when only agents of unknown model are at stake.
2. Once picked, a line below the menu names the target, who would stop and why: "On <account>, the Fable limit is full for the week, so Lyra could not run there." (99.5%+, engine MODEL_FULL_PCT) or "... is at 72% for the week, so Lyra may stop there soon." Agents whose model Kosmos cannot tell are named too, with the level stated ("On X, the Fable limit is at 70% for the week. Kosmos cannot tell which model Una uses, so it may stop there."; "too" only after another sentence). One reading per model family, the highest. Names joined with "and" ("both" for two). A planned model counts as known and comes first, as on the tile (the board sends it only for a stopped agent). The first sentence names the account, later ones say "there"; with unknown-model agents, the highest limit there is always in words.
3. The person can still move them (their call: the limit may reset in an hour).
4. The click re-reads the target. An account-level reason (signed out, weekly full, gone) is said first. Otherwise it refuses ("Nothing moved: <warning> Pick again.") only when something NEW came in the way compared with the risks the menu DREW for that target (kept per row and target; for a kept pick, a repaint that changed the words silently does not count as shown, since a screen reader does not hear a live region inserted already filled; a pick's change handler speaks it and counts; read at the press), judged per agent by session: an agent at stake now that was not warned about at all (for example one whose model changed to a limited family since the paint), or one that now faces a full limit where it was shown a near one (its family's level, or for an unknown model the highest limit there). A reading moving within its level, an agent that left or was renamed, a card gaining or losing its model at the same level, or a full limit the person was shown, does not refuse.
5. Same model match as the mover (acctModelKey mirrors engine/autobalance.js modelKey); the page's two levels are tested equal to the engine's.

## Calls
- Warn, not hide (the card's weakest premise: a full model limit may reset within the hour, so the person decides).
- Text only through esc() and textContent; the warning lives in a data attribute on each option and in an aria-live line kept in the page while empty; the menu and Move are described by the restart note and the warning.
- Refusal compares risks by family and level, never the sentences, which carry a live percentage (review 2), against what was drawn, with the cards as they are at the click (review 3).
- Left as is (review 8 nits): a model name with no family word ("Claude (its default model)", written briefly after a model switch) counts as known and matches no limit, exactly as the engine's modelKey does; the warning stays under the disabled menu during a move (true, if odd).
- Left as is (review 7 nit): a stopped agent under a near limit reads "may stop there soon" (true of its next start).
- Left as is (review 4 nit): drawn risks are never deleted from the page's map; the click reads only a key its own paint wrote.
- Left as is (review 3 nits): the warning is both aria-live and in the menu's description, so a screen reader may speak it twice on a pick; review 1 asked for both, and twice is the safer failure than never. The model name is printed as the usage reading sends it (Anthropic sends "Fable").
