## What finished looks like (this increment)
On the agent GRID card, an agent with unread direct messages shows a red numbered bubble top-right
(the same red-bubble shape as the memory badge). Opening that agent's thread clears it. The bubble is
suppressed for the agent you are currently reading, so it does not flicker back before the clear lands.

## Approach (web/index.html only, mirrors the project p.unread precedent)
- `dmBadge(a)`: renders the bubble when `a.dmUnread > 0`; nothing for 0/null (unknown); suppressed when
  `CURRENT.sessionName === a.sessionName` (the agent being read), exactly as the open project shows 0.
- Card: `${dmBadge(a)}` in the `.agauge` (position:relative, no overflow clip), so it is absolute and
  shifts nothing. Both the running AND the offline (not-running) card render it: the engine attaches
  `dmUnread` to offline agents too, so a stopped agent that messaged you still shows the bubble (Josh's
  ask has no running-only qualifier). When an agent is BOTH near-full on memory and has unread DMs,
  `.agauge:has(.dmbadge) .membadge` drops the memory badge below the DM bubble (the DM bubble keeps the
  corner, since "someone is waiting on you" outranks "memory nearly full").
- CSS `.dmbadge`: same red `#b3261e` bubble as `.membadge`, absolute, pointer-events:none. Dark twin
  (#ff8c82) generated into the forced-dark region by tools/sync-forced-theme.js (edit the media-query
  source, not the generated twin).
- Clear-on-read: `paintTalk` fires `POST /api/agent/<name>/seen` (Angel's route), GATED like the
  project /seen: paintTalk re-runs every ~5s poll while the panel is open, so the POST fires ONLY when
  the agent (looked up in LAST) has unread, and zeros the local copy first (like the project's
  `p.unread = 0`) so the re-run sees 0 and does not re-fire a full dm-seen.json write every tick. Body
  read+dropped (#39 networkidle rule). Suppress-while-open gives the immediate hide; the cursor advance
  keeps it cleared after navigating away.
