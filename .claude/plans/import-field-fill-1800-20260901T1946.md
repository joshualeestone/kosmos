# import-field-fill-1800: dress the import paste box as the field it is

Written after the fact, at PR time, because the gate requires a plan file and the
challenge loop had deferred that convention. The card kosmos#1800 was the plan:
a release-blocking one-rule fix taken mid-cut. Recorded here so the next reader
has the intent in the place the tooling looks.

## What finished looks like

- `render-fields.js` green in webkit and chromium, light and dark, on the fix.
- A planted revert of the CSS turns the new named assertion red in all four arms.
- The full gate on the committed tree reports `render-fields` PASS and no new red.

## The change

1. `web/index.html`: `#import-text` joins `#create-instr`'s rule (one selector,
   one appearance); the width-only `#import-text` rule is removed.
2. `docs/browser-checks/render-fields.js`: a named pair assertion, floor first,
   comparing border colour, border width and radius, and requiring the import box
   to stand apart from its own card. Fill is deliberately not compared, because
   `--field-fill` resolves per container by design.
3. `web.role-picker.test.js`: the only stylesheet rules naming `#import-text` are
   the shared pair, scanned over the stylesheet block only.

The four stale first-run and radio-count checks on main; those are fixed on
