# roapp-6149: the read-only app's small follow-ups (kosmos#6149, from the #4455 reviews)

## In this branch
- **Point 2.** `install/setup.sh`: a `KOSMOS_READONLY_APP` value other than 0 or 1 (and not empty) prints one line saying it was not understood and the app is left read-only. Only 0 is still off; nothing about the decision changes.
- **Point 3.** The locked-file refusal gives a Terminal line instead of the Finder's Get Info route: `chflags -R nouchg,nouappnd '<part>'` on every part that has a lock, all three searched (both flags a person can set; measured: `nouchg` alone leaves an append-only file refused, both together free it), and `sudo chflags -R noschg,nosappnd '<part>'` for a lock an administrator set.
- **Point 4.** The locked-file search calls `/usr/bin/find`, so a GNU find first on PATH (Homebrew findutils, which has no `-flags`) cannot make it read as nothing locked.
- **Point 5.** `tools/test-install.sh` unsets `KOSMOS_READONLY_APP` instead of exporting 1, so every install in it, the part a cut's gate runs included, measures the default people get.
- **Point 6.** `.github/workflows/test-linux-setup-4920.yml`: the four `test A && test B` lines are one test a line (under `bash -e` a false first test in an `&&` list cannot fail the step).
- **Point 7.** The same workflow's uninstall step checks the whole Kosmos folder is gone (uninstall removes it, the read-only app included).
- **Point 10.** `tools/test-update-locked-app-4455.sh`'s header says which arms skip on Linux and that dash has no pipefail, so NOISY there does not cover its fault.
