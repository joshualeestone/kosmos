# msgsubmit-6249: a line left unsent in an idle agent's input box must not read as placed

Addresses #6249. Liu Kang m5847 (the card), m5853 (inputs: the second writer, never Enter over text that is not
ours, read with ANSI). Measurements posted on the card (issuecomment-6200022706) before any code.

## Finished means (from the card)
1. Delivery is confirmed by submission, not placement: after the Enter the board checks the input box, retries the
   submit once, or reports the line unsubmitted.
2. A stranded message is visible: the log records it, and an agent whose box has held text for a few minutes says so
   on its card.
3. Two messages are not run together in one box.

## Measured (scratch Claude Code pane on its own tmux server, never an agent's pane)
- `placed` meant only that tmux took the Enter (`send-keys` exit 0). Nothing read the box afterwards.
- No single-writer strand reproduced on Claude Code 2.1.296 or 2.1.299/300: idle at 80x24 and 160x45, 300 B to 6 KB,
  the two real messages byte for byte, during Stop hooks, Claude paused across paste and Enter, queued behind a busy
  turn (one and two), an Esc interrupt. On 2.1.296 the first line after start sat about 1 s before submitting.
- Two board-style sends at once interleave at 256-byte chunk boundaries into one prompt.
- Case 1 traced (m5853 input 1): the community nudge goes through chat.deliverAutomatic -> deliver (in the board's
  lock), and its stamp "(Sent 04:14 CDT)" is 09:14:37Z, the board log's community-turn for that agent, 35 min before
  the ruling. So it was an earlier line left in the box, and the ruling was pasted behind it.

## Change
- engine/status.js: `composerText` reads the LIVE box from an ANSI capture: the last row starting with the prompt
  glyph and a NO-BREAK SPACE (sent prompts, queued lines and menu options use a plain space; a slash menu's glyph is
  indented), down to the rule; dim text (SGR 2 until 0 or 22; a colour's own numbers skipped) is not typed text.
  `unsentInputOf` puts `unsentInput: { since }` on a Claude card once the same text has sat there 3 minutes: the plain
  capture already made decides whether to look, so only a pane showing something gets a second, ANSI capture.
- engine/chat.js `deliverWithGap`, Claude panes only: before the paste, a box already holding text is COULD_NOT
  (`inputHeld`), nothing typed. After the Enter, `submitConfirmSteps` reads the box: empty is placed; only ours still
  there after a 1.5 s settle gets ONE more Enter (on a pane still an agent's), then placed or unsubmitted; anything
  besides ours never gets an Enter (m5853 input 2) and is unsubmitted; no box to read keeps today's verdict. Read
  first, wait only while ours is there. Sync and async drivers as for the gap.
- Unsubmitted is UNCONFIRMED with `unsubmitted: true`, not a fourth state: every sender already treats UNCONFIRMED as
  "may be there, do not type it again". engine/messages.js logs and returns the flag; `kosmos msg` already prints the
  server's sentence for unconfirmed.
- web/index.html `stateReason`: "Text has been sitting unsent in its input box for about N minutes. Open it to send it
  with Enter, or clear it."

## Decisions
- No fourth delivery state (above). Would change my mind: a sender that re-types on UNCONFIRMED.
- The pre-paste refusal also covers a person typing in the pane: pasting into someone's typing is the same defect.
- Weakest part: the box is read from the screen. A Claude Code that is not drawing (stalled) shows the box as it was,
  so a read can say empty while the paste is still unread; it then submits with the Enter it already has (measured:
  paused across paste and Enter, it submitted). And the cause of the two real strands is not reproduced; this fix
  makes any strand visible and retries once, whatever left it.
