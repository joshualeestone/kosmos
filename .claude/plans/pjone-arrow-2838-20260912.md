# Plan: remove the project-header description pop-down arrow (#2838)

## The ask
Josh, live review of 0.6.57 (2026-09-11): "I think we missed deleting the arrow
to pop down the project description and instead putting the project settings cog
there." The disclosure arrow left of the project name was supposed to be removed;
the settings cog is the door to the description now. It was missed, the arrow is
still there.

## The call (Option A), and what I rejected
There are two clean end-states once the arrow goes, because the arrow's whole job
was to disclose the inline description:
- A (built): remove the arrow AND the inline description; the description lives
  only in Project settings, reached by the existing cog (#pj-settings-link).
- B (rejected): remove the arrow, keep the description always visible inline.

Chose A. It matches Josh's clearest ruling on this exact copy (#1005: the inline
description above every conversation read as clutter) and his literal "cog
instead" (the description moving behind the cog / Settings). B would reintroduce
the always-visible clutter #1005 removed.

Weakest premise: #980 (2026-08-26) said the full description text should be
readable on the page, not only in Settings, and the 2026-08-20 empty-slot
placeholder ruling wanted a visible "add one in Settings" slot. A reconciles
those under #1005 plus the new instruction. Fully reversible: Josh eyeballs it
in-app and one word flips it to B. Recommendation posted on the card 04:59;
implemented per the no-parking rule rather than waiting.

   block inside `paintOneProject`. Fix the stale `placeProjectHead` comment that
