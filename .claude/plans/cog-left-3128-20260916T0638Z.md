# Plan: move the project-title settings cog to the left of the title (#3128)

## The ask
Josh, 6.68 feedback (#3128): in BOTH grid view and consolidated view, the settings
cog for a project title should be on the LEFT side of the title (it is currently on
the right). Owner: Mona.

## What finished looks like
- In the project detail header, the settings cog renders immediately to the LEFT of
  the project name, on the same line, in both grid and consolidated layouts.
- The cog keeps its id (pj-settings-link), its click handler (opens Project settings),
  and its accessible name ("Project settings").
- A browser-check pins the new position so a silent swap back to the right reds.
- Full test suite green.

## The change (web/index.html)
1. DOM: the cog button was a direct child of .pjhead, pushed to the right by
   justify-content: space-between. It now sits inside .pjtitle-row, ahead of the
   `<h2 id="pj-one-name">`. One DOM move covers both layouts because grid and
   consolidated render the same header markup; only the layout class differs.
2. CSS: .pjtitle-row changed from align-items: baseline to align-items: center so
   the 28px cog centers with the name instead of sitting on the text baseline.

## Verification
- docs/browser-checks/render-projects.js: after entering a project, measure the cog
  and name bounding rects in the page and assert cog.right <= name.left (+1px) and
  their vertical centers line up (a shared row). Position pin, not a screenshot.
- Full suite via tools/run-tests.sh (catches meta-guard signature pins blind review
  misses).

## Decisions
- Chose "left of the name line" over a far-left gutter cog. "Left of the title" reads
  most naturally as left of the name; the gutter form reads as a leading icon/avatar
  and needs a justify-content override. Reversible if Josh meant the gutter.

## Weakest premise
"Left of the title" means left of the project name. If Josh wanted a far-left gutter
cog vertically centered against the whole crumb+name+hint block, that is a reversible
swap.
