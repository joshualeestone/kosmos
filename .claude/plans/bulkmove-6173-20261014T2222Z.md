# bulkmove-6173: move several agents to an account without blocking the board once per agent

Addresses #6173. Liu Kang's rulings m5429, m5431, m5433, m5435. Windows and Linux follow-up: #6183.

## Finished means (yes/no, posted on the card)
1. Moving several agents from Settings sends one request, and it answers without running any restart inside it.
2. While the agents restart, the board answers other requests. On the Mac only; on Windows and Linux the board
   still freezes for one restart at a time (#6183).
3. Each agent's outcome reaches the note in today's words: moved, moved while stopped, saved but not restarted
   (the engine's sentence), not moved (refused).
4. A failure partway never reads as Moved: a restart that throws, a refusal, the board restarting mid-move (404).

## Measured live (main dacb944f7, by reading the code)
Settings sent one POST /api/agent/<name>/account per agent; the route ran removal.restart synchronously inside it
(execFileSync launchctl, Atomics.wait: up to 25s unload wait #4964 plus 2s retry #4006).

## Why not a worker thread (audit)
live-execution's `allowed` is set only on the board's thread (allowLiveExecution at real start): in a worker every
restart would silently dry-run. Also tmux re-pick state in status.js, and the test seams.

## Change
- engine/remove.js: restartInner becomes restartSteps, a generator that yields every command and wait. driveSync
  answers with run() and Atomics.wait (every existing caller, unchanged, burst cap included). driveAsync answers with
  execFile and timers (restartAsync). The Mac's acts are MAC_STEPS and sessionOps().endSteps, and the sync ops drive
  those same steps (one body per act). The unload wait is unloadSteps: the sync wrapper keeps the burst allowance;
  the async one takes the whole wait and neither spends nor needs the allowance (it blocks nothing).
- A restart keeps its own bootstrap answer (`boot`): lastBootstrap is shared, and an async restart can be interleaved.
- RESTARTING: a sync restart of an agent an async restart is working on is refused with a sentence.
- engine/status.js: tmuxPanes is one body (tmuxPanesSteps) with sync and async drivers; paneRosterAsync. The tmux
  re-pick search stays synchronous (rare: a version wall or a removed tmux).
- engine/accountmove.js: the move. The request does the account writes and answers 202; restarts run one at a time;
  the record lives in memory; one move at a time (409 with a sentence); the shared result sentence.
- server.js: POST /api/agents/account, GET /api/agents/account-moves/<id> (404 when unknown); the single-agent route
  refuses with 409 while a move runs and words its answer through accountmove.sentence.
- web/index.html: moveAccountAgents sends one request and reads the record every second; 404, five failed reads or
  the time bound leave unconfirmed agents as "No answer yet", never Moved.
- Windows and Linux: their acts run inside `now` (synchronously) under either driver. #6183.

## Sync restart callers (new refusal)
server.js /restart (400 + because; page restartFailureLine), /trust-and-restart (400), provider switch and model
switch (partial: saved but not restarted, with the because), class-1 auto-handle (handled false, reported with the
because), single account Move (409 at the route while a move runs). Liu Kang checked the list (m5435).

## Decisions
- Generator with two drivers, not a copy of the restart: one body, so the two cannot drift.
- Refuse a clashing sync restart rather than queue it: a refusal is reported by every caller; a queue would hold a
  sync route.
- Weakest part: on Windows and Linux check 2 is not met (#6183). And the async path is proven with a scripted
  runner, not a real launchd.
- Would change my mind: a caller that reads REFUSED as success.

## Bounds (Liu Kang m5496 / m5499, accepted)

- Each async restart: 300 s cap (round 4: a healthy restart at every limit is about 250 s); it stops waiting, sends no
  further command, answers partial, marks the card failed if begun, and keeps its hold until its in-flight command
  really ends.

  refused. Follow-up, not this PR: a control to cancel a move.
