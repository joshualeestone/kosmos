# linuxclaude-5419: Linux downloads Claude Code (slice 1 of #5419, Kosmos Cloud #4903)

## Why
On Linux the board refused to download Claude Code ("this platform (linux) has no published Claude Code build").
Kosmos Cloud v1 is Claude first (#4903), and a fresh Linux server could not get Claude Code through Kosmos at all.

## Measured
Anthropic's release manifest publishes linux-x64, linux-arm64, linux-x64-musl and linux-arm64-musl
(downloads.claude.ai/claude-code-releases/2.1.292/manifest.json, read 2026-10-06), each with a sha256.

## Change
- engine/platform.js: CLAUDE_DOWNLOADS gains 'linux'.
- engine/connect.js `platformKey`:
  - linux maps to `linux-<arch>`, or `linux-<arch>-musl` when Node reports no glibc.
  - Musl is detected only when actually on Linux; there is a seam for tests.
- The rest of download() is unchanged and platform-neutral:
  - the manifest checksum is verified before the binary is placed;
  - the file is chmod'ed executable;
  - a key the manifest lacks is refused.

## Not this slice
The provider runners (OpenAI's Codex, Gemini, Grok, Muse) on Linux are slice 2. Each needs real Linux pins with
registry checksums in runners.js. That is about 29 of the card's 66 failures.

## Weakest premise
That `claude install`, run from the downloaded binary, places its launcher under HOME on Linux as it does on the
Mac (connect.installClaudeCode). To be checked by the Linux CI lane (#4919).
