## The four, as built
1. **Say each thing once per row.** A row's state line (dot + group name) shows only when Group
   by is Project. In a status group the heading already names it. The agent pill stays in both.
2. **The Assigned row's sentence, in Josh's voice.** "<Agent> has not reported what it is
   working on yet." It is used only when that is TRUE: the agent has never written its report.
   - Why not Mona's exact words ("has not said yet whether it started"): the field knows only
     that the report was never written. The agent may have said so in the project room, so "has
     not said" would claim more than we know. Review iteration 1 caught this.
   - The engine carries it as a field. `commitments.read` returns `neverReported` (from the
     record's own `absent`), and `tasks.claimFor` passes it on in the claim. The page matches
     none of our prose; `commitments.js` already explains why a field and not a sentence.
   - A record we could not read, a report too old to trust, or an agent that left the project
     keeps its reason ("We cannot tell whether it started: <why>."). Saying "has not said" there
     would be false.
3. **Closed is not a tile.** The tiles are the three open groups; Closed stays the folded list.
4. **The two big gaps, halved.** Measured on a sandbox board at 1400:
   - 51px above the title, now 25. The empty crumb takes no room, and the top padding is 25px
     (22px on a phone).
   - 49px from the tile hint to the first group, now 24. The status line KEEPS exactly one
     reserved line (`1lh`), so a one-line message never pushes the list down under the pointer. Iteration
     3 caught that collapsing it did exactly that, measured as a 7px jump on "Closed 2 tasks.".
     The hint's bottom margin and the first group's top margin are what shrank. It stays a live
     region.

   - **One fact, one wording:** `claimNotReported(claim)` in the page says it the same way on
     every surface that draws a claim. On the Tasks row and the task page it reads "Rex has not
     reported what it is working on yet."; on the project card, beside the agent's pill, "has not
     reported what it is working on yet". (Review iteration 2 found the card and the task page
     still showing the engine's prose for the same fact.)

## 5. Josh's ruling (relayed by Splinter, 2026-09-25 06:36): the Tasks tab appears at 25 tasks
Splinter's calls: count all tasks ever created (open and closed); once shown it stays shown (a
saved flag); 25 is one constant. Built into this branch as instructed.
- Engine: `tasks.TASKS_TAB_MIN = 25`.
  - `tasks.tasksEverCreated(everyProject)` sums each project's `taskCounter` (never reused;
    tasks are never deleted), with the task list as a floor. Archived projects count.
  - `tasks.tasksTabShown()` returns the saved flag, or counts. The count is redone only when the
    projects file changed, because it rides the 5s status poll. On reaching 25 it writes
    `tasksTabShown: true` into settings.json, once.
- Status: `/api/status` carries `tasksTab`.
- Page: the Tasks tab and the consolidated projects rail's Tasks button start `hidden`, and
  `tskTabGate(data.tasksTab === true)` runs on every status tick.
- The flag write never clobbers settings. `writeSettings` merges over a read that answers `{}`
  for an unreadable file, so the flag is written only into a settings file that is absent or
  parses as an object. Otherwise it is skipped and retried on every poll until it lands.
  Iteration 7 caught this: the flag write could have replaced a person's timezone.
- This viewer's last answer is kept in localStorage (a per-viewer convenience), so a board past
  25 does not pop the tab into the bar after every load. The status tick stays the authority.
- My call: below 25 a project's **View All** still opens the Tasks view, because since #3703 it is
  that project's only full list. So does a `?tab=tasks` link. Only the top-level ways in wait
  for 25.
- Weakest premise: a DELETED project's tasks no longer count, since they are gone from the
  store. The saved flag makes that matter only before the tab first appears.

## Decisions (reversible)
- Item 2's wording and guard are mine: Mona's short form, narrowed to what the field proves.
- ACCEPTED: a rare message long enough to wrap (a long project name plus "Could not confirm Rex
  saw it: ...") pushes the list one line. Truncating it would hide the part the person needs.
- Wording, recorded: the Tasks row's other could-not-tell sentence reads "We cannot tell whether
  it started: <why>." (was "whether it has started"), shorter in Mona's spirit.
- The task page names the agent the claim was read for, even on a task kept as parts (it has
  no `t.who`), rather than "It".
- The crumb collapses when empty, so picking a project moves the title down one line as the
  crumb appears. That is a content change the person made, and it buys most of the gap.
- Weakest premise: "never reported" is the common case on a real board. If most unknowns turn
  out to be stale reports, the long reason stays common, and "too long ago" wording is the next
  thing to shorten.
