# model-provider-1026: a model belongs to a provider (kosmos#1026, engine half)

## Why

Josh, 2026-08-26 16:19: *"now we need to look at what the actual models are that we can let
users select from once they create an OpenAI agent."*

The answer, read from the code rather than remembered: **there are none.** `engine/create.js`
holds one list of four, all Anthropic, and **the picker is not provider-aware**, so a GPT agent's
model menu offers four Claude models.

Mona Lisa's split, which this branch is the prerequisite for:

- **Validation is automatic and mine.** `engine/openaiaccounts.js` already calls
  `GET /v1/models` with the person's key on every key check and reads only the status code. The
  set of models that key can use is in the body we discard.
- **Curation is human and hers.** `"gpt-5.6-turbo-preview-0325"` is a name, not a reason. The
  `why` line under each entry is the whole value of the menu and no runner can produce it.

⇒ **This branch adds no GPT entries.** It is the shape that makes adding them safe.

## What

1. Every entry carries `provider`. `modelsFor(provider)` and `modelFor(provider, key)` are the
   ONE resolution, used by the route, by `createAgent` and by `setModel`, so the menu, the create
   check and the change check cannot disagree.
2. `createAgent` resolves within the chosen provider, and its refusal tells "no such model" apart
   from "a real model belonging to the other vendor" -- those send a person to different places.
3. `setModel` resolves **after** `readJob`, because which models are valid depends on which
   provider that agent runs on.
4. The route serves `provider` with each row. ⚠️ `arg` stays absent: the page must never name the
   executable-facing id, which is the line the payload allowlist draws.

## 🛑 A false claim I put in my own comment and caught by reading

The first version of the docblock said `setModel` would hand `--model claude-opus-5` to codex,
"reachable through the API now". **It would not.** `setModel` has refused codex agents outright
since #245, three lines into its own body. **I asserted that before reading the function I was
describing, in the comment justifying the change.**

What is actually wrong there is narrower and is what this branch fixes: the refusal says OpenAI
*"picks its own model for now"*, which is **a sentence rather than a check**. It was true while
the list had one vendor and would have become false the day OpenAI rows were added, with nothing
to catch it. Scoped to the provider, the right refusal falls out of the data.
