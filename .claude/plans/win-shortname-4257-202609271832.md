## The product question (#2281 key spelling): no product change
Call: trustFolder keeps keying on realpathSync.native (long form).
Why: every Kosmos-created agent folder hangs off the home folder (store.workersRootFor(homeDir())),
and Windows gives the home folder in long form (measured: C:\Users\runneradmin). Kosmos never
builds an agent folder from %TEMP%, the only place the short form shows up here. So the spawn cwd
and the key are both long form.
Rejected: writing both spellings (pollutes the user's config, forgetFolder rolls back one key);
canonicalising the spawn cwd (changes Claude Code's per-folder session directory for an agent
whose folder is a junction, losing resume).
Weakest premise: whether Claude Code realpaths its cwd before keying. Its minified source keys on
O$(xn(We(cwd))) and I could not resolve xn/We by name. It matters for any spawn folder whose spelling
differs from its native realpath: a user-recorded 8.3 path, a junction or redirected folder, or
an AGENT_WORKFORCE_WORKERS override spelled short. That exposure predates this branch and is
split out as #4260 (needs a Windows machine); the PR says "Addresses #4257", not "Closes".
Pinned here: trust.win32-key-2281 has a Windows-only arm that hands trustFolder the short
spelling and asserts the long-form key.
What would change my mind: a Windows run of Claude Code started in a short-form cwd, with the
long-form key pre-accepted, showing the trust dialog.
