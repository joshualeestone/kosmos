# qhorder-5332: a main-lane queued-heavy waiter keeps its queue place until its take is won (#5332)

Card: joshualeestone/kosmos#5332 (Angel's 10-05 reds: the #5064 control at 13:39 and 21:19, the MAIN arm at 15:4x).

## Cause
kosmos_wait_until_clear (tools/lib/cut-guard.sh), on a clear pass in suite-queue mode, unmarks and returns; then
tools/queued-heavy.sh takes queued-heavy-take.lock and claims. Between the unmark and the claim the run holds no
marker, so a later waiter's kosmos_refuse_if_earlier_suite_waiter passes and both race to the lock.

## Change
- cut-guard.sh: KOSMOS_WAIT_KEEP_MARK=1 makes a clear pass return with the marker KEPT (no unmark, no second ask).
- queued-heavy.sh: sets it for the main lane; _qh_take asks the order (kosmos_refuse_if_earlier_suite_waiter) and
  _qh_clear under the lock, claims, then unmarks (a lost take keeps the marker). Unset for the wrapped command.
- QH_TEST_LOST_PAUSE_S: a main-lane test seam, a pause after a lost take, so the #5064 control (old code) is not a race.
- Tests: control removes both ways of keeping the place; arms for kept-marker-alone and marker-gone-after-a-won-take.

## Decided
- run-tests.sh does not set KEEP_MARK: it has no take lock, and its second ask covers it.
- The order check under the lock has no arm (perturbing it away leaves the suite green). It is reachable in normal use,
  not only on a vanished marker: a light or canary waiter that joins between this run's wait and its lock ranks ahead
  (#4609), so this run loses the take and waits one poll (up to 30 s) while that run goes first. That is the queue's
  intended order, at a cost of one idle poll; an arm would need to land a join inside that gap. Review 2.
- run-tests.sh's `unset KOSMOS_WAIT_KEEP_MARK` before its wait has no arm (review 3): arming it needs a queued
  run-tests.sh inside test-cut-guard.sh with the var leaked in. It is a one-line guard against a leak queued-heavy
  already prevents (it unsets the var for its command); stated, not tested.
- Deployment: agents run an installed wrapper (~/.cache/claude-handoffs/queued-heavy.sh) with a lib checkout; the fix
  reaches them only once both are updated. A new wrapper with an old lib degrades safely (no marker, no order check).

## Weakest premise
That a still-marked waiter is never read as a live suite. Measured: kosmos_refuse_if_suite_live drops waiters (#4498).
