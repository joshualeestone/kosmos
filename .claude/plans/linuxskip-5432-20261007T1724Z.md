# #5432: Linux skip sweep after Linux port B (#4918)

## Finished looks like
The Linux lane (linux.yml, a linux-ci-* push) on this branch shows no red outside the workflow header's expected list
(#4920 install, #5419 downloads, #5420 kill guard timing, #5424 projects preview), and macOS and Windows run every test
they ran before (no skip fires off Linux).

## Measured starting point
- Lane on B's head: 446 failing tests in 63 files. Lane on this branch before the last two commits (run 37614809233):
  134 in 16. Remaining reds after it: the header's expected files plus server.stray-removable, server.socket-split and
  server.offline-nextmove, which #5445 (PR #5469) also edited, so they waited for it.
- After rebasing on #5469 (6cd43e75a), forced Linux (scratchpad forcelinux.js, preloaded into child boards via
  NODE_OPTIONS): stray-removable passes (fixed by #5469); socket-split and offline-nextmove fail 2 tests each.

## What the branch does
1. Sandboxes give systemd its own unit folder (SYSTEMD_DIR beside LAUNCH), so no test can write a real unit.
   test-support/jobfixture.js writes the platform's own job (a plist on macOS, a unit on Linux); jobPath refuses on Linux
   with no sandbox, and jobPathIn serves sandboxes that exist only for a child board.
2. Tests that drive the launchd job itself (plist text, launchctl answers, the launchd runner seam) skip on a Linux host
   ONLY where they fail there, each with a one-line reason naming the Linux test that covers the same behaviour
   (LX(WIN_*, LINUX_*_WHY) in engine/create.test.js; a local LINUX_LAUNCHD in the server files).
3. Tests whose subject is not the job itself (status, forget, leftovers, switch, providers, team create) seed the
   platform's own job and keep running on Linux.
4. One real defect found by the sweep: undoing an add on Linux left the agent's systemd unit, so the row could not be
   added again. discover.disconnect now removes the unit (with a test).

## Decided
- Skip rather than port, when the test's subject IS launchd (plist text, launchctl list parsing): a Linux port of it
  would test systemd, which linuxjob.test.js, create.linux-4918.test.js, linuxwiring-4918.test.js and
  linux-parity-5445.test.js already do. Each skip names which.
- Port rather than skip, when launchd is only the fixture (the agent has to exist): seeding the platform's own job keeps
  the behaviour tested on Linux.
- socket-split (#668) and offline-nextmove (#671): skipped on Linux. Their fixture finds the agent from a plist, and a
  board pinned to the Mac probe (setProbePlatformForTests) still discovers agents the Linux way. Porting them means a
  systemd stub for the running-with-no-session row. The pill and the sentence are drawn the same on every platform and
  stay covered on macOS and Windows; the Linux halves (runningJobs reads active units; the self-starts sentence with
  linger on and off) are in linux-parity-5445.test.js.

## Weakest premise
The forced-Linux preload stands in for a Linux host locally. It fakes process.platform, not the filesystem or the
binaries, so the lane run (a real ubuntu runner) is the evidence, not the local count.

## Not covered
- The #668 could-not-check pill is not exercised end to end on a Linux board (its data half and its drawing are).
- Linux reds outside the launchd path keep their own cards (listed in the linux.yml header), per the card.
