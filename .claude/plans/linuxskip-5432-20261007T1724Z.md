## What the branch does
1. Sandboxes give systemd its own unit folder (SYSTEMD_DIR beside LAUNCH), so no test can write a real unit.
   test-support/jobfixture.js writes the platform's own job (a plist on macOS, a unit on Linux); jobPath refuses on Linux
   with no sandbox, and jobPathIn serves sandboxes that exist only for a child board.
2. Tests that drive the launchd job itself (plist text, launchctl answers, the launchd runner seam) skip on a Linux host
   ONLY where they fail there, each with a one-line reason naming the Linux test that covers the same behaviour
   (LX(WIN_*, LINUX_*_WHY) in engine/create.test.js; a local LINUX_LAUNCHD in the server files).
3. Tests whose subject is not the job itself (status, forget, leftovers, switch, providers, team create) seed the
   platform's own job and keep running on Linux.
4. One real defect found by the sweep: undoing an add on Linux left the agent's systemd unit, so the row could not be
   added again. discover.disconnect now removes the unit and tells systemd (daemon-reload), only after the teardown
   fully landed; the live-execution refusal still throws. engine/disconnect-agent.test.js tests it on every platform
   (remove and the systemd seam stubbed), with a partial-teardown control; measured red with the fix removed.

## Decided
- Skip rather than port, when the test's subject IS launchd (plist text, launchctl list parsing): a Linux port of it
  would test systemd, which linuxjob.test.js, create.linux-4918.test.js, linuxwiring-4918.test.js and
  linux-parity-5445.test.js already do. Each skip names which.
- Port rather than skip, when launchd is only the fixture (the agent has to exist): seeding the platform's own job keeps
  the behaviour tested on Linux.
- socket-split (#668) and offline-nextmove (#671): skipped on Linux. Their fixture finds the agent from a plist, and a
  board pinned to the Mac probe (setProbePlatformForTests) still discovers agents the Linux way. Porting them means a
  systemd stub for the running-with-no-session row. The pill and the sentence are drawn the same on every platform and
  stay covered on macOS and Windows; the Linux halves (runningJobs reads active units; the self-starts sentence with
  linger on and off) are in linux-parity-5445.test.js.

- After review 1, six tests that had been skipped are ported instead, because launchd was only their fixture: the
  three adopt runner controls (discover.adopt: the runner is read with create.readJob on either platform) and three
  create name guards (a live session's name, missing programs, a shared key), which counted Linux's read-only
  `systemctl --user is-active` as running something (a `notARead` filter; a Mac never makes that call).
- Sandboxes now set AGENT_WORKFORCE_SYSTEMD_DIR, which lifts linuxjob's "sandboxed without systemd" refusal on purpose:
  the unit folder is the sandbox's. A child board spawned with the parent env (server.test.js) inherits it; there,
  systemctl reads reach the runner's real user manager, which holds no Kosmos units. No FILE write goes outside the
  sandbox folder; such a child's systemctl calls do reach the host's user manager (the in-process parent still throws
  LIVE_EXECUTION_REFUSED). Measured after review 6: of the changed test files that set the systemd folder, exactly one
  starts a child process (server.test.js's seam probe), and it only loads engine/accounts.js to compare two folder paths:
  no board, no systemd call. So no child of these tests reaches the host's user manager today.

- After review 2: 104 Linux skips classified by what the test ASSERTS. 31 assert launchd itself (plist text, launchctl
  calls and parsing, the macOS temp-folder leftover sweep). After reviews 3 to 5 a reason names a specific Linux test only
  where one was checked to cover it; the #4279 leftover-job tests say there is no Linux equivalent; the shared reasons say
  their Linux tests cover the Linux side in general, not the test one for one; everything else says not tested on Linux
  yet and names #5500. 'Tested on macOS' is the claim, not macOS and Windows: most of these skip on Windows too, or are
  not in the Windows lane. 73 assert something
  platform-neutral with launchd only as the fixture; porting all of them to a systemd fixture is a sweep of its own, so
  their skip reason now says plainly that the behaviour is NOT tested on Linux yet (it is on macOS and Windows), and
  names #5500, which lists all 73 (reviews 3 and 4 added about 16 more, in its comments). This is the card's own "say plainly that it is uncovered on Linux, and why".
  The -discord name guard was split out of a launchd test and runs on Linux.
- cli.sandbox-4636's listener test (the one unexpected red in lane run 37658787467) stubs /usr/sbin/lsof by name, and
  Linux keeps lsof at /usr/bin, so the lookup ran the real one: the test now also names the stub (_lsof_cmd).

## Weakest premise
The forced-Linux preload stands in for a Linux host locally. It fakes process.platform, not the filesystem or the
binaries, so the lane run (a real ubuntu runner) is the evidence, not the local count.
