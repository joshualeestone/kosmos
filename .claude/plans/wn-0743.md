## Weakest premise
That an existing install gets the sealed app on update the way a fresh download does. The line is worded for a
downloaded copy, which #5976's cut check measures (a quarantined copy accepted as Notarized Developer ID); whether an
update replaces an older unsealed app in Applications is not measured here. And setup.sh places the sealed app only when
it wrote the account's install config; a sandbox, a custom home, a failed config write or a tarball with no sealed app
falls back to the old per-install bundle, which is not notarized (install.sealed-app-5896.test.js covers those). The
line is kept: it is true for the download-and-install path a person takes.
