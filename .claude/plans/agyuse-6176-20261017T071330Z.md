# agyuse-6176: Gemini usage on the Google-subscription row (kosmos#6176 slice 4)

Built on slice 3 (PR #6351, merged 2026-10-17, main 18593c8795), whose shared renderer `acctLimitsUsageHtml` this
reuses; rebased onto main after that merge.

## Why
#6176 asks for usage at a glance for every provider. Claude, ChatGPT sign-ins and (slice 3) Grok subscriptions are
built. Gemini on a Google subscription runs through Antigravity (agy), which can report its plan's limits.

## Measured first (2026-10-17, this computer, agy 1.4.0, signed in)
One deliberate run of `agy -p "/usage" --output-format json`: `num_turns: 0`, `usage.total_tokens: 0`, about a second.
It does not start an agent turn and spends nothing. Payload `command.data.groups[]`, each `{ name, buckets[] }`, each
bucket `{ name, window: "weekly" | "5h", remaining_fraction, reset_time }`. Groups: "Gemini Models" (weekly + 5h),
"Claude and GPT models" (weekly + 5h), "Gemini 4 Argon" (weekly). The call is recorded on the card.

## Change
- `engine/agyusage.js`: `parse()` reads the "Gemini Models" group (matched by name) into codexlimits.read's shape,
  `{ windows: [{ usedPct, windowMinutes, resetsAt }], plan: null, at }`, used = 1 - remaining_fraction, five-hour first.
  A run that started a turn, another command, an unknown window or a fraction outside 0..1 gives nothing.
  `refresh()` runs agy (with its own 30 s print timeout) at most every 5 minutes, one run at a time, keeps the last
  good reading; a run that FAILS (offline, or agy signed out since Kosmos checked) stops the asking until agy's
  sign-in is next confirmed, because a signed-out print run may open a browser and must not repeat unprompted
  (review 3); an answer that cannot be read waits the full interval; no run without agy's sign-in file
  (`~/.gemini/antigravity-cli/antigravity-oauth-token`, existence only; whether sign-out removes it is unmeasured); a new sign-in answer or a Remove clears the
  reading (agystatus remember/forget call `clear()`); never runs agy in a test process unless the test supplies the
  runner. Used percent is rounded DOWN to a whole number once, so 99.6% never reads as at the limit (review 1).
- `server.js` GET /api/accounts: the Antigravity row carries `limits` (the last reading, or null), asks for a new one
  without waiting, and only when Settings lists the accounts (`?agents=1`), not the create picker, and sets `connection.liveCheckPending` while it runs so the page reads again (as Codex limits do).
- `web/index.html`: the Antigravity row draws `acctUsageHtml` (it had its own drawing that never called it);
  `acctAgyUsageHtml` uses the shared renderer ("Antigravity last reported it ..."; no reading: "No current usage reading from
  Antigravity for this sign-in."); the reset timer covers Antigravity windows.

## Known limits
- Only the "Gemini Models" group. Kosmos runs Gemini agents there; a renamed or split group shows no reading, never
  another group's figure.
- A network call, so the row shows the last reading (with its age) and a new one arrives a moment later.
- macOS only, by agystatus's own platform (on Windows a signed-out print run can open a browser; /usage there is
  unmeasured). Elsewhere the row carries no `limits` field, so it draws nothing rather than promise a reading (review 1).
- Not changed: agystatus still confirms sign-in with a tiny prompt; this free /usage could replace it (follow-up).
- Deferred (review 1): if agy is killed while a child holds its output open, its temp folder is left (as agystatus).
- A run that ends after a sign-in change (Sign in again, Remove) is dropped: `clear()` bumps a generation the run
  checks (review 2). Tested, as is the remember/forget wiring.
- A slow run: a pending Antigravity reading is followed by TIME, 56 s from the paint that first saw it pending
  (review 5; review 7: by time, not count, so a reset or retry read that arrives at the count cap still follows it;
  a window that ended more than a read ago belongs to an earlier run). That is longer than Kosmos waits for agy
  (50 s), so the row reaches its answer or "could not report" rather than stopping on "Asking". A typical run takes
  about a second. Other rows keep the 6-read count.
- Deferred (review 7): a renamed Gemini group leaves the previous reading drawn with its age (never a wrong figure);
  `liveCheckPending` doubles as "a usage reading is on its way" on this row (accountline.js and `kosmos accounts`
  are unaffected: the badge decides first, and the CLI never asks with ?agents=1).
- Stopped with an earlier reading still in its period: the meters stay (with their age) and the stopped line shows
  under them (review 5). The three test seams are excused in engine.reachable.test.js with their reasons.
- Weakest premise (review 3): that ONE unprompted run on a signed-out Mac is acceptable. Kosmos runs agy only while
  its record says signed in and the sign-in file exists, and stops after the first failure; a signed-out /usage run on
  a Mac is unmeasured (measuring it needs signing out, which this session does not do).
- Review 4: the stop is kept in a file beside agystatus's record (`agy-account/usage-stopped`, never in a test process),
  so a board restart does not run a possibly signed-out agy again; a confirmed sign-in removes it. The row says each
  state: "Asking Antigravity for its usage." while a run is on its way, "Antigravity could not report usage. Sign in
  again to ask it again." when stopped, otherwise "No current usage reading from Antigravity for this sign-in."
- The safety cap is the kill time plus up to 5 s (50 s by default), scaled so a test can exercise a hung run.
- Review 6: a reply that exits 0 but is not a successful usage answer (an error object, a sign-in prompt, nothing)
  stops the asking like a failure; a well-formed answer whose Gemini group is renamed only waits the interval.
