# shortpath-5645: Windows CI red on 8.3 short TEMP paths (#5645)

## Why
Since ~23:20 on 10-08, main's `windows` check fails on some runners: tools.win-installer-native.test.js (W-20 and
the hand-off/update probes) and tools.win-launcher-native.test.js. Measured on run 37885046546: the product reports
`C:\Users\runneradmin\AppData\Local\Temp\...`, the test expects `C:\Users\RUNNER~1\AppData\Local\Temp\...`. The
runner's TEMP is spelled in 8.3 short form; os.tmpdir() returns it as-is. Same folder, different text: test-only.

## Change
- Both test files: a `scratchBase()` = `fs.realpathSync.native(os.tmpdir())`, which expands 8.3 names (and links),
  used at every place a scratch path is built from os.tmpdir(). Expected and actual paths are then built from the
  spelling the product reports.
- A short-form arm (Windows only): cmd's `%~sI` gives the 8.3 form of the scratch base; it must expand to exactly the
  long form. Skips, saying so, where the volume keeps no 8.3 names.

## Decided
- Normalise at the source (one long-form base) rather than in each comparison: every expected path in these files is
  derived from the scratch base, so one change covers all of them, including ones not yet failing. Rejected: a
  case-insensitive, 8.3-expanding compare at each assertion (many sites, easy to miss one).
- Weakest premise: realpathSync.native expands 8.3 on the runners' NTFS volumes (it calls GetFinalPathNameByHandle);
  the short-form arm measures exactly that on the runner.

## Tests
Windows-only; on macOS the files run and skip (56 tests: 21 pass, 35 skipped, 0 fail). The PR's `windows` check is
the measurement.
