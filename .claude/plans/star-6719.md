# star-6719: a star on each agent tile pins that agent to the top

Card: #6719. Josh, #admin 2026-10-20 08:44: "lets add a small star functionality to the top right of these tiles so
like if I starred you it would basically pin you to the top".

Stacked on `tiletext-6716` (#6716 changes the same tile renderer); rebased onto main when #6716 merges.

## Done when
- Every agent tile has a star in its top-right corner, and every list row has one at the right of the name: an
  outline when off, filled gold when on, labelled "Star <name>" / "Unstar <name>".
- Clicking it (or Enter on it) stars or unstars that agent without opening it; a starred agent sorts first in every
  sort order, and the starred group keeps the chosen order among itself.
- Stars are kept on the board, so they hold across restarts and on every screen that views this board (Kosmos+
  remote included); only the person can set them.
- The corner star does not overlap the unread badge, a list row's star does not cover the name, and on a touch
  screen the star is a 44 px target.

## Decisions
- **Kept on the board, not in the browser** (`store.ROOT/agent-stars.json` via GET/PUT `/api/agent-stars`): the card
  asks for every computer they view it from. Rejected: localStorage (one browser only). Weakest premise: a person
  with two Kosmos computers has two boards, and stars them separately on each.
- **By session name**, the board's unique key, not the display name (which can change).
- **A set, not an order**: within the starred group the chosen sort applies, as the card asks.
- **Another computer's agents (the "other computers" groups) take no stars**: a session name there names a different
  agent, and these stars are this board's.
- **Drawn at once, confirmed by the board, put back on a refusal.** A newer read or write always wins over an older
  answer (`STARS_SEQ`). Stars are re-read every 30 s so one set on another screen shows here.
- **An unreadable stars file is never overwritten** from an empty reading (that would drop every star); the board
  answers ok false and refuses a star with a 500 until the file is fixed.
- **One repaint for the sort control and the star** (`repaintAgentOrder`), so they cannot disagree about order.
- **Every repaint keeps a focused star focused** (`keepStarFocus`, wrapping the poll's grid paint and the list paint),
  so the 5 s poll never drops a keyboard user's place.
- **A reload waits for a write in flight** (`STARS_WRITING`): a read answered before the write landed would undo it.
- **A failed save undoes only its own star and says so** in the board's message line (shown, and cleared by the next
  star that saves, only while it still holds the star's own words).
- **The star comes after the name** in each tile's order, so the name (which opens the agent) is the first stop.
- **Decided, not missed: the project tab's Members card has no star.** It is a project's roster, not the board's tiles
  or list, and its order is the project's; the consolidated rail's member rows (the board's list) do have it.
- **In the consolidated rail the star is compact** (26 x 20 on the name line, pulled in from the corner) so it clears
  the row's unread badge and the title under the name; the row itself stays the large target. Weakest premise: on a
  touch screen in that rail the star is under 44 px; the rail is the desktop board's list.
- **On an upright tablet a running tile's name reserves room** for the 44 px corner star.
- **A stopped list row dims the name, not the cell**, so its star keeps its contrast.
- **Decided, not missed: a star outlives a removed agent.** A later agent given the same session name would start
  starred, and dead names count toward the 500 cap. Pruning needs the remove flow to know about stars; not worth it
  for this card, and a star is harmless and one click to take off.

## Decided (night shift, reviews 3 to 6)
- **A failed save's receipt shares #board-msg** with the could-not-open receipt (web.agents-summary names both writers). A
  line of its own would be a 41st direct body child, and the consolidated grid reserves exactly 40 pre-rail rows
  (web.consolidated-980). The star clears only its own two sentences. Weakest premise: both receipts at once is rare;
  if it happens the newer one shows.
- **Saves are chained per star** (one PUT in flight per agent, in press order), and an answer sets only its own star:
  saves for different stars run side by side, so a whole-set replace from either answer could drop the other's star.
- **A failed save goes back to what the board last confirmed** (BOARD_STARS), and speaks only when that is not what was
  asked. Rejected: going back to the page's previous state, which can be an earlier press that also failed.
- **Not fixed (review 6, noted):** a press before the first star read answers discards that read, so starred agents
  draw unstarred until the 30 s reload. Pressing then only re-stars, so nothing wrong is saved. Would change it: a
  report of it being seen.
- Rail star: 26 px in from the name column's edge, 5 px short of a "99+" badge, measured (render-star-6719 reports the
  boxes). The 18 px first try was an estimate and overlapped by 3 px.

## Reviews 7 to 9 (night shift, 2026-10-21)
- **Fixed (7):** a read the board says failed (`ok: false`) keeps the stars shown; an agent with no session name gets no star.
- **Fixed (8):** a repaint restores a star's focus without scrolling (only a press follows it); a save's answer is handled
  outside the try that guards the request; a refusal no retry can fix says what is wrong (500 stars, or the list cannot
  be read or saved); the check measures the scroll.
- **Not changed (9):** an unreadable stars file is never moved aside or replaced: writes are atomic, so it means real
  damage or a permission problem, and moving it aside would silently drop the person's stars. The page keeps what it
  showed and the first press says the list cannot be changed. Would change it: this happening to anyone.
- **Fixed (10):** the gated check's refused save stubbed a 500 and expected the try-again line, which review 8 had
  turned into the "cannot read or save its list" line: the stub is now a passing 503 (the unit tests cover the stuck
  line). Only this route's own 500 says the list is stuck; any other 5xx says try again. Only a keyboard press follows
  its star to its new place; a mouse click leaves the page where it is.
- **Fixed (11):** a press whose repaint throws still sends its save; a good stars read clears a star's stale failed-save
  line (only its own sentences).
- **Not changed (11):** a focused star is focused again on every 5 s poll, which a screen reader may re-announce. Before
  this card the poll dropped that focus outright; skipping unchanged repaints changes the whole board's poll and is a
  card of its own. The base `.lname` padding is checked by the neighbouring gated checks in the full validation.
- **Fixed (12):** the rail star had a 20 px touch target, and the premise that the rail is desktop-only was false: a
  touch tablet held sideways opens on the consolidated layout. On a coarse pointer it now has an invisible 44 px hit
  area (`::after`), so the drawn star and its measured badge clearance are unchanged. Still to do before converging:
  a touch arm in render-star-6719 that measures it, and the check's per-engine count, both from a real run.
