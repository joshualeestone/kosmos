# Plan: keep the "Model and Memory" agent-nav pill on one line (#3045)

Branch: `modelmem-onewrap-3045`
Card: #3045 (enhancement). Source: Josh 6.63 testing, 2026-09-14, filed by Splinter, for 6.65.
Related: #2916/#2948 (agentnav restructure that created the combined pill), #2809 (buttons size to content).

## Goal / done condition
On the View Agent screen, the "Model and Memory" nav pill (#d-nav button[data-go="model"]) stays on
ONE line instead of wrapping to two. Verified headless (light + dark) by render-agent-nav.js.

## Cause
The agent-view nav (.snav) column is a fixed 176px (.dbody grid-template-columns 176px minmax(0,1fr)).
.snav buttons are width:100% with padding: 8px 28px, leaving ~118px for the label. "Model and Memory"
(the longest label in the nav) renders right at that edge, so white-space:normal word-wraps it to two
lines (measured: button height 50px = two lines, vs 34px for a single-line pill).

## Fix
One scoped rule: `#d-nav button[data-go="model"] { white-space: nowrap; padding-left: 18px; padding-right: 18px; }`
- nowrap keeps it on one line.
- 18px side padding (down from 28px) gives the label real slack (~138px available for ~118px text)
  rather than a 1px-tight fit that could wrap or clip on a different font render (e.g. Josh's WKWebView).
- Scoped to this one pill: the button is width:100% with centered text, so the reduced side padding is
  invisible (same box width, same centering) and the other nav buttons are untouched.

## Files
- `web/index.html`: the one scoped CSS rule + its comment.
- `docs/browser-checks/render-agent-nav.js`: a #3045 arm comparing the model pill's height to a
  single-word pill (Instructions) in both themes; equal height (within 2px) = one line. Relative, so
  value/padding tuning does not break it.

## Verification
- render-agent-nav.js (server + fixture fleet, light + dark): the #3045 arm passes (model 34 == instr 34).
- Negative control (rule removed): the arm FAILS in both themes (model 50 vs instr 34), proving it
  discriminates.
- Browser-check surface (#2518) + coarse (#1720) gates exit 0.
- No `<tag>`-like comment tokens, no em dashes.

## Weakest premise
That 176px is the only width where it wraps and 18px padding gives enough slack everywhere. The relative
height check (vs a single-line pill) holds regardless of the exact column width, and the padding slack
(~20px) covers font-render variance. Josh's in-app pass on 6.65 is the final look.

## Decision recorded
nowrap + a small padding reduction on the one pill, over: widening the whole 176px nav column (affects
every agent-view and settings layout) or shrinking the nav font (affects all labels). Scoped to
data-go="model" so nothing else moves.
