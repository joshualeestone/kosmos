# diag-5959: one button that saves a diagnostics file (#5959 slice 4)

Card: joshualeestone/kosmos#5959, item 2 of the Windows agents' QA report (the Codex agent's top ask): "one button that
packages each agent's state across views, recent failures, provider, build and redacted log lines into one file for
the builders." Built after slices 1 (`reportshow-5959`, cardlabel) and 2 (`healthline-5959`, lastWorked) are on main:
it reuses both readers. This plan is written while they wait in the validation queue.

## The call (first written; "As built" below is what the code does)
- **Route:** `GET /api/diagnostics`, board-token auth like the other `/api/*` reads, read on demand (never polled).
  Answers `Content-Disposition: attachment; filename="kosmos-diagnostics-<date>.json"` and the JSON below.
- **Button:** "Save diagnostics" in Settings > Advanced (`#s-sec-advanced`), a plain download link to the route, with
  one sentence under it: what is in the file and that it is redacted, and that nothing is sent anywhere.
- **The file:**
  - `board`: Kosmos version and build (what `/api/version` answers), the platform, when the file was made.
  - `agents[]`, one per card (status.snapshot()):
    - name and runner;
    - `card`: raw state, the label the person sees (cardlabel.labelOf, slice 1), and stateReported;
    - `report`: the last report's state, writer (`by`) and time; not its `on` text;
    - `lastWorked` (slice 2);
    - `crashLoop`, if looping;
    - `account`: accountProblemOf(card)'s kind and provider (not its text, which quotes the vendor);
    - `logLines`: the board log lines that name this agent (session name or display name), redacted, newest last,
      at most 50.
  - `unlistedAccounts`: the accounts route's "not signed in" rows (#5984), redacted.
  - `logTail`: the board's last 300 output lines, redacted. Measured on this computer (card comment 16:4x): most log
    lines name no agent (33 of the last 500 do), so per-agent lines alone would drop most failures.
- **Where the lines come from (measured 16:3x, a change from the first call):** the board does not know its log's path.
  board.log is its own stdout and stderr, redirected by whatever started it (launchd, install/kosmos's nohup, the systemd
  unit; on Windows the supervisor), and engine/logstamp.js stamps only when that is a regular file. So:
  - an in-process ring of the last 2,000 lines the board wrote, tapped where it writes (beside logstamp's install,
    for every stream type, so Windows and a pipe work too). It holds only lines since the board started;
  - plus, when it exists, the tail of `$KOSMOS_HOME/logs/board.log` (the app folder's parent), which install/kosmos and
    the Linux unit both name, so a failure from before a restart is still there on Mac and Linux. Each section says
    which source it is.
- **Redaction, before anything leaves the engine,** one function applied to every string in the object:
  `secretmask.mask` (the backup scan's redactor), then the home folder as `~`, then email addresses, and the computer's
  user name and host name, each replaced with a fixed word.

## Not in it
- Message text, instructions, a report's `on` text, a vendor's own sentence: the person's and the agent's words. A
  builder needs the states and the failures, not the conversation.

## Tests (planned; superseded by "As built" below)
- A fixture board (test-support/fleet) with agents in several states: the file has one entry per card, the label
  matches cardlabel, and the route needs the board token.
- Redaction: a token, an email address, a home path, the user name and the host name planted in a report, a log line
  and an account row: none reaches the file (checked on the raw response bytes), each replaced. Control: the same
  strings unredacted would be found by the same check.
- A log line that names no agent is in `logTail`, not in any agent's `logLines`.
- Browser check: the button is in Settings > Advanced and its link is the route.

## Weakest premises
- That `secretmask.mask` catches every credential shape that can reach the board log; it is the backup scan's
  redactor and was built for files, not log lines.
- That the ring catches what matters on Windows: it holds only lines since the board's last start, and on Windows there
  is no board.log path to fall back to (not found in the engine or the Windows tools).

## As built (2026-10-12 21:3x to 22:xx CDT), and where it differs from the call above
Built off main now rather than after slices 1 and 2: everything except two fields needs neither slice.
- `engine/logring.js`: tap() wraps a stream's write (any stream type), keeps the newest 2,000 finished lines, each cut at
  2,256 chars (2,000 shown; see review 5), a UTF-8 decoder per stream; the write itself is never changed. server.js taps stdout and stderr right
  after logstamp, only when it is the board.
- `engine/diagredact.js`: secretmask.mask, then the home folder as `~`, email as [email], and the user and host names
  (whole, any case, at least 3 characters) as [user] / [computer]; redactDeep covers values only (review 3).
- `engine/diagnostics.js`: build() takes what the route gathered and always redacts (this computer's own redactor when
  none is given). readBoardLog() reads the last 256 KB of board.log only when that file is this board's stdout (same
  device and inode), so a board.log left by another run is not presented as this board's.
- `GET /api/diagnostics` (board token only; not an agent-token route) and "Save diagnostics" in Settings > Advanced.
Differences from the call:
- **One log source, not two.** When board.log is readable it already holds every line the ring holds, so using both
  listed each line twice. The file says which it used (`log.source`).
- **No `unlistedAccounts` yet.** Those rows are computed inside the accounts route from lists that route builds first;
  reusing them means moving a block of a route merged today (#5984). Each agent's `account` (kind and provider) still
  shows a signed-out agent. Rejected: re-deriving the rows here (a second derivation of one fact).
- **No card label or `lastWorked` yet.** They come from slices 1 and 2 (engine/cardlabel, observed.lastOk) and are added
  when those are on main. The file carries `card.state`, `stateReported` and `stateReportedBy` now.
- `runner` is the snapshot card's (null for a paneless card), not the status route's runnerOfCard, which lives inside
  that route.
