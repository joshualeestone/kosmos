# agyhooksfsync10-5434: agy's .agents/hooks.json save flushes before it renames (#5434 slice 10)

Addresses #5434. Group 1 of the rename inventory on #5434: `engine/agyhooks.js` `writeKeepingMode` rewrites
`<workdir>/.agents/hooks.json` (Kosmos's hook entry for an Antigravity agent; for an agent Kosmos found, the
workdir is the person's own folder) through `<file>.kosmos-<pid>-<time>`, with no flush, so a crash could leave
it at full length but zero-filled (#5431), which agy would read as broken hooks. It was the same writer as
agytrust.js's, which slice 9 moved.

## Change
- `writeKeepingMode` saves through `securewrite.writeSecret(target, body, mode, { atomicOnly: true, ownTempsOnly: true })`,
  with the mode it had (`stat & 0o777`, 0644 for a new file). It still throws; `ensureHooks` still answers
  `{ ok:false, why:'could not write <file>: ...' }`.
- New `engine/agyhooks.fsync-5434.test.js` (6 tests, slice 9's arms for this writer), in `tools/windows-tests.js`.

## Decided
- **Same trade as slices 6, 7 and 9**: kept born-at-mode, the mode set on the fd (best effort; it was a chmod),
  atomic rename only, no temp left on failure; gained a unique `wx` temp (a planted link is refused, not written
  through; a file planted at the temp name moves the save to a fresh name); `ownTempsOnly` is the one new delete
  path in `.agents` (this file's own dead temps only). Old-named temps are not reaped.
- **securewrite is required directly.** The supervisor runs `$_eng/agyhooks.js` from the engine folder
  (bin/agent-supervisor.sh:1320), beside securewrite.js, as for agytrust.js.
- **A symlinked hooks.json** is still written at its target (resolved before the write, unchanged).
- **A save whose rename keeps failing writes the file three times before refusing**; hooks.json is small.

## Tests
- the temp is flushed before its rename; mode kept under umask 077 (POSIX); all atomic attempts refused leaves
  the file as it was; a link planted at the temp name is not written through or removed (POSIX); only this
  file's own dead temps are reaped (another file's and a live writer's survive); a failed flush refuses the save
  and leaves the file and no temp.
- Mutation: main's writer fails 5 of 6 (the mode arm passes against main, as expected; the planted-link and
  reap arms fail there by temp NAME, the other three by behaviour). Related set (65 files, list5434s10.txt):
  2065, one fail = the #4468 server.test.js timing flake under load 20 (passes alone; filed #5715).

## Weakest premise
That nothing reads the old temp name. It was private to this writer.
