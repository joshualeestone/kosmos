## What this branch does
The dialog-SUPPRESSION half of #2281 was already on `main` (#2394 forward-slash
trust key + win32launch's trust-first, id-pinned gate). This branch adds the
missing DIAGNOSTIC: a Windows agent stuck at an invisible workspace-trust prompt
now surfaces as "waiting at a workspace-trust prompt no one can see" on the task
log instead of a silent empty fleet.

- `engine/win32trustwait.js` — pure detector: a `sessions/<pid>.<hash>.key` with
  no sibling `<pid>.json` is a session that started and did not register.
- `engine/win32supervisor.js` — a bounded one-shot post-start registration check
  (90s), emitting a task-log `unregistered` line.
- `engine/trust.js` `folderTrusted()` — the positive discriminator: the strong
  "trust prompt" wording is used ONLY when the cwd is verifiably NOT trusted in the
  config the agent reads, reusing trustFolder's exact key + config derivation.

## Convergence

### Round 1 — 4 findings, all addressed
1. **Honesty bug (Findings 1+3): strong claim rested on a lone `.key`**, which a
   slow-but-healthy start also produces. FIX: added `trust.folderTrusted` as a
   POSITIVE signal; strong wording only on an explicit `false` (cwd verifiably not
   trusted), hedged wording on `true`/`null`. Reuses trustFolder's key + config
   derivation (config-parity confirmed in round 2).
2. **Honesty/correctness bug (Finding 2): /clear session rotation** — a #2669
   `/clear` rotates the id under the same live child, so matching the captured
   start id would cry "unregistered" over a healthy agent. FIX: match
   `handle.sessionId` (kept current by `rekeyTo`).
3. **pid-verify (Finding 3):** measured on-box in a sandbox `CLAUDE_CONFIG_DIR`.
   `child.pid = 2124` == the `2124.<hash>.key`/`2124.json` pid == the
   `agents --json` pid; only child process was `conhost.exe`. ⇒ the pid assumption
   is sound; `trustWait` stays as corroboration, folder-trust is the discriminator.
   Bonus: the pre-seeded sandbox agent registered with NO dialog — end-to-end
   confirmation of the pre-seed read side, no dialog accepted.
4. **test-gap (Finding 4):** added a real-fs true-return test for `pidWaiting`.
   NITs: grace 45s→90s; prose (age gate is for pollers, not the production path);
   clear the prior pending registration timer on re-arm.

### Between rounds — a real defect the full-suite comparison caught
The FIX-4 real-fs test passed in isolation but failed under full-suite load:
`statSync().mtimeMs` is a float while `Date.now()` truncates to whole ms, so a
just-written `.key` could compute a hair-negative age and be rejected at
`olderThanMs:0`. FIX: clamp age at 0 (`olderThanMs:0` honestly = "accept all
ages"; no-op for positive thresholds) + back-date the test file mtime. Verified
5/5 stable. Production never affected (real `.key` files are ~90s old at check).

### Round 2 — converged
All 5 fixes confirmed correct (including the `folderTrusted` config-parity point).
No must-fix. Three OPTIONAL items folded into #3013:
(a) `win32trustwait.sessionsDir(null)` should mirror `defaultAgentSettings`
    (ignore the engine's `CLAUDE_CONFIG_DIR` for a default-account agent) before
    `trustWait` becomes load-bearing;
(b) a control test for the float-ms clamp;
(c) a test for `folderTrusted`'s default-account arm.
