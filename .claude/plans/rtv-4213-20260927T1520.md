## Measured before building
- Card #4213: every attempt of runs 36321499316 and 36321518671 fails only the RIGHT-edge sample (the page
  ground), at w - 2 where w = document.documentElement.clientWidth. The left edge is right.
- #4076 (94f4916f) recorded the mechanism for the nightly: `scrollbar-gutter: stable` on the root reserves
  an empty 15px gutter on a page that does not scroll, and clientWidth counts it. It fixed
  render-plus-bar-3837 by measuring to the root's box, with a rootOk guard.
- Sweep of docs/browser-checks for reads at `clientWidth - N`, `innerWidth - N,` or `.w - N,`: 3 files.
  Only this one samples colour at the edge. render-build-marker-2066 hit-tests 40px in, beyond a 15px gutter;
  render-room-msgbox-2806 picks an outside tap point.

## Change
`w` is `Math.floor(document.documentElement.getBoundingClientRect().right)`. A new chk asserts `rootOk`:
the root's left is within 1px of 0, and the gap to innerWidth is 0 or a scratch scroller's scrollbar width,
within 1px. That is #4076's yardstick, copied, not reinvented.

## Decided
- The narrowed claim is deliberate, following #4076: on a classic-scrollbar machine with a page that does not
  scroll, a ground-coloured strip shows in the reserved gutter to the right of the white band, and this check
  no longer asserts about it. #4076 made the same call for plus-bar. Filed as #4216 for Josh's
  decision (a gutter takes one colour, so it cannot match both bands).
- Copy #4076's pattern rather than add a shared helper (the copies are now pinned by
  browser-checks-gutter-yardstick.test.js): three checks would then share one measurement
  (plus-bar, boot-no-flash, this one), and a helper change would move all of them at once. Worth a card if
  a fourth appears.
- Weakest part: none of this is proven until it runs on the classic-scrollbar runner. This Mac draws
  overlay scrollbars, so a local pass shows only that nothing else broke. The rootOk chk is new on this check
  and could itself go red on the runner if the root's box differs there in a way #4076 did not meet.
