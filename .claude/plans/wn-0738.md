  - "A daily task can repeat at several times" (PR #5764, #5752 slice 1), rank 9.5, status `held`.

- The button, reply-by-number and "Kosmos waits while Claude asks you" are tagged Mac-only (`platforms` ["mac"]).
  All three act on Claude's question menu as read off the agent's screen, and a Windows agent has no window: it runs

  `keysAllowed` refuses to send keys to it (`WIN32_NO_KEYS_SENTENCE`, around line 1078), and `claudeMenuRefusal`, the

- The window: the button, then the four highest pending items already in the pool (stuck agents, the community picking
  your agent, the task tree, recovering after sleep). The button and the sleep item are Mac-only, so Windows shows 3.

## Decided
- The button is rank 4.5, first in this window: something a person sees and presses in every Claude question.
- Reply-by-number moves below the window (8.6, just under "Kosmos waits while Claude asks you" at 8.5). Both lines would
  tell a person how to answer the same question menu, and the button is the version they will see. It is still pending,
  not retired.
- The daily-times item is `held` until slice 3 (#5771, a room row with an add button) merges; then set it pending. Today
  only the CLI sets several times (the agent rules still teach one, on purpose), so a person cannot do it in the app,
  and once 0.7.38's window is shown it would be next in line. Its line says a DAILY task (a weekly rule still takes one)
  and names no control. #5764's Repeats control edits one time and keeps the others
  beside it. Adding a second time is the CLI's `--at 09:00,21:00`; the room row with an add button is slice 3 (#5771),
  which is unmerged. My first draft said "set on its Repeats control", which was wrong, and I fixed it before committing.
- Not highlights: #5769 (more question-menu screens read as needs-you; a fix to an existing signal), #5758 (an agent's
  refusal names its fix), #5768 and #5747 (#5683: company-enrolled computers report rule stops; enterprise only),
  #5757 (enrolled-computer rollup, enterprise), #5770 (token-only guard, enterprise), #5772 (an agent CLI prints a
  comment id), #5766 and #5767 (a Gemini bridge fd fix and a test).
- #5762 (Token Usage reads only what today's transcripts gained since the last open) is NOT in the pool. Its benefit
  is speed, and its done condition (under 2 s on a running board) has not been measured on a release; without the speed
  claim the line describes an internal read nobody sees. Add it once #5759 measures it on a release.
- "Your agent hears when a person needs an answer" (pending since 0.7.33) is retitled "The community can pick your
  agent to answer": prod users just saw "Agents answer people on the community" (replies to the agent's own post), and
  the old title read like a repeat. The line already said it was a different feature; it now says "picks". A retitle can
  stop `shown` matching by title, but Mac prod never showed this item (lastProd went 0.7.35 to 0.7.37), so nothing is lost.

## Weakest premise
That the button belongs first in the window. It is shown only for Claude's single-choice question menu, never at a
permission prompt or for other providers, so how often a person sees it depends on how often their agents ask (not
measured). If that is rare, "Kosmos says when an agent is stuck" (5) should lead. Changing it is one number in the pool.
