# win32-trust-board-card-3013 — surface a Windows agent stuck at the workspace-trust prompt on the board card

Addresses #3013. Branch off `origin/main` (`b7907c3e`).

## Problem

#2281 (`fd0e76ad`, on main) built the DETECTION (`engine/win32trustwait.js`: a lone
`<pid>.<hash>.key` with no `<pid>.json` is a session that started and never registered) and
the SUPERVISOR's task-log classification (`trust.folderTrusted` → "waiting at a workspace-trust
prompt no one can see"). But the BOARD could not show such an agent usefully: it is enumerated
by `register.survey()` (win32 arm, via `win32job.list()`) as an offline row, and rendered as a
misleading generic "Not running" / "Can't tell" card — the "silent empty fleet" of #3013. The
agent is actually running, hung at a trust prompt in an invisible headless console.

## Approach (reuse the detector + the supervisor's classification; do NOT re-detect)

1. **Engine path — `engine/win32trustcard.js` (new).** `waiting()` composes the existing pieces:
   - known-owned = `win32job.list()` (registered Scheduled Tasks in this world);
   - not-registered = owned name not in the live `claude agents --json` list crossed with the
     `win32sessions` ownership record;
   - only ENABLED tasks (`win32job.taskEnabled`); cwd/configDir from `win32job.taskSpec`;
   - classification = `trust.folderTrusted(cwd, {configDir, agentDefaultAccount:!configDir})`
     (the supervisor's own positive signal) — skip when `true` (a slow start);
   - detector = `win32trustwait.dirWaiting(configDir, {olderThanMs: 90s})` (the #2281 lone-`.key`
     rule, folder-level) — no lone unregistered `.key`, no claim.
   Returns `[{name, needsTrust, because}]`. Fail-closed to `[]` off win32, on a null job list, or
   a null live look.
2. **`win32trustwait.dirWaiting()` (new export)** — the folder-level sibling of `pidWaiting`
   (the board has no pid for an unregistered agent), keeping the IO seam inside win32trustwait.
3. **`server.js` /api/status** — win32-gated, compute the trust map once in the `offline` builder
   and set the new per-card field `needsTrust` + override `state`→`needs_trust` and `because`→the
   supervisor reason. Off-win32 / refused look → byte-identical offline rows.
4. **`web/index.html`** — additive `needs_trust` in `STATE_COPY`/`CARD_ST` (pres `unsure`, NOT
   `off` — server.test.js:9290 requires `stopped` to be the sole `off` state); `card()` and
   `lrow()` grow a `needsTrust` branch in the existing offline early-return, drawing the
   `attn`/`needstrust` treatment with the because as guidance (label "Waiting on a trust prompt").
   `STATE_COPY.needs_trust.label` is referenced only inside the untaken branch, so existing
   render-extraction harnesses (web.not-running, etc.) are unaffected.
