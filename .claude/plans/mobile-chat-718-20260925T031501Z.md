# mobile-chat-718: agent chat messages fit on a phone (first slice)

Addresses #718 (Josh 2026-09-24 22:02 CDT: "really flesh out all the native mobile apps and pay close
attention to make sure the designs fit well on mobile"). Assignment: Liu Kang m526, plan comment
https://github.com/joshualeestone/kosmos/issues/718#issuecomment-5825987811 . Scorpion owns the agent chat.

## Finished looks like
At 375x667, 393x852, 412x915 and 430x932, light and dark, Chromium and WebKit (engine approximation,
not Safari): every DM bubble is on screen, attachment cards sit inside their bubble, a markdown table
scrolls inside its bubble with word-wrapped cells, and the page never scrolls sideways. Desktop
unchanged.

## Audit (before, offline file:// page with a fake thread, no live board data)
1. A message with attachment cards sat 112px off the LEFT edge of an iPhone SE: `.att` is
   `width: min(100%, 34rem)` and the bubble shrink-wraps its caption, so 100% resolved against a
   caption-wide box and the card (and the right-aligned bubble with it) overflowed.
2. Tables crushed to one character per line: the DM's `overflow-wrap: anywhere` (#3414) makes every
   cell's min-content one character, so `.mdtablewrap` never needed to scroll.
3. The text column was ~155px on an SE (avatar 34 + gap 14 + 48 reserved opposite, both sides).
4. NOT this PR (next slice): opening Direct Message on a phone shows the whole identity column
   (avatar, name, five nav tiles, Files) first; the conversation starts two screens down and the
   composer 2.5 screens down. Tap targets under 44px (back, search, attach 34, Post 64x33).

## Change
- `#d-dmthread .mdtablewrap { overflow-wrap: normal }`, headers nowrap: the wrapper scrolls.
- Below 56rem, a bubble holding `.att` takes the whole row so the percentage resolves. Scoped
  narrow because at desktop the caption-wide bubble already fits the card, and widening it would
  change the desktop look (measured: 387px -> 540px).
- Below 40rem, DM-only gutters: avatar 28, gap 8, 20px reserved opposite.
- All scoped to `#d-dmthread`. The room (`.msg` in `#pj-room`, Kano's screen) shares `.msg`/`.att`
  and likely has the same two defects; told Kano rather than touching it.

## Rejected
- Fixing `.att` globally: changes rooms and desktop in a PR that should be one screen's.
- Code blocks scrolling sideways instead of wrapping: wrapping already reads fine on a phone.

## Weakest part
WebKit in Playwright is not Safari; the iOS app is WKWebView, so real-device confirmation waits for
the simulator (Josh-gated). `:has()` is required (Safari 15.4+, already used across this file).
