## Finished looks like
At 375x667, 393x852, 412x915 and 430x932, light and dark, in Chromium (the gate) and WebKit by hand
(engine approximation, not Safari): every DM bubble is on screen, attachment cards sit inside their bubble, a markdown table
scrolls inside its bubble with word-wrapped cells, and the page never scrolls sideways. Desktop
looks the same for ordinary messages; the table rules apply at every width, so a desktop DM table
cell holding a long unbroken token (a URL, a hash) now scrolls with its table instead of breaking
mid-token.

## Audit (before, offline file:// page with a fake thread, no live board data)
1. A message with attachment cards sat 112px off the LEFT edge of an iPhone SE. Cause (corrected
   in challenge iteration 1; the first diagnosis blamed percentage resolution): `.att-name` is
   `nowrap`, so the whole file name is the card's min-content and therefore the bubble's minimum
   width. A name wider than the row pushes the right-aligned bubble out of it. Width-independent:
   a long enough name does it on desktop too.
2. Tables crushed to one character per line: the DM's `overflow-wrap: anywhere` (#3414) makes every
   cell's min-content one character, so `.mdtablewrap` never needed to scroll.
3. The text column was ~155px on an SE (avatar 34 + gap 14 + 48 reserved opposite, both sides).
4. NOT this PR (next slice): opening Direct Message on a phone shows the whole identity column
   (avatar, name, five nav tiles, Files) first; the conversation starts two screens down and the
   composer 2.5 screens down. Tap targets under 44px (back, search, attach 34, Post 64x33).

## Change
- `#d-dmthread .mdtablewrap { overflow-wrap: normal }`: cells wrap at words and the wrapper scrolls. (A headers-nowrap rule was tried and dropped in post-rebase review round 3: removing it changed nothing the check or a person could see.)
- The person's own bubble is capped at its row (`max-width: min(78ch, 100%)`): it is sized to its
  content in a right-aligned column, so a long one-line file name or a wide table made it wider than
  its row. With the cap the name ellipsizes and the table scrolls. Two earlier versions were dropped:
  stretching the bubble below 56rem (treated a symptom, left long names overflowing on desktop),
  and a breakable, line-clamped file name (second post-rebase review showed the cap alone does the
  job; the name rule only moved the ellipsis off the line's end).
- Below 40rem, DM-only: avatar 28, gap kept at 14 (an 8px gap let the tail's 14px ground mask
  paint over the avatar, found in challenge iteration 3), far side mirrors it (28 + 14), keeping
  Josh's #3340 rule that a bubble never grows into the opposite avatar column.

- All scoped to `#d-dmthread`. The room (`.msg` in `#pj-room`, Kano's screen) shares `.msg`/`.att`
  and likely has the same two defects; told Kano rather than touching it.

## Rejected
- Fixing `.att` globally: changes rooms and desktop in a PR that should be one screen's.
- Code blocks scrolling sideways instead of wrapping: wrapping already reads fine on a phone.

## Weakest part
WebKit in Playwright is not Safari; the iOS app is WKWebView, so real-device confirmation waits for
the simulator (Josh-gated).
