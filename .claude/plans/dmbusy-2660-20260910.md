# kosmos#2660: the dialog's working indicator fires after the reply

Josh, 2026-09-10: *"I'll get a reply and then it will show the little thing that
says the agent is working. It'll last for a few seconds and then go away. But it
doesn't show it as soon as the agent is working while he's typing."*

## 🛑 That sentence is already in this repo

**#1150 fixed it, for the ROOM.** Its comment says the same thing: the state
"is not wrong, it is OLDER THAN THE REPLY ALREADY ON SCREEN, and asserting it
there is what made the indicator look like it followed the answer."

**The dialog box is the surface that fix never reached.** Two working lines were
deliberately built to share their markup (`busyRow`) and the one word that
carries the claim (`WORKING_VERB`), and the correctness filter went to one:

| surface | element | staleness guard |
|---|---|---|
| project room | `#pj-busy`, `paintRoomBusy` | **yes**, #1150's drop-when-the-reply-is-newer |
| **agent dialog** | `#d-busy`, `paintBusy` | **none** |

⭐ **The question that finds this class is "which surfaces have NO guard", not
"where else does the defect appear".** The second gives you instances; the first
tells you where the next one lands.

## The mechanism, which is more specific than "a race"

Both paint in the **same tick**, in this order: `paintTalk` fires an async thread
fetch, then `paintBusy` runs **synchronously** off the status snapshot that tick
already holds. So on the tick an agent finishes, the snapshot can still read
`working` (sampled before the reply existed), the line asserts it, and the reply
renders underneath a moment later. The next tick says idle and it vanishes.

## 🛑 The room's fix could not be copied, and that is the trap

It reads `ROOM_SPOKE_AT`, whose `learnedAt` is stamped against
`ROOM_SPOKE_SEEDED`, **keyed on the open PROJECT**. A dialog has no project, so
seeding would read as unseeded forever, every reply would stamp `learnedAt: 0`,
and the filter would never fire.

⭐ **A guard that always misses is indistinguishable from no guard, and it reads
as fixed.**

⚠️ And the reason first written down for using a separate map was **only
conditionally true** (it said reusing the room's map could not seed; keying its
set on the session would seed fine). **The load-bearing reason is the one the
room's own loop states: `ROOM_SPOKE_AT` is keyed on the SPEAKER GLOBALLY**, so a
dialog stamp would suppress that agent in the ROOM's line too.

## Design

`DM_SPOKE_AT` + `DM_SPOKE_SEEDED`, stamped in `paintTalkThread`, read in
`paintBusy`. Mirrors the room's loop including its deny test (a row Kosmos
refused is not the agent speaking, #1397).

- **`learnedAt: 0` on a thread's first load.** Backlog is not a new reply.
- **Seeded only on a read that answered.** `Array.isArray(body.messages)`: the
  route ships `null` when a thread read FAILS, `[]` when the name is unfilable.
  Seeding on a failure marks the thread known-with-zero-rows, so the next poll's
  real backlog reads as all-new and blanks the line for a genuinely working
  agent. **That is the HIDE direction, the one this branch exists not to fail in.**
- **`working` only, never `auth_failed`.** #874 put that state in this slot
  because an agent sat there claiming to work while its terminal retried a 401.
  A reply arriving does not make an auth failure stale.

## Rejected

- **Reusing `ROOM_SPOKE_AT`**: keyed on the speaker globally, so a dialog reply
  would silence the room's line for a room nobody is looking at.
- **`!body.historyBecause` as the seed guard** (suggested in round 1): it would
  refuse to seed the **unfilable** case, where `historyBecause` is set AND
  `messages` is `[]`, and seeding is correct because there genuinely are no
  messages and never will be.

## Weakest premise

That Josh's "dialog boxes" means the agent page's DM panel rather than the room.
Read that way because the room already has the fix and he still sees the
symptom. **If he means the room, this is a regression in the existing filter
instead**, which is a different investigation.

## Challenge-loop iteration 1: 3 WARNING, 2 NIT

### 🛑 The stamp block had ZERO coverage, and making the whole fix inert left every test green

Measured, the same mutation before and after:

```
replace `learnedAt: seededThread ? Date.now() : 0` with `learnedAt: 0`
  before   6/6 PASS   <- the shipped fix is a no-op and nothing says so
  after    1 FAIL     <- the stamp arm
```

⭐ **Why it slipped: the arms drove `paintBusy` with a HAND-SUPPLIED map, and the
browser check set the map by hand too. Both tested the READ side. Nothing touched
the WRITE side, which is the half that decides whether the read ever fires.**
A fix with two halves needs a test per half, and "the tests pass" said nothing
about one of them.

The new arm **slices the real block out of the shipped source** rather than
retyping it, which is the technique the room's own seeding test uses and states
the reason for: a retyped copy tests this file's version of the logic, which is
exactly how a defect ships under a green test.

### The rest

- **A failed read seeded the thread** (the hide direction). Now gated.
- **A stale cached thread could seed the wrong agent.** `__lastBody`/`__lastName`
  were assigned on every paint and cleared nowhere, and the search input repaints
  from them. Folded the clear into the block that already resets what the thread
  box remembers about the agent being left.
- **The boundary was unpinned**: every arm used SNAP plus or minus one, so `>`
  and `>=` were indistinguishable.
- **The separate-map justification was only conditionally true** (corrected
  above).

### ⚠️ And I broke the page in the middle of it

The first cache clear declared `const th0`, **a name already taken in that
scope**, so the entire script stopped parsing. It surfaces as `paintBusy is not
defined`, the browser check dead and two unrelated web tests red, which reads as
a missing function rather than a syntax error. Caught by the browser check plus a
parse of the script blocks, not by reading. **Asking why the name was taken then
produced the better fix**: the block that owns that element was already there.

## Checked and found clean, so nobody re-derives it

- **Map lifetime.** `DM_SPOKE_AT` / `DM_SPOKE_SEEDED` are never deleted from, and
  neither are the room's. Bounded by agent count; a stale entry goes inert as the
  snapshot advances past its `learnedAt`, and a later reply re-stamps it.
- **No double-suppression.** `#pj-busy` and `#d-busy` live in different panels.
- **The clear is ordered correctly**: after the `setThread` placeholder paint the
  block's own comment warns about, and before the new agent's async fetch
  resolves, with the search handler's existing early-return covering the gap.

## Iteration 3: NO NEW ISSUES. Converged.

A round that says how it looked, which is worth more than one that says clean.
It **independently reproduced both mutations** rather than taking them on trust
(the inert-fix stamp and the `>` to `>=` boundary, each redding its own arm),
confirmed the script still parses after the diff, and traced the question I most
wanted answered:

**Can a genuinely working agent stay hidden for longer than one poll?** No.
`LAST_AT` is set unconditionally every 5s in `tick()` and is never paused while
a dialog is open, so `learnedAt > LAST_AT` goes false on the next global poll
regardless of dialog state. Both `paintBusy` call sites read `LAST`/`LAST_AT`
from the same snapshot, so there is no cross-poll mismatch path.

It also confirmed the clear runs unconditionally on every open (not gated on the
agent having changed), synchronously after `CURRENT` is set and before the async
fetch, which is what actually closes the stale-repaint race.

### What three rounds found, and where the work was

| round | found | kind |
|---|---|---|
| 1 | the stamp block untested and the fix inert-able; seeding on a failed read; a stale cache seeding the wrong agent; an unpinned boundary; a conditionally-true justification | instrument + product + prose |
| 2 | the fold left an orphaned comment | prose |
| 3 | nothing | converged |

⭐ **The diagnosis was the hard part and the code was small.** The fix is about
twenty lines; finding that the symptom was a solved bug on an unguarded surface,
and that the solution could not be copied because its seeding is keyed on
something a dialog does not have, was the work.

⭐ **And the review found almost nothing about behaviour.** Round 1's real prize
was that the fix could be made INERT with every test green. Rounds 2 and 3 found
prose and nothing. The product surface stopped yielding immediately; the
instruments took one more round.
