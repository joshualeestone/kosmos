## Findings

- [BLOCKER] ios/Kosmos/RoomView.swift:245 and :297-298. RoomView already has `.onChange(of: draft) { _ in keepDraft() }` (and the same for `replying?.id`), and this change put `dictation.stop()` at the top of `keepDraft()`. **Scenario:** in a project room, press the microphone and speak. The first partial result writes `draft`, the onChange calls keepDraft, keepDraft stops dictation. The person gets the first word or two, the button goes back to the microphone, and VoiceOver says "Stopped dictating". Dictation in rooms does not work past the first partial result. Picking a reply while dictating stops it the same way. The ChatView equivalent is in onDisappear, which is fine. The room's keepDraft runs on every keystroke, so it is the wrong place. **Fix:** take `dictation.stop()` out of keepDraft. The room already keeps the draft on every change, so a late result is kept through the same onChange. If you want stop-before-leave, it is already done by the composer's `.onDisappear { dictation.reset() }`. Add a wiring test that fails when `dictation.stop()` (or `reset()`) shows up in any function called from an `onChange(of: draft)`, at least in `keepDraft`. Today's suite passes with this bug in place.

- [WARNING] ios/Kosmos/ComposerExtras.swift:162-174 together with the composers' `onChange(of: draft…) { dictation.boxChanged(to: $0) }`. The override check runs on the value SwiftUI hands to onChange, after coalescing, and not on each write. **Scenario:** the person types while dictation is on. A keystroke sets the box to "abc x", and before SwiftUI runs onChange, a queued result Task runs and writes "abc hello" with `lastWritten = "abc hello"`. onChange then sees text equal to lastWritten and does not stop. The keystroke is lost and dictation keeps going over the person's typing. Partial results arrive several times a second, so the window is real. **Fix:** check in the result Task before writing. Pass a `current: () -> String` (or a Binding) into toggle, and in the callback, if `current() != lastWritten`, stop and do not write.

- [WARNING] ios/Kosmos/ComposerExtras.swift:183-191. A press of the stop button does `task.cancel()` right away, and later results are dropped by the generation bump. Partial results run about half a second behind speech. **Scenario:** someone says "send it tomorrow" and presses stop at once. The box keeps "send it" and "tomorrow" is lost. People will hit this every time they stop by hand. **Fix:** for a user stop, call `request.endAudio()` and stop the engine, but keep the generation and onText until the final result (or an error) arrives, then release. Keep the immediate cancel for Send, leaving, account switch and the box override, where no more words are wanted.

- [WARNING] ios/Kosmos/ComposerExtras.swift:164 and :172. A recognition error ends as a plain `stop()`, which says "Stopped dictating" and shows no line. Server recognition with Siri and Dictation turned off, no network, the on-device model not ready, or "no speech detected" all look like the mic switching itself off with no reason given. That breaks the rule that every refusal is said. **Scenario:** a phone with Siri and Dictation disabled in Settings is authorized, the button goes red, then flips back with "Stopped dictating" and nothing on screen. **Fix:** when `error != nil` and nothing was heard in this session, end with `refuse(.unavailable)` (or a more specific line) instead of a bare stop.

- [WARNING] ios/Kosmos/ComposerExtras.swift:87-96. The observers cover interruptions and going to the background, but not `AVAudioEngineConfigurationChange` (for this engine) or `AVAudioSession.mediaServicesWereResetNotification`. **Scenario:** while dictating, the person connects or removes AirPods, or a wired headset. The engine stops itself because its input format changed, the tap stops sending audio, and the button stays red over a dead microphone with nothing new arriving. That is exactly the state review 2 set out to remove. **Fix:** observe `.AVAudioEngineConfigurationChange` with `object: engine`, plus the media-services reset, and stop on each (same Task hop).

- [WARNING] ios/Kosmos/ComposerExtras.swift:248-267 (CursorField18), along with ChatView/RoomView emoji button, which sets focus to false when the panel opens. Inserting at the cursor depends on `selection` surviving the field losing focus, because the panel only opens after the field is unfocused. If SwiftUI sets the selection to nil (or to the end) when focus goes, onChange(selection) records it, and every pick lands at the end. Nothing in this branch shows that it survives. The logic tests cover `ComposerExtras.insert` only, never the binding. Setting `selection` on an unfocused field could also take focus back, which would close the panel after every pick through `onChange(of: composerFocused)`. **Scenario:** on iOS 18, put the cursor in the middle of "ok then", tap the face, tap 👍. The glyph may land at the end, or the panel may close. **Fix:** check on an iOS 18 device or simulator and record the result. If the selection is dropped on blur, capture the range in `onChange(of: selection)` only while focused (keep the last focused range plus its text) and use that.

- [NIT] ios/LogicTests/composer/main.swift:44-50. The wiring check takes everything after `private func send() {` to the end of the file and looks for plain substrings. A comment that contains `dictation.stop()` placed above the clear passes it with the real call removed, and `contains("dictation.boxChanged(to:")` is satisfied by a comment too. **Fix:** strip `//` comments before matching and cut the body at the function's closing brace (or at the next `private func`).

- [NIT] ios/Kosmos/ComposerExtras.swift:101-107 with ChatView:946 / RoomView:1009. After a refusal, a new press keeps `state` at the old refusal, so the old "not allowed" line stays on screen during the new start (and the button shows its stop look under a line saying it cannot listen). A person who has just allowed access in Settings sees the refusal while it starts. **Fix:** set `state = .ready` in toggle when starting.

- [NIT] ios/Kosmos/ComposerExtras.swift:192-195. `stop()` posts "Stopped dictating" on Send and on leaving the screen. That announcement competes with the send's own announcements and the new screen's. **Fix:** announce only when the person pressed the button, or when dictation ended by itself.

- [NIT] ios/Kosmos/ComposerExtras.swift:139 and :203-207. If `setCategory` throws, `savedSession` has already been taken, and the catch path's releaseAudio calls `setActive(false, .notifyOthersOnDeactivation)` on a session dictation never activated. If the app's own audio was active at that moment, it is cut. **Fix:** record a `didActivate` flag after `setActive(true)` succeeds, and deactivate only when it is set. Restore the category whenever savedSession is set.

- [NIT] ios/Kosmos/ComposerExtras.swift:232-235 and :256-266. `insert` is a `String?` that is cleared in onChange. Two quick taps on the same glyph before the clear runs leave the value unchanged, so the second tap is lost. **Fix:** carry a counter or UUID with the glyph (for example `(id: UUID, glyph: String)?`).
