# pool-0814: record prod 0.8.13 in the What's New pool and rebuild 0.8.14's window

## Why
The 0.8.14 re-cut (2026-11-21 21:46 CST) was refused by step 1b-ii: "prod serves 0.8.13 but the pool records 0.8.11".
0.8.13 was promoted to prod by 21:45 CST (the promote's phase B log ends then, DEPLOY rc=0), after #8872 built 0.8.14's window while the pool still recorded 0.8.11.
So that window repeated four highlights 0.8.13's prod window already showed (Older Safari, Cloud machines update
themselves, an apostrophe in a name, fewer sign-in asks from a phone).

## What
The tool did it, and web/whats-new.json was never hand-edited: `node tools/whats-new-pool.js build 0.8.14`. Its prod sync (#5713) read prod's
served 0.8.13 manifest, marked 0.8.13's highlights shown (shownIn 0.8.13), set lastProd 0.8.13, then built the window
from what is still pending. Kept: auto-balance (#8846) on top. New: four pending pool items, lines as already in the pool.

Then two pool TITLES were reworded on Mona Lisa's copy read (fleetreleases m5750), in release/whats-new-pool.json, and
the window rebuilt with the same command: "Starring an agent shines" is now "A starred agent stands out", and
"A phone's first-run shows the code box" is now "On a phone, the Claude code box comes into view". Their lines are
unchanged. Both items are pending, so `shown` (which matches by title) has never recorded either old title.

## Rejected
- Hand-editing web/whats-new.json to keep #8872's reviewed four: they would be shown to prod users a second time.
- `shown 0.8.13 --promoted` first: build's sync does exactly that from prod's own manifest, so a second step adds nothing.
- Cutting with the check overridden: the check is right.

## Weakest premise
That no version between 0.8.11 and 0.8.13 reached prod (0.8.12 did not: prod went 0.8.11 -> 0.8.13 on 11-21, by my own
promote scripts; there is no 0.8.12 promote). The risk is small either way: 0.8.12 was cut with no What's New
(88418b05fb), so even had it reached prod there would be no highlights to retire, only a
`shown 0.8.12 --promoted --none` record.
