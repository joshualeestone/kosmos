## Why
The 0.8.14 re-cut (2026-11-21 21:46 CST) was refused by step 1b-ii: "prod serves 0.8.13 but the pool records 0.8.11".
0.8.13 was promoted to prod at 21:4x CST, after #8872 built 0.8.14's window while the pool still recorded 0.8.11.
So that window repeated four highlights 0.8.13's prod window already showed (Older Safari, Cloud machines update
themselves, an apostrophe in a name, fewer sign-in asks from a phone).

served 0.8.13 manifest, marked 0.8.13's highlights shown (shownIn 0.8.13), set lastProd 0.8.13, then built the window
from what is still pending. Kept: auto-balance (#8846) on top. New: four pending pool items, lines as already in the pool.

## Rejected

- `shown 0.8.13 --promoted` first: build's sync does exactly that from prod's own manifest, so a second step adds nothing.
- Cutting with the check overridden: the check is right.

## Weakest premise
That no version between 0.8.11 and 0.8.13 reached prod (0.8.12 did not: prod went 0.8.11 -> 0.8.13 on 11-21, by my own
promote log). If it had, its highlights would need a `shown 0.8.12 --promoted --from-history` record.
