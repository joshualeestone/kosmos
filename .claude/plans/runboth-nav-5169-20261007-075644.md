## Open implementation question — RESOLVED (read-only investigation, 2026-10-06 ~19:25)
YES, it needs board-awareness, and main already has the plumbing — do NOT add #5188's parallel
isBoardURL.
- A run/both computer shows its OWN LOCAL board at `http://127.0.0.1:<port>`. That is NOT caught by
  `isKosmosPlusURL` (which requires https + a kosmosplus.com subdomain), so a naive extension of
  `connectLinkDecision` to run/both would send the local board to `case "http": clicked ? .browser :
  .block` and WRONGLY block/browser the computer's own board. That regression is the whole risk.
- Main already tracks the own-board origin: `badgeOrigin: (host, port)?` (main.swift L1724), set to
  `("127.0.0.1", resolved.port)` for a local board (L2140) / `url.host:port` otherwise (L2127), nil
  when there is no board (L2441). And main already has `isBoardPage(_ page:, board:)` (~L353) that
  recognizes BOTH a Kosmos+ board and a local host:port board; it is already used in the download
  path as `isBoardPage(committedPageURL, board: badgeOrigin)`.
- Design: in the nav handler, drop the `computerMode == .connect` restriction (apply to connect, run
  AND both). Make the decision board-aware: if the target URL is the computer's own board (check
  against `badgeOrigin`, local-board case) return `.inApp`; otherwise fall to `connectLinkDecision`
  (connect's kosmosplus.com board already stays in-app via isKosmosPlusURL). Either add an optional
  `board` param to connectLinkDecision or a thin board-aware wrapper in front of it — reuse
  `badgeOrigin`, do not reintroduce #5188's isBoardURL.
- Apply finding (a) inside connectLinkDecision: non-Kosmos+ https becomes `clicked ? .browser :
  .block` (was `.browser` regardless). Remember this also changes CONNECT mode's unclicked-foreign-
  https handling (open-browser -> blocked); flag on the card.
- Keep download-first ordering (shouldPerformDownload checks run before the nav decision).
