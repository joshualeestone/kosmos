## Finished means
`phonenotify.defaultSend`, the one function that sends a board event to the coordinator,
is exercised by a test CI runs, on the real code path, with no production change.

## Measured before building (origin/main 401f7292a)
- Every phonenotify test injects a sender with `setSender`.
- Without one, `happened()` returns early while NODE_TEST_CONTEXT is set.
- So `defaultSend` (the real POST, its 4 s timeout, its non-2xx and error logging) ran in no
  test. Only the hand-run relay `docs/push-e2e-check.sh` reached it.

## Build
`phonenotify-send-4163.test.js`: each case runs `happened()` in a child `node` process with
NODE_TEST_CONTEXT deleted, enrolled against a sandbox state dir, with
AGENT_WORKFORCE_TUNNEL_COORDINATOR pointed at a local server playing the coordinator. It covers:
- the request, under a self-hosted path prefix;
- 401/500 logged with the status and never the token;
- ECONNREFUSED logged, and the process exits;
- a silent coordinator given up on after about 4 s.

## Decided
- **A child process, not an export of `defaultSend`:** exporting would change production code,
  and Liu Kang's condition for this card is tests only. The child also covers
  `coordinatorUrl`, the state read and the enrolment check on the way. That is the path
  that actually runs.
- **Weakest part:** the timeout test takes about 4 s of wall clock, and its window (3.5 s to
  15 s) is wide on purpose for a loaded runner. A runner slow enough to take over 15 s would
  fail it for load, not for the product.

## Controls
- Keeping NODE_TEST_CONTEXT in the child fails the request test (no request arrives).
- Removing the non-2xx log fails the refusal test.
