# #4103: the phone app's offline copy is only ever the board

Filed by Johnny Cage from the #4086 review. web/sw.js cached every same-origin 200 navigation as '/', so a signed-out
navigation through the relay (its Kosmos+ sign-in page, a same-origin 200) became the offline copy. Still live on main
(read web/sw.js).

## Change (web/sw.js)
- isBoardShell(res): reads at most the first 16KB of a CLONE and looks for `<meta name="kosmos-version"` (the board's
  own head tag, at byte ~900; the relay's page has none). cacheShellIfBoard(probe, copy) puts '/' only when it is.
- The navigation handler uses it (two clones taken before the response goes to the page).
- Install: the manifest and icons are pre-cached as before; '/' is fetched and checked the same way (a signed-out
  install no longer pre-caches the sign-in page).
- SHELL_CACHE v1 -> v2: activate drops a copy the old worker already poisoned; install re-caches the board.

## Decided
- A marker inside the page, not a response header: the relay is a separate service (kosmos-relay) whose header
  forwarding this repo cannot see; a header it strips would stop the offline copy updating at all (silently).
- The existing kosmos-version meta, not a new tag: it is already unique to the board's head.
- Weakest premise: the relay's sign-in page never contains that meta string. It is the relay's own page; if it ever
  embeds the board's head, this check would pass it. A stricter marker (a board-only element id) is one line.

## Tests (web.sw-shell-4103.test.js: the real install and fetch handlers, real Responses, the real board page)
- board navigation cached (whole board, page gets it too); sign-in page not cached (page still gets it); a marker past
  the scanned prefix is not the board; install caches the board and never the sign-in page, and still caches the
  manifest and icons; the cache version is v2. Removing the check reds 3; the board arms stay green.
- web.sw-718 and server.sw-718: pass.
- Browser: render-push-718 (Chromium, a real worker) gains three arms: after a navigation the cached '/' is the board;
  CONTROL a signed-out reload really served the sign-in page (ctx.route intercepts the worker's fetch); the cached '/'
  is still the board. With main's sw.js the last arm FAILS (the copy becomes the sign-in page): the bug reproduced.
  21/21 on the branch (run against a sandboxed board on 4399, as the driver boots one).
