# windisabled-8417: Windows shows a switched-off agent as switched off

Addresses #8417. Found in #8410's review 3 (Ice Cream Kitty), the sibling of #8410's runningJobs fix.

## Done when
1. `create.disabledJobsResult(undefined, 'win32')` names the agents whose Scheduled Task is switched off, `{ ok: false }` when the Kosmos folder could not be listed, and never asks launchctl.
2. A task switched off by hand in Task Scheduler shows at the next poll after its Status word moves, and within 10 minutes if it never does (reasoned from the code and tests, not measured on Windows). Kosmos's own disable shows at the next poll. Cost: no extra folder query (round 7: the listing is kept for the presence memo's 2 s, so register.survey's `list` and this read share one spawn per poll), plus up to 4 definition reads per poll while a board starts or words change.
3. The offline row's sentence on Windows names Task Scheduler and the task, not System Settings.

## Decided
- **Source of truth: the task's own `<Settings><Enabled>`**, read by `win32job.taskEnabled`. Rejected: the CSV Status word as the answer (localized, so a German Windows would never say switched off), and reading the switch through `cachedTaskSpec` (round 1: `taskSpec` gives up on an unreadable argument line, an accented user folder among the ways, and throws away a readable switch; and a `known:false` answer is never cached, so it would spawn every poll).
- **Freshness from the Status word, compared and never interpreted.** `win32job.switchedOffNames` keeps each task's switch beside the Status word it was read under (`SWITCH_SEEN`) and reads it again only when the word changes or the task is new to this process. A read switch is asked again 10 min later even if the word never moved (round 4: a backstop for the weakest premise below). A failed read is kept as unknown and asked again 60 s later (round 2: kept until the word moved, a switched-off task whose first read failed would never be said, since its word stays Disabled). At most 4 definitions are read per call (round 2: each is a synchronous schtasks spawn on the poll, and a 40-agent board start would block for the whole fleet); the rest fill in on later polls, and a task not read yet is left out. When a word moves, what was read under the old word is dropped, never reported.
- **Decided (round 3): a moved word past the cap drops the old answer, so the sentence can blink off for a poll or two** when more than 4 tasks change Status at once (the board stopping its whole fleet, say). Kept on purpose: the old answer was read under the old word, and keeping it would say "switched off" about a task just switched back on by hand. Briefly not saying it is the lesser error; the cap test pins it. What would change my mind: a report of the blink from a real board, then keep the old answer for one extra poll.
- **Round 3:** four comments elsewhere (server.js trust-card call, engine/win32trustcard.js twice, server.trust-wait-offline-3013.test.js) said `create.disabledJobs` was darwin-only or threw on Windows; reworded. The trust card still keeps its own enabled read from `cachedTaskSpec`.
- **Round 5:** `forgetTaskSpec` (called by install, remove, disable and enable) also forgets the remembered switch, so a flip Kosmos makes itself shows at the next poll and does not lean on the Status-word premise. A fifth stale "darwin-only" comment (engine/win32trustcard.test.js) reworded.
- **Round 7:** an end-to-end test (server.win32-switchedoff-8417.test.js) drives /api/status with the probes pinned to win32: an offline switched-off agent carries `jobSwitchedOff: true` and the Task Scheduler sentence, a switched-on one neither.
- **Deferred (round 2):** the injected launchctl `runner` ignored on win32 needs no guard: the first test passes one with platform win32 and asserts it is never asked. The unmeasured Status-word premise is the weakest premise below, not a code defect.
- **`folderRows`** is the one CSV parse `list` and `switchedOffNames` share, and (round 7) one spawn: kept for `presenceTtl()` (2 s, off under an injected runner unless a test turns it on), forgotten by any call that may change a task (round 9: `forgetReads`, run by `run()` for a non-read and by the step forms `installSteps`/`endSteps`/`startSteps`, which bypass `run()`), and keyed on the world id, so a listing is never served to another Kosmos. Before this change the win32 arm spawned nothing (it threw on `process.getuid`), so a second listing per poll was a real added cost.
- **Could-not-look stays distinct:** a failed folder listing is `{ ok: false }`; an empty folder ("cannot find") is a real empty set. One task whose definition could not be read (or whose switch is neither true nor false) is left out of the set: this feeds a sentence, and an unread task is not said to be off.
- **The injected `runner` is ignored on win32.** It is a launchctl runner (machine.agentAutostartCheck), and every caller that passes one is darwin-only; worldstarts excludes win32 before asking. So this arm reaches only the board's display path (server.js jobSwitchedOff and switchedOffSentence).
- **Sentence:** "this agent is not running because its background job was switched off in Task Scheduler. Open Task Scheduler, find agent-<name> in the Kosmos folder and choose Enable, and it can start again". The task name comes from `win32job.taskName`, so a named Kosmos says `agent-<name>+<world>`. No full stop, as the Mac and Linux sentences.
- **Overlap with #8410 (winroster-8410, open):** it edits `runningJobs` just below; this edits `disabledJobsResult` and `switchedOffSentence`. Separate hunks; rebase on whichever lands first.

## Weakest premise
That the Status word changes whenever the switch does. Measured nowhere on a real Windows: it is read from Microsoft's documented Status values (Ready, Running, Disabled, Queued). If a task could be switched off while its word stays the same (say it reads Running while its process is still up after a disable), the board says it at the next Status change or within 10 minutes (the recheck), not at the next poll. Why the gap is narrow even then: the sentence only shows on an OFFLINE row, and a task whose process ends leaves Running, so its word moves at the moment the row could first say it. What would change my mind: a real Windows box where `/Change /DISABLE` on a stopped agent task leaves its Status word unchanged; then the recheck interval should come down.

## Not measured on a real Windows board
Read from code and the schtasks shapes the existing win32 tests already pin.
