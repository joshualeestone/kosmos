# #3387 Consolidated project view: "Project Members" + "Other Agents", two + buttons

Branch: `3387-project-members`  ·  Repo: joshualeestone/kosmos  ·  Owner: Mona Lisa (UI half)

## What finished looks like
In the CONSOLIDATED view with a project open (and at least one of its members on the board), the
agents column reads:
1. Header "Project Members" (was "Agents"), and its existing top `+` now ADDS AN EXISTING AGENT to
   the highlighted project (opens the existing add-member modal).
2. That project's members listed.
3. A sub-header "Other Agents" (in place of the old plain rule) with its OWN `+` that CREATES A NEW
   AGENT (the existing create-new flow).
4. The rest of the agents listed below it.

Everywhere else (tab view, consolidated with no project open, no members visible) the column stays
"Agents" with the top `+` = New agent, exactly as today.

## Key discovery (measured against origin/main, worktree at d690f2077)
The engine AND the picker UI for "add an existing agent to a project" ALREADY EXIST and are wired:
- `#am-modal` (a global `.rm-back` overlay) with `#pj-one-add` (a select of free agents),
  `#pj-one-add-go` ("Add to project"), `#pj-one-msg`.
- `paintFreeAgentPicker(p, sel, btn)` fills the select with agents NOT already on the project.
- `addMemberToProject(who, msg)` POSTs `/api/project/:id/agent/:name` (server.js:13030,
  projects.addAgent). The `pj-one-add-go` handler commits + closes the modal on success.
- Today this modal is opened only by `#pj-add-member` inside the tab-view project card.

So this card is purely about EXPOSING that flow from the consolidated agents rail. No backend work
(confirmed by Angel on the card), and no new picker.

## Decision + weakest premise (per night-shift: decide, document, he can undo)
- Decision: the grouped treatment triggers on MEMBERS-PRESENT (the existing #3218 condition), not on
  bare project-open. Rejected: triggering on any open project, because with zero visible members it
  would show an empty "Project Members" section and an "Other Agents" header over the whole list,
  which reads worse than the current flat "Agents". In the empty-members case the project card's own
  "Add member" button still adds members.
- Weakest premise: that a project you open in the consolidated view almost always has >=1 member on
  the board (true for any project you created with agents). If Josh wants the header/`+` to switch
  the instant a project is highlighted even before it has members, that is a one-function change to
  the trigger.
- Reversible: yes, entirely client-side layout + handler wiring, no data migration.
