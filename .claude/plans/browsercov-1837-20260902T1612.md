## #1710 -- extend render-accounts-openai.js (no new wiring)

`render-accounts-openai.js` already renders the Accounts page, completes first
run through the product route, and exercises the two-press disconnect confirm
(#1683/#1702): first press ARMS the button, second removes. So it already holds
the armed `.acct-disconnect` state -- the gap #1710 left is only that nobody
asserts the armed button PAINTS the danger treatment (CSS at index.html:578,
`.acct-disconnect.armed { font-weight: 600; color: var(--danger, #b3261e); }`).
The #1710 fix shipped a source-presence grep; the gate wanted a rendered/
computed-style check.

Add, at the point the check has armed a button (first press):
- read `getComputedStyle` `color` + `fontWeight` of the UNARMED button (control),
- click once to arm,
- assert the armed button's `fontWeight` is 600 AND its `color` is the danger
  color (resolve `--danger` / rgb(179,38,30)) and DIFFERS from the unarmed color.
Control is built in: if the `.armed` rule regressed (only the word changed, which
is exactly the #1710 defect), the armed color would equal the unarmed color and
the assertion fails. render-accounts-openai.js is chromium-only + computed-STATE
by design; computed `color`/`fontWeight` are style resolution (not compositing),
so they read reliably headless -- consistent with the file's existing stance.

## #1786 -- new check render-create-reset.js (wired into the runner)

`refillDetails(resetDirty)` (index.html:25108) is the single reset choke-point.
On a role CHANGE (roleChanged=true -> refillDetails(true)) it resets the whole
step-two field set (name, create-msg, avatar+input+hint, projects, mark seed,
pending avatar) plus the dirty-guarded label/instructions -- #1786 fixed a
half-reset where a role re-pick left name/avatar carrying the previous role's
entries. On a SAME-role re-pick (roleChanged=false -> refillDetails(false)) the
dirty label/instructions are preserved.

New focused check, modeled on render-create-form.js's boot (sandbox with first
run complete, step two reachable):
- open create, reach step two, type a name + edit instructions (make dirty),
- change to a DIFFERENT role -> assert name is cleared AND instructions refilled
  to the new template (whole reset happened),
- re-pick the SAME role -> assert an edited (dirty) instructions/label is
  PRESERVED (control for the other direction: the reset must NOT fire on a
  same-role re-pick).
Wire it into tools/browser-checks.sh (near the other create checks) and add it to
tools.browser-checks-wired.test.js's expected set. Dual-engine (chromium+webkit)
like render-create-form.js.
