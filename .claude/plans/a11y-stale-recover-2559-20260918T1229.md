# a11y-stale-recover-2559 -- tmux Accessibility row: actionable Turn On when the grant is unreadable on a real Mac

kosmos#2559 (KEEP path; Josh ruled tmux IS needed, 2026-09-18). Fixes the fresh-Mac stuck-"Checking..." tmux Accessibility row.

## Goal (what is true when done)
On a fresh Mac whose board has no Full Disk Access, the tmux Accessibility onboarding row no longer hangs on a dead "Checking..." spinner. It paints "Not activated" + Turn On, so the user can grant tmux (Turn On fires the osascript-under-tmux prompt, which does NOT need FDA). A browser tester still keeps the honest advisory (nothing to grant).

## Root cause (grounded in server.js:/api/tmux-a11y-status + engine/a11ystatus.js)
tmux's grant is only readable via the system TCC db, which needs FDA. On a fresh Mac the board lacks FDA -> tmuxGrant() returns checkable:false (db unreadable) -> the route left that as a dead "Checking..." because it could not tell a real no-FDA Mac from a browser. The engine already handles the readable-but-unregistered case (checkable:true, present:false -> actionable). The gap was only the unreadable case on a real Mac.

## Change
`server.js` /api/tmux-a11y-status: compute `nativePresent` (promptrequest.nativePresent() = a11ystatus.read().checkable === true, the SAME signal /api/file-access-status uses). When tmuxGrant is checkable:false AND nativePresent, return `{ checkable:false, actionable:true, because: 'we cannot read the tmux Accessibility grant yet; turn it on to grant tmux' }`. Stays checkable:false so the S3 Next gate is still non-blocking (#2912). A browser (nativePresent false) is untouched -> honest advisory. Also corrected the stale #3113 comment that conflated "browser" and "no-FDA box".

## Tests (server.tmux-a11y-status-2911.test.js)

- #2559 CONTROL: unreadable db + NO native app (browser) -> checkable:false + NOT actionable (the discriminator; if it trips, the fix would show a dead Turn On in a browser).
- The 4 original #2911 route tests still pass unchanged (present:false / off / granted / unreadable).
`node --test server.tmux-a11y-status-2911.test.js` -> 6 pass, 0 fail.

## Weakest premise
That Josh's fresh-Mac stuck row IS this no-FDA checkable:false path (inferred from the route's own branches, not measured on a fresh box). The fresh-Mac verify (Josh's #3188 test20 pass) confirms both that Turn On now appears AND that firing it yields a tmux-keyed grant (the osascript-under-tmux probe is itself verify-pinned, main.swift:1365). If the fresh-Mac `because` shows a different branch, the same actionable-on-native-present mapping still covers it (it keys on nativePresent + checkable:false, not on the specific branch).
