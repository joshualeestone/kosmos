# shots-files-718: the harness's Files screens step into Profile first

Found by the #718 re-sweep (Raiden, 2026-09-26, https://github.com/joshualeestone/kosmos/issues/718#issuecomment-5847862356).

## Problem
`mobile-shots.js`'s `agent-files` and `agent-files-all` screens load the agent page and wait for the short Files
list (`#d-files-list .pj-doc`, `#d-files-all`). On a phone the agent page now opens on its conversation (the
chat-first page), and that view hides the short Files list by design (web/index.html, the #718 Files rule: "Talk
still hides #d-files above; Profile and the other agent sections keep this short list"). So both screens timed out
in every shot of the re-sweep: 16 of 96 Chromium shots and 4 of 24 WebKit shots.

## Done looks like
Both screens are shot at every size, theme and engine, and still assert that they arrived (the Files list is showing).

## Change
Each screen clicks the Profile section (`#d-nav button[data-go="profile"]`, the same control `agent-profile` uses)
before waiting for the Files list.

## Measured
With the change: 16 of 16 Chromium shots and 4 of 4 WebKit shots of the two screens, 0 errors. Without it (main):
every one of those shots errors with a waitForSelector timeout.

## Rejected
- Waiting for `#d-sec-files` (the View All section) directly: the agent-files screen is about the short list on the
  agent page, which is what a person sees first.

## Weakest part
If the default section a phone opens on changes again, these screens need the same care; they fail loudly (a
timeout) rather than photographing the wrong screen, which is the point of the arrival assert.
