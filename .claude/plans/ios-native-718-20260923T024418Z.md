## Design / changes

- **`AppDelegate.swift` (new)** — a `UIApplicationDelegate` installed via
  `@UIApplicationDelegateAdaptor` (a pure SwiftUI `App` cannot receive the
  UIKit-level APNs callbacks). Forwards the three APNs registration results
  (`didRegisterForRemoteNotificationsWithDeviceToken`,
  `didFailToRegisterForRemoteNotificationsWithError`,
  `didReceiveRemoteNotification:fetchCompletionHandler:`) to the push manager;
  configures + requests notifications at launch.
- **`PushNotificationManager.swift` (new)** — owns the notification surface:
  `UNUserNotificationCenter` authorization, `registerForRemoteNotifications()`,
  the `AGENT_PERMISSION` category with Approve/Deny actions, foreground
  presentation, and action-response handling. `handleRegistration` hex-formats
  the device token and hands it to `registerTokenWithBoard`.
- **`BiometricAuth.swift` (new)** — `LocalAuthentication` wrapper
  (`deviceOwnerAuthentication`, so a passcode fallback is offered), completion
  always on the main thread.
- **`KosmosApp.swift` (edit)** — install the `@UIApplicationDelegateAdaptor`;
  comment updated to say the native surface is now wired.
- **`ContentView.swift` (edit)** — optional biometric gate controlled by
  `KosmosConfig.requireBiometricUnlock` (default **false** → shell behaves
  exactly as before; flip to true to demonstrate the unlock). `boardURL`
  placeholder unchanged.
- **`project.pbxproj` (edit)** — add `INFOPLIST_KEY_NSFaceIDUsageDescription`
  to both Debug and Release so the generated Info.plist carries the Face ID
  purpose string (required for a functional Face ID gate). Verified present in
  the built `Info.plist`.

## Deferred / gated (stubbed, marked, NOT blocked on)

- **APNs auth key (.p8)** — external ask, already surfaced to Josh (Liu Kang
  confirmed). Until it lands + the app is provisioned with the `aps-environment`
  entitlement, `registerForRemoteNotifications()` fails in development;
  `handleRegistrationFailure` logs it as expected, not fatal.
- **Device-token upload endpoint** — the coordinator already carries VAPID /
  web-push; APNs token registration is the sibling path. `registerTokenWithBoard`
  is the single place to POST `{ token, platform: "ios", bundle_id }` when the
  endpoint is decided.
- **`aps-environment` entitlement + `UIBackgroundModes=remote-notification`** —
  need code signing / an Apple ID (gated); added at provisioning time. Not wired
  now because they require signing, which this SDK-only build disables.
- **iOS simulator runtime** — `xcrun simctl list runtimes` is empty; a `-scheme`
  build cannot run here (Josh's `xcodebuild -downloadPlatform iOS`). Verified
  with `-target -sdk iphoneos26.5` per the #2869 README instead.
- **Front-door origin (#2854)** — `boardURL` stays the `app.kosmos.io`
  placeholder.

## Weakest part of my reasoning

The biometric gate falls **open** when biometrics are unavailable/unenrolled
(rather than forcing a passcode), so with the flag on, a device with no
enrollment is not actually gated. That is a deliberate no-lockout default for a
stub; whether production requires a hard passcode fallback is a product decision
(noted in code + here). Would change if Josh rules the board must be hard-gated.
