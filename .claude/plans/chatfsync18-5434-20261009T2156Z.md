# chatfsync18-5434: conversation threads and the DM seen-cursor are flushed before they count (#5434 slice 18)

Addresses #5434. Group 3 of the rename inventory. `engine/chat.js` saved a conversation thread (`appendLocked`, a
reaction in `reactDirect`, the reactions-told mark in `markDmReactionsTold`) and the DM seen-cursor (`markDmSeen`) by
writing `<file>.<pid>.new` / `dm-seen.json.tmp` and renaming, with no flush, so a crash could leave a thread at full
length but zero-filled (#5431), which parses as no messages: the conversation would be gone.

## Change
- The four saves call `store.saveFlushed` (securewrite, atomicOnly, the existing mode kept). Each caller's error
  handling is unchanged (appendLocked and reactDirect catch and answer; markDmReactionsTold and markDmSeen throw).
- `store` exports `saveFlushed` (the identical one-line change as slice 17, so the two merge cleanly).
- `supersede`'s move-aside rename (:3074) is a MOVE, not a save: unchanged.
- New `engine/chat.fsync-5434.test.js` (4 tests), in `tools/windows-tests.js`.
- `engine/chat.test.js`: the test that a move-aside is reported even when the write then fails planted a DIRECTORY at
  the old `<file>.<pid>.new` temp name to make the write fail; that no longer blocks securewrite's unique temp. It now
  refuses the save's `.kosmos-` temp at open with EISDIR (so its no-errno-in-the-sentence check still bites) and
  asserts the refusal fired.

## Decided
- **Thread listing unaffected:** `DIRECT_THREAD_FILE` is anchored on `.json$`, so a `.kosmos-...tmp` beside a thread
  is never read as one.
- **No guard matched the old temp names** (grep for `.new` / `dm-seen.json.tmp` across engine and server).

## Tests
- append flushed before its rename; an append whose flush fails keeps the thread and leaves no temp; a reaction
  flushed before its rename; the DM seen-cursor flushed before its rename.
- Mutation: main's chat.js + store.js fail all 4. Related set (128 files, list5434s18.txt): 3600 tests; the one
  failure was the move-aside test above, re-aimed; it passes.

## Weakest premise
That nothing outside chat.js reads `<thread>.<pid>.new` temps. Grepped engine and server: none.
