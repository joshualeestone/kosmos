## #3217 — Projects MAP fits on one page (no horizontal overflow)
Josh (screenshot on 0.6.74): the Projects TREE/org-chart view overflows the right edge ("Northstar
Robotics" clipped, sideways scroll). "this thing still needs to fit on one page."
- Component: paintProjectsMap() -> .pjorg (top-down nested ul/li tree) inside #pj-map (.pjorgwrap,
  overflow:auto). Overflow driver: .pjorg min-width:max-content lays siblings side-by-side; a wide
  fleet exceeds the panel. Measured: 10 projects -> +442px, 16 -> +2088px at the check viewport.
- Fix (design call): pjMapFit() scales .pjorg down to the panel width with CSS `zoom` (NOT
  transform:scale, which is visual-only and leaves a phantom scrollbar; zoom reflows so the box
  shrinks, the sideways scroll goes, and vertical space compensates). Measured natural width at
  zoom:1 first, then zoom = avail/natural (down-only), plus one measured correction pass for the
  sub-pixel/intrinsic-width residual. Called from paintProjectsMap() and on window resize (no-op
  when the map is hidden). Nodes are static (no drag math), so a single container scale is safe.
  Both Kosmos engines (app WebKit + Playwright/Chromium check) support zoom.
- Guard: render-projects-map.js gains a NON-VACUOUS fit arm (seed 16 wide projects; assert they
  WOULD overflow unscaled, then that after the fit scrollWidth <= clientWidth). Existing
  "scrolls in both directions" assertion still passes (CSS overflow properties unchanged).

## Weakest premise
The fit uses `zoom`, which has no prior precedent in this file (transform:scale is used only for
animations). It is the correct tool here (reflows, so the fit is real and cleanly measurable) and is
supported in both engines Kosmos renders in, but a reviewer may CONVENTION-flag the novelty; the
rationale is documented inline. If zoom ever proves unsupported in a target engine, the fallback is
transform:scale + overflow-x:hidden + vertical margin compensation (messier, visual-only).
