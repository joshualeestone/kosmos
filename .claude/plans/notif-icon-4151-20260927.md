# notif-icon-4151: the Android push icon is a bitmap

Addresses #4151 (found by Kano on #4140). Routed by Liu Kang (m1369, 2026-09-27).

## Finished means
On the AVD a Kosmos push shows the Kosmos icon, with before and after shade screenshots; a test
fails if the notification icon becomes a vector again; merged before the next APK built for Josh.

## Decisions
- **PNG per density, not a different vector route.** androidx.browser 1.4.0 decodes the icon with
  `BitmapFactory.decodeResource` (javap), which cannot decode a vector; overriding the service to
  rasterise the vector would be more code in a class we do not otherwise own.
- **Same shape as before** (planet and ring), redrawn from the vector's numbers by a committed
  script, so the icon can be regenerated.
- **The test reads the PNGs itself**: the Android unit-test classpath has no javax.imageio. It
  accepts only 8-bit RGBA, non-interlaced, which is what the script writes.

## Check
`IconResourceTest`: no `ic_notification.xml` in any drawable folder; a white RGBA silhouette PNG at
each density. Controls: putting the vector back fails it; a non-white PNG fails it.
AVD before and after: `android/evidence/notif-icon-4151/`.

## Weakest part
The fix is proven on one emulator and one Chrome (124). Other browsers that support TWA
delegation receive the same bitmap, but were not tried. The `size=40x40` in the after record is
what Chrome scaled our bitmap to; which density it picked was not checked.
