# #4082: first run keeps keyboard focus when a subscription sign-in finishes

Found by the #4081 browser check (Angel): when Gemini's subscription step reaches Ready it hides, and focus that was
inside it (the paste box's Continue) falls to the page. Still live on main (read web/index.html: FR_AGY_SUB's onReady
moved no focus).

## Change (web/index.html)
- Gemini (FR_AGY_SUB onReady, now async): after the row repaints (awaited, failure tolerated), if focus was lost (on
  the page, or inside #fr-gemini-sub-step) and first run is still on step 5, focus #fr-gemini-msg (tabindex -1, a
  live region holding the gold "ready" box). If the box is empty (repaint failed) it gets a sentence first.
- GPT (frOpenaiSubConnected): the card asked to check GPT and Grok. Grok already focuses its box. GPT had the same
  drop (it hides #fr-openai-sub-step, whose "Open the sign-in page" link or Stop can hold focus): same fix, with focus
  read BEFORE the step hides, and the focus move in a finally so a failed repaint still lands it.

## Decided
- The connected box, not the Next button: Grok's precedent, and the live region reads what happened. Weakest premise:
  a person might expect Next; the box is one Tab from it.
- Only when focus was lost: a person who moved to another row keeps their place (tested).
