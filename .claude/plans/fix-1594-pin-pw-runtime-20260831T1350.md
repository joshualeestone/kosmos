# Plan: pin the Playwright runtime so the browser gate is deterministic (kosmos#1594, pinning half)

## The defect (measured in tools/browser-checks.sh)

kosmos#1594 (OPEN): "Two Playwright installs on one box pin different browser builds; the page
gate skews unpredictably." Pete shipped the DIAGNOSTIC half; the PINNING half is mine (I filed it).
#1615's browser check waits on this: that check must run against a pinned Chromium or its verdict
is against an unknown build.

- `resolve_pw()` (browser-checks.sh:165) resolves Playwright from, in order: `$KOSMOS_PW_NODE_PATH`,
  `~/work/pw-runtime/node_modules`, then `~/.npm/_npx/*/node_modules` (the MCP's OWN npx cache).
- The DOCUMENTED provision (doc comment lines 37-38 and the failure-message hint 191-192) is
  `PW=$(mktemp -d); npm i playwright; export KOSMOS_PW_NODE_PATH="$PW/node_modules"`. The mktemp dir
  is a THROWAWAY, gone by the time the gate runs later, so `KOSMOS_PW_NODE_PATH` points at nothing
  and `resolve_pw` silently falls back to `~/work/pw-runtime` or the MCP's cache. Following the docs
  exactly leaves NO persistent runtime. THE INSTALL WRITES TO A THROWAWAY, THE RUN READS FROM A
  PERSISTENT ONE, so the two do not compose.
- `~/work/pw-runtime/package.json` = `"playwright": "^1.62.1"` (a RANGE); `npm i playwright` installs
  latest. So the browser BUILD is not pinned. 1.62.1 is the current known-good (chromium-1234 on
  disk); the checks are multi-engine (need webkit too).
- `~/work/pw-runtime` is NOT a git repo, so the PIN must live in the repo, never in pw-runtime.

## Checklist

- [ ] 1. Add `tools/provision-pw.sh`: an idempotent script that provisions the PERSISTENT
      `~/work/pw-runtime` (the dir resolve_pw already reads), installs an EXACT pinned playwright
      version (a `PW_VERSION=1.62.1` constant), and runs `npx playwright install chromium webkit`
      (BOTH engines the checks use). Idempotent (safe to re-run; skips a re-install when the pinned
      version is already present), persistent, pinned. So the documented INSTALL and the RUN both
      target `~/work/pw-runtime` and the browser build is deterministic. Respect an override of the
      runtime dir (KOSMOS_PW_RUNTIME_DIR, default ~/work/pw-runtime) so a CI/box can relocate it.
- [ ] 2. browser-checks.sh: replace the mktemp dance in the doc comment (37-38) and the
      failure-message provision hint (191-192) with `bash tools/provision-pw.sh`, so the documented
      install composes with the run. Do NOT change resolve_pw's resolution ORDER (env, pw-runtime,
      npx) -- only how it is provisioned + the visibility below.
- [ ] 3. browser-checks.sh resolve_pw: when it resolves from the `~/.npm/_npx` cache (the MCP's
      UNCONTROLLED build) rather than the pinned `~/work/pw-runtime` or an explicit
      KOSMOS_PW_NODE_PATH, LOG IT LOUDLY ("using the MCP's unpinned Playwright; provision the pinned
      runtime with tools/provision-pw.sh"). Keep the fallback (do not brick a box without the
      runtime), but never let the skew be silent. This is the #1594 defect made visible.
- [ ] 4. Pin as a SINGLE SOURCE OF TRUTH: the pinned version lives once (in provision-pw.sh's
      PW_VERSION); browser-checks.sh references the script by name, not a second copy of the version.
- [ ] 5. Test (bash test in tools/, symmetric with the repo's other `tools/test-*.sh`): assert
      (a) provision-pw.sh exists and names an EXACT version (not a range, not bare `playwright`);
      (b) browser-checks.sh's provision hint points at provision-pw.sh and no longer tells the
      operator to `mktemp -d` (the non-composing step is gone); (c) resolve_pw has a loud-log branch
      for the npx-cache fallback. Wire it into the test suite (tools/run-tests.sh / the shell test
      list) if the repo requires wiring. Run the FULL `tools/run-tests.sh`.

## Explicitly out of scope

- Running the actual browser gate / any Playwright browser test -- that is Donnie's #1615 check,
  which THIS unblocks. This PR is browser-INDEPENDENT: the provision script + the pin-consistency
  test verify it headlessly.
- Changing which version is pinned beyond 1.62.1 (the current known-good). If the team wants a
  different Playwright version, that is a one-line follow-up to PW_VERSION.
- The `~/work/pw-runtime` directory itself is not committed (not a git repo); this PR pins via the
  script + docs in the repo.

## Risk

The only behavioural change to the gate is the loud log on npx-cache fallback (visibility, not a
new failure) and the documented provision command. resolve_pw's resolution order is unchanged, so
a box that currently passes still passes; a box relying on the mktemp docs now gets a persistent
pinned runtime instead of nothing. Arrives as a PR for the Kosmos team to review.
