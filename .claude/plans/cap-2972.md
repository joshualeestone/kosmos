# #2972 — operator raises the team cap in-flow (board-token path)

## Problem
`POST /api/team` resolves the per-team cap via `team.resolveCap(undefined, process.env)`
— so over HTTP the ONLY way to raise the default cap (12) is the operator env var
`AGENT_WORKFORCE_TEAM_CAP` set before the board starts. Josh's org-chart target is
15-20 people, so pasting 15-20 rows is refused until the operator sets an env var
out-of-band and restarts. #1280 shipped the honest refusal; this is the in-flow raise.

## Change (backend only; scope confirmed with Splinter)
On the **OPERATOR (board-token) path only** of `POST /api/team`, accept a bounded
`cap` in the request body and pass it as `deps.cap` to both the route's pre-check
`resolveCap` and `createTeam`. The **AGENT-token path never gets it** — a model
cannot raise its own bound, preserving "Kosmos owns the bound, not the prompt".
`resolveCap`/`createTeam` already validate (positive integer) and clamp to
`MAX_TEAM_CAP` (50), so an invalid/absent `body.cap` falls back to env/default and
any value is ceiled at 50.

- `server.js`: compute `capDeps` = `{cap: Number(body.cap)}` only when
  `callerKind === 'operator'` and the value is a positive integer; pass it to the
  route's `resolveCap` (line ~4527) and both `createTeam` calls, so the pre-check
  and the engine never drift on the effective cap.

## Why it is safe
- Trusted channel only: the board token IS the operator, the exact `deps.cap` seam
  `engine/team.js` blesses. The agent path stays capped.
- The engine already clamps to MAX 50 and validates; the route override rides that.

## Tests (verified by mutation)
- `server.team-route-1279.test.js` (operator path):
  - raise: 16 members + `cap:15` → refused, resolved cap = 15 (reds if override
    ignored).
  - clamp: 51 members + `cap:100` → refused, resolved cap = 50 (reds if not clamped).
  - invalid `cap` (`'abc'`,0,-5,15.5) → ignored, cap stays 12.
- `server.team-agent-token-1279.test.js`:
  - agent path + `cap:15` + 13 members → still refused at 12 (reds against an
    over-broad fix that drops the `callerKind === 'operator'` guard).

## Out of scope (follow-on)
The org-chart UI "raise the cap" control (#1280 is Mortals' frontend card). This
card is the backend enable; the UI can now offer the control instead of only
surfacing the refusal.
