# Plan: worldsw-lockout-3055 (kosmos#3055, the lockout)

Directive-driven build (night-shift shard card, SEVERE). Scope is the WORST symptom of a
multi-symptom SEVERE bug; the rest is documented as follow-up on the card.

## The bug (from Josh's 0.6.63 report)

Switching between Kosmoses (worlds) fails, and — worst — a hard refresh makes the Kosmos
dropdown disappear so the user is "totally locked out" of their original Kosmos with no way
back.

## Root cause of the lockout (diagnosed on origin/main)

- The switcher `#worldsw` (web/index.html) is `hidden` by default.
- `worldsFetch()` is the ONLY thing that reveals it (via `worldswRender` -> `sw.hidden =
  false`), called once on page load with NO retry.
- It bailed early — leaving the switcher hidden — on any non-ok `/api/worlds`, on a fetch
  throw (board unreachable), or an empty list.
- `GET /api/worlds` (server.js) returns 500 when the board is not signed in — the exact
  broken state a failed switch leaves it in.
- So: failed switch -> broken board -> hard refresh -> `/api/worlds` 500s -> switcher never
  un-hides -> no other code path shows it again -> locked out.
- None of the prior cluster fixes (#2528/#2628/#2238/#2454) touched this front-end
  visibility gate; they harden the engine boot/abandon.

## Approach (scope: the lockout)

`web/index.html`: make `worldsFetch` NOT fail closed.
1. Persist the last-known world list to localStorage on every successful read.
2. When the live read fails/empties, render the switcher from that last-known list so the
   user can always switch back to a working Kosmos.
3. Show an honest "last-known list" note in the switcher's own status banner, guarded so a
   live switch never fights it; clear it on a live read.
4. Retry so a recovered board self-heals to live.
5. With NO cache (a board that never had the route / first run) stay hidden — today's clean
   single-world degrade, pinned by a control arm.

`docs/browser-checks/render-worldsw-lockout-3055.js`: hermetic (file://) check with the
500-with-cache, unreachable-with-cache, live, and no-cache-control arms.

## Out of scope (follow-up on the card)

Symptoms #1-#3 — the missing persistent animated-K loader, the switch never verifiably
completing (shows old/no agents), and "board not signed in" on Projects — are the deeper
switch-restart failure, scoped as follow-up rather than blocking the lockout fix.

## Weakest premise

That localStorage is an acceptable place for the last-known list. It survives a hard refresh
(the lockout trigger) and is per-viewer; a private window / disabled storage degrades to the
prior (hidden) behaviour, which is no worse than today. The switcher being reachable is the
recovery; a stale current-account marker in the degraded render is acceptable and noted.
