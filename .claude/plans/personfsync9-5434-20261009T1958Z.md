# personfsync9-5434: ~/.claude.json and agy's settings.json saves flush before they rename (#5434 slice 9)

Addresses #5434. Group 1 of the rename inventory posted on #5434 (2026-10-09): the person's own files. Two
of the writers that still saved by rename with no flush, so a crash could leave the file at full length but
zero-filled (#5431):
- `engine/accounts.js` `clearDefaultIdentity`: rewrites **~/.claude.json** (removing the main Claude
  connection clears `oauthAccount`) through a fixed `.tmp-<pid>` temp.
- `engine/agytrust.js` `writeKeepingMode`: rewrites **agy's settings.json** (adding an Antigravity agent's
  folder to `trustedWorkspaces`) through `.kosmos-<pid>-<time>`.

## Change
- Both save through `securewrite.writeSecret(target, body, mode, { atomicOnly: true, ownTempsOnly: true })`,
  with the mode each had (`stat & 0o777`, 0600 when unreadable) and the refusals each had
  (clearDefaultIdentity's catch answers its sentence; writeKeepingMode throws to trustAgyFolder's callers,
  as before: the supervisor script and win32agy both catch).
- New `engine/personfsync-5434.test.js` (13 tests: six arms per writer, plus agy's symlinked settings), in
  `tools/windows-tests.js` mid-list.

## Decided
- **Same trade as slices 6 and 7.** Kept: born at the mode, then set on the fd (best effort; it was a chmod),
  atomic rename only, no temp left on failure. Gained: a unique `wx` temp, so a planted link is refused, not
  written through; a file planted at the temp name moves the save to a fresh name.
- **The one new delete path** in each person's folder: `ownTempsOnly` reaps a dead temp with securewrite's
  exact shape for THIS file (never another file's, never a live writer's). The old-named temps are not reaped.
- **agytrust requires securewrite directly.** It runs as a script from the engine folder
  (`bin/agent-supervisor.sh` runs `$_eng/agytrust.js`), beside securewrite.js; it is never copied alone, unlike
  kosmos-statusline.js, so no unflushed fallback is kept.
- **agy's symlinked settings.json** is still written at its target and stays a link (the target is resolved
  before the write, unchanged). The test here repeats engine/agytrust.test.js's, kept so this file covers each
  writer whole (review 1).
- **A save whose rename keeps failing now writes and flushes the file three times before refusing** (a
  read-only file on Windows, or one held without delete sharing): for ~/.claude.json that can be several MB.
  Only on the refusal path; trust.js saveConfig accepts the same trade (review 1).
- **A symlinked ~/.claude.json is replaced by a plain file** and the `oauthAccount` stays in the link's target.
  Not changed here (the old rename did the same); trust.js refuses a symlinked config instead. Left for its own
  card, since choosing refuse or write-through is a behaviour change (review 1).
- **Not in this slice:** undo.js:481/286 (Undo restoring the person's file, and its kept copy),
  instructions.js:896, agyhooks.js:139, setup-assistant.js:1604/1688. Each is its own shape (copyFileSync,
  'wx' briefs, writes through links) and gets its own slice.

## Tests
- per writer: the temp is flushed before its rename; mode kept under umask 077 (POSIX); all atomic attempts
  refused leaves the file as it was; a link planted at the temp name is not written through or removed (POSIX);
  only the file's own dead temps are reaped (another file's and a live writer's survive); a failed flush
  refuses the save, leaves the file and no temp.
- The temp matcher is securewrite's exact shape: a bare `<file>.kosmos-` prefix also matched agy's own lock
  (`settings.json.kosmos-lock`), planted the link on the lock and refused the lock instead of the temp.
- Mutation: main's two writers fail 10 of 13 (all five non-mode arms for each; the two mode arms and the
  symlink arm pass against main, as expected). Related set (82 files, list5434s9.txt): 2279, 0 fail, 5 skipped.

## Weakest premise
That nothing reads the old temp names. Both were private to their writer. What would change my mind: a
reader or cleanup of `.claude.json.tmp-*` or `settings.json.kosmos-<pid>-<time>`.
