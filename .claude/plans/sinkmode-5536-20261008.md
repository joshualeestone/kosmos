# sinkmode-5536: the restore sink reads the root's mode back after making it private (#5536)

## Why
E0.7's restore sink (engine/restoresink.js, PR #5603) makes the restore root 0700 before writing into it, so a
shared group (macOS staff) cannot write there. Its review round 19 left one NIT worth doing, carried to #5536: the
mode is never read back. A mount that reports success but ignores modes (a CIFS dynperm mount, some FUSE mounts)
would leave a group-writable root accepted, and the group could then swap folders under a restore in progress.

## Change
- After the chmod, lstat the root again and refuse unless (mode & 0o077) is 0, with a message that names the cause
  and suggests a folder on this computer's own disk.
- Test: a chmodSync stub that silently no-ops on the root (the drive "ignores" it): refused. Red-checked: the suite
  goes 11 pass, 1 fail with the read-back removed.

## Weakest premise
That lstat reports the mode the drive enforces. A FUSE mount could report 0700 and still enforce something else;
nothing the Mac can read would show that, so this check catches the honest-but-ignored case only.
