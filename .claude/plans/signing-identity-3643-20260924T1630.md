# Mac signing identity in one place, ahead of the team switch (#3643)

## Why now
Josh enrolled Kosmos Agent Manager, Inc. as a new Apple Developer team (waiting on Apple). The switch
itself is gated on Apple's approval and Josh creating the Developer ID certs. What is unblocked today:
the Stone Syndicate identity was hard-coded in FOUR places (bundle codesign, installer pkg + notary
key, cut signing preflight, the served-pkg signature check). A partial switch would ship an app signed
by one team with a checker expecting another.

## Call
`tools/lib/signing-identity.sh` names the team, both Developer ID identities, and the notarytool API
key id/issuer. All four sites source it; every existing env override (KOSMOS_CODESIGN_ID,
KOSMOS_INSTALLER_CERT, KOSMOS_NOTARY_KEY_ID, KOSMOS_NOTARY_ISSUER) still wins. Resolved values are
byte-identical to the old literals (checked), so cuts behave exactly as before.

The identity lib is a hashed INPUT of the installer pkg (lib/pkg-inputs.sh). The Installer identity
used to live in the build script, which is hashed; moved out, it would otherwise stop triggering a
rebuild, and a team switch would keep serving a pkg signed by the old team. Consequence: the pkg
input sha changes once with this merge, so the next cut rebuilds and re-notarises the pkg (minutes).

## Rejected
- Leaving the four copies and editing them all at switch time: that is the drift this prevents.
- Hashing only the resolved identity string rather than the file: the file is what a switch edits,
  and a file input keeps the existing all-or-nothing refusal (a missing input refuses).

## Tests
test-cut-sign-preflight: step 4 signs with the shared default, the preflight probes it, and no other
tools/*.sh names the team. test-pkg-input-guard: changing the identity file changes the pkg input sha
(red when that section is removed, checked in a scratch copy), and a missing identity file refuses.

## Weakest premise
That the notarytool API key is team-specific and belongs here. If the new team's notarisation uses a
keychain profile instead, the switch edits the call in build-installer-pkg.sh as well.

## Between merge and the next cut (expected, not an incident)
The pkg input sha changes with this merge (it differs from the served `Kosmos.pkg.inputs`; the exact
value moves with every edit to the lib, so it is not quoted here). A
by-hand `verify-served.sh` from a checkout on or after this merge reports `/dist/Kosmos.pkg.inputs STALE`
until the next cut. deploy-site does not run verify-served, and a cut's step 9 runs after 3c rebuilt
the pkg, so neither goes red. The next cut (staging too) rebuilds, productsigns and notarises the pkg at
3c, which needs the Installer identity and the notary .p8 on the cut box. Checked on Mortals 16:40: both
identities are in the login keychain and `kosmos-notarize` resolves. A notarytool flake at 3c aborts
that cut; re-run.

## Served-pkg signer check
verify-served matches `Developer ID Installer: <team name> (<team id>)` from the lib and ignores the
build-time KOSMOS_INSTALLER_CERT override (it can be loose or a SHA-1); if the lib cannot be read it
says so and fails. Checked against the live Kosmos.pkg: matches our team; a wrong team does not.

## At the switch (for whoever does it)
Edit tools/lib/signing-identity.sh only (team name, team id, notary key id/issuer, and
KOSMOS_NOTARY_SECRET_TARGET if the new .p8 is filed under a new target), install the new certs on
Mortals, file the new team's .p8 with /add-secret, cut, then verify the served app with `codesign -dv`
(new team) and `spctl -a -vv`. Release note: macOS may re-ask Files and Folders permissions once.
