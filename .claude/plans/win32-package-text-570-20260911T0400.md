# win32-package-text-570: the Windows zip stops saying agents do not work

Issue: #570. It follows `win32-launch-handoff-570`, and merges after it, because
the README describes that branch's behaviour: the launcher window closes by itself.

## Why

`tools/build-kosmos-windows.sh` still describes the 0.6.27-era preview. Josh asked
for this fix in the handoff (2026-09-11). Three places are wrong:
- **The header** says "AGENTS DO NOT WORK: an agent is a tmux pane". That has been
  false since slice 7c: #2661, #2672, #2714, #2722, #2728, #2731, #2737, all
  measured on the Windows box (R1-R8).
- **The header** says the by-hand update is "NOT acceptable for the thing behind a
  Download for Windows button". Josh approved it for v1 on 2026-09-10.
- **The README shipped inside the zip** tells people "AGENTS DO NOT WORK IN THIS
  BUILD" and "To stop it, close the black window". **manifest.json** says
  `agents_supported: false`.

A download whose README sends people away from the one feature that works is the
defect.

## What changes

- The header says what the package does now, and that updates are by hand with
  Josh's approval.
- The README:
  - Its first instruction is where to unpack. The folder IS the install: every
    logon task runs the app from the unpacked folder through the engine pointer,
    so a Downloads folder tidied away later breaks the next logon.
  - It explains that the launcher window closes by itself, which would otherwise
    look like a crash.
  - It says Kosmos and the agents keep running in the background and come back at
    logon.
  - It says agents need Claude Code, and the board says how to install it.
  - It explains the by-hand update: unpack over the folder, then run Kosmos.exe.
  - It says where the logon tasks are listed (Task Scheduler > Kosmos).
  - The SmartScreen and Unblock paragraphs are unchanged.
- manifest.json: `agents_supported: true`.
- `tools.build-windows-570.test.js`:
  - It pins the new manifest value.
  - It pins the old warnings ABSENT.
  - It pins the two new sentences that matter: the window closes by itself, and
    the folder is the install.

## Verified

Every claim the README makes is measured with a zip built from this branch on top
of the hand-off branch:
- the window closes by itself;
- the board keeps running in the background;
- a relaunch opens the board;
- an unpack over the running install followed by Kosmos.exe replaces the board,
  and the agents keep running.

## Weakest part

"The board says so and shows you how to install it" rests on BLOCKER 3's fix (the
card names the real installer, WINDOWS-ROADMAP.md §3c). That was not re-measured on
a box without Claude Code. This box has it, and a clean box is still owed
(capability 1).
