# worlds-comment-2874 -- correct the stale "Mac does not apply the world yet" comments

Branch: `worlds-comment-2874` (off `origin/main` at `f120a6e2`). Comment-only; no code moves.

## Why

CLAUDE.md convention 5: a comment that asserts behaviour the code does not have is the
two-derivations defect in prose. `engine/worlds.js` still says the Mac agent-side world
bootstrap is future work ("the Mac slice, PR1m"; "nothing on the Mac does yet"). That was
true when #2845 (PR1w, `a677a0b5`) landed the Windows half, but #2874
(`1b3b81b0`, world-mac-identity-1704) shipped the Mac half, so both sentences are now false.

## Evidence (verified on this branch's base)

- `bin/agent-supervisor.sh:318-339`: when `KOSMOS_WORLD` is set, the supervisor runs a
  child `node -e` that `require`s `worlds.js` and calls `w.applyAgentWorldEnv(process.env)`
  (line 324), then `export`s the three `AGENT_WORKFORCE_*` roots into its own shell
  *before* the sender-token mint (`sendertoken.js`, line 355), so the token lands in the
  world's store.
- `bin/agent-supervisor.sh:440-453`: every pane is handed `KOSMOS_WORLD` and the three roots
  explicitly with `tmux -e` (empty for the default world), because a pane does not inherit
  the supervisor's environment.
- `engine/win32anchor.js:160-180`: the Windows boot shim reads the world from field 7 of
  the task's argument line (`args[6]`, parsed by `win32argv.specFromArgv`), sets
  `KOSMOS_WORLD`, and calls `applyAgentWorldEnv` before `require(entry).main(args)` (#2845).
- `engine/launchidentity.js:27-33` already describes both platforms correctly (updated by
  #2874), so worlds.js is the one place that disagrees with it.
- `git merge-base --is-ancestor 1b3b81b0 origin/main` and `... e07ec774 origin/main` both
  true: #2874 and #2886 are on main.

## Changes (comments only)

1. `engine/worlds.js` header SCOPE block (lines 23-28). Before:
   > On Windows an agent's supervisor gets the same world through `KOSMOS_WORLD`
   > (launchidentity.js) and applies its roots with `applyAgentWorldEnv` before its first

   > which is why the Windows boot shim calls it before it loads the supervisor. The agent's
   > hooks and `kosmos` command inherit the roots it applied rather than calling it. (The Mac

   After: the Windows boot shim calls it before it loads the supervisor (#2845), and the
   Mac's `agent-supervisor.sh` calls it (in a child node) and exports the roots before its
   token mint requires `sendertoken.js` (#2874). The parenthetical is removed.
