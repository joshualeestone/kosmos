# Two nightly reds are the classic-scrollbar gutter, measured against the wrong box

**Branch:** `nightly-3973` · Card kosmos#3973 (nightly full browser-check run not green on main)

## What was wrong

Mona Lisa's triage (on the card) found three checks failing on the macOS runner by exactly 15px, and
passing on this Mac. The runner draws CLASSIC scrollbars; this Mac draws overlay ones.

I reproduced classic scrollbars on this Mac for one process only, without the global "Show scroll
bars" setting: a wrapper as Playwright's Chromium `executablePath` that appends
`-AppleShowScrollBars Always` to the real binary's argv (NSUserDefaults reads it per process), plus
dropping Playwright's headless `--hide-scrollbars`. A probe page measures 15px of scrollbar with it
and 0 without it (control: the real binary, headed, on this Mac).

Under it, two of the three reproduce exactly:

| check | overlay | classic |
|---|---|---|
| render-plus-bar-3837 P2 | pass | fail, `right: 15` (the runner's number) |
| render-boot-no-flash | pass | fail, `covers=false` (the runner's failure) |
| render-provider-combobox-1040 | pass | pass (so its runner red is something else) |

**Mechanism.** `html:not([data-layout="consolidated"])` has `scrollbar-gutter: stable` (#1309, so
pages do not shift when a scrollbar appears). On a classic-scrollbar machine, when the page does not
scroll, the browser reserves an empty 15px gutter: `html` and `body` are 1265 wide, and the Kosmos+
bar and the header end at 1265. But `document.documentElement.clientWidth` still reports 1280 there
(measured), and both checks compared against it. The boot-no-flash check's own comment says clientWidth
excludes the gutter; for a reserved-but-empty stable gutter it does not.

## Decision

Measure both checks against the ROOT's box (`document.documentElement.getBoundingClientRect().right`),
which excludes the reserved gutter. It is the same measure the page itself uses to size the gutter
(`innerWidth - root.getBoundingClientRect().width`, in the #3497 block of web/index.html).

**Rejected:**
- Changing the product to paint into the gutter. A gutter paints only the page's single canvas
  colour (the file's own tip-dimming comment, measured), and a fixed layer cannot paint it, so there
  is no CSS that makes just the top 35px navy. The options are dropping the #1309 gutter (brings the
  page shift back) or a navy gutter the full height. That is a look decision, carded separately for
  the page's owner, not something to decide inside a check fix.
- Widening the thresholds by 15px: that would pass a genuinely short bar on an overlay machine.

## Evidence

- Review round 1 asked that the new yardstick not come from the page alone: the root may leave a gap
  only as wide as a real scrollbar, measured on a scratch scroller (within 1px). Measured: with a
  classic scrollbar the gap is 15 and the scroller reads 15, whether or not the page scrolls. A CSS zoom
  on the root scales the scroller (14 at 1.1, 12 at 1.25) and is not supported; neither check zooms.

- Both checks pass under overlay and classic scrollbars with the change.
- **Red check** (scratch copy): CSS that makes the bar and the boot cover genuinely 20px short fails
  both checks under BOTH scrollbar styles.

## Also: tmux on the nightly runner

render-talk calls the real `status.snapshot()`, and on the runner it threw "we could not see what is
running on this computer"; live-connect's own FAIL line says there is no runnable tmux at
/opt/homebrew/bin/tmux. test.yml already installs tmux for exactly this (#1794: macos-latest ships
none); browser-checks-full.yml did not. This branch adds the same `brew install tmux` step.

Measured on this Mac, running render-talk directly:
- tmux unreachable: the runner's two snapshot failures, per theme (reproduced).
- a real tmux with no server (a fresh socket directory): zero snapshot failures; the check takes its
  documented recorded-card path ("no PANE-based agent card of ours was available").
- ⚠️ My first try at the second arm put the socket under the scratchpad, whose path is too long for a
  Unix socket; tmux answered "File name too long", not "no server", and the snapshot still failed. That
  read as "installing tmux does not help" until the socket path was shortened.
- With tmux on the runner, live-connect gets as far as starting a real session, and a red run exits
  without cancelling it. So live-connect now runs its own tmux server in a private socket directory and
  kills it on exit (review round 3). Measured: a session under a private TMUX_TMPDIR never appears on
  the default server, and kill-server there removes only it (the fleet's 20 sessions unchanged).
- tools/test-browser-checks-workflow.sh pins the tmux step before the checks (red-checked: removing the
  step, or moving it after the checks, both fail the test).
- Locally, render-talk's two `clock:` arms fail in BOTH arms (with and without tmux). The runner did not
  report them, so they are something about this Mac and not part of this branch.

## What this does not fix (recorded on the card)

- render-provider-combobox-1040 and render-accounts-openai: pass here even with classic scrollbars,
  so their runner reds are a different cause, not yet found.
- live-connect beyond its tmux precondition: it touches real services; whether it passes once tmux
  exists is only known from the next nightly.

## Weakest premise

That the 15px pale notch at the right end of the navy bar on a classic-scrollbar machine is an
acceptable consequence of #1309 rather than a defect. The bar reaches the edge of the page's layout,
exactly like the header row beside it; it only shows because the bar is navy and the gutter is not.
If the page's owner decides the notch must go, the check still holds: it would then assert against
whatever width the new design gives.
