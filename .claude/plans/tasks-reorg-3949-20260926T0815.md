# tasks-reorg-3949: the Tasks page reorganised (Josh 2026-09-26 08:01)

Addresses #3949. Checklist and Josh's words are on the card. Mona owns the Tasks view (#3559) and reviews the design on the PR.

## Tile mapping (item 4, posted on the card before any code)
- **Needs Your Decision** (red): an open task whose holding agent (`claimWho`) needs the person right now. That is `status.needsPerson`: a question, a trust wait, or a connection given up on. For a question it also has to name this task's project (`stateProject`), which is the project page's needsYou rule (#763, #3726). Tied cards only (`isNamedOurs`), the same gate as the project members.
- **In progress** = `working`, **Assigned but not started** = `assigned`, **Unassigned** = `nobody`, **Completed** = `closed`.
- **Built but waiting**: not drawn. No task stores it. Follow-up is #3951.

## Change
### Engine
- `tasks.taskState(task)` returns `'decision'` for an open task whose `waitingOnPerson` is true, ahead of working and assigned. The view still renders the word and never computes it.
- The `/api/tasks?view=tasks` route sets `waitingOnPerson` from the roster it already reads: the card of `claimWho(t)`, tied, `needsPerson`, and for `needs_you`, `stateProject === t.projectId`.

### Page (web/index.html)
- The left Projects rail is removed, and the main body takes the full width.
- Projects becomes the existing `tsk-projsel` dropdown, shown at every width, on one line with **Created:**, a dropdown replacing the Added-in buttons (24h / 48h / 1 week / 1 month / All).
- Search is about half as wide, with the "N open tasks across M projects" line to its right.
- Five single-label tiles with no bylines. Josh named six; Built but waiting is not drawn (see the mapping). Needs Your Decision is red, and Completed is a tile again (Josh), where #3559 had Closed only as the fold.
- The "Tap a tile..." hint is gone. Tiles still filter on tap.
- **Group by** (a dropdown, default Status) and **Sort** move under the tiles.
- The group sections keep their one-line "why", and Needs Your Decision gets its own.

## Tests
- engine: `taskState` returns decision only when open and `waitingOnPerson`, and closed wins. The route test covers the roster join (the tied gate, and a question about another project not counting).
- page: the existing Tasks view tests are updated for the new structure. Checks: no rail; `tsk-projsel` and `tsk-win` are selects on one row; the tiles' order and labels, with no `.ts` byline; Completed is a tile; the hint is gone; Group by and Sort sit after the tiles.
- Browser: before and after shots, served.

## Weakest premise
A question belongs to the AGENT and names a project, not a task. An agent holding two tasks in one project lights both. That is the same granularity as the project page's red pill.
