## Goal (what "done" looks like)

The board shows, per agent, the honest state the day-one report asked for: a plugin or connection the
person installed in their OWN provider app is "ready" there but its tools never reach THIS agent, and
there is no repair loop that would fix it. Part 2 slice 1 (#5561, merged) landed the pure decision engine
`engine/pluginreach.js` with no production caller. This slice wires that signal into a live caller and
renders it.

## What it does

- **`server.js attachPluginReach`**: attaches a per-agent `a.reach` to the `/api/status` rows, resolved
  from each row's own `runner` + `account.dir`. Evidence-gated, so a secondary-account or Codex agent with
  nothing added renders nothing (no false warning on a healthy setup).
- **`engine/pluginreach.js`**: the evidence gate (`agentPluginReach` / `gateOnEvidence`) reporting the
  `missing` ids; `_parsedFile` parse cache (one bounded entry per path, mtime compared) so the person's
  files are read at most once per poll.
- **`web/index.html paintDetailState`**: the `#d-pluginreach` detail-page notice, shown only on
  `reach.reaches === false`, by reason, guarded with `'reach' in a` (the sibling #5668/#5820 pattern).
- **`docs/browser-checks/render-pluginreach-5309.js`**: the gated browser-check (hermetic file://).

## Key decisions

- **Per-project mcpServers scope (Liu Kang's ruling, recorded Decided on the card):** count top-level
  mcpServers PLUS only the `projects` entry keyed exactly by this agent's own working folder (canonicalized
  via `trust.canonicalOnDisk`); unknown folder falls back to top-level only (the safe, missed direction).
- **Lazy folder resolution:** the agent's working folder is a thunk resolved only on the separate-account
  path, so its syscalls never run for a reaching or other-runner agent each poll.
- **Fail-safe posture:** every unreadable/ambiguous input resolves to `reaches: null`; the UI fires only on
  `reaches === false`. A missed notice is always preferred over a false one.

## Deliberately deferred (with reasons)

- `accounts.configFile` vs the inline `.claude.json` derivation: `attachPluginReach` is an injectable seam
  (opts.personHome/opts.fs) and `configFile` reads the real `homeDir()`, so routing through it would break
  the test contract; the inline derivations are each correct for the branch they handle.
- The agent `.claude.json` location rule: matches `accounts.configFile`'s non-default branch; the
  ENOENT-to-empty path is correct behaviour for a separate account that configured nothing.
- The `~/.codex/plugins` non-empty heuristic: measured on this box, `~/.codex` has no `plugins` dir at all,
  and a missing dir is treated as not-present, so it does not false-fire for a real Codex home.
