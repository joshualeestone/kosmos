# quotable-emits-1864 -- make catch/launch failure emits quotable + scan them in the guard

Card: kosmos#1864 (split off #1836/#1867). Two failure emit SHAPES in
docs/browser-checks/*.js print lines the release-gate reason grep
(`^\s*(FAIL|✖)|Error|Timeout|REFUS|refus`, tools/browser-checks.sh:619) cannot
quote, so a red from either reports "(no FAIL or error line in its output)":
1. top-level crash catch with a non-matching string ("HARNESS FAILED",
   "render-boot-no-flash ERROR:" -- uppercase ERROR vs case-sensitive Error,
   "threw: ").
2. browser-launch catch ("<name>: could not start a browser") -- no marker.

#1867 (branch `reasongrep-guard-1836`, PR #1867) lifts the reason-grep guard
(`browser-checks-reason-grep.test.js`) that scans the FINDING-emit shapes and
**names this catch/launch shape as out-of-scope in its header**. #1864 = fix these
emits + EXTEND that guard to scan the catch/launch shapes (the card's "done when":
"widen the reason-grep guard to also scan catch-block/top-level-error emits").

## Part 1 -- the 7 emit fixes (DONE, verified, committed 0a465be2)

Prefixed each with `FAIL  ` at the print site (the #1836 / live-connect
convention) so the printed LINE matches `^\s*(FAIL|✖)`:
- contrast.js:172, named-controls.js:180, regress-a-night.js:316 ("HARNESS FAILED")
- render-boot-no-flash.js:97 ("ERROR:" -> "FAIL  render-boot-no-flash crashed:")
- render-grid-card-width.js:169 ("threw: ")
- render-busy-line.js:37, render-memory-words.js:81 ("could not start a browser")

live-connect already uses `console.error('FAIL', m)` -> quotable, not touched.

**Control (measured against the exact gate pattern):** all 7 OLD printed lines are
unquotable; all 7 NEW `FAIL`-prefixed lines quote. The control message contains no
Error/Timeout, so the FAIL prefix is what does it (per the anchored-pattern
discipline: test the printed line, not the pushed string). `run_one` captures with
`2>&1 | tee`, so these console.error (stderr) lines do reach the grep.
