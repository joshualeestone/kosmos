## Decisions and known limits at a glance (review 26)
The sections further down keep the reasoning and its review history; this is the current list.
- **Agents:** Restart=always, RestartSec=10, KillMode=process (the tmux server is shared). **Board:** Restart=on-failure,
  ConditionPathExists=!board.stopped; a clean board-run exit (another board holds the port) is not retried.
- **Unit folder:** always ~/.config/systemd/user (systemd's own default), never the board's XDG_CONFIG_HOME.
- **Sandboxed boards** (AGENT_WORKFORCE_LAUNCH, no deliberate AGENT_WORKFORCE_SYSTEMD_DIR) never run systemctl.
- **Linger** is turned on and read back (logind's file as a fallback); it stays on by design; off is said plainly.
- **Minimum systemd 240** (StandardOutput=append:). /bin/bash is assumed (NixOS/Guix unsupported).
- **"Not loaded"** is exit 5 or systemd's English wording. A failed unit does not hold its name.
- **Not in this piece:** the installer (piece D: board unit, version check, kosmos start/stop live); the board listings
  that read only .plist files (display parity, follow-up card); one Windows-path change, stated below.

## Goal (from #4916)
An unmodified Kosmos board on a plain Linux server keeps one always-on Claude agent running, and the agent survives
a kill. This piece is the keep-alive: what launchd does on a Mac, systemd user units (with linger) do on Linux.

## What the change does
- `engine/linuxjob.js`: one systemd user unit per agent (`kosmos-agent-<session>.service` in
  `~/.config/systemd/user/`), running `bin/agent-supervisor.sh` with `Restart=always`, `RestartSec=10` (see Decided).
- `engine/linuxboard.js`: the board's unit (`kosmos-board.service`), with
  `ConditionPathExists=!$KOSMOS_HOME/board.stopped` so a stop stays stopped, and support for the board
  restarting itself.
- `engine/create.js` and `engine/remove.js`: create, adopt, repair, roll back, stop, disable, enable, remove and
  restart reach the Linux units where the Mac reaches launchd.
- `engine/boardrestart.js`: a Linux branch for the board restarting itself.
- `install/kosmos`: `cmd_start`, `cmd_stop` and `_kosmos_board_supervised` know the systemd unit.
- Tests:
  - unit tests (linuxjob, linuxboard, boardrestart.linux-4918);
  - a shell test of the installer's supervised check;
  - a live systemd test that runs in its own GitHub workflow on `ubuntu-latest`.

## Must not change
Mac and Windows behaviour. Every Linux branch is behind a platform check, and the Mac and Windows suites stay
green.

## Rejected
A system-wide (root) unit: Kosmos runs as the person, and their agents run under their own login.

## Weakest premise
That `loginctl enable-linger` is available and allowed on the target machine. Without linger, user units stop when
the last session ends, so an agent would not survive a logout or a reboot. The reboot test waits on a Hetzner
machine (#4916 rules); CI covers start, kill and restart.

## Decided in review
- **The board's unit is installed by piece D, not here (review 1).** On a Mac the board's keep-alive job is put
  in place at install time, and installing Kosmos on plain Linux is piece D (#4920, the setup one-liner, also
  Ice Cream Kitty's). This piece ships the unit, its self-restart and the installer's supervised check;
  `installBoard` gets its production caller in D. Until D merges, a Linux board is not kept alive by systemd.
- **KillMode=process on both units.** The tmux server is shared by every agent, and it may have been started from
  any agent unit's cgroup. A stop kills the supervisor only, as launchd does for the agent job. For the BOARD it differs from the Mac (review
  17): launchd kills the board's process group, while KillMode=process leaves children the board started
  undetached running after a stop. That is accepted for one rule across both units; a board child that must die
  with it should be started detached.
- **Unit names are systemd-escaped** (a named world's "+" becomes "\x2b"). The tmux session name is unchanged.
- **Unsafe unit values are refused, not escaped:** control characters, quote, backslash, `$` and `%`. The model
  must match the same id rule that create uses.
- **A test process never reaches real systemd:** the live-execution gate's test half. Production is unchanged,
  so a missed opt-in cannot silently stop agents from starting.
- **Linger is read back and said:** when it is off, the person is told the agent stops at logout.
- **The board restarts on failure, not always (measured on GitHub's ubuntu runner, 10-06).** systemd's automatic
  restart does not re-check `ConditionPathExists`, and board-run exits 0 when board.stopped is there, so
  `Restart=always` restarted a stopped board every 5 seconds (the live check saw ConditionResult=yes after a crash
  with the marker in place). With `Restart=on-failure`:
  - a crash or kill -9 is restarted;
  - a clean exit (stopped, or deferring to a board already on the port) is not;
  - `kosmos stop`'s SIGTERM counts as clean.
  The Condition still keeps a stopped board from starting at boot.
- **Covered elsewhere (review 5):** the installer's `kosmos start`/`stop` against real systemd, and the board's
  self-restart live. D's workflow (#4920) installs, starts, stops and uninstalls on ubuntu-latest once setup.sh
  calls this piece's `installBoard`. Unit tests cover the restart decision (MainPID against the process).
- **A world switch on Linux asks systemd** (`is-enabled`) whether each agent is switched on. The launchctl
  question had no answer, so every agent read as unknown and none was paused.
- **A sandboxed board (AGENT_WORKFORCE_LAUNCH) keeps its units in the sandbox**, and the unit's HOME is
  create.homeDir(), as on the Mac.
- **Every systemctl call in remove.js's Linux arm goes through remove.js's own run()** (review 6), as the Mac's
  launchctl does: setRunner, dry run and the live gate hold. The same applies to create's name-taken check. linuxjob's own
  runner and remove.js's Linux arm give systemctl 30 s; create.js and delete-leftover.js keep their run()'s 20 s.
  Both cover a stop, which waits on the supervisor's sleep of up to 10 s.
- **Follow-up, not in this piece (review 6):** `create.disabledJobsResult` and `runningJobs` still ask launchctl,
  so on Linux:
  - a hand-disabled agent is not shown as switched off;
  - the "supervisor alive but board says not running" probe (#668) does nothing.
  - (review 17) three listings of Kosmos-created agents read only `.plist` files in create.AGENTS_DIR:
    createdroster.js:115 (the board's agents with no live pane), status.createdKeys() and register's stray-job
    sweep (register.js:257). On Linux a stopped or crash-looping agent drops off the board, and its Restart
    button with it.
  This is display parity, not keep-alive correctness. Linux had no jobs before this branch, so it is not a
  regression. It goes on its own card after B merges.
- **Live linger and the real board-run** are exercised by D's workflow, which installs with the real setup.sh and
  runs the real `kosmos` (#4920).
- **create's systemd calls go through create's own run(), and a thrown exit becomes a result (review 7).**
  create.js's run() throws on a non-zero exit, and `systemctl is-active` answers "inactive" with exit 3, so
  iteration 6's routing crashed the first agent on every Linux board. `linuxRun` catches it. The test's fake
  throws exactly as execFileSync does; the earlier fake returned { ok:false }, a shape the real runner never
  produces, and that is what hid the crash.
- **Agent restarts (reviews 7, 9, 11, 13): a constant RestartSec=10.** The Mac's ThrottleInterval 30 is a minimum gap
  between spawns, which systemd cannot express. A growing delay (RestartSteps) keys on a counter that only an explicit
  start clears, so it could pin a long-lived agent at the maximum. A stop's exit 143 counts as success
  (SuccessExitStatus).
- **A name systemd still runs with no unit file gets the command that frees it** (systemctl --user stop),
  because delete-leftover finds nothing to delete in that case.
- **Register's job survey and the status reader ask for the systemd unit on Linux (review 11)**, never a plist.
  Before this, the register screen said no Linux agent comes back after a restart.
- **rewriteAgentJob writes the unit only (review 11)**, as the Mac writes the plist. The restart that applies a
  change reloads systemd first.
- **A clean board-run exit is not retried (review 12, a known limit).** Under Restart=on-failure, board-run exits
  0 when another board holds the port, and the unit then stays down. On Linux the board is started only through
  systemd (piece D's installer never starts a nohup board beside the unit). `kosmos start` on a supervised board
  runs `systemctl restart`, which recovers it. launchd's KeepAlive would keep retrying on its throttle; systemd
  does not after a clean exit.
- **installBoard ensures linger and reports it (review 12)**, as the agent paths do. D's installer says so when it
  is off.
- **systemctl finds the user manager without XDG_RUNTIME_DIR (review 12):** /run/user/<uid> when it exists, for a
  board started from cron or after its login session ended.
- **A board that finds the port taken exits 0 and is not retried (review 14, known limit, as review 12).** When a
  board process dies, the kernel closes its listening socket at once, so a crash does not leave a listener behind
  to trip this. Changing board-run's exit code would also change the Mac path, which test-board-foreground-2956 pins.
- **One Windows-path change, stated (review 18):** creation's launchctl name-taken probe now runs only off win32. On
  Windows it always threw and was read as "not loaded", so the result is the same with no wasted call.
- **Minimum systemd 240 (review 20).** The units use StandardOutput=append:. Ubuntu 20.04 ships 245 and Debian 11
  ships 247; older systemd (CentOS 7, Ubuntu 18.04) rejects the unit. A version check belongs in piece D's installer.
- **"Not loaded" is systemctl's exit 5 or its English wording (review 20)**, so a non-English locale still reads a
  never-loaded unit as stopped.
- **What remains untested live after this piece:** `kosmos start`/`stop` through the real installer, and linger
  off. The workflow is path-filtered and cannot be a required check. Piece D's workflow covers the installer.
- **`kosmos stop` with no live board pid (review 22):** on Linux the systemctl stop runs only when a pid is found. A
  board waiting out RestartSec then starts once, sees board.stopped and exits 0, so the stop holds; the unit is left
  inactive rather than cleaned up. The installer is piece D's, which owns that branch.
- **A unit systemd holds as `failed` is not "name taken" (review 24, decided).** A re-create reloads, enables and
  starts it, which replaces a failed unit correctly; refusing would block a legitimate re-create. The Mac refuses a
  loaded job only because launchd cannot bootstrap over one.
- **Linger is turned on by design and stays on (review 26, decided).** Agents must survive logout, which is the point
  of Kosmos Cloud; a failed first create leaves it on, harmless without enabled units. Piece D's installer states it
  at install time. The create step "kept it running with nobody logged in" reports the result.
- **A sandboxed board's create fails with the sandbox's reason in the sentence (review 26, decided):** "could not start
  it (a sandboxed board does not manage real systemd units)". The refusal itself is review 21's.
- **A dangling default.target.wants link after a hand-deleted unit file (review 26):** systemd ignores it; remove
  reports ok, as the unit is gone.
- **A repaired unit takes the current environment (review 30, parity):** readUnitJob reads back only the config
  folder, so KOSMOS_PORT/KOSMOS_WORLD/TMUX_TMPDIR come from the repairing board, as the Mac's readPlistJob does.
- **Follow-up (review 30):** delete-leftover's Trash is ~/.Trash on every platform. On Linux that is not the
  desktop Trash (~/.local/share/Trash), so a folder-only Linux leftover "goes to the Trash" somewhere a person may not
  look. Pre-existing on main, not this branch; a folder with a unit is deleted for good and says why.
- **delete-leftover, review 31 (REVERSES review 1's "never the Trash with a unit"):** a unit does not decide the
  folder's fate. The folder goes to the Trash when it can (as a folder-only Linux leftover already does), the unit is
  removed by systemd, and the sentence says both. With no Trash and a unit systemd will not remove, the folder is
  kept and the delete is PARTIAL, never "files gone, unit still there".
- **A leftover unit with no folder (review 31):** the Linux refusal gives the command that frees the name
  (`systemctl --user disable --now '<unit>'`, then delete the file), since no page lists a leftover unit yet.
- **A delete that keeps the folder for an unremovable unit stops there (review 35, reverses review 34's deferral):**
  REFUSED: no files deleted, and the removal record, tokens and crash history stay, so the person can retry it. The
  community standing was already reset (#5000 runs first and cannot be undone), and the sentence says so (review 37).
- **An explicit AGENT_WORKFORCE_TMUX_BIN is trusted by the Linux tmux check (review 34):** main already lets an
  explicit choice win over the bundled and system tmux.
