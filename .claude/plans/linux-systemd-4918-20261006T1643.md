## Goal (from #4916)
An unmodified Kosmos board on a plain Linux server keeps one always-on Claude agent running, and the agent survives
a kill. This piece is the keep-alive: what launchd does on a Mac, systemd user units (with linger) do on Linux.

## What the change does
- `engine/linuxjob.js`: one systemd user unit per agent (`kosmos-agent-<session>.service` in
  `~/.config/systemd/user/`), running `bin/agent-supervisor.sh` with `Restart=always`, `RestartSec=5`.
- `engine/linuxboard.js`: the board's unit (`kosmos-board.service`), with
  `ConditionPathExists=!$KOSMOS_HOME/board.stopped` so a stop stays stopped, and support for the board
  restarting itself.
- `engine/create.js` and `engine/remove.js`: create, adopt, repair, roll back, stop, disable, enable, remove and
  restart reach the Linux units where the Mac reaches launchd.
- `engine/boardrestart.js`: a Linux branch for the board restarting itself.
- `install/kosmos`: `cmd_start`, `cmd_stop` and `_kosmos_board_supervised` know the systemd unit.
- Tests:
  - unit tests (linuxjob, linuxboard, boardrestart.linux-4918);
  - a shell test of the installer's supervised check;
  - a live systemd test that runs in its own GitHub workflow on `ubuntu-latest`.

## Must not change
Mac and Windows behaviour. Every Linux branch is behind a platform check, and the Mac and Windows suites stay
green.

## Rejected
A system-wide (root) unit: Kosmos runs as the person, and their agents run under their own login.

## Weakest premise
That `loginctl enable-linger` is available and allowed on the target machine. Without linger, user units stop when
the last session ends, so an agent would not survive a logout or a reboot. The reboot test waits on a Hetzner
machine (#4916 rules); CI covers start, kill and restart.

## Decided in review
- **The board's unit is installed by piece D, not here (review 1).** On a Mac the board's keep-alive job is put
  in place at install time, and installing Kosmos on plain Linux is piece D (#4920, the setup one-liner, also
  Ice Cream Kitty's). This piece ships the unit, its self-restart and the installer's supervised check;
  `installBoard` gets its production caller in D. Until D merges, a Linux board is not kept alive by systemd.
- **KillMode=process on both units.** The tmux server is shared by every agent, and it may have been started from
  any agent unit's cgroup. A stop kills the supervisor only, which is the Mac's launchd behaviour too.
- **Unit names are systemd-escaped** (a named world's "+" becomes "\x2b"). The tmux session name is unchanged.
- **Unsafe unit values are refused, not escaped:** control characters, quote, backslash, `$` and `%`. The model
  must match the same id rule that create uses.
- **A test process never reaches real systemd:** the live-execution gate's test half. Production is unchanged,
  so a missed opt-in cannot silently stop agents from starting.
- **Linger is read back and said:** when it is off, the person is told the agent stops at logout.
- **The board restarts on failure, not always (measured on GitHub's ubuntu runner, 10-06).** systemd's automatic
  restart does not re-check `ConditionPathExists`, and board-run exits 0 when board.stopped is there, so
  `Restart=always` restarted a stopped board every 5 seconds (the live check saw ConditionResult=yes after a crash
  with the marker in place). With `Restart=on-failure`:
  - a crash or kill -9 is restarted;
  - a clean exit (stopped, or deferring to a board already on the port) is not;
  - `kosmos stop`'s SIGTERM counts as clean.
  The Condition still keeps a stopped board from starting at boot.
