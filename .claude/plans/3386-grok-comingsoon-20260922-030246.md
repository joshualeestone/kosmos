Branch: `3386-grok-comingsoon`  ·  Repo: joshualeestone/kosmos  ·  Owner: Mona Lisa

## What finished looks like
On the first-run setup model screen (fr-pane-5), xAI Grok appears as a "coming soon" tile, grouped
with Gemini (the other connectable-but-not-yet cloud provider) before the "Runs on this computer"
(on-your-computer / local models) tier. It reuses the app's existing initial-letter "X" chip rather
than a new brand asset.

## Measured reality vs the card (bulletin: measure whether a card is still live)
The card says "reuse the existing X logo already used in Settings (Settings already shows xAI Grok
with the X logo)." Measured against origin/main:
- There is NO xAI/Grok vendor SVG anywhere in web/index.html. `PROVIDER_MARK_KEY` explicitly maps
  `xai -> null`, and `providerMarkNode` falls back to an initial-letter chip for Grok "never a
  wrong-brand lookalike" (a deliberate policy).
- That fallback chip is the first letter of the label uppercased -> for "xAI Grok" it is "X". So the
  "X logo" the card means IS the app's initial-letter chip, and "no new asset" is satisfied by
  reusing that chip treatment, not by finding a nonexistent SVG.
- Grok already existed as a `<option ... disabled>xAI Grok - coming soon</option>` in the provider
  `<select>` dropdowns, but NOT as a tile on the first-run model list (which had Gemini, Llama, Qwen,
  Mistral, DeepSeek, GLM, Kimi, MiniMax). This card adds the missing first-run tile.

## Decision + weakest premise (per night-shift: decide, document, Josh can undo)
- Decision: render Grok with the initial-letter "X" chip (the app's established Grok treatment),
  not a new xAI-X brand SVG. Rejected the SVG because (a) the card said no new asset, (b) the app's
  own policy is "no wrong-brand lookalike", and (c) the chip already yields "X" for xAI Grok, which
  is what the card asked to show.
- Weakest premise: that a bare "X" chip reads clearly as xAI/Grok to a first-time user. Mitigation:
  the tile also carries the words "Grok" + "xAI" + "Coming soon", so the chip is decorative and the
  provider is named in text. If Josh wants a real xAI-X SVG later, that is a small follow-up (add a
  vendor mark + map `xai` in PROVIDER_MARK_KEY so both the combobox and this tile use it).
- Reversible: yes, static markup + one CSS rule, no behavior change (the tile is `disabled`/coming
  soon; nothing becomes selectable).
