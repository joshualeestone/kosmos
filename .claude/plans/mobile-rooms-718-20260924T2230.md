## Review iteration 1 (what changed, and what is measured vs reasoned)
- Sticky hover: phones keep :hover on the last tapped element, so the base .msg:hover reveal
  would open the bar on any tap and stop the second tap closing it. In (hover: none) the room
  now reveals only on .rxn-show or focus. REASONED from browser behaviour: Playwright's touch
  emulation does not reproduce sticky hover, so the check cannot see the defect or the fix;
  it measures the toggle itself (open, close, a file tap does not toggle, a mouse click
  toggles nothing).
- The bar (about 156px on a phone) is pinned to an agent bubble's LEFT, so it cannot cross
  the thread's left edge beside a short bubble; top -12px so the first post's bar is not cut.
- A picked reaction or a tap outside the room closes an open bar.
- The tap listener now sits before the data-open-agent listener, which asks to stay last.
- New arms in render-room-msgbox-2806: file name inside the ROOM (not the bubble: without
  the fix both grow together; control: card left -379 fails it), touch toggle open/close,
  file tap, mouse control, operator tail mask. Control: no toggle fails the touch arm.
- web.room-phone-718.test.js pins conversation-first and the touch rules. Control: order 0
  fails it.

## After convergence: the long-file-name fix, corrected (Scorpion m605)
The file-name rule (.msg-b .att-name line clamp) was not the real fix: the person's own
bubble is content-sized in a right-aligned column, so a one-line name set its width. The
fix is to cap that bubble at its row: #pj-room .msg.you .msg-bd { max-width: min(78ch,
100%) }. Measured: with the cap alone, the 120-character name stays inside the room (the
2806 phone arm passes; with neither rule it fails at card left -379). The name keeps its
ellipsis. Scorpion made the same change scoped to the DM in #3687 and dropped his name rule,
so there is no shared rule any more and nothing for either of us to remove on merge.
