# mention-blue-2922 -- highlight @agent mentions in bright blue

Card: kosmos#2922 (label: josh-review). Josh's 6.59 QA, verbatim:
"If I mention an agent in a project dialog and I use the @name, let's highlight it with our bright
blue color so that it stands out both in the message and mostly in the input whenever I'm inputting
it in. If I @ and type a name and keep typing and it recognizes that it is an agent name mention,
let's highlight it blue so I know that it is going to be a flag to that agent."

## Two behaviors (Josh described both)
1. **In the posted message** -- highlight a valid @name (an agent ON this project) bright blue.
2. **Live in the input** -- highlight it blue as the user types a recognized name ("mostly in the
   input").

## What this branch delivers: PART 1 (the posted-message highlight)
When a project-room post names `@<agent>` where `<agent>` is a key (sessionName) of an agent on that
project, the name renders in bright blue, bold. A name that matches nobody stays plain, so the color
means "this will flag a real agent here."

Implementation (scoped, minimal-risk):
- Threaded a new optional `agentNames` Set through the ROOM render path only:
  `pjRoomBody` (has the project `p`, derives the agent-key Set the same way `mentionCandidates`
  does) -> `pjBody` -> `pjProse` -> `pjTableHtml` -> `pjRichSpans`. The dialogue surfaces (pjRich,
  .dm-b, .pj-msg-text) pass no `agentNames`, so this is scoped to the project room per Josh's words
  ("in a project dialog"), and their output is byte-identical to before.
- In `pjRichSpans`' whitespace-token pass (where URLs/citation chips are already held atomically), a
  token whose core is `@<key>` and whose key is in `agentNames` is held as
  `<span class="pjmention">@key</span>`, so it survives the emphasis pass (`**@mona**` bolds the
  whole chip). Trailing punctuation peels off (`@mona!` -> chip + `!`).
- Colour: a new theme-aware token `--pj-mention` (#0a58d8 on light, #5aa2ff on dark) -- no single
  blue clears WCAG AA on both the near-white and near-black grounds. Added to the light `:root` and
  the `@media dark` block AND its generated `:root[data-theme="dark"]` twin (identical text, so the
  forced-theme parity test holds). `.pjmention { color: var(--pj-mention); font-weight: 600; }`.
- Verified via pw-runtime: valid @names -> blue span (#0a58d8 light), invalid -> plain, dialogue
  path (no set) -> plain, trailing punct peeled; no JS errors; screenshot inspected. Node suite green
  (forced-theme parity + label-contrast pass).

## PART 2 (live-input highlight) -- DEFERRED with a concrete plan, see the card comment
The composer `#pj-post` is a `<textarea>` (auto-grows via pjGrowComposer, in a flex `.composerbox`).
A textarea cannot style part of its own text, so the live highlight needs the standard
"highlight-within-textarea" backdrop overlay: a div behind a transparent-text textarea, mirroring the
text with a blue span on the valid `@mention`, synced on input/scroll/resize with identical
font/padding/wrap, re-evaluating valid mentions (via `mentionCandidates`) on each input. It is
alignment-sensitive on a core surface and interacts with the existing mention-autocomplete
(`#pj-mention`) and pjGrowComposer, so it is best built as a focused slice with iterative browser
verification rather than squeezed in. Documented on the card with the approach; ships as a follow-up.

## Weakest premise (named)
That "in a project dialog" means the project ROOM (pjRoomBody), not the agent DM. Josh's phrasing
("project dialog", "flag to that agent") reads as the room; the DM path is a one-line extension
(pass an agentNames set to pjRich) if he wants it there too. Reversible; josh-review.
