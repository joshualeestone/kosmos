# app-reload-965: Cmd-R reloads the native Kosmos window (kosmos#965, native-shell half)

## Why

Josh, 2026-08-26 07:23 CDT, with a screenshot: the native app window (the #677 app shell)
has no way to refresh except relaunching the whole app. Cmd-R does nothing, and there is
no browser chrome to fall back to. "Sometimes I feel like I'm stuck in a spot and I need a
refresh to see something else or I'm stuck on a modal or something."

Issue kosmos#965 splits the work: the toolbar refresh icon is Mona Lisa's (web/index.html);
the keyboard/menu binding in the native shell is this branch. Either half alone satisfies
the issue per its "Done when"; this half is the one that works even when the page itself is
too wedged to show a toolbar.

## What

All changes in `native-app/main.swift`.

1. **A View menu with a Reload item, keyEquivalent "r"** (default modifier Cmd), inserted
   after the Edit menu, matching the standard macOS menu order (App, Edit, View). Action:
   a new `@objc func reloadBoard(_:)` on AppDelegate.

2. **`reloadBoard` picks the right kind of reload:**
   - If the web view has a committed page AND the last navigation did not fail:
     `webView.reload()`. The plain case: refresh the board page, clear any stuck page
     modal or stale screen.
   - Otherwise (never loaded, or the last navigation failed): re-run `loadBoard()`.
     `webView.reload()` on a nil/failed page is a no-op or repeats the failure without
     retrying the board; `loadBoard()` re-runs the full resolve-and-start path, so if the
     board process itself died, Cmd-R restarts it and reconnects. This is the actual
     "stuck screen" Josh described: the recovery is the board start, not just the page
     fetch.

3. **Track load failure state** for the decision above: a `lastLoadFailed` flag set in the
   existing `didFail` / `didFailProvisionalNavigation` delegate methods, cleared in
   `didFinish` and at the top of each `loadBoard()` attempt. The delegate methods already
   exist for logging; this adds one assignment to each, no new delegate surface.

4. **`logLine` instrumentation** on both reload branches, same style as every other
   decision point in the file, so a headed test (and any future field report) can prove
   which branch ran from the log alone.

5. **Test seam, matching the file's established env-var seam pattern**
   (`KOSMOS_APP_TEST_HOME`, `KOSMOS_APP_CONFIG` precedents, all documented testing-only):
   `KOSMOS_APP_TEST_RELOAD_AFTER=<seconds>` fires `reloadBoard` once via a timer after N
   seconds. This exists so the reload decision logic is drivable end to end without
   Accessibility permissions for synthetic keystrokes. The Cmd-R keyEquivalent itself is
   declarative AppKit wiring, verified once by hand in the headed check.

## Out of scope

- The toolbar refresh icon (Mona Lisa, web/index.html half of #965).
- Cmd-Shift-R / reload-ignoring-cache. Not asked for; add later if cache staleness ever
  shows up as a real symptom.
- Native NSAlert dialogs are app-modal and are not (and should not be) dismissed by
  reload; Josh's "stuck on a modal" reads as page-level modals, which a reload clears.

## Done when

1. `swiftc` compiles the file clean and `--kosmos-app-selftest` still passes.
2. Headed check A (happy path): app launched with `KOSMOS_URL` at a live local test
   server; reload fires; log shows the `webView.reload()` branch and a second
   `PAGE LOADED` line.
3. Headed check B (stuck path): app launched with `KOSMOS_URL` at a dead port; initial
   load fails (log: `PROVISIONAL LOAD FAILED`); server then brought up; reload fires; log
   shows the `loadBoard()` re-run branch and a `PAGE LOADED` line, proving Cmd-R recovers
   a window that started against a dead board.
4. Headed check C (the actual key): with the app frontmost, physical/scripted Cmd-R
   triggers the same path as check A, verified once by hand from the log. If scripted
   keystrokes are blocked by Accessibility permissions, this check is performed by the
   operator or deferred to the release walk, and the plan says so honestly rather than
   claiming it.
5. Full repo suite still green (`yarn test` — the shell/js tests do not touch
   main.swift, so this is a regression guard, not the proof).
6. Challenge-loop convergence + proof file, then PR per house convention.
