# buildmark-2658 — uniform "beta build v<version>" build marker (option a)

## Objective (Josh, #2658)
Show the version badge as a uniform "beta build v<version>" and drop the staging/prod visible
indicator. Low priority per Josh; a reversible UI call he can override on the card.

## Design decision (Baron, who owns #2066 — the staging-loud marker)
Baron picked **option (a)**: uniform VISIBLE marker for every channel, and keep the channel tell in
the hover title only (it was already there). Rationale: the staging safety signal survives via the
hover title + the /api/accounts channel metadata (#2036), and staging is opt-in while prod is always
promoted+verified, so no constantly-visible staging indicator is needed. (Options (b) subtle visible
tell and (c) full drop incl. hover were the alternatives; (a) won.)

## Change
`web/index.html`, `paintBuildMark(version, sourceChannel)`: the visible marker branched
staging → loud `STAGING v<version>` badge (class `staging`, a `.bm-v` span) vs prod → plain
`v<version>`. Replaced that branch with ONE uniform line: `el.className = ''; el.textContent =
'beta build v' + shown;` (textContent, so the version is escaped by construction). The hover
`title` (which already names the channel: "Kosmos v… · staging/prod · port …") is UNCHANGED — that
is where the channel tell now lives. The now-orphaned `.staging` / `.bm-v` CSS and the stale #2066
`paintBuildMark` docblock were removed/updated in the challenge-loop iteration-1 pass, so the whole
loud-badge apparatus goes with option (a).
