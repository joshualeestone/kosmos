# orgchart-keys-4560: read org chart pictures and PDFs with a key-connected OpenAI, Gemini or Grok (#4560)

Liu Kang m3675: follow-up to #4598 (#4559). The plan was posted on #4560 (issuecomment-5900702071) before building.
It has the provider table: endpoint, model id, inline file shape, JSON-schema field, `store`, where the answer is.
Every fact is from the provider's current docs, fetched raw on 2026-09-29 and quoted there.

Done means: with only an OpenAI, Gemini or Grok KEY connected, New Agent > Upload an org chart reads the synthetic
chart.png and chart.pdf into the same preview #4559 gives with Claude. The consent line names that provider and
account. Stub-server tests prove the request carries the file inline, the documented model and JSON schema,
`store: false` and no tool field anywhere, and that the key is only in its header and never returned or logged.

Choice (Liu Kang): Claude when this computer can run it; otherwise the first key-connected account in Settings order
(OpenAI, Gemini, Grok; default first). ChatGPT, Antigravity and Grok subscription sign-ins stay out of scope.

Rulings during the build (Liu Kang):
- m3686: every provider keeps what is sent even with store:false (OpenAI up to 30 days, Google 55, xAI 30, sources on
  #4560, issuecomment-5900796804), so the consent box says what the reading provider keeps, and that a key is billed
  per request ("billed to that key", not "using your plan").
- m3688: Gemini is OFF for org charts in v1 (Google's terms say not to send personal information on a free key, and a
  free key cannot be told from a paid one). One switch (orgchartkeys ENABLED_DEFAULT); a Gemini-only person is told
  why. Its request shape stays tested for the day it is switched on.
- Consent is tied to the reader: the needsConsent answer carries an opaque reader id, the page sends it back, and a
  send whose reader changed (an account added while the box was open) is refused with 409.

Refused before the consent, as what to do instead: Grok and a PDF (xAI takes a PDF only by URL or an uploaded file,
which turns on a document-search tool); Grok and WebP or GIF (xAI lists jpg and png); Gemini and GIF (its guide
omits GIF though its API spec lists it).

Weakest part: the request shapes are verified from docs and a stub server, not a real call (no key spend). The first
real read with each provider is a QA item with exact steps, as #4559's single-account read was. Second: gpt-6-astra,
gemini-3.8-flash and grok-4.7 are pinned; a provider retiring one turns reads into the "cannot use <model>" sentence
until the id is updated.
