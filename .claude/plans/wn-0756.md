# wn-0756: What's New for 0.7.56

The cut of 0.7.56 to staging (gap alarm, #1050: main 52 past staging) needs its What's New in `web/whats-new.json`,
built from the pool by `tools/whats-new-pool.js build 0.7.56` (prod is 0.7.54, so the pool's lastProd is current and
nothing new is marked shown).

## The change
- Pool (`release/whats-new-pool.json`): one new item for #6330, merged today and never given an entry:
  "Marking a task built tells the next agent" (rank 3, since 0.7.56): "An agent's built note is now typed to the
  task's other assignees and to whoever holds the task above it, so nobody has to check."
- `web/whats-new.json`, built: the top five pending by rank. Prod users (0.7.54) have not seen 0.7.55's, so the two
  pairing highlights (ranks 1 and 1.6) lead, then "Quiet projects stop flagging you" (2.5), the new #6330 item (3) and
  "A team map for each project" (4).

## Decided
- **Rank 3 for #6330**: it changes what every agent sees on a task handoff, which is more than the team map (a view)
  and less than the pairing fix the release exists for. It displaces "Agents are told how to finish a task" (11.5),
  which stays pending for a later build.
- **"built"**, not "finished" or "done": it is the app's own word for the mark (`kosmos task built`, the "Built but
  waiting" tile).

## Weakest premise
That "whoever holds the task above it" is clear to a person who has not used subtasks. It is the shortest true phrase;
the precise rule (the nearest held task, unless a closed one comes first) is in the agents' instructions, not here.
