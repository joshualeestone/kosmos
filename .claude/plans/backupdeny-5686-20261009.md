Card: #5686 (measured while checking its weakest premise; comment 6082194329). E0.6 (#5535) promises "never credentials".

Already denied before this change: `board.token`, `tls.key`, `signin-device.key`, `secrets/`, `win32-channel/*.key`.

## Change
1. Eight DENY rules in engine/backupscan.js for the stores above, each holding under a world prefix
   (`worlds/<id>/Kosmos/...`) and at the root. Review 5: each FILE rule matches the store's name ANYWHERE in the file
   name, because the content scan stores several of these as they are (measured: mac_key, phone-notify.json, a
   keys.json sample) and copies of them come in shapes no ending list can close (`.mac_key.tmp-9`,
   `board.token.4711.new`, `mac_key copy`, `#mac_key#`). Cost: a person's file whose name contains one of these exact
   store names is skipped.
2. `tempOrigins`, for credentials that are NOT Kosmos's own: a COPY-SHAPED name (COPY_SHAPED: `.tmp .temp .part .swp
   .swo .swx .bak .backup .old .orig .save .prev .new` each with an optional hex/number tail, `~`, `.N`, ` copy`, ` (N)`)
   is also judged as every name it could be a copy of (each leading run up to '.', '-', '_', '~' or space, with and
   without a leading dot). NOT covered, and said so in the code: other endings, and copies named in front of their
   origin (`#id_rsa#`, `.#id_rsa`, `tmp-id_rsa`). The content scan and the final raw check stand behind it. Review 4: split on more than dots (`mac_key-123.tmp`), editor swap and backup
   endings, and a length cap (a copy-shaped name over 255 characters, counted as characters not UTF-16 units, is
   skipped outright; uncapped, 100000 dots exhausted the heap). Only temp-shaped
   names are widened, so `secrets.md`, `server.key.md` and `id_rsa.md` are judged as themselves and kept.
3. Tests: skip rows at the root and under a world prefix for every store and temp shape; controls for the conversation
   stores, `sent.json`, a project's `keys.json`, `remote/mac_id`, `pending.json`, `tls.crt`, a person's own `remote/`
   folder, temps of ordinary work.

## Decided
- Name the stores, not a broad `*tokens*` / `*-secrets*` pattern. Rejected: a broad pattern would skip a person's
  folder called trade-secrets or token-budget work (the existing control `work/token-budget.csv`).
- Judge temps by their origin generally, not one rule per writer. Rejected: per-writer temp rules, because review 3
  found five temp shapes from five writers and the next writer would add a sixth. Rejected: deny every `.tmp`, because
  a person's own `draft.tmp` is work.
- `agent-token-only.json` is kept: it lists agent names (`agents`), not tokens.
- Weakest premise: that the store list is complete. My first sweep missed two; review 2 swept every engine owner-only
  writer and found three; review 3 swept bin/, app/ and the connector in kosmos-relay and found install_key and the
  temp class. A store written by code outside those (a provider CLI's own files inside an account dir beyond its
  sign-in) is covered only by the content scan and the final raw check.

## Red-check
Each store rule removed alone: the new tests fail (one fail each). Temp logic mutants: no temp origins, the leading dot
kept only, no `.new-` staging, and widening every name (not only temp-shaped ones) each fail one assertion (the last on
the `secrets.md` control). Review 4 mutants: dots only, no swap/backup endings, no tilde, no length cap: each fails. A separate cut cap was
removed, not tested: under the length cap it could never change an answer (its mutant survived). With everything in,
41 pass.
Review 5 mutants: each contain-anywhere rule reverted to its anchored form (board.token, remote keys, fed-seal, keys.json,
apikey), no `.backup`, no space split, no `.N`, counting UTF-16 units, a loose `.new` tail: each fails one assertion
(rows like `#board.token#` exist so only the contain rule can catch them). A wall-clock assertion was dropped: the
uncapped mutant fails by heap, not by time.
