# backupdeny-5686: three Kosmos credential stores the backup deny-list let through

Card: #5686 (measured while checking its weakest premise; comment 6082194329). E0.6 (#5535) promises "never credentials".

## Measured
On a real data root (this Mac's `~/Library/Application Support/Kosmos`), `pathDecision` returned include:true for:
- `sendertokens/*.json` (a `tokens` field; engine/sendertoken.js:58), per-agent board tokens;
- `launch-secrets/agent-secrets.XXXXXX` (bin/agent-supervisor.sh:706-710; the existing `secrets/` rule needs a boundary right before "secrets");
- `communitysend/<endpoint>/keys.json` (each agent's Kosmos+ community key; communitysend.js:93), and its temp `keys.json.<hex>.tmp`;
- review 2's sweep of every owner-only writer: `remote/mac_key` (the tunnel signing key, remote.js:1009),
  `remote/phone-notify.json` (notify-only token, phonenotify.js:68), and `.kosmos-<provider>-apikey` in an account dir
  (claudeaccounts.js:43, geminiaccounts.js:62, grokaccounts.js:92);
- `fed-seal-key.json` (this board's X25519 sealing key) and `fed-seal-rooms.json` (every room key), fedseal.js:49-50, and their temps (review 1).
`board.token`, `remote/*.key` (tls.key, signin-device.key) and `secrets/` were already denied; `remote/mac_key` was NOT
(no extension), found by review 2. A named world's data root sits under the world's
folder, so a world snapshot walks straight past all three.

## Change
Seven DENY rules (a file rule also takes any suffix, so a writer's temp file is denied with it) in engine/backupscan.js, each anchored on a path boundary so it holds under a world prefix
(`worlds/<id>/Kosmos/...`) and at the root. A test with skip cases and controls (sent.json beside keys.json, the
conversation stores, a project file named keys.json, a note named launch-secrets.md).

## Decided
- Name the three stores, not a broad `*tokens*` / `*-secrets*` pattern. Rejected: a broad pattern would skip a person's
  folder called trade-secrets or token-budget work (the existing control `work/token-budget.csv` shows the tests want
  that kept). Weakest premise: that this list of stores is complete. It came from a name sweep of one real data root
  plus a code search for `store.ROOT` joins with token/secret/key/connection. Review 1 found two my search missed
  (fed-seal-key.json, fed-seal-rooms.json), so the search was weaker than stated; review 2 swept every engine module
  that writes owner-only (0o600) files and found three more (now denied); it reported the rest already denied or
  holding no credential (webhooks keeps hashes; org files are signed or public). The content scan (secretmask) and the final raw check remain behind it.
- `agent-token-only.json` is kept: it lists agent names (`agents`), not tokens.

## Red-check
Removing each new rule alone makes the new test fail (38 pass, 1 fail each); so does removing the keys.json temp
suffix (the .tmp row fails). Each of review 2's three rules likewise (38/1). With all seven, 39 pass. Kept on purpose, as controls: remote/mac_id,
remote/pending.json, remote/tls.crt (public), a person's own remote/ folder.
