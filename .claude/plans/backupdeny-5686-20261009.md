# backupdeny-5686: Kosmos credential stores, and writers' temp copies, the backup deny-list let through

Card: #5686 (measured while checking its weakest premise; comment 6082194329). E0.6 (#5535) promises "never credentials".

## Measured
On a real data root (this Mac's `~/Library/Application Support/Kosmos`) and by three review sweeps, `pathDecision`
returned include:true for:
- `sendertokens/*` (per-agent board tokens; engine/sendertoken.js:58);
- `launch-secrets/agent-secrets.XXXXXX` (bin/agent-supervisor.sh:706-710; the existing `secrets/` rule needs a boundary
  right before "secrets");
- `communitysend/<endpoint>/keys.json` (each agent's Kosmos+ community key; communitysend.js:93);
- `fed-seal-key.json` (this board's X25519 sealing key) and `fed-seal-rooms.json` (every room key), fedseal.js:49-50
  (review 1);
- `remote/mac_key` (tunnel signing key, remote.js:1009), `remote/phone-notify.json` (notify-only token,
  phonenotify.js:68), `.kosmos-<provider>-apikey` in an account dir (claudeaccounts.js:43, geminiaccounts.js:62,
  grokaccounts.js:92) (review 2);
- `remote/install_key` (the install's Ed25519 key, written by the connector: kosmos-relay
  crates/tunnel/src/assistant.rs:64), and the content scan stores it too (base64url) (review 3);
- every writer's TEMP copy of a denied file, because each rule keys on the end of the name and writers name temps
  around it: `.mac_key.tmp`, `.tls.key.tmp` (connector atomic writes), `signin-device.key.new-<pid>-<hex>` (device key
  staging), `.board.token.<pid>.primary.tmp` (boardauth.js:337), `<file>.kosmos-<pid>-t<n>-...tmp`
  (engine/securewrite.js), `a.key.tmp` (review 3).
Already denied before this change: `board.token`, `tls.key`, `signin-device.key`, `secrets/`, `win32-channel/*.key`.

## Change
1. Seven DENY rules in engine/backupscan.js for the stores above, each anchored on a path boundary so it holds under a
   world prefix (`worlds/<id>/Kosmos/...`) and at the root.
2. `tempOrigins`: a TEMP-SHAPED name (ending `.tmp`, or carrying a `.new-` staging suffix) is also judged as every name
   it could be a copy of (each run of its leading dot-separated parts, with and without a leading dot). Only temp-shaped
   names are widened, so `secrets.md`, `server.key.md` and `id_rsa.md` are judged as themselves and kept.
3. Tests: skip rows at the root and under a world prefix for every store and temp shape; controls for the conversation
   stores, `sent.json`, a project's `keys.json`, `remote/mac_id`, `pending.json`, `tls.crt`, a person's own `remote/`
   folder, temps of ordinary work.

## Decided
- Name the stores, not a broad `*tokens*` / `*-secrets*` pattern. Rejected: a broad pattern would skip a person's
  folder called trade-secrets or token-budget work (the existing control `work/token-budget.csv`).
- Judge temps by their origin generally, not one rule per writer. Rejected: per-writer temp rules, because review 3
  found five temp shapes from five writers and the next writer would add a sixth. Rejected: deny every `.tmp`, because
  a person's own `draft.tmp` is work.
- `agent-token-only.json` is kept: it lists agent names (`agents`), not tokens.
- Weakest premise: that the store list is complete. My first sweep missed two; review 2 swept every engine owner-only
  writer and found three; review 3 swept bin/, app/ and the connector in kosmos-relay and found install_key and the
  temp class. A store written by code outside those (a provider CLI's own files inside an account dir beyond its
  sign-in) is covered only by the content scan and the final raw check.

## Red-check
Each store rule removed alone: the new tests fail (one fail each). Temp logic mutants: no temp origins, the leading dot
kept only, no `.new-` staging, and widening every name (not only temp-shaped ones) each fail one assertion (the last on
the `secrets.md` control). With everything in, 40 pass.
