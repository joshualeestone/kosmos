## Change
1. KOSMOS_STORES (as of review 13; the review sections below record how it got here): every Kosmos credential store,
   judged BEFORE the template exemption and outside DENY. Each store name is a TOKEN (bounded by start/end or a
   non-ASCII-alphanumeric character, plus any glued digits) in a file or folder name, in any folder, so copies,
   renames and moves are denied: sendertokens/, launch-secrets/, communitysend keys, fed-seal key and rooms,
   board.token, mac_key, install_key, phone-notify, .kosmos-*-apikey, undo copies, tls.key, signin-device.key,
   win32-channel/, and the secrets folder keyed on its contents (env/, github and cloudflare tokens).
2. `tempOrigins`, for credentials that are NOT Kosmos's own: a COPY-SHAPED name (COPY_SHAPED: `.tmp .temp .part .swp
   .swo .swx .bak .backup .old .orig .save .prev .new` each with an optional hex/number tail, `~`, `.N`, ` copy`, ` (N)`)
   is also judged as every name it could be a copy of (each leading run up to '.', '-', '_', '~' or space, with and
   without a leading dot). NOT covered, and said so in the code: other endings, and copies named in front of their
   origin (`#id_rsa#`, `.#id_rsa`, `tmp-id_rsa`), and a tail with no digit. The content scan and the final raw check
   stand behind it. Review 6: a tail after the ending is accepted when it carries a digit (`.tmp-k3j9z`, `.bak2`),
   Finder's ` N` is a copy shape, and the over-skip is stated in full (a copy of a KEPT name whose leading run is
   denied, `server.key.md.bak`, is skipped and pinned by a test).
3. Review 6: the Kosmos store rules (KOSMOS_STORES) are judged BEFORE the template exemption, so `mac_key.example`
   or `board.token.sample` is never lifted by it; the generic rules keep the exemption (`.env.example` is kept). Review 4: split on more than dots (`mac_key-123.tmp`), editor swap and backup
   endings, and a length cap (a copy-shaped name over 255 characters, counted as characters not UTF-16 units, is
   skipped outright; uncapped, 100000 dots exhausted the heap). Only temp-shaped
   names are widened, so `secrets.md`, `server.key.md` and `id_rsa.md` are judged as themselves and kept.
4. Tests: skip rows at the root and under a world prefix for every store and temp shape; controls for the conversation
   stores, `sent.json`, a project's `keys.json`, `remote/mac_id`, `pending.json`, `tls.crt`, a person's own `remote/`
   folder, temps of ordinary work.

## Decided
- Name the stores, not a broad `*tokens*` / `*-secrets*` pattern. Rejected: a broad pattern would skip a person's
  folder called trade-secrets or token-budget work (the existing control `work/token-budget.csv`).
- Judge temps by their origin generally, not one rule per writer. Rejected: per-writer temp rules, because review 3
  found five temp shapes from five writers and the next writer would add a sixth. Rejected: deny every `.tmp`, because
  a person's own `draft.tmp` is work.
- `agent-token-only.json` is kept: it lists agent names (`agents`), not tokens.
- Weakest premise: that the store list is complete. My first sweep missed two; review 2 swept every engine owner-only
  writer and found three; review 3 swept bin/, app/ and the connector in kosmos-relay and found install_key and the
  temp class. A store written by code outside those (a provider CLI's own files inside an account dir beyond its
  sign-in) is covered only by the content scan and the final raw check.
