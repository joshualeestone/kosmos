# asbrow-4405: the Kosmos Guide switch is always there, defaults ON, and switching it on makes the guide

Card kosmos#4405 (priority, real users on prod 0.7.05). Josh's rulings on the card: 14:53 "default that
on so everybody gets it and has to turn it off"; the row carries his picture; title "Kosmos Guide", hint
"Turn this on to be able to access the Kosmos Guide from any screen and get help with it." (his words).

## Why the switch was missing
- web/index.html asbPaintSetting hid the Help row unless a guide existed (or it was switched off), and
  the setting was usually read while first run was still showing, with nothing repainting the row after:
  a user with no guide ever made, and one who closed it, had no way to the assistant.
- engine armExistingInstall armed only a first run it could READ as finished, so an unreadable flag left
  an install with no guide for good.

## Change
- Page: the row shows once first run is over, guide or not; repainted every tick. The switch shows the STORED
  setting, ON by default (Josh: "has to turn it off"), so a person can always record a real OFF. ON with no
  assistant to show: #asb-row-state says "The Kosmos Guide is not set up on this computer yet." with a
  "Set it up now" button. asbTurnOn (switch ON or the button) saves on:true; if the board could not make a
  guide, one honest line says why (no model, a model that cannot be reached, names taken until restart,
  else try again), with an Open AI Models button where it helps; a later guide clears that line. A guide just
  made is FOUND (asbFindNow waits out a lookup already running). Josh's picture (24px round) beside
  "Kosmos Guide"; his hint as written.
- Server (/api/settings), switched ON with no usable guide, behind FIRSTRUN_AUTOCREATE_ENABLED:
  - NEVER made (no guide on record at all): ensureGuide({ explicit: true, via: 'settings' }), outcome recorded
    (#4350); replies guide: { state, seeded }.
  - made and then REMOVED (its name on the removed list): removal.restore, the Removed list's own restore;
    replies state 'restored' (or 'refused'). A new one cannot be made there: createAgent refuses a removed name,
    and a second name would be a second guide (review round 3).
  - a recorded guide whose folder is GONE from disk (deleted for good): the record is forgotten
    (setupAssistant.forgetGoneGuide) and a new guide is made as above.
  - anything else ('not-guide' with a folder there: another agent on the name, or the guide's folder lost its
    marker; 'unchecked'; a record that cannot be read): nothing is made; replies state 'unclear', and the page
    says so without advising a restart (a restart would not change it, and in one case would allow a second guide).
  - a restore refused for a lasting reason carries restore's own sentence to the page.
- Engine: ensureGuide `explicit` arms the install and skips the retry wait (each click is a real try; a dead
  sign-in costs one live check per click). Every other gate stands, the never-seeded one and the in-process
  latch included, so it never makes a second guide. armExistingInstall arms unless first run is KNOWN to be in
  progress (an unreadable flag arms: the never-had-a-guide state gets its guide at the next board start).

## Josh's four states
1. Never created, switch ON by default: armed at board start, guide made once a model is connected;
   the row shows ON with the not-set-up line; Set it up now tries at once and says why if it cannot.
2. Explicitly OFF ("close forever"): stays off (ensureGuide 'off'); the row is visible to turn it back on.
3. Guide agent deleted (removed): the seeded flag stays, so the automatic path never re-makes it; Set it up now
   (or switching OFF then ON) RESTORES it through the Removed list's restore.
4. No model: 'no-model' / 'no-usable-model', said in one line with the way to AI Models.
