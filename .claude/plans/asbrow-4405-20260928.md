# asbrow-4405: the Kosmos Guide switch is always there, defaults ON, and switching it on makes the guide

Card kosmos#4405 (priority, real users on prod 0.7.05). Josh's rulings on the card: 14:53 "default that
on so everybody gets it and has to turn it off"; the row carries his picture; title "Kosmos Guide", hint
"Turn this on to be able to access the Kosmos Guide from any screen and get help with it." (his words).

## Why the switch was missing
- web/index.html asbPaintSetting hid the Help row unless a guide existed (or it was switched off), and
  the setting was usually read while first run was still showing, with nothing repainting the row after:
  Ben (no guide ever made) and Nacho (closed it) had no way to the assistant.
- engine armExistingInstall armed only a first run it could READ as finished, so an unreadable flag left
  an install with no guide for good.

## Change
- Page: the row shows once first run is over, guide or not; repainted every tick. The switch shows what is
  TRUE: ON only while an assistant exists (a guide or the hosted one), so Ben's first click is ON.
  Switched on and the board could not make one: one line says why ("needs a connected AI model first",
  with an Open AI Models button), else a try-again line. A guide just made is FOUND (asbFind adopts it),
  not "confirmed" against one the page never knew. Josh's picture (web/icons/setup-guide-avatar.jpg,
  24px round) beside "Kosmos Guide"; his hint.
- Server (/api/settings): saving setupAssistant.on=true while setupGuideNow() finds no guide (reason none
  or not-guide; an 'unchecked' read does nothing) runs ensureGuide({ explicit: true, via: 'settings' }),
  behind FIRSTRUN_AUTOCREATE_ENABLED like the other two call sites, records the outcome (#4350), and
  returns guide: { state, seeded }.
- Engine: ensureGuide `explicit` arms the install, skips the never-seeded gate and the retry wait, and
  re-seeds after a removal (seedSetupAssistant `reseed`). Every other gate stands (switched off, no model,
  none usable, names taken, build switch). armExistingInstall now arms unless first run is KNOWN to be in
  progress (an unreadable flag arms: Ben's state gets its guide at the next board start).

## Josh's four states
1. Never created, switch ON by default (Ben): armed at board start, guide made once a model is connected;
   the row shows, reading OFF until then; clicking ON tries at once and says why if it cannot.
2. Explicitly OFF (Nacho): stays off (ensureGuide 'off'); the row is visible to turn it back on.
3. Guide agent deleted: the seeded flag stays, so the automatic path never re-makes it; switching ON
   (the row reads OFF with no guide) re-makes it (explicit, reseed).
4. No model: 'no-model' / 'no-usable-model', said in one line with the way to AI Models.
