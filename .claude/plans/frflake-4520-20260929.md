# frflake-4520: render-no-conflict-3729 flakes behind first run (kosmos#4520)

## Symptom (from the card)
Intermittent `page.click: Timeout 30000ms` on the Agents grid toggle, with `#firstrun` intercepting pointer events.
The same tree hash passed and failed, so it is timing, not content.

## Fix
The check is not about first run, so it no longer meets it: it POSTs `/api/first-run/complete` to its sandboxed board
before any page loads, as render-agent-pill-3958, render-member-ring-3991 and render-thread-steady-3966 already do.
After each `goto` it waits for the launch cover to come down (firstRunBoot lifts it once it has decided) and asserts,
per platform, that first run is not over the board, so a recurrence fails with its cause named instead of a 30 s
click timeout. The old one-Escape dismissal is gone.

Side effect, checked: completion would seed the welcome project, but `projects.seedWelcomeHome` seeds nothing when the
store already holds a project, and this check creates "Conflict Check" before the server starts. So neither the old
flow (its Escape POSTs the same completion) nor the new one seeds it, and the Projects tab assertions see the same
fixture. The seen-mark also arms the setup assistant exactly as the old Escape did.

## Measured
- Fixed check: 8 of 8 runs, 46 PASS each, 0 FAIL (quiet machine).
- CONTROL: with the seen-mark removed, `[mac] precondition: first run is not over the board` FAILs (and the old
  click timeout follows), so the new precondition can see the danger.
- The old check did NOT reproduce here in 8 runs, and a probe delaying the page's completion POST by 2.5 s still
  passed (Playwright's click waits for the overlay to close). So the reported failure needed the overlay to stay up
  for good: opened after the one check, or its completion POST failed (the "could not remember" path keeps it open
  until a second Escape).

## Decided, not missed
- Weakest premise: I did not reproduce the original failure or pin which of those two paths ran. The fix does not
  depend on it: with first run marked seen before load, neither path can open the overlay.
- Rejected: waiting and retrying Escape (keeps the race, only narrows it); hiding `#firstrun` in the DOM as some checks
  do (leaves the rest of the page `inert`).
- Scope: other checks use the same one-Escape pattern (render-orgchart-phone-718, render-msg-counter-3403,
  render-composer-reset, render-full-width, render-settings-403-2047, render-updates-stale). Listed on the card
  (a comment), not changed here: none is reported flaky, and each would need its own runs.
