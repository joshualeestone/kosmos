# guardstate25-5434: the setup guide's guard-state line is flushed before it is published (#5434 slice 25)

Addresses #5434. The last deferred writer: `engine/setup-assistant.js` `recordGuardState` writes one agent's guard-state
line to `<file>.<pid>.<hex>.new` and publishes it either by an exclusive hard link (a board start: only where there is no
readable line) or a rename (a launch). Unflushed, so a crash could publish a zero-filled line (#5431), which reads as
unreadable and is then replaced, but meanwhile hides the reading.

## Change
- The temp is written through a descriptor and flushed (`securewrite.flushOrThrow`) inside the try whose `finally`
  already removes it, so a failed write or flush leaves no temp; the publish logic (exclusive link, its no-hard-link
  fallback, the inode check, the unreadable-line replacement) is unchanged.
- `securewrite.syncDir(dir)` after the publish (POSIX; never throws).
- `securewrite` exports `flushOrThrow` and `syncDir` (the identical one-line change as slices 8, 12-14, 16, 17).
- engine/guardstate-5668.test.js: two tests, one per publish path, that the line is flushed before it is published.

## Decided
- **Flush in place, keep the hard-link design.** writeSecret cannot publish by an exclusive link; the guard state needs
  that ("a line another run wrote first is kept"). The temp name and this folder's `.new` sweep are unchanged.

## Tests
- Mutation: main's setup-assistant.js + securewrite.js fail both new tests. Related set (89 files): 2591; two failures
  were create.test.js launcher tests ("a NAMED-world launch", "hands the pane its account") with spawnSync ETIMEDOUT.
  Investigated, not this change: neither calls recordGuardState (instrumented syncDir logged no guard-state call), and
  both pass repeatedly with this change (2.8-3.0 s; the second takes 45-53 s alone, near its bound under load). An
  earlier bisect that seemed to implicate syncDir was a coincidence of timing.

## Weakest premise
That those two launcher timeouts are load. Evidence: they pass 3/3 and 2/2 with the change, and the instrumented run
shows recordGuardState is not on their path.
