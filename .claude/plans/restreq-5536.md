# restreq-5536: E0.7 (#5536) the signed two-admin restore request

From design v2 / v2.1 on #5536: a release of a member's backup needs an immutable request signed by two different admins' enrolled device keys, checked by the unwrap service (separate from the coordinator, with its own admin roster), never by coordinator rows.

`engine/restorerequest.js`, pure:
- `requestBytes(req)`: domain `kosmos-restore-request v1\n` + canonical JSON (backupformat's `canonicalJson`). The record: `v, org, unwrap, member, destination` (key fingerprint), `epochs`, `snapshots` ('all' or named ids, never implied), `waitEndsAt`, `requester, approver, breakGlass`, `contact` (break-glass only), `nonce`. Unknown fields are refused, so nothing unsigned rides along; id lists must be in ascending order (so no repeats, and one release has one spelling and one requestId); only the record's own fields are read.
- `signRequest(req, key)`: Ed25519 over those bytes.
- `checkRelease(...)`: the unwrap service's check. Refuses unless: the request names this service's org and id; requester and approver differ; both are on the service's OWN roster and both signatures verify; for break-glass, the roster's security contact is named, is a third person and signs; the service's own clock is past both `waitEndsAt` and `seenAt` + the policy wait (24 to 168 h; break-glass at least 4 h), so a short `waitEndsAt` cannot shorten the wait; it was first seen (fully signed) no more than 7 days after its own `waitEndsAt` (the approver has until then; signatures held back longer are stale), and release is within 7 days of when it opens; the member was shown the request (noticeSentAt; the wait also runs from the notice, which may be at most 7 days late); the destination is one the service trusts for the member; the request is not cancelled; and the nonce is unused. Returns the nonce for the caller to consume atomically at release, and the destination to re-seal to.

Fixed vectors pin the signed bytes and a signature. They were computed from this module and checked independently: `shasum -a 256` of the bytes, and `openssl pkeyutl -verify` accepting the signature (with a control: one flipped byte is refused).

Tests (15), each refusal with a control; every guard mutation-checked red.

Not here: consuming the nonce, the quarterly break-glass limit, the roster's own enrolment rules (v2.1 item 1), and the re-seal. The service itself (its language and where it runs) is not decided; this module is the reference its implementation must match.

Weakest premise: the record's fields are my reading of v2/v2.1. Renet's screens build the request; if the console needs a field this record lacks (a reason, say), it must be added to the signed bytes, which changes the vectors.

Review round 1 (opus): the two-person rule compared ids, not keys (two ids on one key passed; same for the contact); seenAt's key was unspecified, so a second request under a seen nonce could inherit a wait (now requestId, the sha256 of the signed bytes, is exported and seenAt MUST be keyed by it); seenAt 0 fell back to the signers' waitEndsAt (now a caller error); no cancellation (now a required isCancelled(requestId)). Also: attacker-shaped input returns a refusal instead of throwing, waitEndsAt may be at most 169 h past seenAt, the result holds copies, and a break-glass vector is pinned.

Review round 2 (sonnet): nothing tied the destination to the member (now a required destinationAllowed(fingerprint, member), so two admins cannot name a key of their own); an omitted snapshots list was ambiguous (now required: 'all' or ids); first-sight recording had no reference (now recordSeen, keyed by requestId); the doc overstated "two different admins" (now says one person with two enrolled devices counts twice unless the roster allows one key per person). Also: a single canonical copy is read after the shape check, and the 7-day window runs from when the request opens. engine.reachable did not flag recordSeen before its excuse (the in-module-mention blind spot, #5548); the excuse is there anyway.

Review round 3 (opus): a pair of signatures held for a year still released (now refused once first seen more than an hour after its waitEndsAt); recordSeen recorded unsigned requests, so the wait could run before the approval existed (now it shares the signer checks with release and records only a fully signed request). Also: break-glass may not wait longer than ordinary, and a Uint8Array signature is read as bytes.

Review round 4 (sonnet): the service's callbacks failed open (a Promise from destinationAllowed read as allowed; undefined from isCancelled or nonceUsed read as not cancelled or unused); now each must return an exact boolean or the release refuses. Also: a malformed roster contact refuses instead of throwing, and first sight applies the same time bounds as release, so nobody is told of a request that cannot release. Boundary and id-only contact cases added.

Review round 5 (opus): recordSeen trusted its store (a Promise or a string overwrote the first sight, pushing the wait forward on every relay; now only an exact undefined means never seen, and it returns first: true|false for the member notice); the one-hour stale rule killed any approval slower than the wait plus an hour (I set it too tight in round 3; now 7 days, and the doc tells the request builder that waitEndsAt is creation + policy wait).

Review round 6 (sonnet): checkRelease took seenAt as a bare number, so nothing forced the recorded first sight (and its member notice) to exist (now it takes the seen store, reads it by requestId and refuses a request never recorded); recordSeen's get-then-set raced between instances (the store now needs an atomic setIfAbsent returning whether this call inserted; a lost race takes the winner's time and does not notify). Also: a distinct message when two ids share a key, the requester-key contact case, and doc notes on byte signatures and the store's durability.

Review round 7 (opus): the release result left out breakGlass and the signer ids, so a caller counting break-glass or writing the audit trail had to re-read the unvalidated input (now returned from the verified copy). Also: signatures are read once inside the guarded block, a Uint8Array from another realm counts as bytes, the policy doc is complete, and first sights and used nonces must be kept at least 15 days after first sight.

Review round 8 (sonnet): three caller-contract gaps, now stated in the header: re-read cancellation and consume the nonce in one atomic step at release; check the epochs and snapshots belong to the member in that org before re-sealing; only instances on a trusted clock may write first sights (a slow one shortens every wait).

Review round 9 (opus): cancellations were missing from the retention rule (a purged cancellation reads as none; now kept 15 days with the rest); the domain tag protects only if nothing else an admin key signs takes raw caller-chosen bytes (now a stated requirement on E0.1/E0.2, and on #5536). Also: clock skew between instances refuses instead of throwing, the policy is read at release (stated), and first sight's over-long-wait refusal has its own test.

Review round 10 (sonnet): recordSeen recorded a request already cancelled, so the member got an alarm for a dead request (now it takes isCancelled and refuses). Also: 'all' is reserved in a snapshot list, and an inherited contact field (a polluted Object.prototype) no longer refuses every request.
