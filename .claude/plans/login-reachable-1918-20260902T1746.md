# Plan: make the sign-in remedy reachable from the agent page (kosmos#1918)

## Problem
A real external tester was boxed in on 0.6.22. An agent surfaced:
`● Please run /login · API Error: 401 OAuth access token has expired.`
and there was nowhere in the product to run `/login`:
- the Terminal tab is read-only,
- the "Send a message into this window" box talks to the AGENT, not the shell,
- Settings "Sign in again" exists but the account stayed broken (that is #1916, separate).

`Please run /login` is emitted by the underlying CLI, not composed by Kosmos: correct in a
terminal, false inside this product. The card asks not to close by rewording alone.

## Key finding (from the code map)
The interactive re-auth surface ALREADY exists: Settings -> Accounts -> "Sign in again" per
Claude row -> `openAcctReauth(dir,email)` -> the real `engine/connect.js` OAuth/device-code
flow. So #1918 is an affordance/wiring gap, not a build-from-scratch.

## Fix (option 1: make the remedy reachable)
1. `web/index.html`: add a `#d-reauth` "Sign in again" button on the agent detail page,
   shown ONLY when `state === 'auth_failed'` (paintDetail toggles it), wired once to
   `settingsGo('accounts')`. This gives an in-product path from the error to the existing
   re-auth surface. A real affordance, not a reworded dead end.
2. Class fix (Splinter's ask): reword the Kosmos-COMPOSED strings that name `/login` to name
   the reachable action instead:
   - `server.js` account-status remedy (#1885): "run /login in its own window" ->
     "from the Accounts tab in Settings (Sign in again)".
   - `engine/create.js` create refusal (#1903): "(run /login for it)" ->
     "from the Accounts tab in Settings (Sign in again)".
   The PASSTHROUGH quotes (the `#d-said` evidence, and the usage-limit "/usage-credits" line)
   are left as attributed quotes ("X's screen said:") per the existing #991/#996 design; the
   new button supplies the action the login quote names.

## Deliberately parked (documented, per Splinter: parking a half is fine, wording-only is not)
- The usage-limit passthrough ("Run /usage-credits ... /model") has NO in-product surface;
  it stays an attributed quote. No affordance to add.
- Aiming the button at THIS agent's specific account (vs the account list) depends on #1916
  (badge/liveness) and #1917 (picker can't distinguish two accounts on one email). The account
  list is the honest floor; the aimed version is a follow-up once those land.
- Whether the re-auth flow then SUCCEEDS is #1916, not this card. #1918 is reachability.
- The auth_failed toggle (and thus the button) is evaluated at detail-open time, not on
  the 5s poll, so an agent that transitions to auth_failed WHILE its detail panel is
  already open shows no button until the panel is reopened. This is deliberate and
  consistent: the sibling evidence quote it accompanies (d-said/d-why/d-task) is itself
  open-only, so the button and the quote it remedies appear and disappear together.
  Refreshing only the button on the poll would create a NEW divergence (button without
  its quote); moving the whole auth_failed presentation onto the poll is the open-only-
  vs-poll drift class the file already tracks (comments near 12480/12554) and is out of
  scope here. The realistic reachability path (a person navigating to the failed agent)
  fires openDetail and shows the button.

## Verification

the toggle shows it on auth_failed and hides it on idle/working (both arms); the click opens

restored green). Reworded-string tests (#1885, #1903) still pass (they assert "Re-authenticate").
