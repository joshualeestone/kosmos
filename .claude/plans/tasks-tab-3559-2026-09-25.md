## The rule this build lives by (Mona's weakest-premise note, Splinter's brief)
Show ONLY the groups the app can prove today. A group whose evidence the engine does not store is
HIDDEN, not guessed.

| Group (mock)          | Evidence today                                   | This build |
|-----------------------|--------------------------------------------------|------------|
| Nobody on it          | open, no one assigned (`whoOf` empty)            | shown      |
| Assigned, not started | assigned, the agent's report does not name it    | shown      |
| In progress           | assigned, the agent's report NAMES it (`claimFor`)| shown      |
| Closed                | `progressOf(t).closed`                           | shown, folded |
| Waiting on you        | needs a per-task decision flag + question        | HIDDEN     |
| Done, check it        | needs "agent says done"                          | HIDDEN     |

A task whose claim cannot be read (`claimed: null`) stays in "Assigned, not started" and its row
says WHY it cannot tell (the claim's own `because`), never "not started" as a fact.

Also hidden for the same reason: the Categories rail, Group by Category, category/tag chips, the
Answer-in-place box, the "waiting on you" nav badge.

## Supply side (engine derives, the view renders)
- `engine/tasks.js`: `taskState(joinedTask)` -> 'closed' | 'nobody' | 'working' | 'assigned', from
  `progressOf`, `whoOf` and the joined `claim`. The view never computes state.
- `engine/tasks.js`: `lastActivityOf(projectId, task)`: the newest transcript event (taskchat
  `at`), else `createdAt`. That is the evidence behind "Quietest first".
- `GET /api/tasks?view=tasks`: each row gains `claim` (via `projects.joinTaskClaims`, one roster
  read and one commitments reading per agent for the whole request), `state` and `lastActivityAt`.
  Only with `?view=tasks`: those cost a board snapshot plus a transcript read per task, and the
  project View-all door and the agents' `kosmos tasks` keep the cheap list they had.
- `POST /api/tasks/close` `{ tasks: [{ projectId, number }], note }`: closes each, writing the
  note first as a task message (`tasks.say`) so it lands on each task's history, then tells each
  distinct assignee ONCE from one roster read (a snapshot per task froze the board), and returns a
  per-task result. A task already closed is left alone (no second note). A task that fails does not stop the
  others; the answer says which failed and why.
