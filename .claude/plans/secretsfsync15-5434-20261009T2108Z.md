# secretsfsync15-5434: three owner-only records in Kosmos's data are flushed before they count (#5434 slice 15)

Addresses #5434. Group 2 of the rename inventory (secrets in Kosmos's own data), after board.token (slice 14). Each wrote
a 0600 temp and renamed it with no flush, so a crash could leave the record at full length but zero-filled (#5431):
- `engine/orgenroll.js`: the world id (`worldId`), the enrollment record (`writeEnrollment`) and the pending-leave /
  consent markers (`writeWhole`). A zero-filled world id reads as invalid and is re-minted, so this world would report
  under a new id; a zero-filled enrollment reads as not enrolled.
- `engine/orgpolicy.js` `writeApplied`: the applied company policy. Zero-filled, it reads as no policy in force.
- `engine/phonenotify.js` `writeState`: phone notification state, which holds a token. Zero-filled, it reads as off.

## Change
- All five go through `securewrite.writeSecret(file, data, 0o600, { atomicOnly: true })`; orgenroll's three through
  its existing `writeWhole`. Required at call time. Each keeps its error behaviour: worldId answers null,
  writeEnrollment/writeWhole/writeApplied throw, writeState answers `{ ok:false, because }`.
- phonenotify removes the old writer's fixed `<file>.tmp` after a good save: a crash under the old code could have
  left a copy of the token there, which no save overwrites any more (review 1).
- New `engine/secrets.fsync-5434.test.js` (7 tests), in `tools/windows-tests.js`.

## Decided
- **The options of store.js's saves (Kosmos's own data):** `atomicOnly`, no `ownTempsOnly` (these folders are
  Kosmos's), exact mode 0600 as each set before.
- **Temps:** phonenotify's fixed `<file>.tmp` and orgpolicy's `<file>.<pid>.tmp` become unique `wx` temps; orgenroll's
  were already unique.

- **Only phonenotify's old fixed temp is removed.** orgenroll's and orgpolicy's old-named temps (a world id, an
  enrollment, a signed policy: no token) are left if a crash ever left one; securewrite's reap does not match their
  shape (review 2).

## Tests
- world id: flushed before its rename, 0600; a failed flush mints nothing (null) and leaves no temp.
- applied policy (a signed bundle, as orgpolicy-5534.test.js signs it): flushed before its rename, 0600.
- phone notify state: flushed before its rename, 0600; a failed flush answers the refusal and leaves the old file.
- (review 1) applied policy: a failed flush refuses the apply and leaves the record in force; phone notify: an old
  fixed temp is removed after a good save.
- Mutation: main's three files fail all of the first 5. Related set (71 files, list5434s15.txt): 2189, 0 fail, 3 skipped.

## Weakest premise
That writeSecret's folder-wide reap of dead temps in Kosmos's data folder (the default without ownTempsOnly) is as safe
there as it is for store.js's saves in the same folder. What would change my mind: a non-Kosmos file in store.ROOT
with securewrite's temp shape.
