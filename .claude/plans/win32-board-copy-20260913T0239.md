## Design

### One platform fact, served in the page

The page needs the platform BEFORE any signed-in API answers: the not-signed-in panel (W-24) is
painted exactly when `/api/*` refuses. So the static shell carries it.

- `web/index.html` head gains `<meta name="kosmos-platform" content="__KOSMOS_PLATFORM__">`,
  the same shape as `kosmos-version`.
- `server.js` stamps it per request from `platformGate.describe().platform` (the one derivation
  `firstrun.state()` and `publicView` already use). The static shell stays open (no token), and
  the page stays read per request.
- A page with the marker unstamped (file://, a harness) reads as "not Windows", so every
  existing Mac harness keeps rendering the Mac page.

### One copy layer in the page (convention 5)

Near the top of the app script:

- `servedPlatform()` reads the meta.
- `onWindows(platform)` answers from an explicit platform when a caller has one (the connect
  card's served `st.platform`), else the served meta. This is the ONE place `'win32'` is
  compared.
- `windowsCopyTable()` holds every Windows string, keyed.
- `platformCopy(key, macCopy, platform)` returns the Mac string untouched off Windows.
- `applyPlatformCopy(root)` runs once at load. On Windows it stamps
  `html[data-kosmos-platform="win32"]`, swaps `[data-win-copy]` markup from the table, and a
  single CSS rule hides every `[data-win-hide]` element.
- `platformHides(el)` lets the gate poll skip hidden gate rows.
- The Mac strings stay inline at their call sites and in the markup, byte-for-byte, so the Mac
  page reads exactly as before.

### Wizard (W-10, W-11, W-12, W-15)

- `frStepSequence()` is `[1..9]` on a Mac and `[1,3,5,6,7,8,9]` on Windows. `frStepAfter(step)`
  replaces the literal `frGo(n+1)` hops on S1, S3 and S4. `frGo` redirects a deep link to a
  skipped pane onward. Progress dots are computed over the visible sequence; on the Mac the
  arithmetic is identical to `(step-1)/(FR_STEPS-1)`. Pane ids are untouched, because browser
  checks key on identity (`lib-firstrun-steps.js`).
- S3 on Windows:
  - the Energy and Accessibility mocks (traffic lights), the Accessibility caption and the tmux
    gate row are hidden, so there is no illustration;
  - the copy is the audit's Windows wording;
  - the sleep gate row stays and reads the real powercfg check;
  - Turn On opens `ms-settings:powersleep`.
- S7 on Windows: the audit's INTERIM copy (double-click Kosmos.exe in the extracted folder, Pin
  to Start), and the Dock drawing is hidden.

### Engine

- `engine/win32explorer.js` (new): the ONE Explorer launcher.
  - It spawns `%SystemRoot%\explorer.exe` detached, with an argument array and no shell, then
    unrefs. Explorer's exit status is never waited on (it exits 1 on success).
  - Targets are validated first: an absolute drive or UNC path, no quote or control characters,
    no leading switch character, and an existing directory (or regular file for open-file).
    The settings page is a closed allow-list (`ms-settings:powersleep`).
  - It is gated by `live-execution` (convention 3): no runner and no opt-in means refuse, and a
    test process throws. `setRunner` is the seam, so no test ever launches Explorer.
- `engine/machine.js`:
  - `parsePowercfgSleep` / `win32SleepCheck` run
    `powercfg /query SCHEME_CURRENT SUB_SLEEP STANDBYIDLE` through the existing `run()` runner
    (5s timeout). An AC index of 0 means never.
  - `sleepGate`, `check()` and `openSleepSettings` get win32 arms. The platform is explicit
    (`opts.platform`), and an injected `pmset` / `powercfg` text names its platform, so existing
    Mac arms keep their Mac path on this Windows box.
  - `appLocationCheck` / `revealApp` get a win32 arm: `bundleRoot()` and "Open the Kosmos
    folder" (`explorer.exe "<bundleRoot>"`). The autostart row loses the raw schtasks line to a
    structured `admin` field, which the page renders in `<details>` "For IT admins". Windows
    rows say "sign in".
- `engine/projects.js`: `revealFolder` / `openFile` get a win32 arm through `win32explorer`,
  with a platform seam `setRevealPlatform`. The refusal says "File Explorer did not open".

### Round 2 (opus) on 93e8fdc1: no SAFETY, no BUG; NITs and two residuals fixed, rebased onto 49c81470

The reviewer probed the allow-list (8.3 names, symlinks, junctions, U+2024 dots, RTLO,

- **NIT 2:** the update-abort toast told a Windows user to double-click Kosmos.exe. For a

  same build. `updateAbortRemedy` now says only to sign out of Windows and sign back in.
  The engine-stale and world-switch sentences keep the Kosmos.exe remedy, which is true

- **NIT 3, mapped drives (decision: accept them consistently).**
  - The problem: Documents `openFile` judged the RESOLVED path, and a mapped `Z:\`
    resolves to `\\server\share`, so it was refused. Meanwhile "Open in File Explorer"
    judged the raw `Z:\` record and opened it: two answers to one question.
  - The reasoning: the person or their IT chose that server, and the board's own
    `folderState` already reaches it. A mapped drive is not the attack SAFETY 2
    closed; a record the page cannot control naming a share is.
  - The fix: `win32explorer.openFile(target, { namedAs })`. The drive-letter and
    UNC/device rule, the stat and the path handed to Explorer are all the record's
    pre-resolve path. The resolved target must carry no device form, stream or unsafe
    character, and its extension still decides open versus reveal.
  - Literal UNC, `\\?\` and `\\.\` records are still refused, for documents and
    folders.
  - Tested through a `projects.setFsWorldForTests` seam (realpath, stat and access
    together), since no test machine can map a drive.
- **Residual 1:** `.rtf` removed from `OPENABLE_FILE_EXTENSIONS` (its handler's
  parser-bug history); it is now shown in File Explorer.
- **Residual 2:** the powercfg reading's TTL went from 5s to 1.5s (two poll ticks), so
