# codex-choices-998: a Codex agent's choice prompt gets buttons (kosmos#998)

## Why

Found while validating a fleet "can this agent actually hear me" instrument, not
by hitting it. **It is a second, deterministic path to the failure Josh reported
on #989**, and it hits the provider his 10:32 ruling is about to make first-class.

Two parsers read the same prompt and disagreed about which selector glyph exists:

- `engine/status.js`'s needs-you markers know **both** `❯` (U+276F, Claude) and
  `›` (U+203A, Codex). #249 exists entirely because of that difference, captured
  from a live codex-cli 0.149.0 pane on this machine on 2026-08-23.
- `engine/chat.js`'s `OPTION_LINE` knew **only** `❯`.

`optionsIn` returns null unless it saw a selector (`if (!marked) return null`),
so for any Codex menu Kosmos did exactly half the job: correctly announced
"waiting on an answer" and showed the raw prompt, then drew **no buttons**. The
person is told their agent is stuck and handed nothing to unstick it with.

⚠️ Measured before changing anything, same prompt, only the glyph varied:

```
❯ heavy angle    question: FOUND   options: ["1:Yes...","2:No..."]
› single angle   question: FOUND   options: null      <-- the defect
> ascii          question: null    options: null
```

## What

1. **`SELECTOR_GLYPHS` moves to `engine/status.js` and is exported.** It lives
   beside the marker lists whose docblocks record the observation, and it is the
   fix for the general shape rather than the character: two files keyed on a
   hardcoded glyph separately and forked silently. One source, so they cannot.
2. `engine/chat.js`'s `OPTION_LINE` **and** `ANY_NUMBERED` both build from it.
   ANY_NUMBERED matters too: it is the "a menu longer than we can read is
   refused rather than served as its first nine" guard, and a Codex menu of ten
   options would have slipped past a half-fixed version.

## Out of scope

- Plain ASCII `>`. It matches neither parser, and this file's own standing rule
  is *"add to this list by OBSERVING"* -- no runner has been observed drawing it,
  and a guessed glyph is the same 0-for-1 bet as a guessed wording. Recorded on
  the card so the next reader knows it was considered, not missed.

## Verification (done when)

1. A Codex-shaped menu (`›`) produces the same buttons a Claude-shaped one does.
2. **Two controls in the same test, both load-bearing:**
   - the Claude shape still works -- a fix that traded one glyph for the other
     would pass the first assertion and break every agent we currently run;
   - an unmarked numbered list still returns null -- widening the glyph class
     must not have widened "a numbered list is a menu", which would turn prose
     into buttons.
3. ⭐ **The test was run against the UNFIXED code and FAILS there** (107 pass /
   1 fail), then passes with the fix. Every other fixture in `chat.test.js` uses
   `❯`, which is why 108 tests were green while the defect was live; a new test
   that cannot fail would have reproduced exactly that.
4. Full suite; challenge-loop to convergence; PR per house flow.
