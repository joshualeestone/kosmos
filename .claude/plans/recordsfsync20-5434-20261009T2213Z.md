# recordsfsync20-5434: twelve records Kosmos keeps are flushed before they count (#5434 slice 20)

Addresses #5434. Group 3 of the rename inventory, continued. Each wrote a temp and renamed it with no flush, so a crash
could leave the record at full length but zero-filled (#5431): commitments (an agent's commitment record),
instruction-adds (the Undo record for added instructions, 0600), the world boot guard's attempts and confirmed maps,
world starts, federation links and invites, agent permission settings (0600), the restart note (0600), room holds
(0600), the org rollup state (0600), styles, and the community store's saveJson (FILE_MODE).

## Change
- Plain records -> `store.saveFlushed` (commitments, worldbootguard x2, worldstarts, federation, fedmembers, styles).
- Owner-only records -> `securewrite.writeSecret(file, data, 0o600 | FILE_MODE, { atomicOnly: true })`
  (instructionadds, agentpermission, restartnote, roomhold, orgrollup, communitystore). The exact mode is set on the
  temp's descriptor, as each set it before (writeFileSync mode, and instructionadds' extra chmod).
- Error handling unchanged per caller (commitments throws its sentence; orgrollup and restartnote answer false;
  worldbootguard fails open; the rest throw). Each failed save now removes its own temp (several used to leave it).
- The two MOVES here (instructionadds' unreadable-file aside, communitystore's corrupt quarantine) are unchanged.
- `store` exports `saveFlushed` (the identical one-line change as slices 17-19).
- `engine/instructionadds.test.js`: six tests forced a failed record write by planting a directory at the old
  `<file>.tmp`; they now refuse the record save's `.kosmos-` temp at open (`blockAddsWrite`), each keeping its
  "fixture: the record did not fail" precondition.
- New `engine/records.fsync-5434.test.js` (3 tests), in `tools/windows-tests.js`.

## Decided
- **Mode-preserving owner-only writers go through writeSecret, not saveFlushed**, because saveFlushed keeps the
  existing mode (or the umask for a new file) and these must be exactly 0600 / FILE_MODE whatever was there.
- **commitments' "a write that fails AFTER the temp exists cleans it up" test** (a directory at the destination) still
  fails the rename after the temp exists under securewrite, so it still covers the cleanup it is named for.

## Tests
- commitments: a report is flushed before its rename. instruction-adds: flushed before its rename, exactly 0600 under
  umask 077. All twelve held to "a flushed save, no `renameSync(tmp`" by reading their comment-stripped source.
- Mutation: main's thirteen files fail all 3. Related set (135 files, list5434s20.txt): 3850, 0 fail, 6 skipped.

## Weakest premise
That the worlds base folder (worldbootguard) tolerates securewrite's non-dot temp names as it tolerated the old
non-dot `<file>.<pid>.tmp`: the guide's baseEntryToName skips dot temps only, so both old and new are treated alike.
