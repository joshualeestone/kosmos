# Plan: expand project description cap 200 -> 1000 (#2836)

Branch: desc-1000-2836. Addresses kosmos#2836.

Josh: "I want to expand the description of a project to 1000 characters to be usable."

## The cap lives in three code sites, pinned together by a test

- engine/projects.js: `Array.from(flat).length > 200` (counts CODE POINTS, not
  UTF-16 units, deliberately) + the "longer than 200 characters" message.
- web/index.html: `const PJ_DESC_MAX = 200` (client pre-check, also code points via
  pjDescTooLong) and two hardcoded hints "Up to 200 characters." (settings +
  create forms). Deliberately NO maxlength attribute (it counts UTF-16 units and
  would cut an emoji description at half length).
- web.desc-error-1303g.test.js EXTRACTS all three (engine cap, PJ_DESC_MAX, both
  hints) and asserts they agree -- the anti-drift coupling.

## Change

Bump every one of those to 1000, keeping the code-point counting unchanged:
- engine cap `> 1000`, message "longer than 1000 characters".
- PJ_DESC_MAX = 1000, both hints "Up to 1000 characters."
- Comments that state the numeric cap updated for accuracy (the code-point-vs-UTF-16
  principle is unchanged).
- Tests reconciled up front (the trap: tests that used `'x'.repeat(500)` / `repeat(201)`
  to TRIGGER the "too long" refusal now pass the 1000 cap, so they were bumped to
  `repeat(1001)`; the at-cap "legal" emoji test 200 -> 1000; the code-points test's
  boundary values 200/201/150-emoji -> 1000/1001/600-emoji). engine/projects.test.js,
  server.projects.test.js, web.desc-error-1303g.test.js.

## Verification

- 304 tests pass (web.desc-error-1303g pinning + boundaries, engine/projects,
  server.projects, project-settings-hints).
- Full web suite for regression.
- Browser-check gate: a numeric cap + hint-text change; the extraction pinning test
  already verifies source agreement, so a Browser-check trailer documents that rather
  than a low-value render check (unless a mapped check exists).

## Weakest premise

That 1000 code points is the intended cap (Josh said "1000 characters"; the engine
counts code points, so a 1000-emoji description is allowed -- consistent with the
existing deliberate code-point design). No storage concern: descriptions are small
free text with no separate column limit.
