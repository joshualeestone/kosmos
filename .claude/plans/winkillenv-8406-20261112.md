# winkillenv-8406: NAME=value and env before a command no longer hide it from the Windows kill guard (kosmos#8406)

## Problem
Homer, on installed Windows staging 0.8.04, through the installed hook: a leading NAME=value word, or env with its
options, gets past engine/winkillguard.js. MSYS_NO_PATHCONV=1 taskkill /F /IM node.exe is allowed. That spelling is
the standard Git Bash fix for taskkill's /F being turned into a path, so it is the natural way to type the command
the guard exists to stop. The same holds for env X=1 taskkill ..., X=1 taskkill ..., and A=1 B=2 Stop-Process -Name node.

## Change
commandReason's prefix loop now also skips:
- any number of leading NAME=value words;
- env with its options (-u NAME and -C DIR take a value; -- ends the options), then its NAME=value words;
- env -S "...", -S"..." glued, a cluster ending in S (-iS), --split-string: the string, with any words after it,
  is read as the command;
- NAME+=value and NAME[i]=value as well as NAME=value;
- the launchers winpty, nice (-n N, then --), timeout ([-s SIG] [-k T] [--] DURATION), stdbuf, setsid, and the
  options of time, command and exec (exec -a NAME); sudo's common options (-E, -u USER, a cluster ending in a letter
  that takes a value such as -Eu USER, and two-word long options such as --user USER);
- env's other value options -P PATH and -a NAME; an assignment whose value is a $( ) substitution (FOO=$(x) cmd).
Prefixes, assignments and env may come in any order: the loop repeats until none is left. Review round 1 added the -S
spellings, the launchers and the assignment forms; round 2 the option values, -- and FOO=$(x); round 3 reads env's short options letter by letter (-uSHELL unsets
SHELL, it is not -S), and the remaining launcher value options (timeout --signal/--kill-after, stdbuf -o 0, time -f/-o,
nice --adjustment, sudo -U, exec -ca). Named as passing: FOO=$(x)y cmd (a value that continues past the substitution).

## Mac/Linux guard (#4671)
Measured, with and without jq: X=1, MSYS_NO_PATHCONV=1, env X=1, A=1 B=2 and env -i PATH=... before the shapes it
refuses are all refused, because it matches those shapes anywhere in the text, not at command position. The prefixed
forms (X=1, MSYS_NO_PATHCONV=1, env X=1, env -i PATH=..., A=1 B=2) are now pinned in report-hook-killguard-4671.test.js,
so a future rewrite cannot open the gap there.

## Test
Homer's five forms plus env -i, env -u ... --, env -S, sudo/assignment in both orders, and cmd //c "set X=1 && ..."
are refused. Allowed: MSYS_NO_PATHCONV=1 taskkill /F /PID 4242 (Homer's control), a bare X=1, a bare env, and
MSYS_NO_PATHCONV=1 git status. Mutations go red for each part: no leading-assignment skip, no env handling, no glued -S, no launchers, no sudo
options, the plain-= assignment form, env's -P/-a, sudo clusters, FOO=$(x), stdbuf/setsid, env's value letters
ignored, timeout's long options, stdbuf's values.
