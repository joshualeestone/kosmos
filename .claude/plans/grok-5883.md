# grok-5883: Grok agents' transcripts in the company backup (kosmos#5883 slice 2)

Stacked on transcripts-5883 (slice 1). Rebuilt from main when the stack lands.

## What
- engine/backupsessions.js grokRoot: Grok keeps a working folder's conversations in <grok home>/sessions/<the folder,
  encodeURIComponent>/<session id>/ (MEASURED on this Mac 2026-10-11, grok at /opt/homebrew/bin/grok: 28 folders
  under ~/.grok/sessions, each <id>/ holding chat_history.jsonl, events.jsonl, updates.jsonl, summary.json,
  system_prompt.txt, prompt_context.json, locks). The folder name IS the working folder, so ownership is by
  construction. Both spellings of the agent's folder are tried (as given and its real path).
- Named: chat_history, events, updates (.jsonl) and summary.json. NOT system_prompt.txt or prompt_context.json
  (instructions and context, not the conversation), never the locks.
- engine/backuptick.js: the default Grok home (grokaccounts.defaultDir, honours AGENT_WORKFORCE_GROK_HOME) as
  sessions/<id>/grok for every agent; a Grok agent on a named account adds its GROK_HOME (create.js reads it verbatim
  as the job's configDir) as grok-a<8 hex of its true path>, as Codex and Gemini do.

## Measured on the real thing (read-only, names and counts only)
The reader over every real ~/.grok/sessions folder: 27 of 27 absolute folders give a root; the kinds taken are exactly
the four named files.

## Weakest premise
That Grok's folder encoding is encodeURIComponent for every character. Measured only for '/' and plain names here; a
folder with a space or non-ASCII is reasoned. If Grok encodes differently, that agent's root is simply not found
(nothing wrong is taken).
