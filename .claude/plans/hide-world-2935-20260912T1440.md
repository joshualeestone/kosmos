# hide-world-2935 -- soft-delete (HIDE) a Kosmos

Card: kosmos#2935. Josh ruled SOFT-DELETE only (2026-09-12 ~14:10): "make 2935 soft delete so you
dont see it in your Kosmoses list anymore, but notify the user that their files are still
accessible. There will not be a restore a kosmos function." Splinter routed to Angel; Baron's design
+ sketch stand (on the card).

## What finished looks like
A user can HIDE a Kosmos from the Kosmoses list/switcher via the settings-cog pane (next to rename).
A plain confirm dialog states the files remain accessible AND where (`<base>/worlds/<id>/`). The
on-disk store is NOT deleted; the registry row is flagged hidden (so the file pointer survives). The
hidden world's agents are stopped (not deleted) via launchKey. Kosmos 1 is never hideable; the active
world must be switched away from first. No restore. Mac + Windows. challenge-loop. PR to Splinter.

## Design decisions (mine, per Josh's ruling + Baron's sketch)
- **Registry shape:** a `hiddenAt` ISO timestamp on the world row (not a separate `.hidden` list) --
  minimal, and `readRegistry` already preserves unknown fields on a row (it filters by id only), so
  the store pointer + the flag ride the same row.
- **listWorlds filters hidden** (the user-facing switcher list); `readRegistry` keeps hidden rows
  (internal: worldBaseDir still resolves a hidden world's store, so files stay accessible; the
  activeWorldId guard still works).
- **hideWorld(base, id):** refuse DEFAULT_ID (ERESERVED) and the active world (EACTIVE, "switch away
  first"); ENOWORLD if missing; else set hiddenAt under withRegistryLock. Mirrors renameWorld's
  shape + typed errors.
- **Agents (Q2, my call):** STOP (disable) the hidden world's agents via launchidentity.launchKey
  (Mac launchctl + Windows), do NOT delete them -- consistent with "files accessible" + reversible.
- **No unhide.** Re-adding is the import path (#2892), not a restore feature.
