# #4421: after a rename, the agent page kept the old name (Sonya Blade, 2026-09-28)

## Finished means (the card, Liu Kang m2605)
After a rename, the DM title, every message label, the "is working" line and project-room rows show the current
display name, for every provider, and the internal id is never shown. Pinned by a test that renames an agent and
goes red on main, plus a browser check.

## Cause (measured)
The page keeps `CURRENT`, the agent's card as it was when the agent was OPENED, and a dozen places read
`CURRENT.name`: the poll's `paintTalk(CURRENT.sessionName, CURRENT.name)` (the "Direct Message to" title, and
`dmWho`, the label on the agent's own messages), `paintBusy(fresh, CURRENT.name)` (the "is working" line), the
send path, the Fresh start and restart sentences. Nothing refreshed it: the rename's save handler wrote the new
name straight into the heading only, and a restart does not reopen the agent. So Josh saw the heading renamed and
everything under it still "Gemini-Sub" (browser check on main's page: exactly that).
The SERVER side was right for every provider: the card's `name` comes from status.readIdentity, where the recorded
name wins, and the rename also rewrites the name line in the agent's own file. Project rooms label posts through
pjNameOf, a lookup in PROJECTS members (named from the cards), reloaded after a rename.

## Decision
`followRename(fresh)`, called at the top of the poll's CURRENT block, before anything paints a name: it copies the
fresh card's `name` onto `CURRENT.name` and repaints the heading (so a rename made anywhere else reaches this
page). One derivation: the card's name. Only the name, so the rest of CURRENT keeps its open-time meaning. No card,
another agent's card, or an empty name leaves it as it was.
Rejected: replacing CURRENT with the fresh card on every poll (other fields of CURRENT are read with open-time
meaning, a much wider change); patching each of the dozen readers to look the name up (twelve derivations).

## Sweep (an Explore pass over every place a name is drawn) and what it changed
In this PR, because they are the same bug on the same page or in the rooms the card names:
- followRename also repaints the initials, the Instructions lede ("What <name> is for", now one function,
  paintInstrLede, shared with openDetail) and the memory box.
- The RENAME BOX follows too, and this one is not cosmetic: Save always sends its value as the name, so after a
  rename made elsewhere, saving the role would have renamed the agent BACK. It moves only while it still holds
  the old name and is not focused; a name somebody is typing is theirs.
- pjNameOf and tkMemberName: a former member (a room post or task row from before it left) is named by its
  current card (tskAgentName, the Tasks page's lookup), and by its id only when there is no card.
Filed as follow-up #4423 (different mechanisms, not the screen Josh reported): the Reports-to menu (built at
open), a pending "Replying to" strip (name copied at the click), the room reactions tooltip (session names from
the server), recommender room notes (names baked into stored text), and the community identity (registered once;
may be intended). (The meta note and dmWho were on that list too, and moved into this PR in review iteration 1.)
