## Decided
- The fix is rank 8.5, outside the window (just below "Kosmos recovers after your Mac sleeps" at 8, by choice). It has
  two halves. The PERMISSION-PROMPT half reaches adopted default-mode sessions and protected-folder prompts the allow
  hook leaves to the person (launched agents otherwise run in bypass mode with the allow hook, since 0.7.28). The
  QUESTION-MENU half (#5743) reaches ANY Claude agent that asks a multiple-choice question, launched or not, where a
  room post or another automatic line used to pick the highlighted default. The call: the window is for features a
  person will use; a fix that stops Kosmos answering for you is named on the versions page, not as one of the five.
- #5746 (a reply by number reaches Claude's question menu as the answer, not the highlighted default) is the one other
  user-facing change merged since 0.7.36 froze (b2e12109350d); it is rank 7.5, also outside the five: a fix to how a
  reply lands, smaller than any of the five. The rest since the freeze is not a highlight: #5434's fsync slices are
  durability work (one, undoindex22, stops an unreadable Undo index from deleting the kept copies, a data-safety
  fix with no new behaviour to announce), #5727 is test migrations, and #5643 makes `kosmos task ran` retry when the board did not
  take a run (one run id per command, so a late retry is not counted twice), agent-side reliability. 0.7.37's versions-page entry names the permission fix (written on the cut box as ~/.release-entry-0737.html; the cut stamps it into chaoskosmos-site's versions.html).
- ORDER, and when THIS merges: #5760 is not merged yet, and this PR is merged only AFTER #5760 is on main (its
  merge-on-green is started once #5760 has merged), so main never holds a pending highlight for code it lacks.
- #5760 is not merged yet. The 0.7.37 cut requires BOTH #5760's merge sha and this PR's on main (the waiter
  passes both to the cut, which aborts unless each is an ancestor of the frozen tree), so the pool's `since` 0.7.37 is
  true of the build that ships it.
- Distinct ranks (7.5, 8.5) so no tie-break decides the order (ties go to the newer version).

## Weakest premise
That a fix belongs on the versions page and not in the five, even though its question-menu half reaches every Claude
agent that asks a multiple-choice question (how often that happens is not measured). The permission-prompt half is
narrow by #5760's own exposure statement (not my measurement; #5755, adopted agents get the launched setup, is
unmerged). If question menus turn out to be common and the silent default answers were seen by people, the fix
belongs in the window. What would change it: Josh wanting safety fixes announced. That is one
number in the pool (rank 2.4 would put it third, after Claude Haiku 5.5 at 2).
