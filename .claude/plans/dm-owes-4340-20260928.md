# #4340: "Nothing back yet." under a direct message (Sonya Blade, 2026-09-28)

## Finished means (Liu Kang, m2393)
The DM thread shows "Nothing back yet." after 2 minutes when the agent owes a DM answer, and not after it has
answered; a test that goes red on main; a browser-check arm.

## Cause (measured)
The DM thread route (server.js) set `owes` from `messages.owesReply(name)`, which reads the `kosmos msg` /
room-post log (rows of kind message/post). The person's DM and the agent's `kosmos reply` are rows of the chat
DIRECT thread, which holds two kinds of row: the person's (no `from`, with a `delivery`) and the agent's, all
written through keepAgentReply (`from` = the agent). So a person DM never made `owes` true, and a colleague's `kosmos msg` could
make it owe under a thread whose answer is visible (both confirmed by server.dm-owes-4340.test.js on main).

## Decision
`chat.dmOwes(rows, agent)`, pure, in engine/chat.js beside readThread:
- heard = the newest person row whose `delivery.state` is placed (an undelivered DM was never received; the rule
  lives in the engine alone, the page draws its answer) and that is not a MENU ANSWER (a row with a `wire`, the keystroke that
  picked one of the agent's own buttons, which appendMessage stores; review iteration 1). The agent carries on
  working and owes nothing for a button;
  sent = the newest row with `from === agent` (its replies, drained replies, and Kosmos's daily-limit notice said
  in its name, all through keepAgentReply);
- owes when heard exists and is newer than sent; clear when never spoken to; unknown when rows is null (the route
  could not read the thread), never a confident clear; a row whose `at` does not parse is skipped.
The route calls it on the STORED rows (before the live question and account rows, which are Kosmos's own and not
a reply), matched on `name`, the key the thread was read under (readThread refuses a file whose stored agent
differs, so every agent row it returns carries that name; review iteration 1).
`messages.owesReply` had no other caller and is DELETED with its five tests, rather than left exported and
covered by tests that nothing in the product reaches (engine.reachable.test.js's exact shape); the `messageLog`
alias existed only for it and is removed too. The page (dmOwesLine) keeps its three states and its 2-minute grace, and now times the grace from the engine's
`owes.lastHeardAt` instead of re-filtering the rows itself: ONE derivation of which message is owed (convention #5,
review iteration 6). The undelivered-row rule it used to enforce lives in the engine, where `owes` is never true for
it. Its unknown sentence says "this conversation".

Rejected: keeping owesReply and adding the DIRECT rows to it (it is the room/msg record, and the thread box is a
different conversation); reading only the served, question-injected rows (a live question row is not a reply).
#3226's firstContact() has the same rule and can share dmOwes once it merges.

## Known limit: a TYPED answer to a question still counts as owed (decided in review iteration 5)
Iterations 3 and 4 tried to excuse it with a `toQuestion` mark set by the DM POST when the card read NEEDS_YOU.
Iteration 5 showed that was built on a wrong model, so it was REMOVED rather than patched:
- appendMessage stores a fixed list of fields and dropped `toQuestion`, so it never reached the thread (every test
  hand-built the row and missed it);
- the "second, fresher read" (delivery.paneState) is the same roster snapshot as the route's card;
- NEEDS_YOU is wider than "a question is on screen": a reported needs_you can stand for hours while the person
  writes about other things, and every such message would have been excused.
Nothing stored says a typed row answered a question, so it is not told apart. The line can therefore show under a
typed answer to a prose question; that fails toward a visible "Nothing back yet.", which the person can read against
the thread, never toward hiding an owed answer. Pinned by a KNOWN LIMIT test. What would change my mind: a stored,
per-message fact that it answered the question on screen (for example the question's own text captured with it).

## Decided, open to overturning (review iteration 2); Liu Kang RULED keep (m2410); follow-up #4354
Kosmos's daily-limit notice ("I paused myself at today's token limit ... I'll start again tomorrow") is written in
the agent's name through keepAgentReply, so it clears the debt, although it does not answer the person's question.
Kept deliberately: the notice is a visible row in this very thread that tells the person why no answer is coming and
when work resumes; "Nothing back yet." under it adds nothing and reads as the agent ignoring them. Rejected: marking
Kosmos-authored rows so dmOwes can skip them (a new row field and a change to every such writer, larger than this
card). What would change my mind: a ruling that the line should persist until a real reply, whatever else is said.

## Weakest part
`owes` is taken on the FULL stored thread, before the 200-row tail the page is sent (review iteration 7: dmOwes
skips menu answers and undelivered rows, so a tail made only of those could hide an owed message just outside it;
pinned by a route test with 201 menu answers behind an owed DM, and by the source order). The residual is cost: a
very long thread is scanned in full on each 5-second poll. It was already read in full to slice it.
