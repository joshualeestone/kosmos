# dailylog-full-5855: the daily-log compiler must not destroy day files after a conversation rolls over

Card: #5855 (follow-up to #5841 piece 2). This is step 1 of two; step 2 is on the card.

## What is wrong

A conversation that reaches its message cap will roll over (#5841 piece 2, branch `dmroll-5841`, not on main yet): the
full file is moved aside as `<thread file>.<stamp>.<pid>.<ms>[.<n>].full` and a fresh file carries a copy of its
newest rows. `engine/dailylog.js` recognises conversation files by `.json` at the end of the name, so it does not see
`.full` files. A compile after a rollover would then, from the current file alone:

- **rewrite** a day that straddles the rollover with only the rows the fresh file carried (the card does not name
  this one; the control test shows it), and
- **prune** every day whose rows now live only in a `.full` file.

Both remove compiled history that is still true. Nothing calls the compiler today; it has a working command line.

## The change (step 1)

`readConversations` counts `.full` files (`rolledOver`). With even one present, `compileAll` refuses the run: nothing
written, nothing pruned, `refused: 'rolled-over'` in the summary. The command prints why to stderr and exits 3. An
`onlyDay` run is refused too, since that day may be the straddling one. The originals in `chats/` are not touched.

It needs only the suffix, not the rollover's helpers, so it can merge before or after the rollover does.

## Rejected

- **Refuse only the prune**, which is what the card offers as the minimum. The rewrite of the straddling day loses
  rows too, and a day file holds every conversation's rows for that day, so the write cannot be skipped per
  conversation.
- **Read the `.full` files now, by hand.** The fresh file repeats the carried rows; reading both needs the rollover's
  own `continues` and `carried` rules. Those live in `chat.asideChain` and `chat.chainRows` on an unmerged branch.
  Copying them here would be a second derivation of rules still in review. That is step 2, with the real helpers.

## Done looks like

- With a `.full` file present: the summary says refused, every existing day file is byte for byte as it was, and no
  new one appears. Without one: the compiler behaves exactly as today (the existing 32 tests).
- A control shows the damage the refusal prevents: the same rollover with the full file invisible prunes two days and
  shrinks a third.

## Measured (c3c6e8730 plus this change)

- `engine/dailylog.rollover-5855.test.js`: 7 pass. Against main's compiler 6 of the 7 fail.
- `engine/dailylog.test.js` and `engine/dailylog.misroute-digest-3224.test.js`: 32 pass, unchanged.

## Weakest part

**The refusal turns the daily log off for anyone with a rolled-over conversation, until step 2.** Today that is
nobody: the rollover is not merged and the compiler has no caller. If the rollover ships and someone wires the
compiler before step 2, they get a clear refusal instead of a daily log.

**The file name is the rollover branch's, read before it merged.** A test pins the suffix to `ROLL_KIND` in
`engine/chat.js` once that exists, and until then checks chat.js still refuses at the cap, so the pin cannot go
blind silently. If the branch changes its naming before merging, that test fails on the merge.
