# h29-flake-4203: H29 waits for the backup line to clear

Card: #4203 (render-assistant-hosted-3660 H29 "and the backup line is gone" fails first try on main, passes on retry).

## Cause (read from web/index.html asbSend, then reproduced on purpose)
In the fallback, a send asks the board first (asbConfirmGuide -> asbFallbackFrom clears ASB.fallback), posts to the
guide's thread (the box clears on `placed`), and only repaints the panel in its `finally`, AFTER one more poll round
trip: `await asbPoll(true); ASB.sending = false; asbPaint();`. H29's waits end when the box clears and the post lands,
which is before that repaint, so its single read of `#asp .asp-note` could catch the old "helping on Kosmos's backup"
line for the length of one poll. On screen the line clears within that poll: a check timing issue, not a product bug.

## Change (test-only)
`docs/browser-checks/render-assistant-hosted-3660.js`: H29's backup-line assertion waits (bounded 8s, the file's own
waitFor) for `ASB.fallback === null && note === ''`, and on failure prints what the note said.

## Evidence (tools/browser-checks.sh, KOSMOS_BC_CI_ALLOWLIST=render-assistant-hosted-3660, frozen at the commit named)
- The fix (10fbcf390): PASS 3 of 3, no retry.
- Control A (5be0be1ad, a TEMP 1.5s delay before the post-send repaint): the fixed H29 still PASSES.
- Control B (3c332a0e5, the same delay with main's read-once H29): FAILS on both attempts. The flake, reproduced on
  demand; and the fix is what makes the difference.
- Both TEMP commits reverted (ab6342f6f, 450f6446a); content equals 10fbcf390.
