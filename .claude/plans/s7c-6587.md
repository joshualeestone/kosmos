# s7c-6587: the Kosmos+ service key warning outside Settings (S-7a slice 2b)

Card: kosmos#6587 (detail private). Stacked on s7b-6587 (slice 2a: the engine state, /api/remote serviceKeys, and the Settings line #plus-sk-line), itself on s7a-6587 (the verifier, PR #6672).

## Finished looks like
With a mismatch, a person on any view but Kosmos+ sees one fixed warning card in the floating stack, right after the certificate notice. Review opens Kosmos+ with keyboard focus on the pane's line; Close puts it away for this browser session. Every other state raises nothing. As shipped (state off) nobody sees anything.

## Decided
- **The certificate notice's pattern and look** (#6613: `utoast cwnote`, role=status on the words, Review and Close, hidden on Kosmos+, repainted by syncPlusChrome when Kosmos+ opens or closes, carried on pollCwNote's /api/remote answer). Rejected: a second poll (one answer serves both).
- **Put away for the session, not for good.** The server passes only a state, so there is no finding key like #6613's: a put-away that lasted would also hide a later, different mismatch. sessionStorage (and the tab's own memory when storage is blocked); a new visit shows it again while the mismatch lasts. Kosmos+'s own line is never put away. Weakest premise: a person who closes it is reminded once per visit, which may feel repetitive; it is a security warning that should be rare, so repetition is the safer side.
- **Review puts it away at once**, unlike #6613, which waits until the pane says the finding: the pane's line for this one is painted from the same answer, and always says it while the mismatch lasts. Weakest premise: a pane that fails to paint costs the person the notice for this session; the line comes back on the next paint.
- **An older board's answer (no serviceKeys)** leaves the notice as it is, as the line does.
