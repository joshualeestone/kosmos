# Widen render-create-form's #2140 settle-wait for the cut box's resident-fleet load

**Branch:** `ick-3275-3b` · **Blocks:** the 0.6.80 / 0.6.81 tmux release cut (Josh's #1).

## The failure

The 0.6.80 cut failed 3b on `docs/browser-checks/render-create-form.js`'s OpenAI-park
assertion (`modelDisabled:false`, `why:""`), and the as-is re-cut RE-SPIKED it TWICE,
byte-identical on both chromium and webkit. Not a one-time spike.

## Root cause (test-timing, NOT product, NOT #3275)

`paintOpenaiCreateModel` (web/index.html) AWAITS `/api/accounts/openai/models?dir=...` before
it sets the park note (`#create-model-why`). render-create-form drives OpenAI selection and
waits up to 8000ms for that note to settle, then reads it.

- The product park WORKS: render-create-form is green in isolation (3x, both engines) AND under
  the full 3b suite locally (~160 checks, 0 failures) on the exact merged main (#3275 + #3274).
- The cut box (Mortals) carries a RESIDENT 7-agent fleet, genuinely hotter than any local run.
  Under that concurrent-fleet starvation the async models round-trip loses the race past the
  8000ms bound, so the note reads empty and the assertion aborts.
- #3275 is not implicated: its diff never touches the create form / paintOpenaiCreateModel, and
  render-create-form navigates to /?tab=create (not onboarding), so frFireTmuxA11yRegister never
  fires in its flow. The blame was a coincidence of timing; the measurement disproved it.

Quiescing Mortals is not an option (the fleet is resident, not the cut's activity; a cut that
only passes quiesced is fragile). The durable fix is a settle-wait bound wide enough to survive
the real cut-box load with margin.

## The change (one file, test-timing only)

`docs/browser-checks/render-create-form.js`: widen the #2140 settle-wait deadline from 8000ms
to 30000ms (~4x, generous margin past the observed starvation, still bounded so a genuine
regression fails in 30s rather than hanging). No product change.

Targeted: only the settle-wait needed it. The earlier 8000ms waits (`#pick-pm`, `cstep-name`)
survived Mortals (the form rendered; the failure was specifically at the park), so they are
left unchanged rather than widened unnecessarily.

Rejected: mocking `/api/accounts/openai/models`. It would remove the race deterministically but
change the check from a real-board integration test to a mocked one AND risk returning the wrong
response shape for a ChatGPT account (the park asserts `modelDisabled:true`, which only the
not-listable branch produces). The wider bound preserves what the check tests.

## Verification

- render-create-form PASSES both chromium + webkit with the 30000ms bound (isolation).
- `node --check` clean; em-dash clean.
