## Definition of done (what is TRUE when finished)

A person can, from the Agents page, SELECT MULTIPLE agents and remove them in ONE user-initiated action, so a tester (Josh) can clear residual/unwanted agents (the demos) before importing their real roster, without opening each agent's detail panel and removing it one at a time. The bulk remove REUSES the existing clean per-agent remove (DELETE /api/agent/<name> -> removal.remove, which is RESTORABLE: task disabled, process gone, card gone, restorable), so nothing new about the removal semantics is invented. It is USER-INITIATED only (never auto-deletes). Per-agent remove (detail panel) is unchanged. Real/imported agents are unaffected and remain (they "supersede" by simply being the roster the user keeps). A light confirm (removal is reversible) names the count; the result reports how many were removed / refused, with the existing restore path still available. Fresh-machine / OpenAI / non-Agents pages are unchanged.

## Mechanism (mapped on origin/main, cite by content not line)

- Remove route: `DELETE /api/agent/<name>` -> `removal.remove(name)` (server.js, the `rm && req.method === 'DELETE'` block) returns `{ outcome, ... }` (OUTCOME.REFUSED = 400, else 200; a PARTIAL is 200 by design -- the screen branches on `outcome`). RESTORABLE via the sibling restore route.
- Agent cards: `<div class="acard ${...}" data-agent="${esc(a.sessionName)}">` (web/index.html ~13580 off/notrunning, ~13644 normal). The card carries `data-agent` = the sessionName, which is exactly the `<name>` the DELETE route takes.
- Per-agent remove today: the DETAIL panel's `#d-remove-agent` / `#d-remove-start` ("Remove this agent…"). Bulk-clear is ADDITIVE to this, on the grid, not a replacement.

## Design

- A user-initiated SELECT mode on the Agents grid (a "Select" / "Manage" toggle in the Agents header). In select mode each `.acard` shows a checkbox (real, focusable, labelled by the agent name); clicking selects/deselects. A "Remove selected (N)" button is enabled when N>0.
- On confirm (a light in-UI confirm naming the count, since removal is reversible), remove each selected agent by the EXISTING `DELETE /api/agent/<name>` (sequential; the route is per-name). Aggregate the outcomes; report "Removed N (M refused)" with the count, and refresh the roster. The existing restore path remains for an undo.
- SUPERSEDE: no special demo-detection (createdBy:null is the default, not a reliable demo marker, so auto-identifying demos is unsafe). Real agents simply remain after the user clears what they chose. This keeps it user-initiated and never auto-deletes.
- Coordinate with Renet's discovery-panel-on-load gating (the complementary declutter half of #2651) -- disjoint surface (grid multi-select vs the found-agents panels).
