# #4160: a TEMP browser-check quarantine cannot outlive its cut

**Branch:** `quarantine-guard-4160` · 2026-09-27 05:40 CDT · Baron Draxum

## What happened

afd16d894 (mine, 2026-09-15) quarantined regress-a-night for the 0.6.67 cut: it printed
`PASS ... QUARANTINED` and exited 0 before its browser started. The real fix sat unmerged and
nobody reverted it, so every cut's 3b reported the heaviest page check green for twelve days while
it checked nothing (#1079, found by Ice Cream Kitty).

## The two halves (as the card asks)

1. **A source test with an expiry.** `browser-checks-quarantine-guard.test.js` (root, so `yarn test`
   runs it) fails when a check has the word PASS on a code line within 6 lines above a `process.exit(0)`
   that comes before its LAST non-comment `.launch(`, unless the dozen lines above carry
   `// QUARANTINE until=<version> card=#<N>: <reason>` AND the PASS line nearest the exit prints the upper-case token
   QUARANTINED in a string (so the print that belongs to this exit carries what the harness reads). It also fails once the version
   reaches `until`: package.json's, or `KOSMOS_QUARANTINE_AT_VERSION`, which release.sh step 1e sets to the
   version being cut so an expiry refuses before the bump. Measured on all checks: the only hit is the real
   one (regress-a-night.js:58).
2. **The harness reports it as QUARANTINED, not PASS, and refuses the run.** `tools/lib/bc-quarantine.sh`
   (sourced by `tools/browser-checks.sh`, which refuses to run if it does not load): after a check exits 0,
   output with the whole word QUARANTINED (upper case, as written) on any line is logged as
   QUARANTINED and recorded (so is output awk cannot read: it fails closed); the summary adds it to FAILED unless `KOSMOS_BC_ALLOW_QUARANTINE=1`, which is
   printed with the names it let through. Release 3b runs this script, so a cut refuses by the same path,
   and its summary shows the QUARANTINED lines.

## Evidence

- Real harness, `KOSMOS_BC_CI_ALLOWLIST=regress-a-night` on main's quarantined check:
  before this change `PASS regress-a-night`, rc=0; with it rc=1, FAILED names it; with the override
  rc=0 and the override line printed.
- `tools/test-bc-quarantine.sh`: 39 assertions, wired into test:shell. Planted regressions each go red: a PASS
  path bypassing the note, the verdict call removed, a case-sensitive match, the fail-closed guard removed,
  release 3b's grep without QUARANTINED.

## Review rounds

1. opus: fail closed if the lib does not load; scan from the LAST non-comment launch (eight checks launch
   more than once) with a PASS match anywhere in a string and a 6-line window; a marked
   quarantine must print QUARANTINED; the verdict runs before the run log so it counts the refusal; release
   3b's summary shows QUARANTINED lines. All fixed, each with a control.
2. sonnet: the source test's QUARANTINED match is now case-insensitive like the harness; an exit on a
   comment line is not an exit. Fixed with controls.

3. opus: an expiry was caught only after the cut's pushed bump, so release.sh step 1e now runs the source
   test against the version being cut (KOSMOS_QUARANTINE_AT_VERSION), before the bump; the harness counts
   "quarantined" only on a PASS line (the product has a quarantined moderation status); header comments
   say LAST launch; `${QUARANTINED[*]:-}` for bash 3.2; a control pins the 12-line marker window.

4. sonnet: the source test required quarantined anywhere in the 6-line window while the harness needs it on
   the PASS line, so it now requires both on one line; step 1e's diagnostic pipeline tripped `set -e` before
   its message, so the output is captured once. test-bc-quarantine.sh now runs release.sh's real step-1e
   block under `set -euo pipefail` against a fixture (refuses at until, names the check, passes below it).

5. opus: the harness required PASS before quarantined, so it is order-free now (awk, since a grep pipe
   breaks under pipefail); the source test requires both in ONE string literal (two literals on one source
   line print two output lines); a line that only starts with a block comment is code; PASS is found on
   any code line (a multi-line template literal). Plan description rewritten to match the code.

6. sonnet: lower-case "quarantined" is a real moderation status (engine/communitystore.js), so a fully-run
   check reporting on it would have been refused; both halves now match the upper-case token QUARANTINED
   only (this supersedes rounds 2 and 3's case-insensitive match, keeping the two halves identical).

7. opus: a marked exit could pass on a neighbouring exit's string, an unprinted string, or a literal whose
   \n escape splits the words, so only the PASS line nearest the exit counts and escapes split it; three
   controls had gone vacuous with round 6's upper-case switch and use QUARANTINED again; a line starting `*`
   is a comment only in the JSDoc shape; release 1e's grep names the real message.

8. sonnet: one console call with two arguments prints one line, so its literals are read together (two
   calls still count as two lines); a `*/ code` line is code in both block-comment shapes; step 1e's grep
   also shows the test's wrong-place sanity message.

9. opus: under a UTF-8 locale macOS awk exits 2 on an invalid byte and that read as "no match", i.e. PASS;
   awk now runs with LC_ALL=C, and an awk error fails closed (recorded as QUARANTINED, saying it could not read).

10. sonnet: step 1e's diagnostic only knew the scan's own messages, so another failure (a control, a syntax
    error) printed a misleading pass line; it now prints the failing test names and errors, with a test.

11. opus: requiring PASS on the token's line let a coloured PASS, PASSED or a line with no PASS through as a
    pass, so the harness now reads the token QUARANTINED alone, on any line (the upper-case rule already keeps
    the lower-case moderation status out); two word-boundary tests could not fail and now use QUARANTINEDX /
    XQUARANTINED; a none-recorded assertion ran after a reset and could not fail; step 1e shows a missing node.

Residuals, accepted (the source scan is a heuristic; the harness does not depend on it): a PASS-exit between
a function that launches and its later call site (import-agent-flow.js has that shape), a PASS more than 6
lines above its exit, `process.exitCode = 0; return`, a bare early `return` from the main function, unusual
exit spellings such as `process.exit(+0)`, and early exits whose output does not say PASS are not flagged.
Step 1e reads the shared main checkout, not the frozen tree; the cut's own suite after the bump backstops it.
- The source test was red on main while regress-a-night was quarantined, and is green on main since Kitty's
  #1079 fix merged (7908b3235); this branch is rebased onto it.

## Sequencing

Merges after the 0.7.01 freeze (taken at 32fc398a2) and after Kitty's regress-anight-1079 (merged, 7908b3235),
since the source test was red until that landed and the harness change moves the cut's 3b gate. Both are met.

## Rejected

- Treating the honest `SKIPPED` line as a skip too (the card's "or SKIPPED"): the harness already
  refuses a run with no Playwright up front, and ~90 checks print it only in that case. Widening would
  change nothing observable today and risks reading unrelated SKIPPED text.
- Detecting "no browser launched" at runtime: the harness cannot see inside a check; what it prints is
  the only signal it has.

## Weakest premise

That a quarantine always prints the word QUARANTINED. A check could skip itself with other words and
PASS. Half 1 is the backstop for that: it reads the source, not the output, and flags any early
PASS-then-exit regardless of wording.
