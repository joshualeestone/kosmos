# acct-stop-focus-4271: focus stays in the dialog when a Claude sign-in panel is put away

Card: kosmos#4271 (the #1918 stranded-focus class).

## Measured before building
On origin/main, acctFlowPaint's flow-ended branch hides #acct-flow and never moves focus. The
browser check's control arm (the origin/main page) reads document.activeElement = BODY after
Stop, after a stuck poll while typing the code, and after a start that answers already ended.

## Change
- web/index.html acctFlowPaint: read `flow.contains(document.activeElement)` before hiding the
  panel; if focus was inside and the phase is not 'connected', call acctFocusAfterFlow(btn).
- acctFocusAfterFlow: focus "Start the sign-in" (#acct-add) when it is enabled and rendered,
  else the provider picker's .pcombo-trigger when that is rendered (the fallback acctMuseShow uses).
- acctAddStart: /api/connect/start can answer with a phase that has already ended (the review
  found it: server.js answers with connect.start()'s own state). The panel is then hidden and
  the old say.focus() was a no-op, so focus goes to #acct-add-note when it has the reason, else
  to Start. Connected is left to acctShowSuccess in both places.

## Call, and what I rejected
- After Stop or a polled failure, the target is Start (#acct-add), not the picker the card
  suggested: it sits right above the panel, is re-enabled in the same branch, and is where the
  person starts again; Muse's own Stop does the same (focuses its Go). The picker is the fallback.
  The reason reaches a screen reader through #acct-add-note's polite live region.
- After a start that answers already ended with a reason, the target is the note (with none, Start via acctFocusAfterFlow), which is what
  acctAddStart's own failure paths already do (note.focus()). That makes the two endings differ:
  a polled failure focuses Start and lets the live region speak; a failed start focuses the
  note. I kept the polled case on Start because the person has just watched the panel run and
  the next thing they do is start again; I would change it if a screen-reader pass found the
  live-region announcement lost next to the focus move.
- Weakest premise: the picker fallback is unreachable from the page (no natural state hides
  #acct-add while the panel runs), so the browser check cannot drive it;
  web.acct-focus-after-flow-4271.test.js runs the real function on a stub instead (Start
  rendered, not rendered, disabled, neither rendered; mutants on both guards red).
