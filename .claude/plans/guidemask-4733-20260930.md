# guidemask-4733: mask the setup guide's words on task messages, built notes and status reports

Card: kosmos#4733 (found by Angel in review of #4491 slice 4; read from code, not run). Branch
`guidemask-4733`, off origin/main 4569e19a1.

## The finding, checked on main before building
#3769's third layer masks anything shaped like a secret out of what the setup guide says (`guideMasked` in
server.js, over `engine/secretmask.js`). On main it is applied to the guide's replies (`keepAgentReply`), its
messages and room posts (`messages.setSenderTextFilter`), the purpose it gives for an agent it makes, and the
thread as served. Three writes the guide can make with its own agent token took its text as sent:

| write | route | where the text went unmasked |
|---|---|---|
| `kosmos task message` | `POST /api/project/:id/task/:n/message` | `tasks.say(id, n, body.text)` (the task's record) and the preview typed to each assignee |
| the note on `kosmos task built` | `POST /api/project/:id/task/:n/built` | `tasks.setBuilt(..., { note: body.note })` (the task row and its history) |
| a status report | `POST /api/report` | `selfreport.record(who, { because: body.text, on, owner, until })` |

Still live at 4569e19a1: confirmed by reading the three sites, and by the mutation runs below (each site put
back as it was turns the new test red).

## The change
`server.js`, one call per site, each keyed on the sender the route has already identified:
- task message: `saidText = guideMasked(senderCard.sessionName, body.text)` when the caller is an identified
  agent; both the recorded text and the preview use it. The screen, and a caller nobody could identify (recorded
  as "An agent"), pass as sent.
- task built: the note goes through `guideMasked(by, ...)`.
- status report: `because`, `on`, `owner` and `until` go through `guideMasked(who, ...)`. The card names the
  text; the other three are the same kind of field (free text the reporter writes, shown with the report), so
  they are masked with it. `waiting` is two numbers, `project` is an id, `state` is a fixed word.
- `guideMasked` is unchanged: it returns a non-string, and any other agent's text, as it came.

## Decisions
- **Call:** mask at the write, in the route, where the sender is already known. **Rejected:** (1) masking
  inside `tasks.say` / `selfreport.record`: neither is told who is writing, and both are called for the person
  too; (2) masking every agent's text: #3769 decided the mask is the guide's (other agents are given keys on
  purpose and must be able to say them to each other); (3) masking the task record as it is READ, the way
  `guideMaskedRows` does for threads: a task message's record does not say who wrote it, so there is no row to
  key on.
- **Not covered, stated so nobody reads this as complete:**
  - a task message or built note the guide recorded BEFORE this ships stays as recorded (no read-side mask, for
    the reason above). A status report is replaced by the guide's next one.
  - a guide that sends with no agent token and no pane is not identified, so it is not masked. A Claude guide
    on a Mac cannot do that (the board token is what such a call needs, and #4728 measured that its commands
    cannot read the data folder); other guides can (#4728 is that card).
  - the other writes open to an agent token were read, not changed: `react` takes an emoji only
    (`normalizeReactionEmoji`), `msg` / `post` / `reply` and the team purpose were already masked.
- **Weakest premise:** that these three were the last unmasked free-text writes. I checked the routes an agent
  token opens (`AGENT_TOKEN_ROUTES`, `AGENT_TOKEN_ROUTE_PATTERNS`, `LOOPBACK_AGENT_ROUTES`) and not every route
  a board-token holder can reach: a guide with the board token can write anywhere the person can.
- **Not checked (the card's own open question):** whether the guide is ever on a project in normal use, which
  the two task writes need. The fix does not depend on the answer.

## Tests
New `server.guide-mask-4733.test.js`: four tests through the real routes with real agent tokens
(`sendertoken.mint`), reading what was stored:
- task message: the record and the route's answer hold the mask and not the key; the line typed to the assignee
  (captured at `chat.deliverAsync`) holds the mask and not the key. Control: another agent's same words are
  recorded and previewed as sent.
- built note: `builtNote` and the task history. Control: another agent's note as sent.
- status report: `because`, `on`, `owner`, `until`. Control: another agent's report as sent.
- a report with no `on` / `owner` still records them as absent (the mask invents nothing).
