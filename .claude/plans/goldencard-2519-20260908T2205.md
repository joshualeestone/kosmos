# kosmos#2519: render-talk's reopen arm on a box with no live agents

## The card, and which option I took

`docs/browser-checks/render-talk.js`'s reopen arm calls `realCard()`, which pulls a REAL card from
`status.snapshot()`. On a box with no agents there is no card, and the arm pushed a PROBLEM, so 3b
went red on an environment fact rather than a product one. That blocks any cut on a quiet box, which
is the mortals box Josh's ruling moves all cuts to.

The card offers two options and prefers the first:

1. **A recorded golden card, used as a fallback.** Keeps the arm exercised.
2. A loud but non-failing skip. Simpler, loses the coverage.

**Taking option 1**, and the constraint the card states is the whole design problem: *"whichever is
chosen must not reintroduce the invented-fixture bug the check exists to catch."*

## Why that constraint is the hard part

`render-talk.js`'s own header, on why the card is not hand-built:

> `openDetail` reads fields this script has no business knowing about (it wanted `context.percent`
> first), and a literal invented here is exactly the fixture that made six rounds of review pass
> against a world that does not exist.

A real card carries **30 keys**, several nested. A literal written by hand would miss some and would
be wrong in a way no assertion here could see.

## The design

**RECORD, do not write.** `docs/browser-checks/fixtures/agent-card.json` was produced by running the
live path on a box WITH agents. `tools/capture-agent-card.js` neutralises identifying string
CONTENT while PRESERVING each field's type (a null stays null, because status.js emits null for
role, stateEvidence and stateProject on many real cards), scrubs EVERY string under `profile`
rather than a listed subset (it is free-form and the tree also writes absolute paths into it), and
PINS the volatile values (hasAvatar, context.tokens, context.percent, two timestamps) so a re-run
is byte-identical unless the shape moved.

📌 **An earlier version of this paragraph said "neutralising ONLY identifying string content".**
That was false of the tool, which also pins a boolean and two numbers, and it was the same false
claim the tool's own header carried until it was corrected.

**Say which card ran.** `realCard()` returns `{card, source}` rather than a bare card. A silent
fallback would make a quiet box and a populated box print identical output while driving different
inputs, and this file has corrected that class three times already.

**A NOTE is not a FAIL.** The release gate anchors on `^\s*(FAIL|✖)`. Notes print with a `NOTE`
prefix on their own lines and take no part in the exit code, or the fix would re-create the red it
removes.

**Guard the recording, and on EVERY box.** A capture rots the moment `status.snapshot()` gains or
drops a field. Two guards, deliberately in different places:
- the check compares the full NESTED shape, live against live, on any box with a live card;
- `yarn test` compares the TOP-LEVEL shape box-independently, via `test-support/fleet.js`, which
  drives the real `status.snapshot()` over a fake pane source.

📌 **My first version of this section claimed the quiet box "is the only one that cannot check it".
That was false**, and it excused a real gap: nothing verified the fixture on the box this change
exists for. The nested half stays live-only for a measured reason: a fleet agent has no recorded
usage, so its `context` carries `neverRecorded`/`percent: null` where a real agent's carries numbers
and ceiling fields. Demanding nested equality against a fleet card asserts something untrue.

## What I rejected

- **Option 2 (skip).** It is what the card calls weaker, and it would leave the reopen arm
  uncovered on precisely the boxes cuts are moving to.
- **A hand-written literal.** Named by the card and by the file's header as the defect to avoid.
- **Faking a live card in the test.** The test loads the shipped resolvers out of the source file
  rather than reimplementing them, so it cannot drift from what runs.

## Weakest premise

**I have not run the browser check.** This is the static half: the resolvers, the fixture, the
source-level guards. Running `render-talk.js` needs the shared browser, and doing that on this box
at load would add exactly the contention that makes browser checks unreliable (see #1079, which I
parked today for that reason). **Nobody has watched the reopen arm drive the recorded card through a
real page.** What would change my mind: a cut on a quiet box where the arm still fails, or one on a
populated box where the drift guard fires.
