# kosmos#2519: render-talk's reopen arm on a box with no live agents

## The card, and which option I took

`docs/browser-checks/render-talk.js`'s reopen arm calls `realCard()`, which pulls a REAL card from
`status.snapshot()`. On a box with no agents there is no card, and the arm pushed a PROBLEM, so 3b
went red on an environment fact rather than a product one. That blocks any cut on a quiet box, which
is the mortals box Josh's ruling moves all cuts to.

The card offers two options and prefers the first:

1. **A recorded golden card, used as a fallback.** Keeps the arm exercised.
2. A loud but non-failing skip. Simpler, loses the coverage.

**Taking option 1**, and the constraint the card states is the whole design problem: *"whichever is
chosen must not reintroduce the invented-fixture bug the check exists to catch."*

## Why that constraint is the hard part

`render-talk.js`'s own header, on why the card is not hand-built:

> `openDetail` reads fields this script has no business knowing about (it wanted `context.percent`
> first), and a literal invented here is exactly the fixture that made six rounds of review pass
> against a world that does not exist.

A real card carries **30 keys**, several nested. A literal written by hand would miss some and would
be wrong in a way no assertion here could see.

## The design

**RECORD, do not write.** `docs/browser-checks/fixtures/agent-card.json` was produced by running the
live path on a box WITH agents. `tools/capture-agent-card.js` neutralises identifying string
CONTENT while PRESERVING each field's type (a null stays null, because status.js emits null for
role, stateEvidence and stateProject on many real cards); scrubs EVERY value under `profile` -
strings, numbers and booleans, at any depth - rather than a listed subset, because `profile` is
free-form and an allowlist there rests on what the tree happens to write today
(`profile.doctrineVersion` is a producer number that reached the recording before this was
structural, and the tree also writes absolute paths into it); and
PINS to constants: PIN-LIST-BEGIN
`because`, `context.because`, `context.ceiling`, `context.ceilingAssumed`, `context.confidence`, `context.notYet`, `context.overCeiling`, `context.percent`, `context.tokens`, `disruption.startedAt`, `hasAvatar`, `model`, `modelName`, `name`, `role`, `session`, `sessionName`, `stateConflict`, `stateEvidence`, `stateProject`, `target`, `task`
PIN-LIST-END
(Paths, not names: `because` is pinned both top-level and under `context`.) So the
volatile measurements do not move. It does NOT make a re-run byte-identical: an earlier
version of this line claimed that, and `state`, `stateConfidence` and `runner` are restored from the
raw card while the structural booleans pass through as captured, so a re-capture minutes later on
the same box differs with no shape moved.

The enumeration lives ONCE, in the sentinel-bounded list above. A second copy stood here in the
bare-name form and claimed to be arm-checked while sitting outside the sentinels; an arm now reds
on any second enumeration.
That list has gone stale twice, in all four copies at once each time.

📌 **An earlier version of this paragraph said "neutralising ONLY identifying string content".**
That was false of the tool, which also pins a boolean and two numbers, and it was the same false
claim the tool's own header carried until it was corrected.

**Say which card ran.** `realCard()` returns `{card, source}` rather than a bare card. A silent
fallback would make a quiet box and a populated box print identical output while driving different
inputs, and this file has corrected that class three times already.

**A NOTE is not a FAIL.** ⚠️ The gate is WIDER than an earlier version of this line said. It is
not `^\s*(FAIL|✖)`: `tools/browser-checks.sh:730` greps `'^\s*(FAIL|✖)|Error|Timeout|REFUS|refus'`
when quoting a reason, so a note carrying any of those words would be quoted as the cause of a red.
The NOTE text on all three fallback paths matches none of the alternations, and an arm pins that:
it READS the grep out of tools/browser-checks.sh rather than restating it, extracts every NOTE
literal the check emits, and fails if any would be quotable.
⚠️ THAT SENTENCE WAS FALSE WHEN FIRST WRITTEN. It claimed an arm that did not exist: the nearest
one only checked that notes go through notes.push rather than problems.push, never comparing the
TEXT against the pattern. A document describing a test nobody wrote is this branch's most repeated
defect in its most convincing form, because it reads as evidence. The arm exists now.
This was the FOURTH copy of the narrow claim: render-talk.js and the test were corrected and the
plan was not. Notes print with a `NOTE`
prefix on their own lines and take no part in the exit code, or the fix would re-create the red it
removes.

**Guard the recording: ONE guard, and a stated gap.** `yarn test` compares the TOP-LEVEL shape
box-independently, via `test-support/fleet.js`, which drives the real `status.snapshot()` over a
fake pane source.

🛑 **The nested guard was REMOVED and nothing replaced it.** It compared the live card's nested
shape and fired on board composition rather than drift: measured on an 18-agent board, two distinct
`profile` shapes among our pane cards, one of them empty. A guard that reds a release cut on which
agents happen to be running is worse than none.
⚠️ **So nested drift is unguarded.** A rename inside `context` or `profile` leaves the top-level key
set identical and this recording drives a shape the page no longer consumes. `openDetail` reads
`context.percent`, so that is not hypothetical. Closing it needs a comparison that can tell drift
from composition, and I did not build one.

📌 **My first version of this section claimed the quiet box "is the only one that cannot check it".
That was false**, and it excused a real gap: nothing verified the fixture on the box this change
exists for. The nested half stays live-only for a measured reason: a fleet agent has no recorded
usage, so its `context` carries `neverRecorded`/`percent: null` where a real agent's carries numbers
and ceiling fields. Demanding nested equality against a fleet card asserts something untrue.

## What I rejected

- **Option 2 (skip).** It is what the card calls weaker, and it would leave the reopen arm
  uncovered on precisely the boxes cuts are moving to.
- **A hand-written literal.** Named by the card and by the file's header as the defect to avoid.
- **Faking a live card in the test.** The test loads the shipped resolvers out of the source file
  rather than reimplementing them, so it cannot drift from what runs.

## Weakest premise

**I have not run the browser check.** This is the static half: the resolvers, the fixture, the
source-level guards. Running `render-talk.js` needs the shared browser, and doing that on this box
at load would add exactly the contention that makes browser checks unreliable (see #1079, which I
parked today for that reason). **Nobody has watched the reopen arm drive the recorded card through a
real page.** What would change my mind: a cut on a quiet box where the arm still fails, or one on a
populated box where a nested-shape comparison fires.
⚠️ THAT LINE SAID "where the drift guard fires" and there is no drift guard: this same plan
records its removal ten lines above. Sixth copy of that stale reference on this branch, and the
first one found in the document that decided the removal.
