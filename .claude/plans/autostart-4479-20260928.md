# #4479: the "set up to start at login, but turned off" row counts only agents that exist, by their shown names

## Why
An external tester's Settings said "11 agents are set up to start at login, but turned off: alexis, eric, larry,
and 8 more"; none were his agents' names, and he thought they had been renamed (Josh, #admin, 22:53).
engine/machine.js agentAutostartCheck listed launchd's disabled overrides by raw job name. launchd keeps an
override after the job's plist is gone, and the only filter was Kosmos's own removed list, so any agent deleted
another way stayed "turned off" forever; and a renamed agent keeps its original job name.

## Change (engine/machine.js)
- A disabled job counts only when its agent's plist is still there (create.jobPresence: only ENOENT is "not
  there"; a check that could not look counts the agent as live, the safe direction, as the removed list does).
- Each is named by create.spokenName, the board's own derivation (the profile's name, then the identity line in
  the agent's instructions), now exported, so the row and the board cannot name one agent two ways.
- Seams for tests: opts.live(name), opts.shownName(name).

## Decided
- Stale overrides are left out and NOT cleaned: this is a read on every health tick, and launchctl enable on a
  label with no plist is harmless to leave. Rejected: an automatic tidy (a write from a read path), and a separate
  "old login entries" row with a button (nothing is wrong for the person, so nothing to show).
- Weakest premise: a present plist is not quite "on the board": createdroster also needs the worker folder and a
  valid plist. A plist left behind with its folder gone is still named here. That case is rare (Kosmos removes
  both), and naming it points at a real login job; a plist from another world is already scoped out by
  disabledJobsResult (nameInThisWorld).

## Tests
- engine/machine.agentautostart-4479.test.js, through the DEFAULT reads (a sandboxed LaunchAgents folder with real
  plist files, real profiles): the card's fixture (1 live renamed, 2 stale, 1 removed) shows exactly one agent,
  "Harbor"; CONTROL: the old rule (every override, by job name) shows 3; only leftovers is the all-clear; a live
  agent with no display name shows its job name; the row is still null on Windows. Red on the old code.
- engine/machine.agentautostart-3182.test.js: its aggregation arms now say their agents exist (live: () => true),
  so they no longer depend on the host's real LaunchAgents folder.

  named two ways. Now create.spokenName (exported). Test: no profile name, identity line "Neo" -> "Neo".

- The removed agent in the fixture has a plist, so the removed-list filter is tested on its own.
- Three mutations (no removed filter, profile-only name, existsSync) each red.
