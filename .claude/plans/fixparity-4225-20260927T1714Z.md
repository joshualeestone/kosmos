# fixparity-4225: one fixture rule for heavy-gate, the cut guard and the browser-run guard

kosmos#4225 (Liu Kang m1766, m1781), the follow-up to #4211. #4211 made the cut guard ignore a release.sh whose ancestry
proves a `node --test` runner. Two gaps were left out on purpose: heavy-gate also ignores a process in run-tests.sh's
`kt<digits>` sandbox (some fixtures detach from node), and the browser-run guard had no fixture rule at all.

## Done looks like
One shared classifier covers both fixture forms; heavy-gate, the cut guard and the browser-run guard use it without
drift; unreadable process state counts as a real run; focused controls prove both forms are ignored and an identical
ordinary process is still refused by both guards; tests never spawn a pgrep-visible release.sh or browser-checks.sh; a
missing classifier stays fail closed for callers without `set -e`.

## Change
- tools/lib/process-fixture.sh (#4211's library):
  - `_kosmos_path_in_kt_sandbox`: heavy-gate's rule, moved here verbatim;
  - `_kosmos_pid_cwd`: `lsof -a -p PID -d cwd -Fn`, with the `KOSMOS_PROCESS_CWD_PROBE` test seam beside #4211's
    `KOSMOS_PROCESS_ANCESTOR_PROBE`;
  - `_kosmos_pid_is_fixture PID [SCRIPT]`: a node-test ancestor, OR a kt sandbox cwd or script. Unreadable is not a
    fixture.
- tools/lib/cut-guard.sh:
  - a fail-closed stub for `_kosmos_pid_is_fixture` when the library cannot be sourced;
  - #4211's `_kosmos_drop_node_test_fixtures` becomes `_kosmos_drop_fixtures`, with the script taken as the command
    line's second word; the cut guard uses it;
  - the browser-run guard calls it after its self-subtree drop.
- tools/heavy-gate.sh:
  - exits 2 ("do not start") if it cannot source the library, instead of relying on an undefined function returning
    non-zero;
  - its private `KT_RE`/`in_kt_sandbox` are removed, and classify uses `_kosmos_path_in_kt_sandbox`.

## Decided
heavy-gate calls the path rule directly on the cwd its own snapshot already read, rather than `_kosmos_pid_is_fixture`
(which would read cwd and ancestry again). The sandbox RULE has one copy; only the reading of cwd differs.

## Proof (probe-only)
tools/test-cut-guard.sh, 10 new arms, with candidates from `KOSMOS_CUT_PROBE`/`KOSMOS_BC_PROBE` (made-up pids) and cwd
and ancestry from the probe seams:
- For each guard: a kt fixture (by cwd, and by script path for the cut guard) and a node-test fixture are ignored; the
  identical ordinary process refuses; an unreadable cwd refuses (both guards).
- Both test files default the cwd and ancestry probes to "nothing", so no arm reads the real process table for a
  made-up pid (review 1).
- A copy of cut-guard.sh without the library, sourced without `set -e`, still refuses in both guards.
- heavy-gate without the library exits 2.
- heavy-gate keeps no private sandbox rule.
- Mutations: without the kt check, the 3 kt arms fail; without the browser drop, the 2 browser fixture arms fail.
- tools.heavy-gate-3805.test.js is unchanged: 39 pass, 1 skipped, 0 fail.

## Weakest part
The real `lsof` cwd read is exercised only by heavy-gate's existing path and by the guards in real use; the tests feed
cwd through the probe by design, never starting a real release.sh or browser-checks.sh.
