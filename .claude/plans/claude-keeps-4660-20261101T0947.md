# Plan: the Claude org-chart consent line says what Anthropic keeps (#4660)

Follow-up to #4559 (the Claude read path) and #4560 (the consent box says what each key-connected
provider keeps). Liu Kang approved the follow-up card for the Claude path. This branch was built
stacked on #4560's branch and shares its plan `orgchart-keys-4560-20260929T2305.md` (whose commit
`f2f65be1ee` is "plan: Claude's retention line is #4660's, on purpose"); this file is the
branch-local plan the Development Process requires, carrying the same design so the record travels
with the branch after the rebase onto current main.

## Problem

The org-chart upload consent box tells the person which provider will read the file. For the
key-connected providers #4560 also says what that provider keeps even though Kosmos asks it not to
store the file. The Claude path (#4559, `claude -p` on the person's own subscription) said only
"read by your own AI provider, Anthropic (Claude, <account>), using your plan" and nothing about
retention. A consumer or Team plan's terms differ from Anthropic's API terms in how long data is
kept and whether a model-training setting applies. An org chart names real employees, so the person
should see what is kept before saying yes.

## Scope

In scope: the consent line's wording for a Claude read, and a test that pins it to the page.
Not in scope: how the file is sent (it stays inline with every tool off, #4559).

## Design

`engine/orgchartkeys.js`:
- `CLAUDE_KEEPS`: the plan-account retention sentence. Each plan is its own case because the
  model-improvement setting is a Free/Pro/Max/Ultra setting Kosmos cannot read: Free/Pro/Max/Ultra keep up to
  30 days, up to 5 years if model-improvement is on (said "in a form it calls de-identified",
  not "anonymous"); Team/Enterprise/API keep up to 30 days; anything safety systems flag can be
  kept up to 2 years. "up to 30 days" (not a flat "30 days") because the sources say "within 30"
  and the API may keep less.
- `CLAUDE_API_KEEPS`: the Anthropic-API-key case, its own 30-day line.
- `keeps(reader)`: Claude reader -> `CLAUDE_API_KEEPS` when `reader.apiKey === true`, else
  `CLAUDE_KEEPS`; key-connected provider -> `KEEPS[provider]`; otherwise null.

`engine/orgchartfile.js` `consentFor()`: a codex reader keeps `orgchartcodex.KEEPS` (#5346), every
other reader routes through `keeps()`. For a Claude reader known to run on an API key the `uses`
clause also says "billed to your Anthropic API key"; a blank/whitespace `ANTHROPIC_API_KEY` is not
a key.

## Sources

Every retention number is cited on card #4660 with its page, the page's modified date, and the
quoted line (Anthropic data-usage docs and privacy center, read 2026-09-30). The numbers are
ceilings ("up to"), true under every source quoted.

## Done means

The Claude consent line states what Anthropic keeps, per plan and per API key, with the sources
quoted on the card, and a test pins the sentences to the page (including a negative-control regex
that forbids a flat "30 days").

## 2026-11-01 re-check of the sources (PigeonPete, took over from Kano's stale claim)
All numbers re-read on Anthropic's live pages. They stand: 30 days, 5 years, 2 years, Team/Enterprise/API 30 days; the privacy articles still read July 1, 2026. One change: the data-usage page now names "Free, Pro, Max, and Ultra plans", so the consumer sentence said Free, Pro or Max and left an Ultra person with no matching sentence. Added Ultra. Rejected "On a personal plan": the pages name plans, and a named list lets the person find theirs. Weakest premise: this list goes stale the next time a plan is added; nothing checks it.

## API-key detection, the riskiest part of this diff
`apiKey` is set when the Claude account row says so, or when `ANTHROPIC_API_KEY` is non-blank in the board's environment, and the environment wins over a subscription login. Checked against code.claude.com/docs/en/authentication on 2026-11-01: "In non-interactive mode (`-p`), the key is always used when present." The read is `claude -p`, so the API-key sentence is the true one. Not measured with a real key.

## Round 2 calls (2026-11-01)
- A redirected read (`ANTHROPIC_BASE_URL`, or a Bedrock, Vertex or Foundry switch not set to off) names no Anthropic retention. It says "Claude Code, through the service this computer has it set up to use" and "What that service keeps is set by whoever runs it." `ANTHROPIC_AUTH_TOKEN` alone does not count: with no address of its own it still goes to Anthropic. The reader id carries the key and the redirect, so a consent cannot carry across a change in what the box said. Rejected: stripping the variables for the read, which changes how the file is sent, out of this card's scope.
- A key in the environment drops the login's address from the box: the key's organisation takes the file, not that account.
- "with details that identify you removed" replaced: it reassured about the account holder when the file is other people's names. Now "in a form it calls de-identified; it does not say the names in the file are removed." Weakest premise: this is our reading of a page that says nothing either way.
- Not fixed, and reasoned rather than measured (the run was denied): a #2420 key account may be unable to complete a read, because `--setting-sources ''` may skip its `apiKeyHelper`. If so the read fails and nothing is sent, so the sentence does no harm. Tracked on #7741.

## Round 4 calls (2026-11-01)
- The credential follows the order on code.claude.com/docs/en/authentication: `ANTHROPIC_AUTH_TOKEN`, then `ANTHROPIC_API_KEY`, then `CLAUDE_CODE_OAUTH_TOKEN`, then the login. A token read says "Anthropic (Claude), on the sign-in set up on this computer", keeps the plan sentences because it still goes to Anthropic, and has its own reader id.
- `apiKeyHelper` sits between the key and the OAuth token on that page. It is not read here: `--setting-sources ''` is the question on #7741.
- `ANTHROPIC_BASE_URL` set to Anthropic's own address reads as redirected. Left so: the box promises less, which is the safe direction.

## Round 6 calls (2026-11-01)
- An old page's send with no reader id no longer reaches a redirected reader: it gets the same refusal as a changed reader.
- Known gap, reasoned and not measured: a managed settings file might set a base URL or provider switch that the board cannot see, and a provider switch added to Claude Code later would not be on this list. Either way the box would name Anthropic for a read that goes elsewhere. Rejected for now: reading managed settings here, which is a second reader of Claude Code's config for a case nobody has seen. Would change my mind: a managed Mac among Kosmos's users.
- `CLAUDE_KEEPS` also goes to token readers because it covers every plan family, so it stays true for them.
- The Design section above is the first version. The calls here supersede it where they differ.

## Round 7 calls (2026-11-01)
- The provider switches come from code.claude.com/docs/en/env-vars, read 2026-11-01: Bedrock, Mantle, Vertex, Foundry and Claude Platform on AWS. `CLAUDE_CODE_USE_POWERSHELL_TOOL` shares the prefix and is not a provider, so the list stays named rather than a prefix match. Weakest premise: the list goes stale when Claude Code adds a provider, and nothing checks it. `LAUNCH_VARS` in `engine/anthropiccompat.js` has only three of the five; that is a separate question, about agents.
- A token read keeps `CLAUDE_KEEPS` although it opens with the consumer plans: its last sentences cover Team, Enterprise and API, so it stays true for any token. Left as is.
