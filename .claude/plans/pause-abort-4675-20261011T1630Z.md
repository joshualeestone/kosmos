# pause-abort-4675: the stops after the update's pause show on the board when nobody else is reading

Card: #4675 (follow-up to #4651 and #2055). Supersedes my plan comment of 2026-09-30 on the card; what changed
since is under "Changed from the earlier plan".

## What was wrong

The update's pause in `install/setup.sh` can stop in four places. Only the first (our board would not pause) left a
record the board can show (#2055's `logs/update-abort`). The three stops after it wrote nothing:

| Stop | When |
|---|---|
| port check failed | `lsof` itself failed, so the run cannot tell whether the port is free |
| holder unreachable | something holds the port and this shell's check of it failed |
| port still held | something holds the port after the pause and answers or stays silent |

When the board starts the update itself, the installer's words go to stderr and `install.log`. So a machine stopping
at any of the three would stop every time with no screen saying so, which is the shape #2055 exists to prevent.

## The change

1. **`install/setup.sh`:** the record is one function, `_kosmos_note_pause_abort <reason>`. The first stop calls it as
   before (whoever ran the installer). The three later stops call it with their own reason
   (`port-check-failed`, `port-unreachable`, `port-still-held`), **only when the board started the run**. `count` is
   the whole streak, whatever the reasons, as before. A new line, `same`, says how many of the latest stops shared
   the latest reason. Getting past the pause clears the file, as before.
2. **`engine/update.js`:** the installer the board spawns carries `KOSMOS_UPDATE_BY_BOARD=1`. setup.sh reads it once
   and removes it from the environment, because the script goes on to start the board and a board that inherited it
   would pass it to its agents. `install/kosmos` also strips it where it starts a board directly. The third thing
   that runs the installer, `kosmos update --if-newer` on a computer that only connects to another, does not carry
   it: that computer runs no board to pause or to show a notice.
3. **`web/index.html` `paintUpdateAbort`:** the sentence is chosen by reason, and says only what the installer saw.
   A reason speaks for the count only when every stop in the streak had it (`same` equals `count`, or the file is
   from before `same` existed, when there was one reason).
   - `board-would-not-pause` keeps #2055's sentence exactly.
   - `port-check-failed`: the computer could not check whether Kosmos had stopped; the step is a restart, because
     reopening does not fix a failing check.
   - `port-unreachable` and `port-still-held` share one sentence: something was still using the connection. Its
     remedy is #2055's own sentence, unchanged.
   - a mixed streak, or a reason the page does not know, gets a plain "the update stopped each time before
     replacing anything", with #2055's remedy.
   No sentence asks for a typed command. The notice repaints only when its words change.

## Changed from the earlier plan

- **Recorded only for the board's own run.** The earlier plan recorded every run. But these stops are what a pasted
  install line meets inside an agent's sandbox (that is what #4651 was about), and that person or agent reads the
  words in their own shell. Recording it would leave "this computer keeps failing to update" on the board because an
  agent tried something, with a remedy that does not fit.
- **The third stop is recorded too.** The card names two; the third is equally silent on the board's path.
- **No typed commands in the notice.** The earlier draft said "open Terminal and paste the install line".
  `web.update-abort-2055.test.js` pins that this notice never asks for that, and it is right: pressing Update or
  pasting re-enters the same pause.

## Rejected

- **Telling the board's run apart by `KOSMOS_UPDATE_CHANNEL`**, which the board already sets: a person sets it too,
  to install from staging.
- **Three inline copies of the counter.** That is how they drift. The cost was re-anchoring three tests that lift the
  block out of setup.sh; each was run after.

## Weakest part

**Whether the board's own run ever reaches these stops is still unmeasured.** It needs `lsof` to fail, or the port
check to fail against a live holder, outside a sandbox. If it never happens this is insurance: a marker line and two
sentences. The wording is mine, a first cut for whoever owns the board's copy.

**A machine only gets this after it has updated once.** The marker is set by the new board's engine and painted by
the new page, so a machine stuck today is not helped by it.

**The remedy sentence is #2055's, with its limits.** "Quit and reopen Kosmos" has no meaning on a Linux server with
no window, and "so the next one can finish" assumes another update will be tried. Both were already true of the
notice on main; this change shows the same sentence in more cases and does not fix either. The page has a Linux
companion to its Windows wording that this notice has never used; that is a separate card.

**Windows is untouched.** It does not run setup.sh, and its notice text comes from `windowsCopy`.

## Review notes

- Round 1 (opus), no blocker. Fixed: the notice blamed the whole count on the latest reason, so the count is now per
  reason; the harness mirrored the marker-reading lines and now runs setup.sh's own; the `--if-newer` spawner's
  comment was stale and the decision not to mark it is written there; four comments still described one reason; the
  wording no longer says "tell us" (no way to do so was named) or puts "agents keep working" after a restart; the
  flag is yes/no like its siblings; sandbox C asserts the marker was left alone; the reason-list test counts calls
  only. Left: the wording table stays inside the function, so a test can lift the function whole.
- Round 2 (sonnet), no blocker and no convention finding; three warnings, all on the notice's words. Quit and
  reopen cannot fix a failing port check, "the next update will try again" assumed automatic updates, "still here
  after that" promised the notice would go, and an unknown reason was told "Kosmos was busy". The words were
  rewritten on one rule: say what the installer saw, advise only steps that can help, and point at the count.
  One existing test (`web.win32-board-copy.test.js`) painted a marker with no reason and expected the busy sentence;
  a real marker always has a reason, so its fixture now carries `board-would-not-pause`.
- Round 3 (opus), no blocker. Its main finding was against round 1's fix: a per-reason count restarts on every
  change of reason, so a machine alternating between stops reads "once" forever, which is the unseen streak #2055
  exists to prevent. Now `count` is the streak again and `same` carries what round 1 wanted: the page names a cause
  only when every stop shared it. Also fixed: the advice no longer depends on watching the count (nothing retries
  when automatic updates are off); the repaint key is the words, so a reason change that changes no words is not
  re-announced; the two board starts in `install/kosmos` that strip the marker are pinned by a test; the comment no
  longer calls the slot an aria-live region; the README row names the new assertions. Left, with reasons above: the
  Linux and automatic-updates limits of #2055's remedy sentence. Left as on main: a 20-digit count overflows shell
  arithmetic; a pasted run stopping at "board would not pause" still counts in the streak, as it always has.
