# srlfix-5552: the tunnel gate test leaks tunnelgate-test.srl on macOS (Addresses #5552)

## Problem
`tools/test-tunnel-handshake-gate.sh` signs its test certificate with `openssl x509 ... -CAcreateserial`.
LibreSSL (macOS /usr/bin/openssl, 3.3.6) names the serial file by cutting the CA's whole path at its FIRST dot,
so it writes `<parent>/tunnelgate-test.srl` beside the temp dir, outside the EXIT trap's cleanup. The #4273 leak
guard then turns `suite (shell 1/2)` red on the self-hosted Mac runner for every PR whose shard runs it.

## Change
Name the serial file inside the temp dir: `-CAcreateserial -CAserial "$W/ca.srl"`. One line, plus a comment.

## Verification (measured, both arms, LibreSSL first on PATH, TMPDIR in a fresh dir whose name has a dot)
- before: 57 passed, and a stray `<first-dot-prefix>.srl` appeared outside the temp dir.
- after: 57 passed, no `.srl` anywhere outside it.
- The bare openssl command alone: old arm wrote `armold.srl` in the grandparent; new arm wrote `ca.srl` inside $W.

## Decided
- No other `-CAcreateserial` in the repo (grep over .sh/.js/.mjs).
- No allowlist entry: the leak is fixed at its source, not excused.
- No full Mortals run: the change is one test script's openssl flag; the CI shell shard runs exactly this file.

## Weakest premise
That OpenSSL 3 (Linux runners) accepts `-CAserial` with `-CAcreateserial`: documented in both, and the Linux
shard runs this file, so CI is the check.
