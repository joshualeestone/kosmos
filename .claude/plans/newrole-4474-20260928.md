# #4474: agents make an agent with a role they wrote, when no role fits

## Why
Josh, quoted on #1279: "if the type of agent they need created isn't there, they can create it from scratch".
#1279 (0.7.07) lets the PM and the guide make agents from the EXISTING roles; this is its planned second card.

## Found before building
- POST /api/team already hands each member to create.createAgent as given, so `{role:'own', label, instructions}`
  already worked through it; only the CLI limited agents to `{name, role}`.
- Agent-written text was only size-checked: it landed verbatim, `{{NAME}}` included.
- create appends the shared working rules (defaults.appendTo) to ANY text, so a made-up role cannot drop them
  (pinned by engine/defaults.test.js).
- An agent could ask /api/team for role `setup` and mint a second, hidden, locked-down guide.

## Change
- `kosmos agent role-draft` (Mac and Windows): prints the default ("Describe it yourself", `own`) text.
- `kosmos agent create "<name>" --new-role "<label>" --from <file> ["<why>"]` (Mac and Windows): the `own` role
  with that label and the file's text, verbatim (the Mac body is built by node, not sed, so a whole file escapes).
- engine/team.js `vetAgentMember`, applied when the request came from an agent's token (`fromAgent`):
  - never role `setup`;
  - a label or text only with role `own` (no arbitrary text under a built-in role's name);
  - `{{NAME}}` filled with the member's name; text that does not open with `You are **...**,` gets
    `You are **<name>**, <label>.` (every role's text opens that way; the board's fallback for the name).
- server.js: `fromAgent` passed for token callers; an agent's label and text are masked like its purpose (#3769).
- PM and guide instructions: when no role on the list fits, draft from role-draft, tell the person the role's name
  and what it does, create only after a yes, and reuse the file for more agents with that role.
- tools.windows-kosmos-cli-verbs-parity.test.js: its subcommand parser accepted only `[a-z_]`, so it could not see
  a hyphenated subcommand; widened to `[a-z_-]` (a `-`-led arm is still a flag).

## Decided
- No saved custom-role store (listed in `kosmos agent roles` and the create menu): a new store plus page UI, and
  Josh's words do not ask for it. Reuse is the file.
- Prepend the identity line rather than refuse text without it: no failure mode for the agent, and the recorded
  display name wins on the board anyway.
- The operator path is not vetted (it is the person).
- Weakest premise: that "creates agents from it" means reusing the saved file, not a named role in Kosmos's own
  picker. If Josh wants the picker, that builds on this.
- Out of scope (own cards): narrowing a created agent's permissions (#4475); making agents on another Kosmos.

## Review iteration 4 (two BLOCKERs, both real, both fixed)
- The setup-role refusal read the role only when it was a string; create reads String(role || '').trim(), so a
  role sent as ["setup"] passed the vetting and create made the guide. The vetting now reads the role exactly as
  create does (one derivation). Engine and route tests; both red with the old reading.
- The identity-line rewrite passed a built string to String.replace, so $&, $' and $1 in an agent-chosen name
  were expanded (a name ending in $' copied the rest of the text into the line). Now a replacer function; test
  red with the string form.
- The label is flattened on every path, including an own role sent with a label and no text.
- instructions is required at the top of team.js; a test message that read backwards is fixed.

## Review iteration 5
- Windows PowerShell 5.1's `>` writes UTF-16LE with a BOM, so `role-draft > role.md` on a Windows agent made a
  file that read as NULs between the letters and passed every check. The Windows CLI decodes a role file by its
  BOM (UTF-16LE, UTF-16BE, UTF-8), and the server refuses agent text containing NUL as the backstop. Tests
  through the real reader and at the engine; both red when their fix is removed.
- The Mac CLI sent the whole role text as a curl argument (argv limits, #2909; an agent's words on argv, where ps
  reads them, #1970). It now goes on stdin, as the post command's body does.
- A role is drafted into a file named for it (role-<short-name>.md), so a second role does not overwrite the
  first and "use the same file" still means that role.
- Left: text whose identity line is not the first line gets a second one (the draft as served has it first);
  the Mac form needs a readable regular file, so --from /dev/stdin works only on Windows.

## Review iteration 7 (changes the design: the guide is out)
- DECIDED: only the Project Manager writes new roles. The setup guide is sandboxed away from the person's secrets
  (#3769); a role it wrote would hand an unsandboxed agent instructions the guide itself may not act on, and
  masking catches only secret-shaped strings, not instructions to go and read them. The server refuses a made-up
  role (any label or text) from the guide (createTeam fromGuide, from isSetupGuide on the route), and the guide is
  not taught it. It walks the person through New agent, Describe it yourself, where the PERSON writes the text.
  This SUPERSEDES iterations 3 and 6: the guide-refresh swap (MAKE_AGENTS_LINES_BEFORE_4474) and the masking of an
  agent's label and text are removed (the guide can no longer send either, so both were dead). Weakest premise: a
  guide user who wants a custom agent takes one more step, through the page.
- An agent's member reaches create with only AGENT_MEMBER_KEYS (name, role, label, instructions, provider,
  account, model, projects, kind). Before, any field went through, including claudeBin/codexBin/tmuxBin, runner,
  configDir and pickedByPerson, which let an agent choose what a new agent's launch job runs. Older than this
  branch, closed here because vetAgentMember is now the gate. Test; red without it.
- The shared working rules: create appends them only when their heading is missing, and the served draft carries
  them, so an agent could keep the heading and gut the rules. Text that keeps the heading must keep the block word
  for word (deleted whole is fine; Kosmos adds it back). Test; red without it. The earlier "cannot drop them"
  claim was false and is gone.
- The identity line is recognised with a period, colon, semicolon, space or dash after the name, not only a comma.
- Windows role-draft trims every trailing newline, as the Mac does.

## Review iteration 8
- The role rule was written twice (create.js and team.js), identical text but two derivations. create exports
  roleKeyOf and both call it; a test runs a battery of role shapes (string, padded, ["setup"], null, 0, an object
  whose toString is "setup") through both and requires they agree.
- The allowlist dropped fields create supports that are not launch mechanics: reportsTo, maxHelpers,
  dailyTokenLimit, dailyAllowancePct are now allowed (placement and limits, which only narrow). A test sorts every
  field create reads into "an agent may send" or "not from an agent" and fails on a field in neither, so a new one
  is decided rather than silently dropped or passed (red with a made-up field added to create.js).
- The Mac CLI says why it reads the role file as UTF-8 only (the board refuses UTF-16 as not text).
