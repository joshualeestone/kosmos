# #4474: agents make an agent with a role they wrote, when no role fits

## Why
Josh, quoted on #1279: "if the type of agent they need created isn't there, they can create it from scratch".
#1279 (0.7.07) lets the PM and the guide make agents from the EXISTING roles; this is its planned second card.

## Found before building
- POST /api/team already hands each member to create.createAgent as given, so `{role:'own', label, instructions}`
  already worked through it; only the CLI limited agents to `{name, role}`.
- Agent-written text was only size-checked: it landed verbatim, `{{NAME}}` included.
- create appends the shared working rules (defaults.appendTo) to ANY text, so a made-up role cannot drop them
  (pinned by engine/defaults.test.js).
- An agent could ask /api/team for role `setup` and mint a second, hidden, locked-down guide.

## Change
- `kosmos agent role-draft` (Mac and Windows): prints the default ("Describe it yourself", `own`) text.
- `kosmos agent create "<name>" --new-role "<label>" --from <file> ["<why>"]` (Mac and Windows): the `own` role
  with that label and the file's text, verbatim (the Mac body is built by node, not sed, so a whole file escapes).
- engine/team.js `vetAgentMember`, applied when the request came from an agent's token (`fromAgent`):
  - never role `setup`;
  - a label or text only with role `own` (no arbitrary text under a built-in role's name);
  - `{{NAME}}` filled with the member's name; text that does not open with `You are **...**,` gets
    `You are **<name>**, <label>.` (every role's text opens that way; the board's fallback for the name).
- server.js: `fromAgent` passed for token callers; an agent's label and text are masked like its purpose (#3769).
- PM and guide instructions: when no role on the list fits, draft from role-draft, tell the person the role's name
  and what it does, create only after a yes, and reuse the file for more agents with that role.
- tools.windows-kosmos-cli-verbs-parity.test.js: its subcommand parser accepted only `[a-z_]`, so it could not see
  a hyphenated subcommand; widened to `[a-z_-]` (a `-`-led arm is still a flag).

## Decided
- No saved custom-role store (listed in `kosmos agent roles` and the create menu): a new store plus page UI, and
  Josh's words do not ask for it. Reuse is the file.
- Prepend the identity line rather than refuse text without it: no failure mode for the agent, and the recorded
  display name wins on the board anyway.
- The operator path is not vetted (it is the person).
- Weakest premise: that "creates agents from it" means reusing the saved file, not a named role in Kosmos's own
  picker. If Josh wants the picker, that builds on this.
- Out of scope (own cards): narrowing a created agent's permissions (#4475); making agents on another Kosmos.

## Tests
- engine/team.newrole-4474.test.js: the text create receives ({{NAME}}, the identity line added once), the refusals,
  and the operator CONTROL. Red with the setup refusal removed.
- server.team-newrole-4474.test.js: through the real route with an agent token: made as `own` with its creator;
  setup and a built-in-role-with-text refused and not made; operator CONTROL. Red with fromAgent removed.
- cli.agent-newrole-4474.test.js and tools.windows-kosmos-cli-newrole-4474.test.js: role-draft prints the text; the
  new-role body is exact (quotes, backslashes, tabs, non-ASCII); a missing file or --from sends nothing; CONTROL:
  the old form is unchanged.
- engine/roles.test.js: the PM and the guide carry the new-role lines with the confirmation; no other role does.

## Review iteration 1
- The identity line padded blank or 2-character text past create's own minimum, so an agent could make an agent
  whose whole brief was its name. The line is now added only to text create would take on its own (at least
  instructions.MIN_CHARS); create then refuses short text in its own words. Engine and route tests; both red with
  the guard removed. (The birth log also records refused attempts, so the tests look for a CREATED record.)
- The label is flattened (newlines, **) before it goes into the identity line.
- The PM and guide lines say to change the draft's first line too (it opens "an assistant").
- The Mac CLI passes `--` before the file path, so a file named with a leading dash is read, not taken as a node flag.

## Review iteration 2
- The flattened label is also the one create stores for the card (it was only flattened inside the identity line).
- An identity line written for another name ("You are **Bob**," for Ann) is given the member's name; a line with the
  member's own name is kept. Tests for both; each red when its fix is removed.
