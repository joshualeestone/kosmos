# #7032 part 1: the room route pages its JSON; room post words for the phone

**Done when:** GET /api/project/:id/room?n=N[&cursor=<olderCursor>] returns the room's last N rows (before the
cursor's row) with olderCount and a server-made olderCursor, refuses a cursor naming no row with a 400, and without ?n
returns exactly what it did; GET /api/phone/notice?id=post:<post id> returns an agent's post
text (shortened) and its author, and 404 for the person's own, unknown or empty posts. Part 2 (the phone) follows in
its own PR.

## Decisions
- The cursor names a row and is made by the server (`<at>|<k>`: the page's first row's stored time and how many rows
  share that time ahead of it). Review 1 found a time-only cursor skips a tied row; review 2 found a phone-built id
  cursor served id-less Kosmos lines twice and that an unknown cursor read as the start of the room (now a 400).
  Weakest premise: a row written later with the exact same time AND sorting ahead of the cursor's row would shift k by
  one; rows are written one at a time with millisecond times, so it needs two writes in one millisecond.
- Weakest premise, stated: a post is dated when its send starts and written when delivery ends, so a post written after
  a page was read can sort into it. It lands in the newest page unless more than N rows arrive during its delivery; the
  phone (part 2) re-reads the newest page and merges by id.
- Server work: paging saves bytes and parsing on the phone, not the server's per-read mapping (a residual if the phone's
  polling ever gets hot).
- n reuses the text arm's 1 to 200 rule; a bad n or before is ignored, as the text arm ignores a bad n.
- The post's author comes from the post row itself, never from the id.
