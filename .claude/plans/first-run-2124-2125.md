# Fresh-install launch regressions: #2124 + #2125

Josh live-tested a fresh macOS install on a new user account and hit two launch-critical
first-run regressions. Root-cause + plan are on the cards (kosmos#2124, kosmos#2125) and
are the spec. Both trace to the recent installer-launches-app + relaunch work (#2080, #2094,
#2103). Verify needs a FRESH macOS user account (Josh); Splinter batches it into one
clean-machine pass. Done = Josh confirms, NOT merge.

## #2124 — multiple Kosmos instances (single-instance guard) — DONE in this branch
Root: `native-app/main.swift:applicationDidFinishLaunching` had no single-instance guard;
macOS keys single-instance on bundle PATH not id, so the installer's launched copy + the
dragged /Applications copy ran as two apps.
Fix (implemented + verified):
- Dedup by bundle id in `applicationDidFinishLaunching`: if another instance is running,
  activate it and terminate this duplicate (before building a window).
- EXCLUDE #2094's self-update relaunch via a one-shot handoff carried TWO ways: a launch-env
  var (`KOSMOS_RELAUNCH_HANDOFF`, merged onto the current env) set on the relaunch's
  OpenConfiguration, and a short-TTL (30s) token file. Either suffices, so a failed token
  write cannot reintroduce the quit-to-nothing race (env is primary, no disk).
- Pure `shouldDeferToExistingInstance(handoff:otherRunning:)` = `!handoff && otherRunning`.
- `--kosmos-app-instance-selftest` hatch prints the decision table; `build-kosmos-bundle.sh`
  diffs it against the expected 4 rows so BOTH ARMS are RUN at build; a fast-suite
  source-assertion test pins the wiring.
- VERIFIED: compiled + ran the selftest, table exactly right on both arms; swiftc clean.
Residual (decided, not a gap): the guard makes the FIRST-launched instance (= the
installer's APP_DIR launch, #2080) canonical, which IS the icon the user drags, so Josh's
"the dragged /Applications one is THE app" holds. The /Applications-vs-~/Applications install
LOCATION question is a separate pre-existing tangle (setup.sh ~201-280); NOT expanded here.

## #2125 — fresh-install macOS permission flood — NOT STARTED
Root (bash burst): one macOS background-activity notice per launchd bash agent; the recent
work added a NEW one-shot open agent `com.kosmos.open-once` (setup.sh ~3937) on top of
`com.kosmos.board` (~3660). Fix: consolidate + register the persistent one under ONE
app-identity background item (SMAppService / app login item), not N bare-bash launchd
notices; the one-shot open agent should tear itself down.
Root (Documents prompt): the icon-location step `engine/machine.js:appLocationCheck` (~684)
now trips a Documents-TCC prompt (pre-allowed before). PIN the exact read on a fresh account;
a dropped pre-grant/entitlement is the likely change. Fix: don't need Documents (scan only
/Applications + ~/Applications) or restore the pre-grant.
