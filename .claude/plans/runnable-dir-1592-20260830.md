`fs.accessSync(p, X_OK)` SUCCEEDS ON A DIRECTORY. Every hand-rolled runnable
check in engine/ therefore accepted a folder as an executable.

## The stripper is gone. Four of them failed; the problem was size four.

Iterations 3 to 6 each fixed the previous comment-stripper and each opened a new
hole, every one in the direction that HIDES a defect:

    1  regex over the file    a `/*` inside a STRING opened a comment.
                              803 live lines across 10 files invisible.
    2  character scanner      broke on REGEX LITERALS. 8 live lines blanked, and
                              a regex containing a quote desynced it permanently.
    3  line-initial only      a TEMPLATE LITERAL puts `/*` at a line start.
                              A planted weak call stayed green.
    4  backtick parity        defeated by a regex CONTAINING a backtick, which is
                              LIVE at engine/create.js:1449. Parity inverts and
                              never recovers; 4 files desynced today.

⇒ **Each fix was right about the case it named and wrong about the next one.**
That is a heuristic aimed at a parsing problem, and there is no parser in this
repo (no acorn, espree, esprima or babel).

✅ **THE MEASUREMENT THAT ENDED IT: exactly FOUR lines in the whole repo match the
weak-call shape in raw source.** Two are prose, two are real calls. The sweep was
never doing a parsing job; it was judging four lines, and four is a list.

So there is no stripper. The sweep reads RAW source, and every matching line must
appear in `KNOWN_WEAK_LINES`, each entry declaring `kind: 'prose'` or
`kind: 'guarded'`. Nothing is blanked, so nothing can be hidden, and there is no
state to desync.

📌 **NAMING, RECORDED BECAUSE THIS PARAGRAPH WAS WRONG FOR TWO ITERATIONS.**
It said `ACKNOWLEDGED_PROSE` and `SELF_GUARDED`, two constants that appear nowhere
in the test file; `KNOWN_WEAK_LINES`, the thing that actually ships, appeared
nowhere in this plan. A reader taking the plan as the design went looking for a
classifier that does not exist. Caught in review pass 8 and corrected here rather
than quietly: **a plan that describes a design the branch does not ship is a
second source of truth, which is the defect this whole branch is about.**

⚠️ **The cost, stated rather than discovered later:** a new comment mentioning
accessSync(X_OK) turns the test red until it is listed. That is deliberate. It is
loud, it is a two-line fix, and it makes somebody documenting this defect notice
that they are documenting it.

Both stale directions are also asserted now: a listed prose entry whose comment

### 🛑 A CORRECTION TO PASS 9, MEASURED, AND IT MATTERS FOR SEVERITY

Pass 9 recorded that reverting `willInstall` "does NOT change the function's
answer for a directory", because the `--version` probe catches it anyway, and
scoped the harm there as a guard failure rather than a user-facing one.

**Measured here, both arms:**

    fixed     willInstall(directory) = true,  version probes spawned = 0
    reverted  willInstall(directory) = FALSE, version probes spawned = 1

**The answer flips whenever the probe answers ok**, which is what an injected
runner and a dry run both do. `connect.js`'s own docblock names that outcome: *"we
say willInstall FALSE and it was true -> AN UNANNOUNCED 281MB DOWNLOAD"*. So the
reverted site can produce the harmful answer, not merely fail a guard.

### The one site with no behavioural arm, stated rather than hidden

**`becomeStuck` cannot be called from a test.** It is not exported and
early-returns unless the module-internal `driver` matches the caller, so reaching
it needs a full `start()` flow driven to failure, which nothing in this repo does
today. Carded.

Until then it is defended by SOURCE, which this file otherwise refuses to do, so
that arm is written to survive the three shapes that actually defeated one:
**it counts assignments rather than looking for a token.** Both pass-9 defeats
worked by ADDING the token nearby, in a comment or in dead code, which leaves
three assignments where correct code has two. Proven red on all three shapes.

⚠️ **Its named weakness:** a decoy that REPLACES the real assignment rather than
adding to it still leaves the right count, and only the override arm would catch
what follows. Two arms, neither sufficient alone.

### ⭐ One thing the rewrite gained for free

Pass 9's decoy mutation leaves `connect.js` **syntactically unparseable**, and the
old guard still went 9 pass / 0 fail on it, because it only ever read the file as
text. **The new arms load the module, so a connect.js that cannot parse now fails
loudly.** A guard that passes on a file that does not compile was never a guard.
