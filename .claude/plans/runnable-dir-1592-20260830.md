# runnable-dir-1592: one definition of "is this runnable", so a directory can never pass again (#1592)

`fs.accessSync(p, X_OK)` SUCCEEDS ON A DIRECTORY. Every hand-rolled runnable
check in engine/ therefore accepted a folder as an executable.
`engine/runners.js`'s `isRunnable` is the correct form and differs by one line,
`statSync(p).isFile()`. This exports it and makes it the single definition.

## Why the guard is a source sweep and not six mocked arms

Fixing a subset is a route change rather than a behaviour change: harden the
entry check, leave the post-install check weak, and a directory takes a
different path to the same wrong answer. #1580 demonstrated that. A per-site
mock proves one site and says nothing about the next one added, so the sweep
asserts the CLASS: no file in the repo may ask the weak question unless it is on an audited allow-list (it formerly said "unless it guards itself", which was a heuristic that measured as not discriminating)
with isFile itself.

## What went wrong while building it, because the guard nearly shipped as decoration

The sweep stripped comments by DELETING them, which shifts every line number
below, so it reported a real defect at `machine.js:191` when the call is at 412.
Comments are now blanked and numbering survives.

My first planted arm DID NOT FIRE and I nearly recorded that as the sweep being
fine. I had planted the call inside a block comment, so blanking correctly ate
it. Planted in real code it reports `firstrun.js:43` for a call at line 43.

I also introduced a regression mid-edit, caught by reading the result rather
than trusting the edit: replacing the accessSync line at `canRunClaude` left the
following `canRunClaude = true;` in place, which would have made the check
always true. That is the exact direction this card is about.
