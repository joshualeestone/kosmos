# s7dc3-6590: the automatic Allow on this computer's own address (kosmos#6590, S-7d branch c, part c3)

Stacked on s7dc2-6590. The design is private (kosmos-relay `.claude/plans/s7dc-6590.md`).

## Scope (engine/remote.js; all of it only under the board-v2 marker)
- `vouchUrl`: `https://<this computer's address>/#allow=S` instead of the coordinator's page (no valid address: nothing
  is opened, as before when the page was not https).
- The window starts once more when the tab opens (`opened` is set once), since the tab on the computer's own address has
  no session and the person signs in there.
- `vouchStepV2`: one `devices allow-vouched` run (S on stdin, never argv) per NEW waiting row that carries a vouch;
  Allowed notes the device as on this computer and ends S; no match keeps S and never retries that row; two keys
  reproducing S end S at once (leaked); a passing refusal (certificate alarm, pause, lock, read error, or a connector
  that names no reason) is retried after 6 s, never counted, the row not marked tried. Kosmos+ not knowing the device
  (unknown_device) takes it back out, as the coordinator-origin path does.
- Not me racing it is settled by the tunnel's lock (pressed first: no row; second: drop-waiting says already allowed).
- Reads the tunnel's `reason` on a refused allow (no_row / ambiguous); the relay adds that field in s7dc0-6590.
- A test seam, startVouchForTests, excused in engine.reachable.test.js.

## Tests

refusal is retried only after its wait; ambiguous ends S. Six mutants each go red. remote.test.js (the old path)
unchanged and green.
