# notify: the outbound "something happened" call, the seam a phone rides on

**2026-08-23, Josh 1:34 PM:** "we want an outbound ping whenever an agent
posts something (from an api perspective), we would know to push a push
notification on a smartphone app. That would be something we should think
about architecturally as we're building it." The plan
(`Josh-Brain/Projects/kosmos-remote-access-and-push-plan-2026-08-23.md`)
names this as the one relay piece that can be built before any decision.

## What finished looks like

- `engine/notify.js`, the shape of `ping.js`: off by default, one setting,
  a closed list of kinds (`posted`, `replied`, `needs_you`), a payload that
  carries who (the agent's shown name), what (the kind), which project's name,
  when, and the install's random id, and never a message's words. Fire and
  forget, three-second timeout, never sent under test without an injected
  sender, an endpoint nobody answers yet (`/api/happened` on the site, set by
  `AGENT_WORKFORCE_NOTIFY_URL` when the relay exists).
- Two hooks today: an agent's post that reached a room (`/api/post`), and an
  agent's reply into the person's thread (`/api/reply`). Not the person's own
  post, not a refused post. `needs_you` is named in the list and waits for the
  state transition.
- `GET/PUT /api/notify-setting`, and a row in Settings > Updates beside the
  created-ping switch whose copy says exactly what leaves the Mac.
- Tests: the engine (off by default, the payload's fields, the under-test
  guard with a fetch-counting control, the Settings copy against the payload)
  and the wire (both hooks, the person's post, a refusal, off again).

## What this decides for the relay team

The payload's field names and the kind list are the contract. The relay's
coordinator receives exactly this body at `/api/happened` and pushes from it;
the phone learns who and what, and fetches the words from the Mac.

    { installId, id, kind, agent, session, project, at }

`id` is the event's own key (a post's message id; a reply's agent-plus-time;
null when there is none) so the coordinator can de-duplicate and the phone can
ask the Mac for this one. `agent` is the shown name for the notification's
words; `session` is the key the Mac's routes use. Both are sent so neither
side has to look the other up. A reply fires only once it is recorded.
