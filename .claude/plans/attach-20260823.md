# attach: documents in a conversation, the engine half (#358)

**2026-08-23.** Josh, 11:43: the + on the conversation box to upload a
document, and the document shown inline the way Discord does. Mona Lisa's

`{id, name, type, size, url, preview, kind}`; this branch makes the routes

## What finished looks like

- `PUT /api/agent/<name>/attachment` and `PUT /api/project/<id>/attachment`
  take raw bytes (the avatar route's shape, no multipart) with the file's type
  as content-type and its name in `x-attachment-name`, and answer the record.
  25 MB; a larger body is refused before anything is written.
- `POST .../thread` (agent) and `POST /api/project/<id>/thread/<agent>` accept
  `attachment: <id>`; the attachment must belong to that agent or project; the
  stored row carries `attachment` (checked field by field, like `wire`), and
  the pane's bracketed line ends with `[attached file: <absolute path>]` so the
  agent can open it where it stands.
- `GET /api/attachment/<id>` serves the file as a download (content-disposition
  attachment, nosniff, sandboxing CSP), never inline. `GET .../preview` serves
  the image itself for images and a first-page PNG for PDFs, drawn by macOS's
  own `qlmanage` in a subprocess with a timeout and cached beside the file;
  a kind with no preview is 404 in words.
- Attachments live under `<data>/attachments/<project|agent>/<owner>/<id>/`,
  never in the project folder (the card's second ruling).
- The name is sanitised to one path segment; ids are 24 hex and `read` walks
  only the two scope folders, never a path the id built.
