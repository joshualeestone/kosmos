# tz-1464: read and write the versions release stamp in Central, not machine-local

## The bug (#1464)

The versions-page release gate compares a release entry's `rel-d` stamp against the clock to
decide whether the entry is fresh. `kosmos_versions_entry_stamp_off` parsed the stamp by
matching `... H:MM AM/PM` and building `new Date(y, mo, d, h, mi)` in the **machine's local
timezone**, ignoring the trailing timezone token. The writer (`insert-release-entry.js`)
stamps in **America/Chicago** and hard-codes the literal ` CDT`.

On a Central release box the two cancel (machine-local == Central), so the gate worked and
the tests passed. On a **non-Central** box, or after the November CDT->CST switch, a freshly
written entry read ~300 min (CDT) or ~360 (CST) in the past, so step 1 refused every cut, for
everybody. The existing tests could not see it because the fixtures ALSO used machine-local
time and cancelled the reader's identical flaw.

This is foundational to the step-1 early gate that just shipped (#1463): a timezone parse the
release gate depends on.

## The fix

- **Reader** (`tools/lib/versions-entry.sh` `kosmos_versions_entry_stamp_off`): force
  `TZ=America/Chicago` on the node call so the wall-clock reconstructs as a Central instant on
  any machine, DST-aware (CDT in summer, CST in winter). Deliberately ignore the trailing
  label: the writer hard-codes `CDT` even in winter, so the wall-clock time is the trustworthy
  part and the label is not. This is strictly more robust than honoring the label.
- **Writer** (`tools/insert-release-entry.js`): emit the correct seasonal label via
  `timeZoneName: 'short'` (CDT/CST) instead of a hard-coded literal `CDT`.
- **Operator recovery**: the refusal's clock display (`$now`) and the `docs/releasing.md`
  recovery section were still machine-local, so on a non-Central box "copy the printed clock
  line" sent the operator in a circle. `$now` now uses `TZ=America/Chicago date`, and the docs
  tell the operator to copy the printed Central clock, not run `date` on a non-Central box.
- **Separator**: the reader regex uses `\s` before AM/PM (not a literal space), tolerating the
  narrow no-break space (U+202F) that `toLocaleString` emits on some ICU builds.
- **Fixtures**: all three rel-d producers (the writer and both test fixtures) build Central
  stamps, closing the fixture-cancels-the-bug hole that hid the defect.

## Tests

New guard arms in `tools/test-versions-entry-gate.sh`, each forcing its own TZ so it catches a
machine-local regression even on a Central box, and each mutation-verified:
- cross-TZ: a Central stamp read under `TZ=UTC` reads ~0, with a 90-min-stale control.
- separator: a U+202F-separated stamp still parses.
- recovery: the refusal's printed clock, read back under `TZ=UTC`, is ~now (Central).

Full suite 2937/2937; gate suite 73/73 under both `TZ=America/Chicago` and `TZ=UTC`.

## Deliberately not fixed (documented, fail-closed)

During the November fall-back repeated Central hour (1:00-1:59 twice), a bare wall-clock
reconstruct resolves to the first (CDT) instant, so an entry stamped in the second (CST) hour
reads ~60 min stale and is refused -- never wrongly accepted. Not fixable without trusting the
label the reader deliberately ignores; once a year, one hour, and the operator re-stamps.
