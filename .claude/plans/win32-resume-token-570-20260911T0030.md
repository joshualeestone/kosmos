# win32-resume-token-570 -- a crash-restarted Windows agent can report again (#570)

Addresses #570. Road: `.claude/plans/WINDOWS-ROADMAP.md` ("the crash-restart token
defect").

## The defect

When a Windows agent crashes, its supervisor restarts it in-process with
`--resume <session>` (keep-alive, 7c-1). The resume path in
`win32launch.launchStreaming` builds `prepared = { ..., token: s.token || '' }`,
and no caller ever passes `token`. `childEnv` then DELETES `KOSMOS_AGENT_TOKEN` on
an empty value. So every resumed agent runs with no credential, and the board
refuses all its self-reports. A Windows agent has no pane to fall back on
(`server.js` `denyPaneFallback`), so its card loses needs_you/blocked and every
other state only a self-report can carry.

A fresh start from the Scheduled Task (`main()` with no resume id) goes through
`prepareSession`, which mints a token. That path is correct.

## Mac parity

`bin/agent-supervisor.sh` mints a NEW token on every launch, restarts
included. It never reuses one. This slice mirrors that.

## Design

1. **`win32create.mintForRun(name)`** is the ONE mint point, used by
   `prepareSession` and by a resume. It never throws and never refuses a
   launch; `tokenBecause` says why a mint failed.
2. **`win32create.retireRun(name, instance)`** is the ONE retire of a single run's
   credential, used by `abandon` and by a resume whose spawn failed. Retire,
   never revoke: other runs of the same name keep theirs.
3. **The resume branch of `launchStreaming` mints and writes NO record** (a second
   ownership row per restart is the duplicate-name hazard that branch exists to
   avoid). A spawn that throws on a resume retires the new run's token but leaves
   the record alone. `launchStreaming` returns `instance`.
4. **The supervisor retires the DEAD run's token** when that run ends (death or
   stop), so tokens do not pile up one per crash. This part edits the same code as
   `win32-headless-570`, so it lands after that branch merges.

## Tests

- `win32launch.test.js`:
  - a resume's spawn env carries a hex `KOSMOS_AGENT_TOKEN`;
  - `sendertoken.live` grows by one;
  - the record gains no row;
  - a resume whose spawn throws leaves no extra live token and no extra row.
- `win32create.test.js`: `prepareSession` still mints exactly one token (the
  refactor changes nothing), and `abandon` still retires it.
- `win32supervisor.test.js` (after the headless merge): the dead run's instance
  is retired when it dies and when the supervisor stops.

## Weakest part

The supervisor's retire on death covers a supervisor that sees its child die. A
supervisor that is itself killed outright (a reboot, a taskkill of the host)
retires nothing. Those tokens stay until the 32-per-agent cap drops them, which
is the same as the Mac today.
