# lingerflake-5648: a 1-in-62 flake in the #4920 install-snippet test (#5648)

## Why
The stand-in installBoard in install.linux-board-4920.test.js reports lingering as `home.endsWith('L')`. The "held"
case's home is `fs.mkdtempSync(path.join(WORK, 'held-'))`, whose last character is random; when it is `L` the
stand-in says lingering and the test reads `held lingering`. Seen on run 37887146464 (PR #5647, which touches only
Windows tests).

## Change
`lingering: home.endsWith('/kosmosL')`: only the one home that is meant to linger (`/home/u/kosmosL`) matches, and
no random temp name under WORK can end in `/kosmosL`.

## Tests
Measured with the held home forced to end in L (a throwaway copy, deleted): old line 31 pass / 1 fail, new line
32 pass / 0 fail. The file as committed: 32 pass.

## Decided
- Fix the marker, not the temp name (rejected: a fixed `held` folder; the random folder keeps each run's state apart).
- Weakest premise: no other stand-in in the file keys on a random name. Checked: one endsWith in the file (this
  line); mkdtempSync has 5 sites (WORK, held-, left-, w-, sb-), and none of the others is read by name (left- goes to
  a stand-in that ignores it, w- to a fixed fake node, sb- to the real linuxboard). Review 1 caught my first count.
