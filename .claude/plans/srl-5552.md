# srl-5552: the tunnel gate test no longer leaks a serial file (kosmos#5552)

Finished means: tools/test-tunnel-handshake-gate.sh leaves nothing outside its temp dir with either openssl flavour, so the suite's #4273 leak guard stops failing shell shards on the self-hosted Mac runner.

Cause (measured): `openssl x509 ... -CA "$W/ca.pem" -CAcreateserial`; LibreSSL (macOS /usr/bin/openssl 3.3.6) names the serial by cutting the CA PATH at its first dot (in $W's own name, tunnelgate-test.XXXXXX), writing tunnelgate-test.srl beside $W; the EXIT trap removes only $W. OpenSSL 3 writes $W/ca.srl.

Change: `-CAserial "$W/ca.srl"` on that call, with a comment.

Checked: with PATH=/usr/bin first (LibreSSL) and a private TMPDIR: origin/main's test, 57 passed, left tunnelgate-test.srl in TMPDIR; this branch, 57 passed, left nothing. The test still makes its certificate (57/57 includes the handshake rows).

Decided: no allowlist entry for the file (that would hide a real leak). Grep (all files): this is the only -CAcreateserial or x509 -req signing in the repo.
Weakest premise: only this one file was found leaking in the failing run; other tests using -CAcreateserial with a dotted temp path would leak the same way (grep for them before calling it closed).
