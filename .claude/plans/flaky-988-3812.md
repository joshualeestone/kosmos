# The updating-988 "announce goes out SIGNED" test: not load, a path holding "900" (kosmos #3812)

Addresses kosmos #3812.

## Done looks like

The test passes whatever temp directory the suite runs in, and still fails when the body is put on
argv. Shown by a repro that failed every time before the fix and passes after, plus two mutations.

## What was actually wrong (measured, not the card's guess)

The card guessed timing under load. The saved log of the failing run (`/tmp/vlog-3692-60.log` on
Mortals, 15:52 CDT 2026-09-25) says the failing assertion was `and the body is not on argv`, which
was `!c.args.some((a) => a.includes('900'))`. The same log shows that run's TMPDIR was
`.../T/kt62900/`: `tools/run-tests.sh` makes `kt$$`, named after its own pid, and the test's
`--state-dir` lives under TMPDIR. Pid 62900 contains "900", so the state-dir argument matched and
the assertion read "the body is on argv". Run alone, TMPDIR has no `kt<pid>`, so it passed: that is
why it looked like load.

Repro, deterministic: `TMPDIR=<dir>/kt62900 node --test --test-name-pattern='announce goes out
SIGNED' engine/updating-988.test.js` failed 1 of 1 before the fix; the same with `kt12345` passed.

## The fix

Leave out the flag values the test already asserts exactly (`--state-dir`, `--coordinator`), then
require that no remaining argument contains `900` or `seconds`. The intent (no part of the body on
argv) is kept, and path noise cannot trip it.

Rejected: matching the JSON text `{"seconds":900}` only. A body leaked as `--seconds 900` would pass.

## Measured

- After the fix: the repro TMPDIR (`kt62900`) passes; `kt12345` passes; the whole file passes 40/40
  under the repro TMPDIR.
- Negative controls (product mutated in `engine/remote.js`, then restored): `--body <json>` on argv
  is red; `--seconds 900` on argv is red.

## Weakest part (named)

Any other test that looks for a short token in argv or in a path under TMPDIR has the same one-in-a-
few-hundred exposure to the runner's pid. I searched tracked tests for `args.some(`, `argv.some(` and
body-on-argv assertions: this was the only one that matches a bare substring against every argument.
A substring check against a message or a path elsewhere is not covered by that search.
