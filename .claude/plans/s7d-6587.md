# s7d-6587: the board hands the connector its verified coordinator keys (S-7a slice 3, Kosmos side)

Card: kosmos#6587 (detail private). Stacked on s7b-6587 (slice 2a, PR #6686: engine/servicekeys-check.js). Pairs with kosmos-relay #500 (expectkey-6587), in which the connector refuses to register under a key not in KOSMOS_EXPECT_COORDINATOR_KEYS.

## Finished looks like
With a verified service key set shipped and the production coordinator, every setup and sign-in run the board starts (setupRun, the one door for both) carries KOSMOS_EXPECT_COORDINATOR_KEYS with the set's keys, so the connector refuses to pin any other. Otherwise (off as shipped, no set, a set that does not verify, another coordinator) the run is spawned exactly as before: no env option at all, so it inherits this process's environment.

## Decided
- **The set's own SPKI spelling** is passed (relay #500 accepts it as listed), so no conversion here.
- **A set that does not verify hands nothing** (null): a broken build, which the staging check (tools/lib/stage-service-keys.sh) refuses to ship. Rejected: refusing every setup on a refused set (it would lock out setup on a build bug the build already stops).
- **Another coordinator hands nothing**, as slice 2a's `elsewhere`.
- **No env option when there are no keys**, so today's spawn is byte-for-byte unchanged.

## Weakest premise
That the connector the board ships understands the variable. An older connector ignores it (no check, no harm); the turn-on rule (no service-keys.json committed before slice 3 ships) covers the order: the connector with relay #500 must be in the release that commits the set.

## Validation
- engine/remote-servicekeys-6587.test.js (+2: the spawn options with and without keys, via setSetupSpawnForTests and the real setupStart), engine/servicekeys-check-6587.test.js (+1: on, off, another coordinator, a refused set, no set). With engine/remote.test.js and engine.reachable: 261 pass.
- Mutants measured red: no env passed to the spawn (1), env always passed (1), the production flag ignored (1). Survivor, no answer changed: dropping `set.ok !== true` (a refused set has no keys, which the next condition already refuses).
