# win-provenance-1749 - stamp source provenance into the Windows build

Kosmos #1749. On 2026-09-01 `build-kosmos-windows.sh` happily packaged a DIRTY,
2-behind-origin tree and said nothing; the resulting zip was byte-for-byte
indistinguishable from a reproducible origin/main cut, and it nearly shipped to
Josh as the real one. The build records the Node runtime's checksum and the
version, but nothing about WHICH source commit built it or whether that tree was
clean.

## The fix: STAMP, not REFUSE (Ice Cream Kitty's call, and the load-bearing one)

A hard refuse-on-dirty would block a legitimate use: the "ship one unsigned to
see it function" preview builds are deliberately made from a working tree. So the
fix makes every artifact self-describing rather than blocking the dirty case:

1. **Stamp** the manifest with `source_sha` (the commit the build was made from)
   and `source_dirty` (whether the tree had uncommitted changes). Passive
   provenance that travels inside the artifact, so any zip can be traced back to
   its source and a preview can never again be mistaken for a reproducible cut.
2. **Warn loudly on stderr** when the tree is dirty, so the builder is told AT
   BUILD TIME (the moment they act), not left to read a manifest nobody opens.
   This is the `can-they-see-it-at-the-moment-they-act` lesson: the signal has to
   reach the actor, not just exist.
3. **Do NOT hard-refuse.** A dirty preview is legitimate; blocking it would break
   the exact workflow Josh asked for. The stamp + warning are the right weight.

## Implementation (`tools/build-kosmos-windows.sh`)

- After `ARCH` is set (before the ~35MB Node download, so the warning is early):
  compute `SOURCE_SHA="$(git -C "$REPO" rev-parse HEAD 2>/dev/null || echo unknown)"`
  and `SOURCE_DIRTY` = true/false from `git -C "$REPO" status --porcelain`. Warn on
  dirty.
- Add `"source_sha"` and `"source_dirty"` to the `manifest.json` heredoc.
  (`source_dirty` is a JSON boolean; `source_sha` a string.)

## Tests

`tools.build-windows-570.test.js` is the build's test and is entirely STATIC (it
reads the script as text and asserts patterns, the same way it already asserts
`"signed": false`). A full build downloads a Node runtime over the network, so an
end-to-end manifest assertion is impractical in the suite. Following the file's
own convention, add static assertions that:
- the script computes the sha from `git ... rev-parse HEAD`;
- it computes dirtiness from `git ... status --porcelain`;
- the manifest carries `"source_sha"` and `"source_dirty"`;
- a dirty tree WARNS (the stderr message is present).

Because a static match proves the code is present but not that it runs correctly,
ALSO verify end-to-end manually (outside the suite): run the real build once and
assert the emitted `manifest.json` `source_sha` equals `git rev-parse HEAD` and
`source_dirty` matches the tree state. Record that in the PR.

## Not in this cut
