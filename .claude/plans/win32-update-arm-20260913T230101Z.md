# win32-update-arm -- S4: arm the Windows in-app updater

Branch: `win32-update-arm`, off `origin/main` @ `1bfd8ad2` (SELF_INSTALL still `['darwin']`;
updater inert). Design: `kosmos-scripts/win32-updater-design.md` (§1, §4, §5, §6b, §7-S4, §9).
Brief: `kosmos-scripts/brief-win32-update-arm-S4.md`.

This slice flips the updater on: `SELF_INSTALL` gains win32, `installedRoot()`/`beginInstall`/
`maybeAutoInstall` grow win32 arms that drive the S3 board-side entrypoint
(`win32update.begin()`), the status carries channel + phase + the win32 outcome record, and the
Settings card / confirm / overlay show honest Windows wording. Nothing auto-cuts a build; the
next Windows build cut from main after this merges carries a LIVE updater.

## The S4 build

### 1. platform.js
- `SELF_INSTALL = Object.freeze(['darwin', 'win32'])`. Keep frozen. Update the doc comment (win32
  now self-installs because the S2-S4 updater exists).

### 2. update.js
- `installedRoot()`: add a win32 arm returning `windowsBundleRoot()` (null on source checkout).
- New `windowsLocationRefusal()`: on win32 with a bundle root, delegate to
  `win32update.unusualLocationRefusal(root, process.env, cache.base || releaseBase())` (lazy
  require, cycle-safe). Sentence or null. THE single client-facing surface of the ONE named rule.
- New `installOffer()`: `installedRoot() && !windowsLocationRefusal() ? available() : null` — the
  [Update] offer. One derivation for both status call sites and the install route.
- `manualOffer()`: keep the source-checkout guard (null when no bundle root); ADD `if
  (!windowsLocationRefusal()) return null;` so a normal armed bundle shows [Update], and only a
  OneDrive/Program Files bundle shows the manual download.
- `beginInstall` win32 branch (`beginWindowsInstall`): after single-flight + fresh lastAttempt,
  call `win32update.begin({ root: installedRoot(), port, boardPid })` via a `windowsInstallerFn`
  seam. On `{ok:false}` release single-flight, record `because` on lastAttempt, set `autoFailedAt`
  when `opts.auto`. On `{ok:true}` leave single-flight set (helper will stop+restart this board).
  Board port/pid come from a new `setBoardContext({port,pid})` the server calls at listen time.
- `maybeAutoInstall`: unchanged logic — now reaches the win32 branch via installedRoot()/beginInstall.
- `updatePhase()`: win32 only — `win32apply.readJournal(journalPathFor(anchorDir)).journal.phase`
  or null.
- `lastAttemptView()` win32 arm: when no Mac record, read the win32 update-status.json
  (`win32apply.statusPathFor(anchorDir)`) and map its outcome to the `{startedAt,endedAt,code,
  because,log}` shape the overlay reads (`code` non-zero on a failed/stuck outcome so
  `updateVerdict` says 'failed'; null log).
- Exports: `installOffer`, `windowsLocationRefusal`, `updatePhase`, `setBoardContext`,
  `setWindowsInstaller`.

### 3. server.js
- Status (3247/3253): `update: updates.installOffer()`, add `updatePhase: updates.updatePhase()`.
- Check route (8198): `offer: updates.installOffer()`.
- Install route (8219): after the `selfInstallRefusal`/`installedRoot` arms, add
  `const loc = updates.windowsLocationRefusal(); if (loc) 409 {error: loc}` (readable refusal for a
  OneDrive/Program Files bundle — belt-and-braces; status already shows manual there).
- Real-start block (~13052): `updates.setBoardContext({ port: server.address().port, pid:
  process.pid })` next to `startPolling`.

### 4. web/index.html (Mac byte-identical via the copy layer)
- Confirm `#uc-small` (8656): add `data-win-copy="updateConfirmBody"`; table key
  `updateConfirmBody` = "Kosmos downloads the update, then closes for a few seconds while it swaps
  it in. <b>Your agents keep working the whole time.</b>". Mac inline text unchanged.
- Overlay initial lead: `onWindows()` → `<b>Downloading {body.updating}.</b> Your agents keep
  working.`; Mac branch keeps the exact `<b>Updating.</b> Your agents keep working.` bytes.
- Overlay poll loop: on Windows, set the `<b>` lead per reachability — reachable = "Downloading X.",
  unreachable (swap) = "Updating." — and skip the Mac 'slow' "Still updating." relabel on Windows.
- `settle()` failure/slow copy: Windows-ize via `platformCopy`. did-not-take/failed →
  "...Kosmos is still on Y. Nothing else was changed." (design/brief); slow → the Windows
  "double-click Kosmos.exe in your Kosmos folder." instead of "open it again from Applications".
  Add table keys (`updateStillOn`, `updateSlowRemedy`).
- Card: no change needed — a normal win32 bundle now arrives with `update` (offer) set, so the
  existing offer arm paints "Version X is ready." [Update]; a OneDrive/Program Files bundle arrives
  with `updateManual` set and paints the existing manual arm. Staging label already handled.

### 5. Channel (design §6b) — confirm, don't rebuild
`KOSMOS_UPDATE_CHANNEL=staging` (win32 ignores AGENT_WORKFORCE_*), `KOSMOS_RELEASE_BASE` honoured,
channel in status + boot log, unreachable staging never falls back to prod. All S1; a test confirms
it holds once armed.

  during the swap (the board is down then). Honest but coarse; recorded here.

  on win32, so the armed win32 path does not call it; no Windows banner exists yet.
