# Plan: assert the pinned Playwright version in the page gate (kosmos#1708)

## Problem

The release page gate (`tools/browser-checks.sh`) launches Playwright to render
pages during a cut. #1594 pinned the Playwright version in
`tools/provision-pw.sh` (`PW_VERSION`) and stopped the PROVISION step drifting
(`--save-exact`), but the gate only ever checked that *a* Playwright could
launch, never that it was the pinned one. A drifted `pw-runtime` (a bare
`npm i` there resolves a newer 1.6x) launches fine and silently renders on a
different browser build. Splinter's framing: "the risk is unpinned, not
unexecuted." The gate had to RE-check the version at run time.

## Approach

1. **Assert the version in the gate.** After resolving the runtime, read the pin
   from its single source of truth (`tools/provision-pw.sh` via the freeze-aware
   `$REPO`) and parse the resolved runtime's `playwright/package.json` version
   with node. Compare.
   - Default: a mismatch or an unreadable version WARNS loudly (names both
     versions, points at `provision-pw.sh`) and continues to the launch check.
   - `KOSMOS_PW_STRICT_VERSION=1`: hard-stop (exit 2), including on an
     UNVERIFIABLE version (unverified is not verified-pinned; a fail-closed flag
     must not fail open).

2. **Enforce in the cut.** `tools/release.sh` invokes the gate with
   `KOSMOS_PW_STRICT_VERSION=1`, so a drifted or unpinned build fails the cut.
   Manual dev runs stay warn-only. This is a deliberate operational tightening:
   a release machine relying on an unpinned npx-cache Playwright will hard-fail
   until `provision-pw.sh` is run. Recovery is one command.

3. **Functional test** (`tools/test-pw-version-assert.sh`, wired into
   `test:shell`): drive the gate with a fake runtime carrying a chosen version.
   The complete STRICT matrix: non-strict-warn (two-arm control), STRICT-drift-
   stop, STRICT-unreadable-stop, STRICT-match-proceed, plus a wiring guard so the
   enforcement cannot become dead code in the cut via a refactor.

## Checklist

- [x] Version-assert block in `tools/browser-checks.sh` (warn default, STRICT hard-stop, fail-closed on unreadable)
- [x] `tools/release.sh` enforces STRICT for the cut; default stays warn
- [x] 6-case functional test, each arm red-capability verified
- [x] Wire the test into `test:shell`
- [x] Challenge-loop to convergence + proof file
- [x] Operational caveat documented in the PR body

## Out of scope / decided

- Not softening the npx-cache tightening (would reintroduce the drift the card
  exists to catch). Documented as an operational note instead.
- Auto-provisioning the runtime inside the cut (a network install every cut) is a
  separate, heavier decision; the current design relies on a pre-provisioned
  runtime and enforces the pin.
