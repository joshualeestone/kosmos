# render-talk's clock arm checks the #3966 contract, not the rewrite #3966 removed

**Branch:** `talkclock-0701` · Blocks the Mac 0.7.01 staging cut (3b red, 2026-09-26 21:48 CDT)

## What happened

The 0.7.01 cut aborted at 3b on one check, render-talk, in both themes and twice:
"clock: a minute passing did not change the markup, so the rewrite is UNCHECKED".

5a2aae1e3 (#3958/#3966/#3991, "threads stop flashing", merged after 0.6.99) made `setThread` compare
the thread by SHAPE (`threadShape` blanks the `.mwhen` words and ring arcs), so a change in the time
words alone is no longer a rewrite: `refreshWhens` updates those words in place. That is the intended
fix for the flash. render-talk's clock arm still required a rewrite as its control, so it fires by
design. A stale check, not a product bug. That PR's CI never ran render-talk (the PR-time browser job
runs a subset); the nightly and the 0.6.99 cut both ran before it merged.

## Decision

The clock arm now checks the new contract after a repaint where only the clock moved (+120s):
- the thread was NOT rewritten (`__lastThread` unchanged and the same first child element);
- CONTROL: the time words DID move (the repaint saw the later clock), else the arm is unchecked;
- a reader parked at the floor is still at the floor (distance from the floor, within 1px, so a
  longer time phrase that wraps a line cannot read as a move). Only the at-floor case is covered; the
  scrolled-back anchor path (#1926) has its own check (render-talk-anchor-1926).

The comment's sentence that said `setThread` rewrites `innerHTML` is replaced with what #3966 does.

**Rejected:** deleting the arm (it is the only check that a time-only repaint does not move a
reader), and keeping the old rewrite control with the failure downgraded (it would check nothing).

## Evidence (this Mac, render-talk run directly)

- Current page: passes, 0 clock problems.
- Red 1, scratch copy with `threadShape` returning the whole markup (the pre-#3966 rewrite): fails,
  "a repaint where only the time moved REWROTE the thread", both themes.
- Red 2, scratch copy with `refreshWhens` a no-op: fails the control, "the time words did not move
  (a minute ago -> a minute ago)", both themes.

## Weakest premise

That `t.firstElementChild` identity is a sound second signal of "not rewritten". An innerHTML write
replaces every child, so the same first child means no write; a future partial update that leaves the
first row in place would still pass this arm, which is the intent (it is about the flash of a full rewrite).
