Josh ruled YES on push (2026-09-24 13:41 CDT): "100% the main reason we want mobile
apps is for push notifications." Kano leads. Liu Kang's design calls, checked against

## Finished means
1. With phone notifications OFF (the default), nothing about agents leaves the Mac.
   Proven by a test with a counting sender, not by reading the code.
2. A person turns them on from Settings, subscribes a phone on the coordinator's page,
   and when an agent reports needs_you a real notification lands on that phone.
3. Tapping it opens that Mac's board.
4. Turning it off stops all sending at once.

## Decisions
- **Subscribe path: option C.** The phone subscribes on the coordinator's own page
  ("Notify me on this phone", coordinator/src/signin.html). The board's Settings links
  there. No new security surface. Under C nothing calls the board's own `/v1/push/*`
  routes, so the vapid-key proxy, the subscribe 501 and the board-origin subscribe
  flow in the Settings client (#3520) are removed rather than left looking live.
  Option A would bring them back from history.
- **The gate is a switch on the Mac, off by default. That differs from "send only when a
  phone has opted in"**, because the Mac cannot see phone subscriptions: they live on
  the coordinator, and no Mac route reports them. Turning the switch on is part of the
  same Settings step that sends the person to subscribe a phone. Follow-up if wanted: a
  Mac-signed coordinator route that reports whether the account has any subscriptions,
  so a Mac with the switch on but no phone also stops sending.
- **needs_you pushes on the change INTO needs_you**, not on every repeat report (the
  deleted notify.js pushed on every one). The project name is sent when the report
  names a project.
- **Events: needs_you and replied.** needs_you is the reason push exists. replied is an
  agent answering the person in their own thread, so it is addressed to them. Not
  posted (room chatter would buzz constantly) and not check_in (heartbeat). All three of
  needs_you, replied and posted are in the coordinator's KINDS, so this is a board
  choice and one line to change.
- **Payload is the coordinator's EventReq and nothing more:** agent name, session name,
  project name (needs_you, when the report names one; null for replied), event id,
  time, kind, plus a notify install id the credential is bound to. No message text. The coordinator adds the Mac address
  itself.
- **The notify install id is NOT ping.installId().** #2631 kept installId() on the
  promise that it "never leaves the Mac". Push mints its own random id, used only to bind
  the notify credential.
- **Credential:** the coordinator mints a notify-only token at
  `POST /v1/mac/notify-credential`, which needs the Mac's signature. Only the
  kosmos-tunnel binary signs (the board keeps "NO CRYPTO HERE"), and it has no verb for
  this. So: **a new tunnel verb in kosmos-relay** that mints and prints the token on
  stdout. The board stores it owner-only in the remote state dir and never logs it.
- **Sender:** fire and forget, never throws, never sends under node --test without an
  injected sender, and sends only when switch ON + enrolled + credential present.

## Review-driven changes (challenge loop)
- Caps are counted in UTF-8 bytes (the coordinator's `String::len`), never cutting a
  character.
- Turning on always mints a fresh token (the coordinator keeps the latest, so a token it
  no longer knows is never reused), and only one turn-on runs at a time.
- A tunnel too old for `mac-request` says this computer needs an update, rather than
  blaming Kosmos+.
- At most one needs_you buzz per agent per 5 minutes: permission prompts file a
  needs_you each, so a busy session would otherwise buzz on every one. Replies are not
  limited.
- needs_you carries the agent's current project (carried forward when the report
  names none), by name.

## History
Before 2026-09-24 this branch (Raiden) stored subscriptions on the Mac
(`engine/pushsub.js`) and then pivoted to thin `/v1/push/*` proxies. Both were dropped:
the Mac never holds a phone's session token (the tunnel gate forgets it), and under
option C the phone subscribes on the Kosmos+ page. #3520's board-origin subscribe flow
was retired with them; option A would bring it back from git history.
