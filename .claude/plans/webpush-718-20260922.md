## Goal
Wire the outbound web-push SEND path from the Mac using existing VAPID keys in the coordinator. A push sent from the Mac reaches an installed PWA.

## Definition of Done
- Mac-side subscription storage: subscriptions persisted locally
- `/v1/push/subscribe` endpoint: receives and stores client subscriptions
- `/v1/push/vapid-key` endpoint: exposes public VAPID key for client
- Push delivery: events fan out to stored subscriptions
- End-to-end test: push from Mac → arrives in client PWA
- PR with code comments, passes `/challenge-loop`

- Call coordinator's `fan_out()` logic to send to each subscription
- Coordinator handles encryption, VAPID JWT, and push service delivery

## Coordinator Contract
From `coordinator/src/push.rs`:

**POST /v1/push/subscribe**
- Request: `{ endpoint: "https://...", keys: { p256dh: "...", auth: "..." } }`
- Headers: `Authorization: Bearer <session-token>`
- Response: `{ ok: true }`
- Role: Stores subscription for authenticated device

**GET /v1/push/vapid-key**
- Response: `{ key: "<base64url-uncompressed-P256-point>" }`
- No auth required
- Role: Public key for `PushManager.subscribe()`

**Unsubscribe**: `/v1/push/unsubscribe` (DELETE)

## Risks & Tradeoffs
- **Subscription scope**: Per-account (all devices of one account). Kano confirms shape.
- **VAPID key caching**: Fetch once on startup, cache for app lifetime. Coordinator key rotation is rare; operator restart re-fetches.
- **Push service failures**: Coordinator handles 404/410 (dead subscriptions), logs others.

## Notes
- Coordinator already handles encryption (RFC 8291) and VAPID JWT (RFC 8292).
- Mac is outbound-only; subscriptions are POSTed TO the coordinator, not hosted on Mac.
- No inbound push service connection needed; coordinator reaches push services directly.

## Status 2026-09-24 (Kano): PARKED on two rulings, do not merge

Rebased onto main. `GET /v1/push/vapid-key` is wired for real (`engine/pushvapid.js`,
coordinator key, cached on success only, plain 502 on failure, tested in
`server.push-proxy-718.test.js`). `POST /v1/push/subscribe` is a deliberate 501.

Why subscribe is not wired: the contract above assumed the board holds the phone's
coordinator session token. It does not. The tunnel gate forgets the KST once the
phone is admitted and forwards no device identity to the board
(kosmos-relay `crates/tunnel/src/gate.html`, `proxy.rs`), and the coordinator's
subscribe requires `Bearer <phone session KST>`. Options sent to Liu Kang/Splinter:
A) tunnel injects a verified device header + new Mac-cert-authenticated coordinator
route; B) keep the KST in the tab (rejected, reverses the gate's deliberate forget);
C) drop board-origin subscribe and use the coordinator sign-in page's existing
"Notify me on this phone" (a tap opens `https://<mac>.<domain>/`, per
coordinator `sw.js` + `notify.rs:193`, reasoned from source, not measured on a phone).

Bigger blocker: no Mac sends events any more. `engine/notify.js`, the only caller of
the coordinator's `POST /v1/mac/notify`, was deleted on 2026-09-09 as a privacy call
(#2623, PR #2631, 7d0ff983). Until Josh rules on bringing it back (opt-in, off by
default) or shelving push, nothing reaches any phone whichever option is chosen.
