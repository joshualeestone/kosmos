## Coordinator Contract
From `coordinator/src/push.rs`:

**POST /v1/push/subscribe**
- Request: `{ endpoint: "https://...", keys: { p256dh: "...", auth: "..." } }`
- Headers: `Authorization: Bearer <session-token>`
- Response: `{ ok: true }`
- Role: Stores subscription for authenticated device

**GET /v1/push/vapid-key**
- Response: `{ key: "<base64url-uncompressed-P256-point>" }`
- No auth required
- Role: Public key for `PushManager.subscribe()`

**Unsubscribe**: `/v1/push/unsubscribe` (DELETE)

## Risks & Tradeoffs
- **Subscription scope**: Per-account (all devices of one account). Kano confirms shape.
- **VAPID key caching**: Fetch once on startup, cache for app lifetime. Coordinator key rotation is rare; operator restart re-fetches.
- **Push service failures**: Coordinator handles 404/410 (dead subscriptions), logs others.

## Notes
- Coordinator already handles encryption (RFC 8291) and VAPID JWT (RFC 8292).
- Mac is outbound-only; subscriptions are POSTed TO the coordinator, not hosted on Mac.
- No inbound push service connection needed; coordinator reaches push services directly.
